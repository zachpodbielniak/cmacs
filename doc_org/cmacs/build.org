* Quick Start

From a fresh clone, one command does everything — system packages,
=deps/= submodules, =autogen.sh=, =configure= with the full cmacs flag
set, and the build:

#+begin_example
just bootstrap            # system packages + submodules + configure + build
just run                  # run it (sets CMACS_MODULE_DIR for cmacsgi)
#+end_example

=just bootstrap= is idempotent, so re-running it on an already-built
tree is cheap.  The package step is the only one needing =sudo=; set
=CMACS_SKIP_INSTALL_DEPS=1= to skip it (CI without passwordless sudo,
an immutable host, or a container with the packages already baked in)
and bootstrap runs unattended, reporting what is present instead.

The equivalent by hand:

#+begin_example
./install-deps --system   # system packages (Fedora, Ubuntu, Arch, macOS, FreeBSD)
git submodule update --init --recursive   # populate deps/
./autogen.sh              # first time only
./configure               # auto-detects bundled deps in deps/
make -j$(nproc)           # builds deps + emacs
#+end_example

If a build fails on a missing library, ask for the whole list at once
rather than rebuilding to discover them one at a time:

#+begin_example
just check-deps           # or: ./install-deps --check
#+end_example

That checks the *pkg-config modules and tools the build actually uses*
(not package names, which drift between releases), and separates the
ones that fail the build from the ones that merely narrow a feature.

=just run= is preferred over =src/emacs= directly: it exports
=CMACS_MODULE_DIR= so the =cmacsgi= bacon builtin loads when you do
=M-x bacon=.  Bare =src/emacs= still works for plain editing; it
just won't have =cmacsgi= available in the bacon shell.

** Distro detection

=install-deps= picks its package list from =/etc/os-release=: =ID=
first, then each word of =ID_LIKE=, then (as a last resort) whichever
of =pacman=, =apt-get= or =dnf= is on =PATH=.  Derivatives therefore
work without being named explicitly — Omarchy, CachyOS, Garuda and
EndeavourOS resolve to Arch; Nobara and Bazzite to Fedora; Pop!_OS,
Mint and Zorin to Debian.

Package *names* are resolved against the local package index before
anything is installed, for two reasons:

- Where a distro versions a name, the newest supported one wins.
  Arch has no unversioned =wlroots= package at all (only =wlroots0.20=,
  =wlroots0.19=, …), Debian versions =libwlroots-0.NN-dev=, and
  =libgccjit-NN-dev= tracks the default GCC.  These are probed, not
  hard-coded.
- A name this release does not carry is *skipped with a warning*
  instead of aborting.  =apt=, =pacman= and =dnf= all fail the entire
  transaction on one unknown package, which would otherwise install
  none of the ~90 packages that were fine.

** Runtime feature flags: =IS-CMACS-*=

For every =--with-cmacs-<name>= / =--enable-cmacs-<name>= option, cmacs
exposes an always-bound Lisp variable =IS-CMACS-<NAME>= (plus a
lower-case alias =is-cmacs-<name>=) that is =t= when the subsystem was
compiled into this build and =nil= otherwise.  A config can branch on
features without a =void-variable= error:

#+begin_src emacs-lisp
(when IS-CMACS-AI
  (global-set-key (kbd "C-c a a") #'cmacs-ai-call))

(when is-cmacs-gowl                 ; the lower-case alias works too
  (cmacs-gowl-mode 1))
#+end_src

The flags reflect *compile-time* configuration only.  The full set of
compiled-in subsystems is =(cmacs-compiled-features)= (a list of
symbols matching the =--with-cmacs-<name>= options);
=(cmacs-feature-p 'video)= additionally applies a runtime availability
check for a few media subsystems (GStreamer element present, GL
available, ...).

The variables are defined even in an upstream-shaped build with every
cmacs feature off (they all read =nil= there), so a config is portable
across builds.  Names cover every option: =IS-CMACS-GLIB=,
=IS-CMACS-GI=, =IS-CMACS-CRISPY=, =IS-CMACS-BACON=, =IS-CMACS-GOWL=,
=IS-CMACS-PODOMATION=, =IS-CMACS-LIBRECLAW=, =IS-CMACS-AI=,
=IS-CMACS-LIBREGNUM=, =IS-CMACS-LRGTERM=, =IS-CMACS-IMGEDIT=,
=IS-CMACS-VIDSTUDIO=, =IS-CMACS-GNUSEYE=, =IS-CMACS-ROAMGRAPH=,
=IS-CMACS-CAD=,
=IS-CMACS-SCREENSAVER=, =IS-CMACS-GSURF=, =IS-CMACS-GSURF-LRG=,
=IS-CMACS-EMACSCTL=, =IS-CMACS-ORG-EX=, =IS-CMACS-MCP=,
=IS-CMACS-PRINT=, =IS-CMACS-VIDEO=, =IS-CMACS-AUDIO=,
=IS-CMACS-WHISPER=, =IS-CMACS-PIPER=, =IS-CMACS-CINTROSPECT=,
=IS-CMACS-CPATCH=.

** LibreClaw dependencies

LibreClaw drags in a larger dependency graph than the other cmacs
subsystems because it speaks multiple messaging protocols:

- =libsoup-3.0= — Matrix Client-Server API via HTTP long-poll
- =json-glib-1.0= — Matrix JSON payloads
- =libcmark= — Markdown → HTML for rich message bodies
- =sqlite3= — audit log backend
- =libetpan= — IMAP / SMTP for the email channel
- =libpq= — optional PostgreSQL audit backend
- =yaml-0.1= — YAML configuration (via libreclaw's bundled
  yaml-glib; cmacs dedups this at link time via the
  =_libreclaw_strip= logic in =src/Makefile.in=)

On Fedora: =libsoup3-devel json-glib-devel libcmark-devel
sqlite-devel libetpan-devel libpq-devel libyaml-devel=.
On Debian/Ubuntu: =libsoup-3.0-dev libjson-glib-dev libcmark-dev
libsqlite3-dev libetpan-dev libpq-dev libyaml-dev=.

** libcmacs-api.so

The CMacs API shared library is always built from =cmacs/api/=.  It
depends on:

- =glib-2.0=
- =gobject-2.0=
- =gio-2.0=
- =json-glib-1.0=

It does *not* depend on Emacs internals, bacon, or crispy.

** Bacon modules (cmacs_gi, cmacs_pod)

Built automatically by the top-level =make= when both
=--with-cmacs-bacon= and =--with-cmacs-gi= are enabled
(=src/Makefile.in= adds =$(CMACS_BACON_MODULES)= to the =all=
target).  =make install= installs both =.so= files to
=$prefix/lib64/bacon/modules/= (or =lib/bacon/modules/= on
systems without =/usr/lib64=) --- no separate step required.

To rebuild them in isolation during development:

#+begin_example
make -C cmacs/bacon/modules
#+end_example

This automatically builds =libcmacs-api.so= first.  To install
after a dev rebuild without re-running a full =make install=:

#+begin_example
sudo install -d /usr/local/lib64/bacon/modules
sudo install -m 644 cmacs/bacon/modules/cmacs_gi.so \
                    cmacs/bacon/modules/cmacs_pod.so \
                    /usr/local/lib64/bacon/modules/
#+end_example

If the modules are missing after =sudo make install=, check that
=./configure= actually enabled both features --- grep
=config.status= for =CMACS_BACON_OBJ= and =CMACS_GI_OBJ=; both
must be non-empty.

** Embedded dependency documentation

Each dependency under =deps/= ships its own =docs/= folder.  The
=cmacs-deps-docs= Makefile target (a prerequisite of =actual-all=, so it
runs on every =make=) invokes =tools/sync-deps-docs.sh=, which mirrors
each =deps/<dep>/docs/= tree verbatim into =doc_org/cmacs/deps/<dep>/=.
That tree is installed and browsed with the rest of the manual (see the
Dependency Documentation section of the CMacs Manual index).

Key points:

- The generated =doc_org/cmacs/deps/= tree is a *build artifact*: it is
  =.gitignore=-d and refreshed from the current submodule checkouts on
  every build.  Regenerate it manually with =tools/sync-deps-docs.sh=.
- Files are copied as-is --- =.org= and =.md= alike --- so no Markdown
  conversion or extra build dependency is required.
- The script is a clean no-op on a tree without =deps/=, so an
  upstream-style build is unaffected.

* Static Library Deduplication

Crispy and yaml-glib objects are vendored in multiple static archives
(=libcrispy.a=, =libbacon-1.0.a=, =libgowl.a=), potentially compiled
from different git commits.  The build system in =src/Makefile.in= strips
duplicate objects from downstream archives before linking.

#+begin_quote
*Warning*: Do NOT use =-Wl,-z,muldefs= --- it silently picks one
implementation of duplicated symbols, causing ABI mismatches and
non-deterministic crashes.
#+end_quote

* Building on Ubuntu 24.04 / older hosts

gowl builds against wlroots *0.19 or 0.20* (newest present wins; pin with
=make WLROOTS=0.19=).  wlroots 0.20 is recommended --- it unlocks
per-window screencast capture (the "share a specific window" option);
0.19 gives monitor-only capture.  See =deps/gowl/docs/building.org=
section "wlroots version" for the trade-off and the Ubuntu 24.04
build-wlroots-from-source recipe.

Ubuntu 24.04 LTS (noble) --- and other distributions that have not
yet caught up --- ship versions of several gowl dependencies that are
too old to satisfy =pkg-config --exists wlroots-0.19= (let alone 0.20).
Noble specifically ships:

| Package            | Noble version | Gowl requires |
|--------------------+---------------+---------------|
| =wlroots=          | 0.17          | >= 0.19 (0.20 for window capture) |
| =wayland=          | 1.22          | >= 1.23.1     |
| =wayland-protocols= | 1.34         | >= 1.38       |
| =pixman=           | 0.42          | >= 0.43       |
| =libdex=           | 0.6.0 (universe) | any        |

Because gowl's =config.mk= queries all required pkg-config modules
in a single invocation, a single missing package causes
=pkg-config --cflags= to return an empty string, which then cascades
into a =fatal error: glib.h: No such file or directory= when the
vendored =yaml-glib= sources are compiled.  The real fix is to
satisfy the version gates, not to patch the include paths.

** Recipe

First run =./install-deps --system=.  It installs every cmacs
dependency =apt= can provide on your release --- including the full
LibreClaw set (=libcmark-dev=, =libpq-dev=, =libsqlite3-dev=,
=libdex-dev= from =universe=, …) --- and prints a =WARNING= listing
any package that is not in your apt repos instead of aborting the
whole install.  If =libdex-dev= shows up in that warning, enable
=universe= and re-run:

#+begin_example
sudo add-apt-repository universe && sudo apt-get update
./install-deps --system
#+end_example

The only dependencies =apt= cannot satisfy on noble are the gowl
stack (wlroots / wayland / wayland-protocols / pixman), which noble
ships too old.  Install the extra build tools for those, including
the mcp and podomation runtime deps that are sometimes overlooked:

#+begin_example
sudo apt install \
  meson ninja-build pkg-config \
  libglib2.0-dev libjson-glib-dev libsoup-3.0-dev libetpan-dev \
  libdrm-dev libxkbcommon-dev libudev-dev libinput-dev \
  libseat-dev libdisplay-info-dev libliftoff-dev hwdata \
  libgbm-dev libvulkan-dev glslang-tools \
  libxcb1-dev libxcb-composite0-dev libxcb-ewmh-dev \
  libxcb-icccm4-dev libxcb-render-util0-dev libxcb-res0-dev \
  libxcb-xinput-dev
#+end_example

Then build the out-of-date components into =/usr/local=, in
dependency order.  Each step uses the same pattern:

#+begin_example
# 1. wayland >= 1.23.1
git clone https://gitlab.freedesktop.org/wayland/wayland.git
cd wayland && git checkout 1.23.1
meson setup build --prefix=/usr/local -Ddocumentation=false -Dtests=false
ninja -C build && sudo ninja -C build install

# 2. wayland-protocols >= 1.38
git clone https://gitlab.freedesktop.org/wayland/wayland-protocols.git
cd wayland-protocols && git checkout 1.38
meson setup build --prefix=/usr/local -Dtests=false
ninja -C build && sudo ninja -C build install

# 3. pixman >= 0.43
git clone https://gitlab.freedesktop.org/pixman/pixman.git
cd pixman && git checkout pixman-0.44.0
meson setup build --prefix=/usr/local -Dtests=disabled
ninja -C build && sudo ninja -C build install

# 4. libdex --- OPTIONAL on noble: apt's universe libdex-dev (0.6.0)
#    satisfies the unversioned `pkg-config --exists libdex-1' gate.
#    Build from source only if you need a newer release.
git clone https://gitlab.gnome.org/GNOME/libdex.git
cd libdex && git checkout 0.9.1
meson setup build --prefix=/usr/local \
  -Dsysprof=false -Ddocs=disabled -Dexamples=false -Dtests=false
ninja -C build && sudo ninja -C build install

# 5. wlroots 0.19
git clone -b 0.19 https://gitlab.freedesktop.org/wlroots/wlroots.git
cd wlroots
meson setup build --prefix=/usr/local
ninja -C build && sudo ninja -C build install

sudo ldconfig
#+end_example

** PKG_CONFIG_PATH

Everything above installs under =/usr/local=, which is *not* on
Ubuntu's default pkg-config search path.  Export this in every
shell where you run =./configure= or =make= for cmacs, and in any
child build that re-invokes pkg-config (the cmacs top-level make
does not propagate it down to =deps/gowl= or =deps/podomation=
automatically):

#+begin_example
export PKG_CONFIG_PATH=/usr/local/lib/x86_64-linux-gnu/pkgconfig:/usr/local/lib/pkgconfig
#+end_example

Verify before rebuilding:

#+begin_example
pkg-config --modversion wlroots-0.19   # => 0.19.x
pkg-config --modversion libdex-1       # => 0.9.x
#+end_example

** Why gowl fails silently without this

=deps/gowl/config.mk= computes =CFLAGS_DEPS= with:

#+begin_example
CFLAGS_DEPS := $(shell $(PKG_CONFIG) --cflags $(DEPS_REQUIRED) 2>/dev/null)
#+end_example

=pkg-config --cflags= is all-or-nothing: if *any* module in the
list is missing, the command exits non-zero and (with =2>/dev/null=)
produces an empty string.  All the glib/gio/wayland include paths
then vanish from =CFLAGS=, and the first vendored =yaml-glib=
compile unit fails with a missing =glib.h=.  If you see that error,
run =pkg-config --print-errors --exists= on the full
=DEPS_REQUIRED= list to identify the missing module --- do not try
to patch the include paths directly.

* Known Issues

- The pdumper image must be regenerated after changes to temacs-linked
  code --- =make= handles this, but stale dumps cause confusing runtime errors
- Native compilation =.eln= cache is keyed by ABI hash --- version
  mismatches cause silent fallback to byte-compiled code.  Fix with:
  =rm -rf native-lisp/=
- =g_main_context_iteration= in =cmacs-glib-iteration= does NOT go
  through the =waiting_for_input= guard --- only use from Lisp code
  that knows Emacs is not in input-wait state
- Bacon =--bacon= mode forks the emacs process --- =fork()= safety
  constraints apply (no threads before fork)

** Expected failure: =emacs-tests/seccomp/allows-stdout=

Upstream's own suite (=make -C test src/emacs-tests=) has one test that
cmacs cannot pass.  It runs the editor under
=lib-src/seccomp-filter.bpf= and expects a clean exit; under cmacs the
process dies with =SIGSYS= ("Bad system call", exit 159).

This is expected, and structural rather than a regression: that filter
whitelists the syscalls an upstream-shaped Emacs makes at startup, and
cmacs links GLib, wlroots and the rest of the subsystem stack, whose
initialisation reaches outside that set before any Lisp runs.  Nothing
short of regenerating the filter against cmacs's actual syscall set
would change it, and nothing in cmacs depends on =--seccomp=.

When triaging a post-merge run, prove a suspect failure is pre-existing
the same way rather than assuming: the build leaves every previous
binary in =src/= as =emacs-32.0.50.N=, so run the failing command
against the newest one predating the merge.

#+begin_example
./src/emacs-32.0.50.142 --quick --batch \
    --seccomp=lib-src/seccomp-filter.bpf --eval '(message "Hi")'
#+end_example
