* Quick Start

From a fresh clone, one command does everything — system packages,
=deps/= submodules, =autogen.sh=, =configure= with the full cmacs flag
set, and the build:

#+begin_example
just bootstrap            # system packages + submodules + configure + build
just run                  # run it (sets CMACS_MODULE_DIR for cmacsgi)
#+end_example

=just bootstrap= is idempotent, so re-running it on an already-built
tree is cheap.  The package step is the only one needing =sudo=; set
=CMACS_SKIP_INSTALL_DEPS=1= to skip it (CI without passwordless sudo,
an immutable host, or a container with the packages already baked in)
and bootstrap runs unattended, reporting what is present instead.

The equivalent by hand:

#+begin_example
./install-deps --system   # system packages (Fedora, Ubuntu, Arch, macOS, FreeBSD)
just submodules           # populate deps/ (see One Copy of Each Dependency)
./autogen.sh              # first time only
./configure               # auto-detects bundled deps in deps/
make -j$(nproc)           # builds deps + emacs
#+end_example

If a build fails on a missing library, ask for the whole list at once
rather than rebuilding to discover them one at a time:

#+begin_example
just check-deps           # or: ./install-deps --check
#+end_example

That checks the *pkg-config modules and tools the build actually uses*
(not package names, which drift between releases), and separates the
ones that fail the build from the ones that merely narrow a feature.

To get the package *names* rather than have them installed --- to paste
into a Containerfile, an image build, a ticket, or another machine ---
=install-deps --packages= prints one ready-to-run install command and
nothing else on stdout:

#+begin_example
./install-deps --packages          # this machine's distro
./install-deps --packages arch     # sudo pacman -S --needed --noconfirm ...
./install-deps --packages debian   # sudo apt-get install -y ...
./install-deps --packages fedora   # sudo dnf install -y ...
./install-deps --packages macos    # brew install ...
./install-deps --packages freebsd  # sudo pkg install -y ...

just deps-list                     # the same, for this machine
just deps-list arch                # ... or another distro
#+end_example

Everything explanatory goes to stderr, so =just deps-list arch 2>/dev/null=
is a clean one-liner and =just deps-list | bash= works.  Neither make nor
just is required --- =install-deps= needs no configured tree, which is
the point, since the machine that needs the list is the one that cannot
build yet.

=just run= is preferred over =src/emacs= directly: it exports
=CMACS_MODULE_DIR= so the =cmacsgi= bacon builtin loads when you do
=M-x bacon=.  Bare =src/emacs= still works for plain editing; it
just won't have =cmacsgi= available in the bacon shell.

** Distro detection

=install-deps= picks its package list from =/etc/os-release=: =ID=
first, then each word of =ID_LIKE=, then (as a last resort) whichever
of =pacman=, =apt-get= or =dnf= is on =PATH=.  Derivatives therefore
work without being named explicitly — Omarchy, CachyOS, Garuda and
EndeavourOS resolve to Arch; Nobara and Bazzite to Fedora; Pop!_OS,
Mint and Zorin to Debian.

Package *names* are resolved against the local package index before
anything is installed, for two reasons:

- Where a distro versions a name, the newest supported one wins.
  Arch has no unversioned =wlroots= package at all (only =wlroots0.20=,
  =wlroots0.19=, …), Debian versions =libwlroots-0.NN-dev=, and
  =libgccjit-NN-dev= tracks the default GCC.  These are probed, not
  hard-coded.
- A name this release does not carry is *skipped with a warning*
  instead of aborting.  =apt=, =pacman= and =dnf= all fail the entire
  transaction on one unknown package, which would otherwise install
  none of the ~90 packages that were fine.

** Runtime feature flags: =IS-CMACS-*=

For every =--with-cmacs-<name>= / =--enable-cmacs-<name>= option, cmacs
exposes an always-bound Lisp variable =IS-CMACS-<NAME>= (plus a
lower-case alias =is-cmacs-<name>=) that is =t= when the subsystem was
compiled into this build and =nil= otherwise.  A config can branch on
features without a =void-variable= error:

#+begin_src emacs-lisp
(when IS-CMACS-AI
  (global-set-key (kbd "C-c a a") #'cmacs-ai-call))

(when is-cmacs-gowl                 ; the lower-case alias works too
  (cmacs-gowl-mode 1))
#+end_src

The flags reflect *compile-time* configuration only.  The full set of
compiled-in subsystems is =(cmacs-compiled-features)= (a list of
symbols matching the =--with-cmacs-<name>= options);
=(cmacs-feature-p 'video)= additionally applies a runtime availability
check for a few media subsystems (GStreamer element present, GL
available, ...).

The variables are defined even in an upstream-shaped build with every
cmacs feature off (they all read =nil= there), so a config is portable
across builds.  Names cover every option: =IS-CMACS-GLIB=,
=IS-CMACS-GI=, =IS-CMACS-CRISPY=, =IS-CMACS-BACON=, =IS-CMACS-GOWL=,
=IS-CMACS-PODOMATION=, =IS-CMACS-LIBRECLAW=, =IS-CMACS-AI=,
=IS-CMACS-LIBREGNUM=, =IS-CMACS-LRGTERM=, =IS-CMACS-IMGEDIT=,
=IS-CMACS-VIDSTUDIO=, =IS-CMACS-GNUSEYE=, =IS-CMACS-ROAMGRAPH=,
=IS-CMACS-CAD=,
=IS-CMACS-SCREENSAVER=, =IS-CMACS-GSURF=, =IS-CMACS-GSURF-LRG=,
=IS-CMACS-EMACSCTL=, =IS-CMACS-ORG-EX=, =IS-CMACS-MCP=,

** Embedded dependency documentation

Each dependency under =deps/= ships its own =docs/= folder.  The
=cmacs-deps-docs= Makefile target (a prerequisite of =actual-all=, so it
runs on every =make=) invokes =tools/sync-deps-docs.sh=, which mirrors
each =deps/<dep>/docs/= tree verbatim into =doc_org/cmacs/deps/<dep>/=.
That tree is installed and browsed with the rest of the manual (see the
Dependency Documentation section of the CMacs Manual index).

Key points:

- The generated =doc_org/cmacs/deps/= tree is a *build artifact*: it is
  =.gitignore=-d and refreshed from the current submodule checkouts on
  every build.  Regenerate it manually with =tools/sync-deps-docs.sh=.
- Files are copied as-is --- =.org= and =.md= alike --- so no Markdown
  conversion or extra build dependency is required.
- The script is a clean no-op on a tree without =deps/=, so an
  upstream-style build is unaffected.

* One Copy of Each Dependency

cmacs's deps bundle their own copies of deps cmacs already has.  Left
alone that is 128 submodule checkouts and about 8 GB for a fresh clone,
most of it never compiled --- and the copies disagree: crispy appeared at
five distinct commits, mcp-glib at five, yaml-glib at four, all linked
into one binary.  That is the hazard the next section papers over, so
the fewer copies reach it, the better.

Two mechanisms, and the first is the one that matters.

** Point the dep at the canonical copy

Every dep uses the three-file Makefile pattern, so every =config.mk=
carries =*_DIR= variables --- and a variable given on make's command line
beats the assignment in the makefile.  So a dep can simply be told where
the real copy lives:

#+begin_example
$(MAKE) -C deps/gsurf        LIBREGNUM_DIR=$(abspath deps/libregnum)
$(MAKE) -C deps/screensavers LIBREGNUM_DIR=$(abspath deps/libregnum)
$(MAKE) -C deps/libregnum    CAD=1 CAD_GLIB_DIR=$(abs_top_srcdir)/deps/cad-glib
$(MAKE) -C .../libreclaw     AI_GLIB_DIR=$(abs_top_srcdir)/deps/ai-glib
#+end_example

gsurf's own =config.mk= documents the convention: "An embedder (e.g.
cmacs) overrides =LIBREGNUM_DIR= ... so only ONE libregnum is ever linked
into the host."  Prefer this to anything else; it is the difference
between one library in the binary and two.

** Keeping a checkout current

=just pull= (an alias for =just sync=) rebases cmacs onto origin and then
runs =just submodules=, which is the half that moves the deps.
=just submodules= on its own populates deps/ at whatever commits are
*already pinned* and never fetches, so it completes an update rather than
being one.

Two things that update does which a bare =git submodule update
--recursive= does not:

- =git submodule sync --recursive= first, because a URL change in
  =.gitmodules= does *not* reach an already-cloned submodule --- git uses
  the URL cached in =.git/config= when it was first initialised, and the
  failure then reads as a stale pin rather than a stale URL.
- It reports directories left behind by a submodule that was removed
  upstream.  git unregisters those and does not delete them, so they
  linger as untracked checkouts that still look like deps.  It reports
  and never removes: the directory may hold work.

** Then stop cloning what nobody builds

An overridden copy is still cloned.  =SKIP_SUBMODULES= in the =Justfile=
lists those, as =<parent dir>=<submodule name>= pairs, and the
=submodules= recipe applies them before recursing.  It has to be a
per-repository config setting (=submodule.<name>.update none=) rather
than a flag, because =git submodule update --recursive= cannot exclude a
path below the top level --- and =sync= goes through the recipe for the
same reason, since a bare =--recursive= would undo it.

A skip is two settings, not one.  =update none= keeps a copy from being
checked out, but fetch recursion ignores it: git fetches any submodule
whose pointer an incoming commit moves, as long as its gitdir is present
in =.git/modules=, and a copy cloned before its skip keeps that gitdir.
Where the leftover has submodules of its own their worktrees are gone
too, and the recursing fetch dies on =cannot chdir= --- which is how a
pin bump in podomation broke =git fetch= there.  So each skip also sets
=fetchRecurseSubmodules false=, which makes a plain =git pull= safe once
the script has run, and =sync= and the script run their own pull and
updates without recursion, because on a tree that predates a skip the
first fetch happens before the script has configured it.

Together these take a fresh checkout from about 8 GB to under 4 GB, and
leave exactly one *build* of crispy, yaml-glib and mcp-glib where there
were five, six and four.

The rule has a compile-line half too.  cmacs's own objects name the
canonical header directories --- =deps/crispy/src= and
=deps/yaml-glib/src= --- in the bacon, podomation and libregnum CFLAGS,
never the bundled copies those deps would otherwise use.  Naming a
skipped copy is harmless while it is absent and wrong anywhere it is
not: a header from one commit, compiled against an archive built from
another.  Each such path also costs every object that uses it a
=-Wmissing-include-dirs= warning, which is how the last ones were found.

A dep can grow a new bundled copy in any pull.  ai-glib did in September
2026 (=278cfa4=, for its MCP control servers): every ai-glib object now
depends on =$(MCP_GLIB_DIR)/build/libmcp-glib-1.0.a=, so
=src/Makefile.in= hands its build =MCP_GLIB_DIR=, and each of the four
places ai-glib appears in the tree skips that copy.  Without the first
the build runs =make -C= in an empty directory; without the second the
next sync clones mcp-glib four more times.  The tell is a change to
=.gitmodules= in the incoming commits --- look for it before moving a
dep, not after the build fails.

*** Deps that vendor sources

=gowl=, =gsurf= and =bacon= do not link crispy's and yaml-glib's
archives --- they compile those *sources* into their own.  They take
=CRISPY_DIR=, =YAMLGLIB_DIR= and =MCP_GLIB_DIR= as build arguments like
everything else, so they are pointed at the canonical checkout too and
build nothing of their own.  A bare =make= in a standalone clone of any
of them still uses its own submodules.

Two things that took two attempts to get right there, both worth knowing
before touching those makefiles:

- Their source lists are *discovered*, not written down.  A curated list
  is fine while the copy is the submodule pinned beside it and silently
  wrong the moment the variable points at a newer one --- current crispy
  grew a temp registry, a pkg-config resolver and a use-parser, current
  yaml-glib a writer and a comment index, and the link failed on those
  symbols with nothing to say they were new files.  =main.c= and
  =crispy-repl.c= are excluded deliberately: the second pulls in
  readline, which a compositor should not link for a REPL it never
  opens.
- Object paths stay fixed under =OBJDIR= regardless of the variables, so
  switching copies leaves objects *and* =.d= files describing the other
  one.  A stale =.d= naming a source that no longer exists makes make
  fail during graph construction --- before any recipe could have
  cleaned it up --- so the guard is a *parse-time* check, not a rule:
  =-include= of the =.d= files happens at parse time too, and the guard
  has to win that race.

** =just deps-audit=, and why the third column is the whole point

=admin/cmacs-deps-audit.sh= classifies every nested checkout as *used* or
*UNUSED*, and says why: it was *built*, an ancestor's makefiles *name*
it, or a source *includes* a header from it.

Read the reason, not the size.  "Produces no library" is not "unused",
and two of these nearly went in the bin:

- =raygui=, =rres= and =rpng= are *header-only*, compiled straight into
  graylib's sources.  They build no archive of their own.  =raudio=,
  sitting right beside them, genuinely is unused.
- solvespace's =extlib/eigen= and =extlib/mimalloc= are used by
  *cad-glib*, whose Makefile compiles the solver itself with =-isystem
  $(SLVS_DIR)/extlib/eigen= --- from two levels above them.  An audit
  that only looks at the immediately containing repository calls both
  dead.

So the script searches every ancestor, and it *reports* rather than
asserting: a dep that starts using a bundled copy should surface as a row
changing, not as a build that silently picks the wrong copy.

* Static Library Deduplication

Crispy and yaml-glib objects are vendored in multiple static archives
(=libcrispy.a=, =libbacon-1.0.a=, =libgowl.a=), potentially compiled
from different git commits.  The build system in =src/Makefile.in= strips
duplicate objects from downstream archives before linking.

*Warning*: Do NOT use =-Wl,-z,muldefs= --- it silently picks one

non-deterministic crashes.
#+end_quote

gowl builds against wlroots *0.19 or 0.20* (newest present wins; pin with
=make WLROOTS=0.19=).  wlroots 0.20 is recommended --- it unlocks
per-window screencast capture (the "share a specific window" option);
0.19 gives monitor-only capture.  See =deps/gowl/docs/building.org=
section "wlroots version" for the trade-off and the Ubuntu 24.04
build-wlroots-from-source recipe.

Ubuntu 24.04 LTS (noble) --- and other distributions that have not
yet caught up --- ship versions of several gowl dependencies that are
too old to satisfy =pkg-config --exists wlroots-0.19= (let alone 0.20).
Noble specifically ships:

| Package            | Noble version | Gowl requires |
|--------------------+---------------+---------------|
| =wlroots=          | 0.17          | >= 0.19 (0.20 for window capture) |
| =wayland=          | 1.22          | >= 1.23.1     |
| =wayland-protocols= | 1.34         | >= 1.38       |
| =pixman=           | 0.42          | >= 0.43       |
| =libdex=           | 0.6.0 (universe) | any        |

Because gowl's =config.mk= queries all required pkg-config modules
in a single invocation, a single missing package causes
=pkg-config --cflags= to return an empty string, which then cascades
into a =fatal error: glib.h: No such file or directory= when the
vendored =yaml-glib= sources are compiled.  The real fix is to
satisfy the version gates, not to patch the include paths.

** Recipe

First run =./install-deps --system=.  It installs every cmacs
dependency =apt= can provide on your release --- including the full
LibreClaw set (=libcmark-dev=, =libpq-dev=, =libsqlite3-dev=,
=libdex-dev= from =universe=, …) --- and prints a =WARNING= listing
any package that is not in your apt repos instead of aborting the
whole install.  If =libdex-dev= shows up in that warning, enable
=universe= and re-run:

#+begin_example
sudo add-apt-repository universe && sudo apt-get update
./install-deps --system
#+end_example

The only dependencies =apt= cannot satisfy on noble are the gowl
stack (wlroots / wayland / wayland-protocols / pixman), which noble
ships too old.  Install the extra build tools for those, including
the mcp and podomation runtime deps that are sometimes overlooked:

#+begin_example
sudo apt install \
  meson ninja-build pkg-config \
  libglib2.0-dev libjson-glib-dev libsoup-3.0-dev libetpan-dev \
  libdrm-dev libxkbcommon-dev libudev-dev libinput-dev \
  libseat-dev libdisplay-info-dev libliftoff-dev hwdata \
  libgbm-dev libvulkan-dev glslang-tools \
  libxcb1-dev libxcb-composite0-dev libxcb-ewmh-dev \
  libxcb-icccm4-dev libxcb-render-util0-dev libxcb-res0-dev \
  libxcb-xinput-dev
#+end_example

Then build the out-of-date components into =/usr/local=, in
dependency order.  Each step uses the same pattern:

#+begin_example
# 1. wayland >= 1.23.1
git clone https://gitlab.freedesktop.org/wayland/wayland.git
cd wayland && git checkout 1.23.1
meson setup build --prefix=/usr/local -Ddocumentation=false -Dtests=false
ninja -C build && sudo ninja -C build install

# 2. wayland-protocols >= 1.38
git clone https://gitlab.freedesktop.org/wayland/wayland-protocols.git
cd wayland-protocols && git checkout 1.38
meson setup build --prefix=/usr/local -Dtests=false
ninja -C build && sudo ninja -C build install

# 3. pixman >= 0.43
git clone https://gitlab.freedesktop.org/pixman/pixman.git
cd pixman && git checkout pixman-0.44.0
meson setup build --prefix=/usr/local -Dtests=disabled
ninja -C build && sudo ninja -C build install

# 4. libdex --- OPTIONAL on noble: apt's universe libdex-dev (0.6.0)
#    satisfies the unversioned `pkg-config --exists libdex-1' gate.
#    Build from source only if you need a newer release.
git clone https://gitlab.gnome.org/GNOME/libdex.git
cd libdex && git checkout 0.9.1
meson setup build --prefix=/usr/local \
  -Dsysprof=false -Ddocs=disabled -Dexamples=false -Dtests=false
ninja -C build && sudo ninja -C build install

# 5. wlroots 0.19
git clone -b 0.19 https://gitlab.freedesktop.org/wlroots/wlroots.git
cd wlroots
meson setup build --prefix=/usr/local
ninja -C build && sudo ninja -C build install

sudo ldconfig
#+end_example

** PKG_CONFIG_PATH

Everything above installs under =/usr/local=, which is *not* on
Ubuntu's default pkg-config search path.  Export this in every
shell where you run =./configure= or =make= for cmacs, and in any
child build that re-invokes pkg-config (the cmacs top-level make
does not propagate it down to =deps/gowl= or =deps/podomation=
automatically):

#+begin_example
export PKG_CONFIG_PATH=/usr/local/lib/x86_64-linux-gnu/pkgconfig:/usr/local/lib/pkgconfig
#+end_example

Verify before rebuilding:

#+begin_example
pkg-config --modversion wlroots-0.19   # => 0.19.x
pkg-config --modversion libdex-1       # => 0.9.x
#+end_example

** Why gowl fails silently without this

=deps/gowl/config.mk= computes =CFLAGS_DEPS= with:

#+begin_example
CFLAGS_DEPS := $(shell $(PKG_CONFIG) --cflags $(DEPS_REQUIRED) 2>/dev/null)
#+end_example

=pkg-config --cflags= is all-or-nothing: if *any* module in the
list is missing, the command exits non-zero and (with =2>/dev/null=)
produces an empty string.  All the glib/gio/wayland include paths
then vanish from =CFLAGS=, and the first vendored =yaml-glib=
compile unit fails with a missing =glib.h=.  If you see that error,
run =pkg-config --print-errors --exists= on the full
=DEPS_REQUIRED= list to identify the missing module --- do not try
to patch the include paths directly.

* Container images

Building cmacs from source on a small machine is genuinely slow --- on
a two- or four-core box it runs for hours.  The container images exist
so that machine never has to: cmacs is built once, centrally, and the
result is unpacked onto the host.

The image is a =FROM scratch= stage holding only =/usr= and =/etc=, so
"installing" it is a copy.  That is also how immutablue consumes it
(=cp -a /mnt-cmacs/usr/. /usr/= in its own image build).

** Building

#+begin_example
./build-container                 # Fedora 44, the default
./build-container 44 --push       # Fedora 44   -> quay.io/.../cmacs:44
./build-container 24.04 --push    # Ubuntu 24.04 -> :24.04
./build-container 26.04 --push    # Ubuntu 26.04 -> :26.04
./build-container arch --push     # Arch Linux   -> :arch
#+end_example

There is one positional argument and no =--distro= flag to forget: the
target is inferred from its *shape*.

| Argument   | Base image                                  | Family |
|------------+---------------------------------------------+--------|
| =arch=, =archlinux= | =docker.io/library/archlinux:latest= | arch   |
| =NN.NN= (=24.04=)   | =docker.io/library/ubuntu:24.04=     | ubuntu |
| =NN= (=44=)         | =registry.fedoraproject.org/fedora:44= | fedora |

The tag is always =quay.io/zachpodbielniak/cmacs:<what you typed>=.
Override the registry with =REGISTRY==.  Anything after =--= is passed
straight through to buildah:

#+begin_example
./build-container arch -- --build-arg WLROOTS_VERSION=0.20
#+end_example

The Containerfile takes three arguments from the script ---
=BASE_IMAGE=, =CMACS_DISTRO=, =CMACS_RELEASE= --- and =CMACS_DISTRO=
selects the package manager.  Everything after the package install is
identical across distros, because it is all =make=.

** Why the package lists are in the Containerfile

The per-distro package lists live in the Containerfile rather than
calling =./install-deps=, deliberately.  A container needs things a
developer's machine already has (=curl=, =git=, =ca-certificates=) and
does not want things a developer does.  =install-deps= remains the
source of truth for the *host* install question, which is what
=just deps-list= answers.

** Ubuntu 24.04 and the bundled Wayland stack

Ubuntu 24.04 (noble) ships wlroots 0.17, wayland 1.22 and pixman 0.42;
gowl needs wlroots >= 0.19, which in turn needs wayland >= 1.23.1 and
pixman >= 0.43.  The builder therefore compiles wayland,
wayland-protocols, pixman and wlroots from source for that target ---
and *only* for that target.

The probe is on =pkg-config=, not on the distro version:

#+begin_example
if pkg-config --exists wlroots-0.20 || pkg-config --exists wlroots-0.19; then
        exit 0    # nothing to build
fi
#+end_example

so a release that starts shipping a new enough wlroots stops building
one without anyone editing the file.  Fedora 44, Arch and Ubuntu 26.04
all take the fast path today.

Two things about this are easy to get wrong, and both fail *silently*:

- *libdir.*  Installing to =/usr/lib= on Debian/Ubuntu does not shadow
  the distro's libraries --- =/usr/lib/<triplet>/pkgconfig= is searched
  first, so meson cheerfully reports "found 1.22.0 but need >=1.23.1"
  with a freshly built 1.23.1 sitting in =/usr/lib=.  The libdir is
  taken from =dpkg-architecture -qDEB_HOST_MULTIARCH=.
- *Staging.*  The final image is only =/build/stage=, so a library
  built here and installed into the builder's =/usr= is not in the
  image.  The result would link against wayland 1.23 symbols and land
  on a host that has 1.22.  Each component is installed twice: once
  into the builder so cmacs can build against it, and once into a
  scratch =DESTDIR= whose *libdir alone* is copied into the stage.
  Headers are deliberately left behind --- the image must not shadow
  the distro's wayland headers for anything else the user compiles.

libwayland and pixman have only ever added to their ABI, so the newer
copies satisfy every existing consumer, and wlroots 0.19 carries its
version in its soname and coexists with the distro's 0.17.  The one
standing caveat is that a later =apt upgrade= of =libwayland-server0=
repoints the soname symlink back at the distro's build; re-running
=install-from-container= puts it right, and the script says so when the
image it installed was one of the bundled-Wayland ones.

** Older distros diverge in ways a newer one cannot show you

Two build failures showed up only on Fedora 43, and both were invisible
on the machine where the code was written.  They are worth reading
together, because the shape is the same and it will happen again.

*** wlroots 0.19 wants protocol headers generated; 0.20 does not

wlroots *0.19* pulls generated protocol headers in by bare name:

#+begin_example
/* wlr/types/wlr_pointer_constraints_v1.h, wlroots 0.19 */
#include "pointer-constraints-unstable-v1-protocol.h"
#+end_example

so every consumer has to run =wayland-scanner= over the XML itself.
*0.20* replaced those with =#include <wayland-protocols/...-enum.h>=, a
header wayland-protocols now installs, so nothing needs generating.

gowl's =PROTO_HDRS= covered xdg-shell, wlr-layer-shell and cursor-shape
but not the three that came with pointer constraints, tablet v2 and
image-copy-capture.  On Fedora 43:

#+begin_example
wlr_pointer_constraints_v1.h:17:10: fatal error:
    pointer-constraints-unstable-v1-protocol.h: No such file
#+end_example

The reason nobody saw it: *gowl builds against the newest wlroots
present*, so a developer machine carrying both 0.19 and 0.20 always
compiles the 0.20 path.  It could only fail on a 0.19-only distro ---
which Fedora 43 is, and which Immutablue still ships.

=deps/gowl/tests/test-protocol-headers.sh= now walks *every installed*
wlroots version rather than the selected one, and asserts that each
protocol header a used =wlr/= header includes is in =PROTO_HDRS=.
Checking only the selected version would reproduce the original blind
spot exactly.

*** libeis 1.6 added an enumerator that 1.5 cannot be told about

=EIS_EVENT_SEAT_DEVICE_REQUESTED= arrived in libeis 1.6.  Fedora 43
ships 1.5, where naming it is a compile error.  The portal's Makefile
probes with =pkg-config --atleast-version=1.6 libeis-1.0= and the case
label is guarded to match.

Dropping the label on 1.5 is behaviour-neutral, which is why this is a
guard and not a version requirement: the enumerator does not exist
because the protocol version that emits it does not either, so a libei
1.6 client negotiating with a 1.5 server falls back to
=EIS_EVENT_SEAT_BIND= --- the label immediately above it, taking the
same branch.  KVM client mode keeps working on both.

*** The general rule

A build dependency that ships two coexisting versions will be resolved
to the newer one on any machine that has both, and the older path then
gets no coverage at all until it reaches a distro that has only the
older one --- typically inside a container build, which is the slowest
and least informative place to find out.

When a dependency spans versions, prefer a check that inspects *every
version installed* over one that inspects the one that would be chosen.
=just deps-list= and =just check-deps= report what is present;
=make WLROOTS=0.19= builds gowl against the older one explicitly, which
is far cheaper than a container round trip.

** Installing onto a host

#+begin_example
sudo ./install-from-container             # detect this distro, pull, install
sudo ./install-from-container             # ...and again, to update
./install-from-container --check          # is an update available?
./install-from-container --dry-run        # show what would change
sudo ./install-from-container arch        # force a target
./install-from-container --prefix /tmp/x  # unpack elsewhere, no root
sudo ./install-from-container --local     # use an already-pulled image
#+end_example

Or through =just=: =just install-from-container=, =just container-check=.

The target is detected from =/etc/os-release= with the same =ID= then
=ID_LIKE= fall-through =install-deps= uses, so derivatives resolve to
their base.

*** Updating is the same command

There is no separate update path.  A second run copies the new image
over the top and then *removes the files the previous image had and
this one does not*.

That prune step is the reason the install keeps a manifest at
=/usr/share/cmacs/container-manifest= --- every path it wrote, one per
line.  Without it a renamed library or a dropped module lingers
forever, and =ld.so= happily keeps loading it, which is a good deal
worse than a missing file: everything appears to work until it
doesn't.  =--no-prune= opts out.

The order matters and is deliberate: *copy first, prune second*.  A
crash between the two leaves a machine with both versions' files, which
still runs.  The other order leaves it with neither.  The manifest is
written last, so an interrupted install leaves the previous manifest in
place and the next run re-prunes from a state we know we wrote.

Only paths from our own manifest are ever considered for deletion, and
only regular files and symlinks --- never directories, and never
recursively.  An empty directory left behind is harmless; an installer
that removes directories recursively is one that eventually removes
something it does not own.

=--check= answers "is there anything new?" and touches nothing, exiting
0 when up to date and 1 when an update is available, so it composes:

#+begin_example
./install-from-container --check || sudo ./install-from-container
#+end_example

It compares the =built= timestamp rather than =version=, because
cmacs's version string moves rarely --- two images a week apart are
both =32.0.50=.

*** What it refuses, and why

Every image records what it was built from at
=/usr/share/cmacs/container-release=:

#+begin_example
distro=ubuntu
release=24.04
libdir=/usr/lib/x86_64-linux-gnu/cmacs
arch=x86_64
built=2026-09-07T18:04:11Z
version=32.0.50
bundled_wayland=yes
#+end_example

The installer compares that against *this machine* --- the family from
=/etc/os-release=, =uname -m=, and =VERSION_ID= --- and refuses on a
mismatch.  Comparing it against the image's own tag instead would be
circular: the tag and the image always agree, so such a check can never
catch the mistake that actually matters, which is unpacking an Arch
image onto a Fedora box.  Those binaries are linked against that
distro's libraries and the failure would otherwise surface much later
as an unresolved symbol, long after the command reported success.

=--force= overrides.  =--prefix DIR= skips the check entirely, because
unpacking into a directory is staging or inspection, not installing
onto this system.

*** Rootless

=--prefix= is meant to work without root, but =podman mount= needs a
user namespace when podman is rootless.  The script re-executes itself
once under =podman unshare= (guarded by an environment variable so the
second pass does not), and root skips that path.  =--local= also passes
=--pull=never= to =podman create=, which otherwise reaches for a
registry on its own when a name is missing locally --- so a typo'd tag
under =--local= would quietly pull instead of failing.

*** The libdir

The =libdir= is read off the staged tree at build time rather than
hardcoded, and is what =/etc/ld.so.conf.d/cmacs.conf= points at so
bacon modules can find =libcmacs-api.so=.  Fedora and Arch use
=/usr/lib64/cmacs= or =/usr/lib/cmacs=, Debian and Ubuntu
=/usr/lib/<triplet>/cmacs=; a wrong path here is silent, since
=ldconfig= will happily cache a directory that does not exist.

* Known Issues

- The pdumper image must be regenerated after changes to temacs-linked
  code --- =make= handles this, but stale dumps cause confusing runtime errors
- Native compilation =.eln= cache is keyed by ABI hash --- version
  mismatches cause silent fallback to byte-compiled code.  Fix with:
  =rm -rf native-lisp/=
- =g_main_context_iteration= in =cmacs-glib-iteration= does NOT go
  through the =waiting_for_input= guard --- only use from Lisp code
  that knows Emacs is not in input-wait state
- Bacon =--bacon= mode forks the emacs process --- =fork()= safety
  constraints apply (no threads before fork)

** Expected failure: =emacs-tests/seccomp/allows-stdout=

Upstream's own suite (=make -C test src/emacs-tests=) has one test that
cmacs cannot pass.  It runs the editor under
=lib-src/seccomp-filter.bpf= and expects a clean exit; under cmacs the
process dies with =SIGSYS= ("Bad system call", exit 159).

This is expected, and structural rather than a regression: that filter
whitelists the syscalls an upstream-shaped Emacs makes at startup, and
cmacs links GLib, wlroots and the rest of the subsystem stack, whose
initialisation reaches outside that set before any Lisp runs.  Nothing
short of regenerating the filter against cmacs's actual syscall set
would change it, and nothing in cmacs depends on =--seccomp=.

When triaging a post-merge run, prove a suspect failure is pre-existing
the same way rather than assuming: the build leaves every previous
binary in =src/= as =emacs-32.0.50.N=, so run the failing command
against the newest one predating the merge.

#+begin_example
./src/emacs-32.0.50.142 --quick --batch \
    --seccomp=lib-src/seccomp-filter.bpf --eval '(message "Hi")'
#+end_example
