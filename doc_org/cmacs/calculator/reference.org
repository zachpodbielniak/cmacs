This is the reference companion to [[file:index.org][the CMacs Calculator guide]], which explains the
corrected semantics you should read first.  Every knob here is a =defcustom= in
the =cmacs-calculator= group (=M-x customize-group RET cmacs-calculator=).  For a
per-function reference — every calculator with its arguments and worked
examples — see [[file:catalog.org][the function catalog]]; the GNU Calc built-ins have
[[file:builtins.org][their own catalog]] and the constants
[[file:constants.org][their own reference]].

* Engine options

| Option                                          | Default | Meaning                                                            |
|-------------------------------------------------+---------+--------------------------------------------------------------------|
| =cmacs-calculator-precision=                    | =12=    | Significant digits Calc computes with.  Arbitrary-precision: raising this costs time, not accuracy.  Matches Calc's own default and Org's. |
| =cmacs-calculator-angle-mode=                   | ='rad=  | =rad= / =deg= / =hms=.  Calc itself defaults to =deg=, which surprises anyone doing physics or calculus. |
| =cmacs-calculator-infinite-mode=                | =t=     | =1/0= ⇒ =uinf=, =0/0= ⇒ =nan=, =ln(0)= ⇒ =-inf=.  Nil signals instead. |
| =cmacs-calculator-multiplication-has-precedence= | =nil=  | =t= restores stock Calc's reading, where =2/3*4= means =2/(3*4)= = =0.1667=. |
| =cmacs-calculator-strict=                       | =t=     | Reject input Calc would silently accept (unbalanced delimiters, unknown functions, unbound variables), and reject unevaluated *results*. |

Modes pinned regardless of customization (=cmacs-calculator--fixed-modes=):
=calc-symbolic-mode= nil, =calc-prefer-frac= nil, =calc-number-radix= 10,
=calc-group-digits= nil, =calc-point-char= ".", and =calc-language= nil.

=calc-language= must stay =nil=: the =c= language would fix the division
precedence but redefines =^= as bitwise XOR, so =2^10= would stop meaning 1024.

* Evaluation API

| Function                                          | Returns                                                     |
|---------------------------------------------------+-------------------------------------------------------------|
| =(cmacs-calculator-eval EXPR &optional MODES)=    | Result *string*, numerically evaluated with corrected semantics.  Signals on bad input. |
| =(cmacs-calculator-eval-symbolic EXPR &optional MODES)= | Result string, free variables permitted, not forced to a number. |
| =(cmacs-calculator-eval-number EXPR &optional MODES)=   | Emacs *float*, or nil if the result is not a plain real number (infinite, complex, symbolic). |
| =(cmacs-calculator-eval-symbolic-number EXPR &optional MODES)= | Float or nil, permitting free variables — for callers that substitute variables themselves, notably plotting. |
| =(cmacs-calculator-to-base-units EXPR &optional MODES)= | Result string in base SI units.                        |
| =(cmacs-calculator-convert-units EXPR UNITS &optional MODES)= | Result string converted to =UNITS=.              |
| =(cmacs-calculator-supported-p)=                  | Non-nil when the engine is usable (i.e. Calc loaded).       |

=MODES= is a flat list of Calc =VARIABLE VALUE= overrides, spliced into
=calc-eval='s list form.  *This is the only mechanism Calc honours* — it rebinds
the mode variables internally and so ignores any surrounding =let=.  Be aware
that Calc's list form sets those variables *globally and permanently* for the
session; that is stock Calc behaviour, not a cmacs choice.

The =-number= variants always return a *float*, never an integer: callers do
float-only arithmetic on the result (=isnan= among others), and ="-1"= coming
back as an integer would break them.  The number regexp is deliberately strict —
Calc also prints =uinf=, =nan=, =(0, 2)= for a complex value and =sin(x)= for an
unevaluated form, none of which are numbers, and a loose pattern would silently
turn them into 0.

** Errors

All are subtypes of =cmacs-calculator-error=, so one handler catches everything:

| Signal                                  | Raised when                                            |
|-----------------------------------------+--------------------------------------------------------|
| =cmacs-calculator-error=                | Base; also a result that did not evaluate (domain rejection), and Calc's own =(POSITION MESSAGE)= failures normalised into a real signal. |
| =cmacs-calculator-syntax-error=         | Empty expression, unbalanced delimiters, unparsable input. |
| =cmacs-calculator-unknown-function=     | A =calcFunc-= call Calc does not define, e.g. =foo(1)=. |
| =cmacs-calculator-unbound-variable=     | A free variable in numeric (non-symbolic) evaluation.   |

=cmacs-calculator-error-message= (in =cmacs-calculator-inline.el=) is the one
place that turns such a signal into a sentence fit for the echo area; the sheet,
menu and REPL reuse it rather than each dumping a raw signal.

** Defining a calculator

=cmacs-calculator-defcalc= defines the function with Calc's =defmath= (so it is
a first-class algebraic function, usable in a sheet, the REPL, inline, and
composed inside a larger formula) and registers its metadata:

#+begin_src emacs-lisp
(cmacs-calculator-defcalc simpleint (principal rate years)
  :category financial
  :title "Simple interest"
  :doc "Interest earned at RATE per year on PRINCIPAL for YEARS, with no
compounding."
  :args ((principal "Principal amount")
         (rate "Annual interest rate as a fraction, e.g. 0.05")
         (years "Number of years"))
  :returns "Interest earned (not including the principal)"
  :examples (("simpleint(1000, 0.05, 3)" . "150"))
  (* principal rate years))
#+end_src

| Key         | Meaning                                                  |
|-------------+----------------------------------------------------------|
| =:category= | Symbol grouping the calculator (=financial=, =physics=, …) |
| =:title=    | One-line human-readable name                             |
| =:doc=      | Longer description                                       |
| =:args=     | =(SYMBOL DESCRIPTION . PLIST)= per argument              |
| =:returns=  | Description of the result                                |
| =:examples= | =(EXPRESSION . EXPECTED-RESULT)= strings                 |

*Never write a bare Emacs float literal in a =defmath= body.*  =defmath= passes
Emacs floats through unconverted, and =math-mul= on one yields a value that is
not a Calc number, which breaks the next operation — the function then fails to
fold and comes back unevaluated.  Use a Calc fraction (=(/ 4 5)=) instead of
=0.8=.  Relatedly, constants meant as ordinary Lisp variables are spelled with a
hyphen: =defmath= turns a bare symbol such as =G= into the Calc variable
=var-G=, but leaves any symbol *containing a hyphen* alone.

** Sheet mode (=cmacs-calculator-sheet-mode=, =.calc=)

| Key       | Command                                  | Action                        |
|-----------+------------------------------------------+-------------------------------|
| =C-c C-c= | =cmacs-calculator-sheet-eval-buffer=     | Evaluate the whole buffer     |
| =C-c C-e= | =cmacs-calculator-sheet-eval-line=       | Evaluate the current line     |

** REPL

=emacs --calc= (batch loop) and =cmacs-calculator-repl-buffer= (in a running
Emacs) share one core.  Commands:

| Command  | Action                                      |
|----------+---------------------------------------------|
| =:prec N= | Set precision for the session              |
| =:deg=   | Angle mode: degrees                         |
| =:rad=   | Angle mode: radians                         |
| =:help=  | Show help                                   |
| =:quit=  | Exit (also =:exit=, =:q=)                   |

Mode commands set the engine's customization variables *buffer-locally*, so a
REPL buffer cannot silently reconfigure your other calculator surfaces; in batch
there is only ever one buffer, so the effect is session-wide.

In batch, =princ= and the prompt go to *stdout* while =message= goes to
*stderr*.  That split is load-bearing: Calc chatters ("Building units table…")
through =message= during evaluation, and it lands on stderr where a caller
piping stdout never sees it.

** C DEFUNs (libregnum tier)

Available when =HAVE_CMACS_CALCULATOR_CHART= (i.e. =--with-cmacs-calculator= and
=--with-cmacs-libregnum=).  Guarded stubs exist otherwise, so calling code need
not =#ifdef=:

| DEFUN                                                  | Purpose                          |
|--------------------------------------------------------+----------------------------------|
| =(cmacs-calculator-chart-supported-p)=                 | Is the GPU tier usable?          |
| =(cmacs-calculator-chart-types)=                       | The supported type symbols       |
| =(cmacs-calculator-chart-attach BUFFER WIDTH HEIGHT)=  | Attach a chart to a buffer       |
| =(cmacs-calculator-chart-detach BUFFER)=               | Detach it                        |
| =(cmacs-calculator-chart-set-type BUFFER TYPE)=        | Set the chart type               |
| =(cmacs-calculator-chart-set-title BUFFER TITLE)=      | Set the title                    |
| =(cmacs-calculator-chart-set-background BUFFER COLOR)= | Set the background               |
| =(cmacs-calculator-chart-add-series BUFFER NAME COLOR POINTS)= | Add a series             |
| =(cmacs-calculator-chart-clear-series BUFFER)=         | Clear all series                 |
| =(cmacs-calculator-chart-refresh BUFFER)=              | Rebuild and redraw               |
| =(cmacs-calculator-chart-snapshot BUFFER FILE)=        | Write the chart to an image file |
| =(cmacs-calculator-c-supported-p)=                     | Is the C half compiled in?       |

Types: =line=, =bar=, =area=, =scatter=, =pie=, =candlestick=, =histogram=,
=radar=, =gauge=, =heatmap=.  2D only — libregnum's 3D chart types are
unimplemented (see its =ROADMAP.md=).

*Architecture note.*  =cmacs-calculator-chart.c= is the *only* calculator
translation unit that includes =<libregnum.h>=, and it must never include
=lisp.h=: raylib's =Color= struct collides with the =Color= typedef cmacs pulls
in through =pgtkgui.h=, so a TU sees one world or the other.  Everything else in
=cmacs/calculator/= talks to it through the plain-C =cmacs-calculator-chart.h=.
It *builds* the chart; *drawing* happens in the libregnum renderer's chart
branch, because charts are =LrgWidget=\s drawn with immediate-mode =grl_draw_*=
calls that are only legal inside the render bracket — which is also what makes a
chart render identically under pgtk and =emacs --lrg=.

** Filing statuses

Canonical: =single=, =married-joint=, =married-separate=, =head-of-household=.
Accepted aliases: =mfj=, =married-filing-jointly=, =joint=, =mfs=,
=married-filing-separately=, =separate=, =hoh=, =household=, =unmarried=, and
=surviving-spouse= (which maps to =married-joint= because the Internal Revenue
Code puts surviving spouses on the joint-return rate schedule, §1(j)(2)(A)).
Anything else signals rather than silently falling back to a status you did not
ask for.

** Table schema

A bracket list is =((THRESHOLD . MARGINAL-RATE) ...)= ascending, first threshold
at 0, each rate applying to income *above* its threshold up to the next; the top
band is unbounded.  Per-status keys suffix a base key with the status, e.g.
=:brackets-married-joint=.

Required: =:jurisdiction=, =:year=, =:structure= (=none= / =flat= /
=bracketed=).  Provenance: =:source=, =:retrieved=, =:verified=, =:note=
(*required* when =:verified= is nil — =cmacs-calculator-tax-validate= enforces
the pairing).  Data: =:brackets=, =:brackets-STATUS=, =:rate=,
=:standard-deduction[-STATUS]=, =:personal-exemption[-STATUS]=,
=:capital-gains-brackets-STATUS=, =:fica-rate=, =:fica-wage-cap=,
=:medicare-rate=, =:medicare-addl-rate=, =:medicare-addl-threshold-STATUS=,
=:se-rate=, =:se-medicare-rate=, =:se-net-earnings-factor=,
=:federal-deduction-allowed=, =:local-tax=.

* Build

=--with-cmacs-calculator= (default off).  Defines =HAVE_CMACS_CALCULATOR= and
builds =cmacs-calculator-init.o=, =cmacs-calculator-defuns.o= and
=cmacs-calculator-cli.o=.  With =--with-cmacs-libregnum= it additionally defines
=HAVE_CMACS_CALCULATOR_CHART= and builds =cmacs-calculator-chart.o=; without it,
configure notes that GPU charts are disabled and the SVG tier still stands.
With =--with-cmacs-mcp= it adds =cmacs-mcp-tools-calculator.o=.

Exposed as =IS-CMACS-CALCULATOR= / =is-cmacs-calculator= and
=(cmacs-feature-p 'calculator)=.

The =--calc= option needs *no* =standard_args[]= entry and no change to
=lisp/startup.el= (which errors on options it does not recognise), because it is
rewritten out of argv before Emacs parses it — =--batch= and =--eval= already
exist and already work.  =emacs -- --calc= still passes =--calc= through as an
ordinary argument.

* Testing

#+begin_src sh
make -C test check-cmacs        # test/cmacs/cmacs-calculator-tests.el
                                # test/cmacs/cmacs-calculator-tax-tests.el
#+end_src

The engine is headless-testable: SVG/unicode charting, every calculator family,
and the tax walk all run under =emacs -Q --batch= with no display.

*If a change seems not to take*, you have almost certainly hit the stale-Elisp
cache: Emacs prefers =.elc= / =.eln= over =.el=.  Either clean them, or force
source with =--eval '(setq load-prefer-newer t)'= — a stale
=cmacs-calculator-tax-data.elc= will happily register a *subset* of the
jurisdictions and everything will look like it merely works.
