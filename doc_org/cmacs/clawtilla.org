* clawtilla in cmacs

[[file:../../deps/clawtilla/README.org][clawtilla]] runs a *fleet* of agents: each with its own persona, model,
credentials, integrations and computer, able to talk to each other and
to divide work among themselves.  The daemon owns the fleet; everything
else is a client of it.

cmacs is one of those clients, and it is held to the same feature set as
the GTK one --- see [[*Parity][Parity]].

** What this is, and is not

*A client, not a daemon.*  The normal use is a =clawtillad= that is
already running: on this machine over its unix socket, or on another one
over TCP.  cmacs links libclawt's =ClawtClient= and the enumerations
every client is required to walk; it does not embed =clawt_daemon_new()=.

That is a deliberate departure from what clawtilla's own
[[file:../../deps/clawtilla/docs/clients.org][docs/clients.org]] suggests for an in-process host.  Embedding the daemon
is possible and would be faster, but it ties the fleet's lifetime to the
editor's: quitting cmacs would stop every agent, and an agent's computer
is a container or a VM.  A daemon that outlives the editor is the
arrangement that makes sense, and it is also the one that lets the GTK
client and cmacs look at the same fleet at the same time.

=M-x cmacs-clawtilla-start-daemon= exists for when there is no daemon.
It is a command you run and not something connecting does for you,
because a fleet quietly starting because somebody opened a buffer is
both surprising and expensive.

** Getting there

#+begin_src
M-x cmacs-clawtilla
#+end_src

With no connection open it offers the saved profiles from clawtilla's
own =~/.config/clawtilla/connections.yaml= --- the same file the GTK
client writes, so a workstation you added there is simply here --- plus
the local daemon.  With one open it shows the fleet.

=M-x cmacs-clawtilla-menu= is the transient that reaches everything:
the fleet, alerts, work, automation, library, recordings and settings.

*** Connecting to another machine

#+begin_src
M-x cmacs-clawtilla-connect-remote
#+end_src

Host, port, token, and whether to use TLS.  A TCP listener needs a token;
=clawtilla daemon token= prints the one the daemon generated.  The token
is read with ~read-passwd~, so it does not land in the minibuffer
history, which is a file.

*Accepting an unvalidated certificate trusts anything answering on that
address*, and is never the default.

** The buffers

| Buffer | What it is |
|--------+------------|
| =*clawtilla: NAME*= | the fleet: teams, agents, rooms |
| =*clawtilla: AGENT*= | one conversation |
| =*clawtilla agent: ID*= | Overview and Mailbox |
| =*clawtilla computer: ID*= | Shell, Screen, Mounts, Exchange, Browser |
| =*clawtilla work*= | Tasks, Decisions, Flow, Activity, Fleet |
| =*clawtilla automation*= | Routines, Triggers |
| =*clawtilla library*= | Skills, Memory |
| =*clawtilla settings*= | eight panels |
| =*clawtilla alerts*= | what is worth interrupting you for |
| =*clawtilla teach*= | recorded demonstrations |

Every one of them takes =?= for a transient of what it can do, =gr= to
refresh, =TAB= to fold a section or move to the next page, and =C-j= /
=C-k= (or =gj= / =gk=) to move between sections.

*Under Doom and Evil the keys are yours.*  Every clawtilla buffer starts
in Evil's =motion= state and its keymap is installed as an Evil
/intercept/ map, so the mode's keys answer before Evil's --- without
that, =RET= is =evil-ret= and =?= is =evil-search-backward=, which means
even the transient listing the keys cannot be reached.

Only keys a buffer binds itself are promoted.  =SPC= is not one of them,
so the Doom leader still works --- verified against Doom's actual
mechanism, an emulation map, rather than assumed.  evil-snipe is turned
off in these buffers, which is what lets =s= and =S= be start and stop.

*Intercept precedence cuts both ways, so a motion key is never taken.*
Whatever these maps bind, Evil cannot get it back: =k= bound to
"interrupt" is not a key that also scrolls, it is a key that reports /No
agent at point/ when you meant to move up.  So =h j k l w b e= and the
rest stay Evil's, =n= stays =evil-search-next=, and =g= is left a prefix
--- this client adds =gj=, =gk= and =gr= to it and =gg= still goes to the
top.  Section motion on =C-j= / =C-k= is not an invention either: it is
where =evil-collection= moves Magit's own =n= / =p=, for this reason.
Editing keys are a different matter and are taken freely, because a
read-only buffer has nothing to insert or delete --- =evil-collection=
says as much by remapping =i=, =a=, =o=, =p= and =d= to =ignore= in
exactly these buffers.  The rule is enforced by a test rather than
remembered, since every new command picks a letter.

*They take over the window rather than splitting it.*  These buffers are
the thing you are doing and not a reference you glance at: a transcript
in half a window is one nobody reads.  =cmacs-clawtilla-display-buffer-function=
is the knob --- set it to =pop-to-buffer= for the split, or to
=display-buffer= and use =display-buffer-alist= if you want different
rules per buffer.

*** The fleet

The agents in no team, then the teams with the agents in each, then
rooms.  Every team gets a heading including an empty one: a team
somebody made and has not filled is exactly the team they are about to
move somebody into.

*Unfiled agents come first*, which is not the order the daemon lists
them in.  They are the agents with no lead to answer for them, so they
are both the rows most likely to be wanted and the easiest to lose:
below every team is below the fold on a fleet of any size.  Set
=cmacs-clawtilla-fleet-no-team-first= to nil for the daemon's order.

The counts beside a team name --- =2/3 up, 1 busy= --- come from
=clawt_team_tally=, not from counting the rows on screen.  Three clients
counting the same thing is three chances to disagree about what "active"
means.

=RET= opens an agent's conversation, =o= its page, =s= / =S= / =R= start,
stop and restart it, =i= interrupts a running turn, =!= resets the
session and =D= removes the agent.  =M-p= and =M-n= move it in the list.

*A reset is not a restart.*  A restart brings the same conversation back;
a reset drops the session, and is what makes an identity change take.

*** An agent's page

=o= on an agent opens its Overview, where every field is a line you
press =RET= on.  The values come from =agent.show=: the agent object
for the summary fields, and its =settings= --- every per-agent schema
key, as strings --- for the rest.  Saving goes through =agent.set= as a
=key= and a =value=, the schema's own agent-relative key
(=model.model=, =runtime.restart=) with booleans spelled =true= and
=false=; the daemon parses the value against the same schema it reports
from.  A change that only reaches the agent at its next session says so.

Four fields are a choice among things the daemon holds:

- *Account* (=model.account=, =A=) --- which login the agent's CLI
  uses.  Offered from =account.list= asked /with the agent/, so each
  account carries the daemon's own =usable= answer
  (=clawt_account_check=, the same check =agent.set= applies).  An
  account this agent cannot use is still listed, with the daemon's
  =reason=, and choosing it is refused --- the picker offers exactly
  what saving accepts.
- *Shared computer* (=computer.use=, =S=) --- a machine declared under
  =computers:= that several agents share, from =computer.shared=, each
  with its type, state, who uses it and how many of them are running.
  A host computer is not shareable and is not offered.  Its settings are
  the machine's, so the daemon refuses any other =computer.*= key on an
  agent that uses one.
- *Browser* (=browser.mode=, =W=) --- none, its own, or a shared one;
  the modes are libclawt's =ClawtBrowserMode=, walked off its GType.
- *Browser session* (=browser.use=, =w=) --- which shared session, from
  =browser.list=.

*Action rules* (=policy.rules=) decide what the agent may do without
asking: =MATCH=MODE=, read top to bottom, the first match deciding and
an unmatched call running.  =MATCH= is an action class (=ClawtActionClass=)
or a tool-name glob; =MODE= is a =ClawtPolicyMode=.  =r= adds or changes
one --- a rule for the same match is replaced where it stands, because
order is meaning here --- =R= removes one and =E= edits the line whole.
The daemon parses each rule where it arrives and refuses one it cannot
read.  An agent's own list replaces the fleet's =defaults.policy.rules=
rather than adding to it, so clearing it brings the defaults back.

*** A conversation

A read-only transcript that appends, with composing as a separate act.
=RET= or =i= opens a *compose buffer* under the transcript: =C-c C-c=
sends it, =C-c C-k= abandons it.  A buffer rather than the minibuffer
because a message to an agent is usually not one line --- it has a
paragraph, a path, a snippet of code --- and the minibuffer is a bad
place to write those.  A slash command works there too: content
beginning with =/= is run rather than sent.

*A turn in progress says so.*  A status line under the transcript reads
=⟳ working for scribe — Read 3 files, Changed 2 files=, in the
library's own words: the sentence is =clawt_agent_activity_label= and
the tool summary is =clawt_turn_step_run_summary=, the same two the GTK
client and the CLI use.  The marker distinguishes a turn that is
running from one that has stopped, which the words alone do not.

*Tool calls stay in the transcript, above the answer they produced.*
A turn's calls are written in before the message that overtook them ---
they happened first, and a transcript that appends them afterwards
reads backwards.  They arrive as one collapsed run headed by the
library's summary, and =TAB= opens it:

#+begin_example
user         17:38
    hey gnuis, whats crackin?
    ▸ Ran 1 command, Searched 1 query, Used 3 tools
gnuisaince   17:38
    Not much happening.  The fleet is up and idle.
#+end_example

Collapsed because a turn can be twenty calls long and what somebody
reads is the answer.  =cmacs-clawtilla-chat-fold-tool-runs= nil starts
them open.  The fold is an overlay rather than a redraw: this
transcript appends and is never rebuilt, so there is nothing to
re-render a fold into.

Two behaviours are worth knowing because they are the ones you would
otherwise notice as the thing being unusable:

- *A refresh appends.*  The transcript is never redrawn wholesale, so a
  turn in progress does not lose your scroll position or a collapsed
  tool run.
- *It follows the live edge only when you are already at it.*  Reading
  further up during a turn is the case that matters, and a transcript
  that scrolls away from you then is one you cannot read.

Markdown is rendered through the library's own cmark, so all three
clients agree about what markdown means.  Day dividers, message runs and
timestamps are the library's decisions too.

*A message to a stopped agent says so.*  The mailbox accepting it is the
point of having one, but nothing will read it until the agent starts.

**** Slash commands

The twenty the GTK client answers, and =/help= lists them:

=/agents= =/attach= =/clear= =/compose= =/copy= =/edit= =/export=
=/files= =/flow= =/help= =/interrupt= =/memory= =/new= =/recall=
=/reset= =/restart= =/retry= =/start= =/stop= =/tasks=

=/edit= opens the file in a buffer rather than in =$EDITOR=, which is
the better answer when the client *is* the editor.

*** A computer

Shell, Screen, Mounts, Exchange and Browser --- five, in that order,
because =clawt_computer_view_count()= says so and not because this
client lists them.

=!= runs a command.  =v= grabs a frame and =V= fetches the whole screen,
=o= watches it and =O= stops; watching is stopped explicitly rather than
when the buffer goes away, because the daemon is producing frames for
somebody.

=u= takes the screen over and =U= hands it back.  *Typing into a screen
the agent is still driving is not shared control*, it is a corrupted
command line, so =i= refuses unless you have taken it over.

An agent with =computer: none= is told it has no machine rather than
offered a shell into nothing --- which type has a machine is also the
library's answer.

**** The browser

Since clawtilla 0.9.0 an agent can drive a real web browser: a gsurf on
a private Xvfb, started by the daemon on the first browser call.  The
Browser view draws the library's line above the picture
(=clawt_browser_session_line=: what it is on, and who is driving), the
picture itself from =browser.frame=, and the sessions from
=browser.list= that this agent drives or shares.

=a= opens an address (=browser.open=, starting the session if it must
and waiting for the load), =r= reads the page again, =X= stops it ---
the open page is lost, the profile and its logins stay.  *A click on the
picture is a click in the page*: the picture is drawn scaled to fit the
window, so the click is mapped back through the PNG's own size to the
page's CSS pixels before =browser.click= is sent.  =x= clicks at a point
typed in, for when there is no mouse.  A person's click does not take a
shared session's driver lease, since a person at the Computer page
outranks an agent.

A frame is asked for when the view is entered and after each action,
never on a timer from a buffer nobody is reading.  A daemon built
without =GSURF=1= answers =available: false=, and the view says that
rather than drawing an empty frame.

*** Work: Tasks, Decisions, Flow, Activity and Fleet

The pages and their order are the library's (=clawt_section_page_count=);
=TAB= moves between them.

**** Decisions

The inbox: what agents are waiting on you for.  =a= answers, =d=
dismisses (the record stays, saying you passed), and =x= deletes for
good --- for a stale ask or one raised by mistake.  All three name the
decision as =decision=, which is the key the daemon reads.  =o= shows
settled decisions too, each saying how it ended --- answered,
dismissed, defaulted or deleted --- from the =decision.settled= event
when this session saw it, otherwise from the state the list reports.
=urgent= is the daemon's (the deadline is inside a day), never worked
out here.

**** Activity

Every turn running anywhere in the fleet, from =activity.list=: who, in
which room, for how long, on whose behalf, how many steps, and the
latest of them summed in the library's words.  The age is
=clawt_activity_elapsed_label= against the daemon's own =now=, so this
machine's clock never shows up as an age.

=s= stops the agent --- =agent.interrupt=, which ends *every* turn it
has, not the row it was pressed on, and leaves it up.  It asks first,
with =clawt_activity_stop_prompt=, because a key that does more than its
row suggests must say so.  =c= steers: the text goes through =msg.send=
into the running turn, which reaches only the agent's conversation with
you, so it is offered only on a turn the daemon marks =steerable=.  An
agent that finished meanwhile takes it as a new message, and the two are
said apart.

The page refreshes on turn events, coalesced, and re-ages every ten
seconds while it is on screen: a turn in one long tool call produces no
step for minutes, and an age that never moves reads as a stale page.

**** Fleet

What each agent costs and which sit idle, from one =usage.summary=
asked the way every client's Fleet page asks it
(=clawt_usage_fleet_payload=: the period's =since=, fourteen days of
daily figures, sorted by cost).  The figures and wording are all the
library's --- the period total, the day's budget line against
=daily_fleet_budget_micros=, the fleet's fourteen-day strip, and per
agent its cost and share, a strip of its own days, and a subtitle with
its turns and last turn.  Cost crosses the wire as integer
micro-dollars and is formatted by the library.

=idle= and =idle_tone= are the daemon's; this client paints the label
in the tone it is given and never decides what idle means.  An agent the
daemon stopped for being idle is marked asleep --- the next message
wakes it.  =p= picks the period from the library's list, =s= stops the
agent at point (=agent.stop=: its process and its computer), and =X=
stops every agent the library offers Stop on --- running, and idle or
never used --- after naming them.

*** Automation: Routines and Triggers

=A= adds a routine; with a prefix argument it also asks for the routine's
own model and its three flags.  =U= changes one field of the routine at
point: schedule, prompt, agent, model, or one of the flags.

- *model* runs the routine on a model other than the agent's own --- a
  cheaper one for a check that compares a number.  Empty is the
  agent's.
- *read_only* runs it unable to change anything.
- *proactive* lets it start work rather than only report.
- *locked* keeps the agent itself from editing or removing it.

The flags travel as JSON =true= and =false=, never as a string: a string
that is not a boolean is read as the default, and the request succeeds
and does the other thing.

*** Settings

Appearance, Integrations, Connectors, Accounts, Teams, Spending, Folders
and Cloud images.  =TAB= moves between them.

Appearance is the only panel that is not the daemon's, and even its
values are the library's: the palettes and measure units come from
libclawt, with each unit's own bounds, so this client cannot offer a
width the library would refuse.

*Connectors never show or accept a secret.*  A connected account keeps
its credential in the daemon and hands only the tools to the agents;
=c= begins a connection and gives you a URL to open.

*Accounts* are logins: a CLI's config directory under a name, so two
agents on the same provider can be two different people.  The panel
lists them from =account.list=; =aa= declares one (=account.add=: id,
provider, config directory, description) and =ar= removes the one at
point (=account.remove=), saying how many agents still name it --- they
become shadows until pointed elsewhere.  Logging in is the CLI's own
business (=clawtilla account login=); no credential passes through
here.  The panel reloads on =account.changed=, so an account added from
another client appears.  Which account an agent uses is chosen on the
agent's page.

*** Alerts and unread

Which events are worth interrupting you for is
=clawt_alert_tier_for_event= --- four tiers, one of which is "skip", so
a turn's constant step events do not become alerts.  =a= shows every
tier rather than the filtered set, =x= clears what is shown, and =o=
loads the daemon's own event log, which goes back further than this
client has been connected.

An alert that lands while the buffer is in front of you *arrives already
read*.  Marking it unread would leave a count that reading cannot clear.

The unread counts beside each agent follow =clawt_unread_should_count=:
not your own message, not the room you are looking at, not older than
the connection, and not a room with no row on screen.

*** Teaching by demonstration

=M-x cmacs-clawtilla-teach=.  Record yourself doing something, and have
the fleet turn it into a skill: =s= starts, =S= stops, =y= proposes a
procedure and =c= adopts it.

Four steps rather than two on purpose.  Synthesising is where a model
reads the trace and proposes something; committing is what makes agents
follow it.  A recording becoming behaviour without anybody reading it
first is not a shortcut worth having.

** Parity

clawtilla holds its GTK and web clients to the same feature set with
=make parity=, which fails when a capability exists in only one of them.
Two clients drifting apart is invisible: nothing breaks, nothing warns,
and somebody finds out by reaching for the half that was not built.

cmacs is held to the same rule by =admin/cmacs-clawtilla-parity.sh=,
which compares this client against the GTK one across four layers:

1. *IPC frame kinds.*  A proxy for "feature", not a definition --- but
   every real feature has to talk to the daemon, so a kind one client
   sends and the other never mentions is a capability that exists in one
   place only.
2. *Slash commands.*  The frame-kind check misses these entirely:
   =/files= and =/agents= are built out of frames both clients already
   send.
3. *Hardcoded vocabulary.*  A client naming a value the library
   enumerates has a copy of the list, and a copy is what drifts.
4. *Declared affordances.*  Capabilities that are pure interface and
   touch no shared symbol.  This layer is honest about its limit: it
   catches one half being removed or never written, and cannot catch a
   feature nobody declared.

The check lives here rather than in clawtilla because clawtilla's script
greps its own =clients/= and should not have to know where cmacs is.  It
reads the same sources --- =deps/clawtilla=' daemon files and GTK client
--- and applies the same rule.

Two kinds are declared as allowed absences with reasons:
=agent.file_read= and =agent.file_write=, because =/edit= opens the file
in a buffer.

The affordance layer declares forty pairs.  Since clawtilla 0.9 they
include the Activity page, its elapsed label and stop question; the
Fleet page, its summary, payload, periods and stop-the-idle action; the
Browser view and its session line; the account and shared-computer
pickers and the action-rule editor; and a routine's model and its
read-only, proactive and locked flags.  Each names the GTK symbol and
the cmacs one, so removing either half fails the check.

=just clawtilla-parity= runs it; it needs no build.

** Why the library answers so much

Nearly every rule this client follows is asked of libclawt rather than
implemented here: the activity sentence, the team tally, run and day
boundaries, timestamps, alert tiers, the unread rule, tool-run grouping,
markdown, a turn's elapsed time and the Stop question, every figure and
sentence on the Fleet page and its sparklines, the browser session line,
and the values of every enumeration offered --- browser modes, policy
modes and action classes included, which libclawt registers only as
GTypes and which are walked off those.

One family is named in C rather than walked: a decision's state.
=decision.list= sends it as the enum's integer and libclawt registers no
GType for it, so the =decision-state= family maps the library's own
constants to the words the daemon uses for the same outcomes in
=decision.settled=.

That is not deference for its own sake.  The failures are on record in
clawtilla's history: the CLI read =busy= and =peer= for as long as they
existed and rendered neither, and the web client drew a bare "busy"
badge that dropped =peer= on the floor.  A sentence assembled in three
places is three sentences, and three clients that disagree about what a
fleet is doing are not one product.

** Building

=--with-cmacs-clawtilla=, in the default flag set.  It requires
=--with-cmacs-glib= (replies complete on the cmacs GMainContext) and
=--with-cmacs-libreclaw= (libclawt is layered on liblc, and one binary
must not hold two copies of it).

=IS-CMACS-CLAWTILLA= says whether it was compiled in;
=(cmacs-clawtilla-supported-p)= says its primitives are reachable.

** Nothing blocks

There is no synchronous request primitive, deliberately.

The library's blocking =clawt_client_request()= turns the caller's main
context while it waits, and here that context is the editor's --- under
=--gowl= it is also the compositor's.  Turning it from inside a
primitive re-enters Lisp where Emacs does not expect it, and a remote
daemon slow to answer would freeze the desktop for as long as DNS and a
TLS handshake take.

Connecting and subscribing are asynchronous for the same reason.  Both
needed adding to clawtilla for this: =clawt_client_connect_async()= and
=clawt_client_subscribe_async()=.
