#+TITLE: cmacs-ai
#+SUBTITLE: ai-glib coding agent for cmacs
#+OPTIONS: toc:2 num:nil

* Overview

The =cmacs-ai= subsystem wraps =ai-glib= (the multi-provider
GObject-based AI library) and surfaces it as a first-class
coding-agent surface inside cmacs.  It is independent of
=cmacs-libreclaw=: libreclaw orchestrates conversations across
channels (Matrix, email, the bridge); =cmacs-ai= is raw, low-
latency, single-conversation model invocation tuned for editing.

Enable with =--with-cmacs-ai= at configure time.  The canonical
=libai-glib-1.0.a= is built once from =deps/ai-glib= and shared
with =--with-cmacs-libreclaw= when both are enabled.

| Symbol           | Wire     | Env / setup                          |
|------------------+----------+--------------------------------------|

| =ollama=         | HTTP     | =OLLAMA_HOST= (default localhost)    |

| =opencode=       | CLI      | =opencode= on PATH                   |
| =claude-tmux=    | CLI/tmux | =claude= + tmux on PATH              |

* Chat buffers

=M-x cmacs-ai-chat= opens a fresh chat buffer in
=cmacs-ai-chat-mode= (derived from =org-mode=).  History above the
=* Compose= sentinel is read-only; =C-c C-c= sends the compose body
and streams the response into a fresh =** assistant= heading.

Keymap:

| Key         | Command                       |
|-------------+-------------------------------|
| =C-c C-c=   | =cmacs-ai-chat-send-compose=  |
| =C-c C-k=   | =cmacs-ai-chat-cancel-stream= |
| =C-c C-l=   | =cmacs-ai-chat-clear-history= |
| =C-c C-s=   | =cmacs-ai-chat-save=          |

* Region commands

| Command                        | What                                         |
|--------------------------------+----------------------------------------------|
| =cmacs-ai-rewrite-region=      | Replace region with AI rewrite (one undo step) |
| =cmacs-ai-explain-region=      | Side-window Org explanation                  |
| =cmacs-ai-doc-region=          | Insert idiomatic doc comment above           |
| =cmacs-ai-test-region=         | Synthesize a unit test in a scratch buffer   |
| =cmacs-ai-suggest-commit-message= | Draft a commit message from the staged diff |

* Inline ghost-text completion

=cmacs-ai-completion-mode= is a buffer-local minor mode that
drives idle-timer FIM completion.  After
=cmacs-ai-completion-idle-delay= seconds of no input, a request is
fired with the buffer prefix+suffix as FIM context; the result
renders as a =shadow=-faced overlay accepted with =TAB=.

Default provider is =claude-code= to avoid per-keystroke HTTP
costs.  Override via =cmacs-ai-completion-provider=.

* Voice loop

=M-x cmacs-ai-voice-chat= opens a chat buffer wired for full voice
round-trip:

1. =cmacs-whisper-dictate= transcribes recorded speech.
2. =ai-glib= streams the reply.
3. =cmacs-piper-speak-region= speaks each completed sentence as it
   streams in.

Requires =cmacs-whisper=, =cmacs-piper=, =cmacs-audio= all enabled.

* Coding agent

=M-x cmacs-ai-agent-open= opens (or resumes) the agent chat for
the current project root.  Before the first turn it builds a
project-aware system prompt:

- The first matching file from =cmacs-ai-agent-project-files=
  (default: =CLAUDE.md=, =AGENTS.md=, =README.org=, =README.md=) is
  read in full and attached as the "Project agent contract".
- The absolute project root path is included.

This makes the assistant honor the project's own conventions
without manual cut-and-paste.

* Tool use

=cmacs-ai-tools-new= returns an =AiToolExecutor= handle with
ai-glib's built-ins pre-registered: =bash=, =read=, =write=,
=edit=, =glob=, =grep=, =ls=, =web_fetch=.  Per the project default
all tools are enabled (full trust).  Set =cmacs-ai-tool-confirm=
to ='destructive= for a per-call prompt on bash/write/edit, or to a
function for custom approval.

The =web_fetch= built-in is model-aware: HTML responses are converted
to readable markdown-style text (scripts and styles stripped, headings
and links preserved; images surface as Markdown =![alt](URL)= with the
src resolved to an absolute URL, so the model can cite or embed real
image links), =http://= URLs are upgraded to =https://=, a real
=User-Agent= and a 30-second timeout are applied, and converted bodies
are cached in-process for 15 minutes.  It accepts an optional =prompt=
argument -- when the model supplies one, a sub-model reads the fetched
page and returns only the requested information instead of the whole
page (extraction runs through the chat's active provider).

Each chat buffer is /also/ auto-augmented with cmacs's own MCP tool
surface (buffer / file / project / eval / apropos / describe by
default) on top of these built-ins -- see [[*MCP bridge][MCP bridge]] below.

Custom Elisp tools are registered via =cmacs-ai-tools-register=:

#+BEGIN_SRC elisp
(let ((exec (cmacs-ai-tools-new)))
  (cmacs-ai-tools-register
   exec
   "open-file"
   "Open FILE in cmacs."
   (cons '(("file" "string" "Path to open" t))
         (lambda (_name input-json _id)
           (find-file (alist-get 'file
                                  (json-read-from-string input-json)))
           "opened"))))
#+END_SRC

** Web search

ai-glib's =web_search= tool returns ranked results (title, URL, source
domain, snippet) and can optionally fetch the top results' pages.
Unlike =web_fetch= it is not a free built-in -- it is registered on a
chat/agent buffer's executor only when a search backend is configured.
=cmacs-ai-chat--init= does this automatically from
=cmacs-ai-search-provider= (default ='auto=):

| Provider symbol | Backend                                          |
|-----------------+--------------------------------------------------|
| =auto=          | Brave or Bing if its key is set, else DuckDuckGo |
| =brave=         | Brave Search (needs a key)                       |
| =bing=          | Bing Search (needs a key)                        |
| =duckduckgo=    | Keyless DuckDuckGo (best-effort, no SLA)         |
| =nil=           | Disabled                                         |

Keyed backends read =cmacs-ai-search-api-key=, falling back to the
=BRAVE_API_KEY= / =BING_API_KEY= environment variable.  A keyed
provider with no key available logs a message and leaves =web_search=
off; =auto= always succeeds thanks to the keyless fallback.

Once registered, the model may pass the tool's options: =count=,
=freshness= (any/day/week/month/year), =safesearch=
(off/moderate/strict), =country=, =language=, =site=, and
=fetch_content= (fetch and attach the top results' page text via the
=web_fetch= pipeline).  Results are cached in-process for 5 minutes.

Switch the backend for an open chat at runtime with
=M-x cmacs-ai-chat-set-search-provider=.  Inspect the active tool set
with =(cmacs-ai-tools-list EXECUTOR)= -- it lists the built-ins,
=web_search= (once a provider is set), custom tools, and bridged MCP
tools.

#+BEGIN_SRC elisp
;; Enable web_search explicitly on a standalone executor.
(let ((exec (cmacs-ai-tools-new)))
  (cmacs-ai-tools-set-search-provider exec 'duckduckgo)
  (member "web_search" (cmacs-ai-tools-list exec)))   ; => t
#+END_SRC

** Inline images

When =cmacs-ai-chat-inline-images= is non-nil (the default), image
links in an assistant response render inline after each turn.  Have
the model embed images as bare Org links, e.g.
=[[https://host/pic.png]]= (a described link =[[url][text]]= shows the
text, not the image).  Local/file images are previewed synchronously
via Org; remote =http(s)= images are fetched *asynchronously* and
shown when they arrive, so a slow or dead URL never blocks Emacs
(Org's own remote-image download is synchronous and would freeze the
UI).  Non-image responses, error statuses, and undecodable data are
ignored silently.  Image width is capped at
=cmacs-ai-chat-image-max-width= (or ~92% of the chat window).
Toggling =org-link-preview= (=C-c C-x C-v=) clears the previews.

* Image generation

=cmacs-ai-image-generate-async= drives OpenAI/Gemini/Grok image-
generator interfaces.  Returns =(:images ((:url ... :base64 ...
:mime ... :revised ...) ...))= or =(:error MSG)=.

* GObject Introspection

The cmacs-ai init path prepends
=$top_srcdir/deps/ai-glib/build/release= to GIRepository's search
path and eagerly requires =AiGlib-1.0=.  After =init_cmacs_ai=
runs, the typelib is reachable from:

- Elisp: =(gi-require "AiGlib" "1.0")= returns =t=.
- The bacon =cmacsgi= builtin.
- The MCP =gi_*= tools.

* MCP tools

Built with =--with-cmacs-mcp=, three tools are exposed:

| Tool               | Args                              |
|--------------------+-----------------------------------|
| =ai_prompt=        | =prompt= req, =provider=, =system= |
| =ai_list_providers= | (none)                            |
| =ai_open_chat=     | =prompt=, =provider= (opt)        |

* MCP bridge

The /outbound/ direction (above) lets external agents drive the
in-editor AI.  The /inbound/ mirror -- this section -- lets the
in-process AI drive cmacs's own MCP tool surface.

Each chat buffer's =AiToolExecutor= is automatically augmented with
cmacs's editor-aware tools (buffer / file / project / eval / apropos
/ describe by default), so the model gets the same toolset external
Claude Code already uses to drive cmacs, on top of ai-glib's
filesystem-level built-ins.

Without the bridge, AI edits land on disk bypassing cmacs buffers
(no undo, no save-hooks); with it, edits go through =edit_buffer= /
=replace_in_buffer= and respect editor invariants.

** Default allowlist

| Tool group           | Tools                                              |
|----------------------+----------------------------------------------------|
| eval / introspection | =eval=, =describe_function=, =describe_variable=, =apropos=, =completions= |
| buffer               | =list_buffers=, =get_buffer_content=, =set_buffer_content=, =create_buffer=, =edit_buffer=, =replace_in_buffer=, =search_buffer=, =goto_line= |
| window               | =list_windows=, =list_frames=                       |
| project              | =project_root=, =project_read_file=, =project_list_files=, =project_find_files=, =project_grep= |
| process + debug      | =list_processes=, =backtrace=, =memory_info=, =process_status=, =recent_messages=, =describe_mode=, =list_hooks= |

** Extending

Patterns are PCRE (the bridge uses GLib's GRegex), NOT Emacs
=\`X\'= syntax.  To add shell access + the full GObject Introspection
surface:

#+BEGIN_SRC elisp
(dolist (re '("^bacon_eval$" "^crispy_eval$" "^gi_"))
  (add-to-list 'cmacs-ai-mcp-bridge-allowlist re))
#+END_SRC

To open a single read-only chat:

#+BEGIN_SRC elisp
(let ((cmacs-ai-mcp-bridge-readonly-only t))
  (cmacs-ai-chat 'claude))
#+END_SRC

** Recursion guard

The C layer always denies =^ai_= regardless of allowlist contents,
to prevent the in-process AI from invoking =ai_open_chat= /
=ai_prompt= on itself.  Not configurable.

** Trust

Bridged MCP tools obey =cmacs-ai-tool-confirm= the same way ai-glib's
built-ins do (see /Tool use/).  Default nil = full trust.
