#+TITLE: cmacs-gsurf — embedded web browser
#+AUTHOR: Zach Podbielniak
#+OPTIONS: toc:2 num:t

* Overview

cmacs-gsurf embeds [[../../deps/gsurf][gsurf]] — a GLib/GObject port of suckless =surf= — as a
first-class cmacs subsystem.  A =cmacs-gsurf-mode= buffer owns a live
WebKitGTK view (a =GsurfView=) that is parented into the buffer's pgtk
frame and clipped to the window showing it (xwidget-style live embed):
the window body *is* the browser, painted on top of the buffer text.

gsurf is library-first, so cmacs links =libgsurf.a= statically into the
editor and drives it directly.  surf's "patches" are gsurf *modules*
(=.so= plugins) that run in-process and apply to the embedded views:
search engines, ad-block, vim-style modal navigation + link hints,
history, dark mode, user scripts, and ~25 more.

You can drive gsurf from:
- *Elisp* — =M-x cmacs-gsurf= and the =cmacs-gsurf-*= commands/DEFUNs.
- *cmacsgi / GObject Introspection* — =(gi-require "Gsurf" "0.1")= then
  call the gsurf API; also from the bacon =cmacsgi= builtin.
- *MCP* — =gsurf_open=, =gsurf_navigate=, =gsurf_current=, … tools.
- *cmacs-ai* — the MCP =gsurf_*= tools are in the default chat tool tier.

* Requirements

** Build flag

: --with-cmacs-gsurf      (alias: --with-gsurf)
: --with-cmacs-gsurf-lrg  (libregnum backend for emacs --lrg)

Requires =--with-cmacs-glib= and =--with-pgtk= (the live widget embed
parents into the pgtk frame's =GtkFixed=).  =--with-cmacs-mcp= adds the
=gsurf_*= MCP tools; =--with-cmacs-gi= makes the bundled =Gsurf-0.1=
typelib resolvable for cmacsgi.

=--with-cmacs-gsurf-lrg= additionally builds the GTK-free *libregnum
backend* so gsurf works under =emacs --lrg= (where there is no GTK widget
tree); it requires =--with-cmacs-libregnum=.  See *Render backends* below.

** System packages

gsurf reuses the same WebKitGTK/GTK3 stack as =--with-xwidgets=, so no
new packages are needed beyond a normal cmacs build:

- =webkit2gtk-4.1=, =gtk+-3.0=, =javascriptcoregtk-4.1=
- =glib-2.0 gobject-2.0 gio-2.0 gmodule-2.0=, =yaml-0.1=, =json-glib-1.0=

* Architecture

| Piece | File |
|-------+------|
| Subsystem init + GIR path | =cmacs/gsurf/cmacs-gsurf-init.c= |
| DEFUN surface | =cmacs/gsurf/cmacs-gsurf-defuns.c= |
| Buffer<->view registry + live embed | =cmacs/gsurf/cmacs-gsurf-view.c= |
| Module-manager glue | =cmacs/gsurf/cmacs-gsurf-modules.c= |
| Elisp mode + commands + MCP helpers | =lisp/cmacs/cmacs-gsurf.el= |
| MCP tools | =cmacs/mcp/cmacs-mcp-tools-gsurf.c= |

*Static link + dedup.* gsurf is built =STATIC=1 BUILD_GIR=1
GTK_BACKEND=gtk3=; =libgsurf.a= is =--whole-archive='d into temacs.
Because =libgsurf.a= merges crispy + yaml-glib objects, the
=src/Makefile.in= dedup machinery strips them (=_gsurf_strip=) so the
canonical copies win — never =-z muldefs=.  temacs is linked
=--export-dynamic=, so the runtime-loaded gsurf module =.so= files
resolve =gsurf_*=/=yaml_*= against the executable (one library
instance, no duplicate GType registration).

*Live embed.* =cmacs-gsurf-view.c= holds each buffer's =GsurfView=,
gets its native =GtkWidget= (=gsurf_view_get_native_widget=), and
=gtk_fixed_put/move='s it into =FRAME_GTK_WIDGET (f)= sized to the
window body.  The Elisp =window-configuration-change-hook= /
=window-size-change-functions= call =cmacs-gsurf-place= to keep the
widget aligned, and =cmacs-gsurf-hide= for off-screen buffers.

*Events.* The view's =uri-changed= / =title-changed= / =load-changed=
GObject signals are bridged (through the cmacs safe-dispatch layer) to
the Emacs abnormal hooks:
- =cmacs-gsurf-uri-changed-functions=   (BUFFER URI)
- =cmacs-gsurf-title-changed-functions= (BUFFER TITLE)
- =cmacs-gsurf-load-changed-functions=  (BUFFER EVENT) — =started= /
  =committed= / =finished=.

* Render backends (pgtk vs =--lrg=)

gsurf has two render backends in one =libgsurf=, chosen *at runtime by the
Emacs frame type* — there is no separate Elisp surface, every
=cmacs-gsurf-*= command drives whichever backend the frame uses:

- *GTK3 / WebKitGTK (pgtk).* The default.  The live =WebKitWebView=
  =GtkWidget= is parented into =FRAME_GTK_WIDGET (f)= (the *Live embed*
  above).  Used on ordinary =emacs= (pgtk) frames.

- *libregnum / WebKit (=emacs --lrg=).*  Built with
  =--with-cmacs-gsurf-lrg=.  Under the lrgterm display backend there is no
  GTK widget tree, so the page is rendered to a libregnum =GrlTexture= and
  composited into the buffer's window rectangle by lrgterm
  (=lrg_paint_libregnum_window=), exactly like a cmacs-libregnum 3D buffer.
  Raylib input that lrgterm receives is routed back into the page
  (=cmacs/gsurf/cmacs-gsurf-lrg.c=): pointer over the window body, and —
  while the page holds focus — the keyboard (Escape always returns control
  to Emacs).  =cmacs-gsurf-focus-page= / a click focuses the page;
  =cmacs-gsurf-release-focus=, Escape, or switching windows release it.

  The web engine for this path is selected at build time: today it is
  *offscreen WebKitGTK* (it reuses the very =webkit2gtk-4.1= the pgtk embed
  already links — two WebKit libraries cannot coexist in one process), with
  WPE WebKit reserved as a future fully-GTK-free engine.  Because the engine
  feeds graylib/raylib through the canonical =liblibregnum.a=, =libgsurf.a=
  does not embed graylib (it is link-only), so no extra dedup is needed
  beyond the existing crispy/yaml-glib stripping.

  Render mode mirrors cmacs's own =LrgRenderMode=: only *2D* (a flat
  textured quad) is implemented; in =emacs --lrg=3d= the same flat texture
  is captured onto the 3D panel automatically (no gsurf-side 3D).  A
  =cmacs-gsurf-lrg-supported-p= predicate reports whether this backend was
  built in.

There is also a *standalone* =gsurf --lrg[=2d]= (the =deps/gsurf= binary):
a full browser in its own raylib window with an address/progress/hover
chrome, sharing all of the above backend code.

* Buffer & mode

=M-x cmacs-gsurf RET URL-or-search RET= opens a =*gsurf*= buffer.

** Focus model (important)

The window body is a *live GTK widget*.  If it held keyboard focus all
the time, Emacs (and evil) would never see your keys --- so cmacs-gsurf
manages focus explicitly:

- A gsurf buffer *starts under Emacs/evil control*.  The page is shown
  but does not capture keystrokes, so every normal Emacs and evil key
  works: window management (=C-w v=, =C-w h/j/k/l=), motions, =M-x=,
  =C-x= ..., plus the commands below.  Under evil the buffer is in
  *normal* state.
- *Scrolling works without focusing the page*: =h/j/k/l= (and =C-d/C-u=
  half-page, =C-f/C-b= full-page, =gg/G= top/bottom) scroll the live page
  while Emacs holds focus --- the buffer text is a hidden placeholder, so
  these keys are rebound from evil motions to page scrolling.  =SPC= is
  *not* bound, so the evil/Doom leader (=SPC b b=, etc.) works normally.
- *Click links with =f== (vimium-style): press =f= to overlay a chord
  label on every clickable element, then type the chord to click it
  (Escape cancels).  This focuses the page and drives gsurf's =modal=
  module.
- To *type* into the page, *give it focus*: press =RET= (or =i=), =M-x
  cmacs-gsurf-focus-page=, or just *click* it.  When focused, gsurf's
  own =modal= module owns the keys (its own =h/j/k/l=, =f=, =i= insert,
  …).
- To hand control back to Emacs: press *Escape* (handled in C --- it
  pulls focus back and drops evil to normal state; a first Escape in
  modal insert/follow returns to normal browsing, a second returns to
  Emacs), =C-c C-g= (=cmacs-gsurf-release-focus=), or simply *select
  another window* (clicking another Emacs window releases page focus
  automatically).

So the fix for "the browser ate my keybindings" is: press Escape (or
click another window) and you are back in evil-normal with =C-w= etc.

* Page events & hooks

Each live view bridges its WebKit signals to Emacs *abnormal hooks*, so
page activity can drive Lisp.  Besides the navigation hooks
(=cmacs-gsurf-{load,uri,title}-changed-functions=), these fire:

| Hook | Called with | Default behaviour |
|------+-------------+-------------------|
| =cmacs-gsurf-hovered-uri-changed-functions= | =(BUFFER URI)= | show the link under the pointer in the echo area (=cmacs-gsurf-show-hovered-uri=) |
| =cmacs-gsurf-progress-changed-functions= | =(BUFFER FRACTION)= | a =[NN%]= load indicator in the mode line |
| =cmacs-gsurf-crashed-functions= | =(BUFFER)= | header-line "web process terminated" notice; reload with =r= (or set =cmacs-gsurf-auto-reload-on-crash=) |
| =cmacs-gsurf-favicon-changed-functions= | =(BUFFER)= | refresh the header line |
| =cmacs-gsurf-download-changed-functions= | =(ID URI DEST RECEIVED TOTAL STATE)= | record the download (see below) |
| =cmacs-gsurf-permission-request-functions= | =(BUFFER ORIGIN TYPE)= | notify (the request was denied — see below) |

The title hook also renames the buffer to =*gsurf: TITLE*= (disable with
=cmacs-gsurf-rename-buffers=), and the buffer carries a header line with
the title/progress.  Popups (=target=_blank=, =window.open=,
middle-click) open in a new gsurf buffer displayed per
=cmacs-gsurf-popup-display-function= (default =display-buffer=; set to
=switch-to-buffer= to focus them, or =nil= to open in the background).

* Downloads

Downloads auto-save (no prompt) into =cmacs-gsurf-download-directory=
(default =~/Downloads=), de-duplicating colliding names
(=name (1).ext=).  =M-x cmacs-gsurf-downloads= opens the
=*gsurf-downloads*= manager, a =tabulated-list= of every download with
live progress:

| Key | Action |
|-----+--------|
| =g= | refresh |
| =c= | cancel the download on this line |
| =RET= / =o= | open the finished file in Emacs |
| =&= | open it with the system handler |
| =d= | remove the row (does not delete the file) |

Downloads are process-wide and outlive the buffer that started them, so
killing a gsurf buffer never aborts an in-flight download.  The lifecycle
is also available to automation via
=cmacs-gsurf-download-changed-functions= and the MCP tools.

* Permissions

When a page asks for a permission (geolocation, notifications,
camera/mic, clipboard, …) the decision is taken *without blocking* from a
per-origin policy table.  An origin with no saved policy is *denied* and
=cmacs-gsurf-permission-request-functions= fires so you can react.  Save a
decision with:

#+begin_src emacs-lisp
(cmacs-gsurf-allow-origin "https://maps.example.com" "geolocation")
(cmacs-gsurf-deny-origin  "https://ads.example.com" "notification")
#+end_src

These update =cmacs-gsurf-permission-policy= (an alist of
=(ORIGIN TYPE VERDICT)=) for the session; customize that variable to make
a policy persistent across restarts.  Recognised TYPEs are
=geolocation=, =notification=, =media=, =clipboard=, =device-info= and
=pointer-lock=.  (Interactive per-request prompting is intentionally not
the default, as a modal prompt inside the WebKit decision callback is
unsafe; the policy table is the non-blocking equivalent.)

* Snapshot, print & pipe

| Command | What it does |
|---------+--------------|
| =cmacs-gsurf-snapshot= (BUFFER FILE &optional CALLBACK FULL-PAGE) | save a PNG of the view (whole document with FULL-PAGE); async — CALLBACK gets the path |
| =cmacs-gsurf-print-to-pdf= (BUFFER FILE &optional CALLBACK) | print the page to a PDF with no dialog; async |
| =cmacs-gsurf-pipe= (=|=) | pipe the page text (HTML with a prefix arg) through a shell command into =*gsurf-pipe*= |
| =cmacs-gsurf-play-external= (=&=) | open the current page URL in =cmacs-gsurf-external-player= (default =mpv=) |

Both snapshot and print are asynchronous (WebKit renders off the main
loop); pass a callback to learn when the file is ready.

* AI: summarize & ask

With cmacs-ai configured, =cmacs-gsurf-summarize= (=C-c C-s=) extracts the
page text and opens an Org =*gsurf-summary*= side window; =cmacs-gsurf-ask=
(=C-c C-a=) answers a question about the page from its text.  Page text is
read with the result-returning JS primitive (no page focus needed) and fed
to =cmacs-ai-prompt-sync=; long pages are truncated to
=cmacs-gsurf-ai-max-chars=.  (These live in =cmacs-gsurf-ai.el=, loaded on
demand so the AI stack stays optional.)

* Native inspector

=cmacs-gsurf-inspect= (=C-c C-i=) opens =*gsurf-dom*=, a navigable DOM
tree of the live page (the walk stamps a =data-cmacs-node-id= on each
element so Emacs can address it).  On a node: =h=/=RET= outline it in the
page and scroll it into view, =c= shows its computed style in =*gsurf-css*=,
=g= re-walks.  Depth is =cmacs-gsurf-inspector-depth=.

=cmacs-gsurf-console= (=C-c C-l=) opens =*gsurf-console*=: it installs a
capture user-script that streams =console.log/info/warn/error= into the
buffer (via the JS bridge below), and =e= evaluates a JS expression in the
page and appends the result.  The whole inspector is injected JavaScript +
the result channel — the page is never focused.

* Bookmarks

=cmacs-gsurf-bookmark-add= (=m=) saves the current page (URL, title, tags)
to a small store (=cmacs-gsurf-bookmarks-file=).  =cmacs-gsurf-bookmarks=
(=C-c C-b=) opens =*gsurf-bookmarks*=, a =tabulated-list=: =RET=/=o= open
in gsurf, =d= delete, =e= edit tags, =/= filter by tag, =a= add, =g=
refresh.

* JS → Emacs bridge (window.cmacs.send)

The =js_bridge= gsurf module (in =cmacs/gsurf/modules/=, so gsurf itself
stays elisp-free) exposes a page→Emacs *data* channel.  Page or
user-script JS calls

#+begin_src js
window.cmacs.send("my-channel", {any: "json"});
#+end_src

and the C host bridge resolves the originating buffer and runs the
abnormal hook =cmacs-gsurf-js-message-functions= with =(BUFFER CHANNEL
PAYLOAD)= (PAYLOAD is the decoded JSON — *data only*, never evaluated).
This is the keystone the console capture rides on, and it is available for
your own user scripts (injected with =cmacs-gsurf-add-user-script=).

* Caret mode

=cmacs-gsurf-caret-mode= is a minor mode (on by default — see
=cmacs-gsurf-caret-mode-default=) that gives the live browser buffer an
in-page *text cursor* you move with Emacs/evil motions, so a page reads
like a normal buffer.  It is driven entirely from Emacs by injecting
JavaScript that moves the DOM selection (=getSelection().modify=) and
paints a fixed-position caret overlay; the page is *never focused*, so
the =SPC= leader, =C-w=, and =M-x= keep working throughout.  (It is
deliberately not a gsurf input-handler module — those only fire when the
page holds GTK keyboard focus, which the focus model forbids.)

| Key       | Action                                          |
|-----------+-------------------------------------------------|
| =h= / =l= | Move caret left / right by a character           |
| =j= / =k= | Move caret down / up by a line                   |
| =w= / =b= | Move caret forward / backward by a word          |
| =e=       | Move caret to the next word                       |
| =0= / =$= | Move caret to line start / end                   |
| =gg= / =G= | Move caret to document top / bottom             |
| =v=       | Start a highlight (subsequent motions extend it) |
| =y=, =M-w= | Copy the highlight to kill-ring + clipboard     |
| =RET=     | Activate (click) the link/button under the caret |
| =/=       | Search the page and jump the caret to the match  |
| =n= / =N= | Jump to the next / previous search match         |

The page auto-scrolls to keep the caret in view.  =C-d=/=C-u= (half
page), =C-f=/=C-b= (full page) and =C-e=/=C-y= (one line, like vim) all
scroll, =f= pops link hints, and =SPC= stays free for the leader.  =/=
runs an in-page search (via =window.find=) and moves the caret to the
hit so you can copy or follow from there; =n=/=N= repeat it.  While caret mode is on, =0= and
=$= move the caret; zoom-reset stays on =+= / =-= / ==.  Toggle with
=M-x cmacs-gsurf-caret-mode= to get plain =hjkl=-scroll back.  The
overlay colour is =cmacs-gsurf-caret-color=; the abnormal hook
=cmacs-gsurf-caret-functions= (=(BUFFER MOTION)=) fires after each
motion.

The caret =y= readback needs the result-returning primitive
=cmacs-gsurf-run-javascript-async= (BUFFER SCRIPT CALLBACK), which calls
CALLBACK with the script's value (the older =cmacs-gsurf-run-javascript=
is fire-and-forget).  The engine is installed once per page as a user
script via =cmacs-gsurf-add-user-script=.

* gsurf-lite — eww-style text buffers

=gsurf-lite= renders a page with gsurf/WebKit *offscreen* (its
JavaScript runs, and logins/sessions persist in WebKit's shared cookie
context) and dumps the post-JS DOM into a *real Emacs text buffer*
rendered with =shr= — like =eww=, but the HTML is WebKit's live
=document.documentElement.outerHTML= instead of a raw =url-retrieve=
fetch.  The result is a normal, navigable, copy/search/yank-able buffer
that works on JavaScript-only / single-page sites and stays logged in.

#+begin_src emacs-lisp
(cmacs-gsurf-lite "https://example.com")  ; M-x cmacs-gsurf-lite
#+end_src

A hidden =GsurfView= is attached to the lite buffer headless: its
WebKit widget is parented into the frame's =GtkFixed= at a full
viewport size but parked far below the visible area (=y=100000=), where
GTK clips it away.  It is realized -- so WebKit spawns its web process
and actually runs JavaScript with a real 1280x1024 viewport -- yet
never visible, and it is never resized to a window rectangle
(=cmacs-gsurf-place= / =-hide= are no-ops for an offscreen view, and
=cmacs-gsurf-offscreen-p= reports it), so the live page can never cover
the rendered text.  (A pure =GtkOffscreenWindow= does *not* start the
web process -- the JavaScript callback never fires -- which is why the
parked-in-frame approach is used.)  On each load-finish the post-JS
HTML is pulled out with =cmacs-gsurf-run-javascript-async= and rendered
with =shr=; links navigate the *hidden* view in place (not
=url-retrieve=), and the next load re-extracts and re-renders.

| Key       | Command                            | Action               |
|-----------+------------------------------------+----------------------|
| =RET=     | =cmacs-gsurf-lite-follow=          | Follow link at point |
| =g= / =r= | =cmacs-gsurf-lite-reload=          | Reload               |
| =B= / =F= | back / forward                     | Hidden-view history  |
| =o=       | =cmacs-gsurf-lite-open=            | Open a URL           |
| =RET=     | =cmacs-gsurf-lite-follow=          | Activate field / link |
| =TAB= / =S-TAB= | next / prev field or link    | Move between controls |
| =C-c C-c= | =cmacs-gsurf-lite-submit=          | Submit the form      |
| =&=       | =cmacs-gsurf-lite-browse-external= | Hand off to full gsurf |
| =q=       | =quit-window=                      | Bury the buffer      |

Links with no usable =href= (SPA / =onclick=) are clicked by a stable
=data-cmlite-id= stamped during extraction, then re-extracted after
=cmacs-gsurf-lite-extract-settle= seconds (pushState fires no load
event).  =cmacs-gsurf-lite-shr-width= overrides the shr fill width.

*Logins / forms work.*  Form controls render as editable items:
=Username: [ ]=, =Password: [ ]=, =[ ] remember=, =[ Log In ]=.  Move
between them with =TAB= / =S-TAB=.  Text, password and textarea fields
are *editable inline* -- just type into the box, characters self-insert
in place, =DEL= erases, and passwords echo as bullets; edits are pushed
into the live DOM on a short idle debounce (and immediately before any
submit/click).  Prefer the minibuffer?  Press =RET= on a field to read
the value there instead (passwords without echo via =read-passwd=).
Either way the value is masked in the extracted HTML -- passwords are
never written into it, only a filled/empty marker.  Toggle a
checkbox/radio or click a button with =RET=, and submit with =RET= on
the submit button or =C-c C-c=.  Filling pushes the value into
the *live DOM* through the native value setter plus =input=/=change=
events (so React/controlled inputs accept it), and submitting clicks
the real control -- so cookies, CSRF tokens, hidden fields and the
session all ride along exactly as a browser would send them.  A real
login (e.g. Fidelity) therefore works from the lite buffer; the
WebKit cookie jar is shared with full =cmacs-gsurf= buffers, so a
session established in one is visible in the other.  Pressing =&= still
hands the page off to a full live =cmacs-gsurf= buffer if you prefer a
real widget.  (File-upload inputs are out of scope -- JavaScript cannot
set =<input type=file>=.)

*SPA / late-rendering pages and redirects.*  Many sign-in and React/SPA
pages render their real content only after the load-finished event.
gsurf-lite re-extracts the DOM at each delay in
=cmacs-gsurf-lite-resettle-times= (default 0.6/1.6/3.0 s) so that content
appears; raise those values for very slow pages, or just =g= (reload) /
=&= (hand off) if a page is still blank.

Clicking a button or submitting -- e.g. *Log In* -- often kicks off work
that finishes later than one settle and may navigate *client-side*
(a =pushState= route change, a =window.location= bounce, or a
fetch-then-update), firing the load event late or not at all.  So after
any click/submit gsurf-lite re-extracts at each delay in
=cmacs-gsurf-lite-action-watch-times= (default 0.3/0.8/1.6/3.0/4.5/6.5 s)
and follows the page wherever it lands -- the buffer updates to the
post-login page even when no load event fires.  Lengthen the tail for
very slow sign-in flows.

* Configuration (from Emacs, by default)

cmacs-gsurf does *not* read gsurf's own =~/.config/gsurf/config.yaml=
(or =config.c=) by default --- it is configured from Emacs.  In fact it
tells gsurf to ignore YAML entirely (=cmacs-gsurf-ignore-yaml=, default
=t=, via gsurf's =ignore_yaml= flag).  gsurf modules are *disabled
unless a config enables them*, so this is also how the vim =modal=
module (=hjkl= scroll, =f= link hints) gets turned on.

The primary knob is =cmacs-gsurf-modules=, an alist of
=(MODULE-NAME . PLIST)=.  Each entry is pushed onto the gsurf config
through gsurf's programmatic C-config setters
(=gsurf_config_set_module_enabled= / =_set_module_option=) *before the
modules load* --- no YAML file involved:

#+begin_src emacs-lisp
(setq cmacs-gsurf-modules
      '(("modal"          :enabled t :scroll_step 100 :hint_chars "asdfjkl")
        ("search_engines" :enabled t)
        ("history"        :enabled t)
        ("dark_mode"      :enabled t)
        ("adblock"        :enabled t)))
#+end_src

PLIST keys: =:enabled BOOL= turns the module on/off (consulted by the
module manager at load time, taking precedence over any YAML); any other
=:KEY VALUE= becomes a module option (string/number/boolean, coerced to
a string for gsurf).  The *default* value enables the windowless
essentials: =modal=, =search_engines=, =history=.  (Modules that draw
their own chrome windows --- =chromebar=, =tabs=, =omnibar=, =find_bar=,
=status_bar= --- are best left disabled in the embedded browser, which
has no gsurf window.)

After editing in a running session: =M-x cmacs-gsurf-reload-config=
(programmatic setters apply live to already-loaded modules too).

** Opting in to gsurf's own config files

#+begin_src emacs-lisp
;; Also read ~/.config/gsurf/config.yaml and config.c if present:
(setq cmacs-gsurf-load-user-config t)

;; Or load a specific YAML file (overrides `cmacs-gsurf-modules'):
(setq cmacs-gsurf-config-file "~/my-gsurf.yaml")

;; Or a compiled C config (crispy) -- e.g. a cmacs init.c:
(setq cmacs-gsurf-config-c-file "~/.config/cmacs/init.c")
#+end_src

Layering, last wins: =cmacs-gsurf-modules= → user =config.yaml= (if
opted in) → =cmacs-gsurf-config-file= → C config.

The underlying primitives (usable directly):

- Programmatic setters (gsurf's C-config API, the default path):
  =cmacs-gsurf-config-set-module-enabled=,
  =cmacs-gsurf-config-set-module-option=,
  =cmacs-gsurf-config-set-homepage=, =cmacs-gsurf-set-ignore-yaml=.
- File / string loaders: =cmacs-gsurf-load-config-data= (a YAML
  string), =cmacs-gsurf-load-config-file= (a YAML file), and
  =cmacs-gsurf-load-config-c-file= (a crispy-compiled C config whose
  =gsurf_config_init()= runs against the config --- it may call any of
  the gsurf =gsurf_config_*= setters, e.g. from =~/.config/cmacs/init.c=).

* Modules

gsurf modules load from these directories (first match by filename
wins, like =$PATH=):

1. =$CMACS_GSURF_MODULE_DIR=  (exported by =just run= for dev testing)
2. =$GSURF_MODULE_PATH=
3. =cmacs/gsurf/modules/=     (cmacs custom modules, compiled-in dev path)
4. =deps/gsurf/build/release/modules/=  (gsurf stock modules)
5. =$libdir/cmacs/gsurf/modules/=  (installed)

Which modules are *enabled* comes from the config (see above), not the
search path.  Inspect / toggle at runtime from Elisp:

#+begin_src emacs-lisp
(cmacs-gsurf-modules-list)                    ; JSON: name/description/enabled/active
(cmacs-gsurf-module-set-enabled "adblock" t)
#+end_src

* Elisp API

#+begin_src emacs-lisp
(cmacs-gsurf "https://gnu.org")               ; open a browser buffer
(cmacs-gsurf-load-uri (current-buffer) "https://example.com")
(cmacs-gsurf-back (current-buffer))

* MCP tools

With =--with-cmacs-mcp=, these tools are exposed (and reachable from
cmacs-ai via the MCP bridge — =^gsurf_= is in the default allowlist):

| Tool | Args | Notes |
|------+------+-------|
| =gsurf_open= | url | new buffer; returns its name |
| =gsurf_navigate= | url, [buffer] | |
| =gsurf_back= / =gsurf_forward= / =gsurf_reload= / =gsurf_stop= | [buffer] | |
| =gsurf_get_uri= / =gsurf_get_title= | [buffer] | read-only |
| =gsurf_current= | — | read-only JSON |
| =gsurf_list= | — | read-only JSON array |
| =gsurf_modules_list= | — | read-only |
| =gsurf_eval_js= | script, [buffer] | fire-and-forget |
| =gsurf_set_zoom= | level, [buffer] | |
| =gsurf_lite_open= | url | offscreen render; returns buffer name |
| =gsurf_extract_text= | [buffer] | read-only; rendered page text |
| =gsurf_download_list= | — | read-only JSON of downloads |
| =gsurf_download_cancel= | id | cancel a download |
| =gsurf_snapshot= | file, [full_page], [buffer] | save a PNG (async) |
| =gsurf_print_pdf= | file, [buffer] | print to PDF (async) |
| =gsurf_permission_policy= | origin, type, verdict | set a permission policy |

=buffer= defaults to the most-recently-opened gsurf buffer.  (To summarize
a page over MCP, compose =gsurf_extract_text= with the =ai_*= tools; the
interactive =cmacs-gsurf-summarize= command is the Emacs-side equivalent.)

Browser activity is also emitted as *podomation events* —
=on_gsurf_navigate=, =on_gsurf_download=, =on_gsurf_permission= and
=on_gsurf_crash= — so pods can react to it (=when on_gsurf_download { ... }=).

* Troubleshooting

- *=cmacs-gsurf-error: gsurf backend unavailable (no display?)=* — the
  WebKit backend needs a display; this is expected under =--batch=.
- *Keyboard goes to the page, not Emacs / keybindings stop working* —
  the page has GTK focus.  Press *Escape* to return to Emacs (evil drops
  to normal state), or *click another Emacs window* (that releases page
  focus automatically), then =C-w=, =M-x=, motions etc. work again.  A
  freshly-opened gsurf buffer starts under Emacs control; the page only
  takes focus when you press =RET=/=i= or click it.  See *Focus model*
  above.
- *A module isn't applying* — check =(cmacs-gsurf-modules-list)=; enable
  it with =cmacs-gsurf-module-set-enabled= or via the gsurf YAML config
  =modules:= section (=~/.config/gsurf/config.yaml=).
- *Stale Elisp* — after editing =lisp/cmacs/cmacs-gsurf.el=, clear the
  =.elc=/=.eln= caches (see the top-level CLAUDE.md).
- *=Overriding existing handler for signal 10= at startup, and podomation
  =on_sigusr1= stops firing* — WebKit's JavaScriptCore pauses threads for
  GC using a signal that defaults to *SIGUSR1* (signal 10), the same
  signal podomation's =engine= source, libreclaw's thread-dump, and
  Emacs's =[sigusr1]= use; whoever installs last wins, so JSC steals it.
  cmacs moves JSC to a free real-time signal (40 = SIGRTMIN+5 on Linux) in
  C at the top of =main()= via JSC's private =JSConfigureSignalForGC()=
  (see =src/emacs.c=), so this is handled automatically for both
  =./src/emacs= and =just run=.  =SIGUSR2= / =SIGHUP= are unaffected.
  (cmacs does *not* set the =JSC_SIGNAL_FOR_GC= environment variable: it
  works, but JSC's option parser also scans every =JSC_*= var and rejects
  it with =ERROR: invalid option: JSC_SIGNAL_FOR_GC=40=, once per
  JSC-initialising process — the programmatic call avoids that noise.)
- *=ERROR: invalid option: JSC_SIGNAL_FOR_GC=...=* — you have
  =JSC_SIGNAL_FOR_GC= set in your environment.  Unset it; cmacs configures
  the GC signal programmatically and the env var only triggers JSC's
  option-parser rejection.
