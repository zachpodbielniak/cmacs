#+TITLE: cmacs-libregnum: 3D scene buffers
#+AUTHOR: Zach Podbielniak

* Overview

=cmacs-libregnum= embeds [[https://github.com/zpodbielniak/libregnum][libregnum]] — a GObject-based game engine
wrapping raylib via graylib — as a first-class cmacs subsystem.
Each =cmacs-libregnum-mode= buffer owns a 3D scene that is rendered
to a BGRA framebuffer and blitted across the whole window area on
every redisplay.

The "buffer text" of a libregnum buffer is a small YAML-ish
description of the scene (scene type, source data path, camera
state).  Saving the buffer snapshots the current camera into the
text; opening a saved buffer rebuilds the scene and restores the
camera.

Besides the built-in scene visualisers, a buffer can also host a full
libregnum *game* loaded as a module — see [[*Game module hosting]].

** Architecture

cmacs does *not* drive libregnum through a native =GtkGLArea= child
widget.  raylib's =CORE.Window= globals make external GL contexts
infeasible without multi-week upstream patches.  Instead:

1. cmacs acquires a single process-shared *hidden* raylib window
   (=FLAG_WINDOW_HIDDEN= set before =InitWindow=).
2. Each view owns a =RenderTexture2D= (a raylib FBO) sized to its
   target dimensions, plus a double-buffered Cairo =ARGB32= surface
   (front read by the paint hook, back written by the renderer).
3. On every redraw tick, =cmacs_libregnum_render_ctx_render_to_bgra=
   draws the scene to the FBO and reads it back with a single
   =glReadPixels= in =GL_BGRA= directly into the back surface, then
   swaps front/back.  =GL_BGRA= matches Cairo's =ARGB32= byte order
   on little-endian, so there is no CPU channel-swap loop and no
   per-frame allocation; the bottom-up GL origin is flipped for free
   by the paint hook's Cairo matrix.
4. The view asks the screen to refresh via =gtk_widget_queue_draw=
   on the GTK widget of each frame showing the buffer.  That re-runs
   =pgtk_handle_draw=, which calls =cmacs_libregnum_overlay_paint= to
   blit the front surface — *without* a full Emacs redisplay.

This is compositor-agnostic — same hook works under Wayland (pgtk)
and any compositor that supports pgtk.

** Rendering pipeline & performance

Three design choices make scene interaction (orbit/zoom) feel
real-time rather than a slideshow:

1. *No hidden-window presentation.*  The render path does *not* call
   =lrg_window_begin_frame= / =lrg_window_end_frame=.  Those wrap
   raylib's =BeginDrawing= / =EndDrawing=, and =EndDrawing= presents
   and *paces* the hidden window: =glfwSwapBuffers= (a vsync block),
   =WaitTime= (the window's =SetTargetFPS(60)= cap — up to ~16 ms of
   sleep per call), and =glfwPollEvents=.  For an offscreen FBO that
   is never shown, all three are pure latency, and the =WaitTime= cap
   alone was throttling every scene update.  Offscreen rendering needs
   only =BeginTextureMode= / =EndTextureMode= plus a current GL
   context — the render batch is set up by =InitWindow= and flushed by
   =EndTextureMode=, so no =BeginDrawing= is required.

2. *Targeted overlay refresh, not full redisplay.*  =notify_frame_ready=
   (in =cmacs-libregnum-view.c=) calls =gtk_widget_queue_draw= on the
   widgets of frames showing the buffer, NOT =force-window-update=.
   A =force-window-update= triggers a full =redisplay_internal= every
   frame; profiling showed that as ~35 ms/frame, capping interaction
   at ~20 FPS even though the render itself was only ~10–15 ms.  The
   targeted invalidate re-runs just =pgtk_handle_draw= (the blit) at
   the GTK frame-clock rate, restoring 40–60 FPS.  This is correct
   because the libregnum buffer's text is static and entirely hidden
   behind the blit, so Emacs's backing surface is already up to date —
   only the overlay needs recompositing.

3. *Double buffering.*  The renderer fills the back surface and swaps
   under a mutex held only for the pointer swap, so the paint hook
   never blocks on an in-flight render.

*Continuous animation.*  Static scenes render on demand (input,
camera changes, explicit redraw).  For animated content, switch a
view into animation mode — =M-x cmacs-libregnum-toggle-animation=
(bound to =a=) or the =cmacs-libregnum-set-animated= primitive.  A
shared GMainContext timer then re-renders the view at
=cmacs-libregnum-target-fps= (default 60) for as long as it stays
on-screen.  Visibility is tracked without Lisp: the paint hook stamps
each view it blits with a generation counter, and the timer skips —
and ultimately stops for — views whose buffer is no longer shown, so
an idle or hidden scene costs nothing.

*Why rendering is single-threaded.*  An off-thread GL worker (moving
the raylib context to a dedicated thread via the GLFW
make-context-current handoff, with double-buffered PBO async readback)
was implemented and then reverted.  It *regressed* frame rate: the
worker→main per-frame handoff plus GPU-driver contention between the
worker's GL context and pgtk's main-thread Cairo/GL outweighed any
benefit, because once the FPS cap was removed the render (~10–15 ms
for ~1500 cubes) was never actually blocking the main thread.  The
experiment is parked on the =libregnum-offthread-wip= branch; don't
re-land it without a profile showing the render blocking the main
thread.

** Translation-unit firewall

raylib defines =Color= as a struct; cmacs's =pgtkgui.h= defines
=Color= as =void *= for opaque colour handles.  These conflict.
The fix: =cmacs/libregnum/cmacs-libregnum-render.c= is the *only*
translation unit that includes raylib headers; everything else
(view, defuns, overlay, input) talks to it through the plain-C
=cmacs-libregnum-render.h= API that exposes opaque pointers.

* Building

=--with-cmacs-libregnum= turns on the subsystem.  Configure probes
for a system =libregnum-1.0.pc=, falling back to the bundled
=deps/libregnum= submodule.  The block requires both
=--with-cmacs-glib= (event loop integration) and =--with-pgtk=
(the only compositor backend wired through =pgtk_handle_draw=).

Emacs links the libregnum *static* archive with =-Wl,--whole-archive=
and =-Wl,--allow-multiple-definition=.  The whole-archive pull-in is
what lets a buffer host an arbitrary game module: a host-agnostic
module (see [[*Game module hosting]]) resolves its libregnum symbols
from Emacs, so *every* libregnum symbol — not just the ones cmacs
itself calls (e.g. game-template types) — must be present and, via
=--export-dynamic=, exported.  =--allow-multiple-definition= absorbs
raylib's inline raymath (=QuaternionToMatrix=, =MatrixDecompose=, …),
which the headers emit without =static= into multiple objects.

* Interactive commands

=M-x cmacs-libregnum-demo= opens an empty scene buffer; useful as
a smoke test for the render pipeline.

=M-x cmacs-libregnum-project-tree= builds a *navigable* 3D
directory tree of the current project.  Directories are spheres,
files are cubes (height = log file size, hue = extension), laid out
as a tidy hanging tree -- depth on =Y=, siblings spread on =X= with
width proportional to subtree size -- and joined to their parent by
thin edge lines.  Directory names (and the selected node's name) are
drawn as labels in the scene.  =.git=, =build=, =node_modules=,
=native-lisp=, and =__pycache__= are skipped; the walk is depth- and
node-capped.  See [[*Navigating the project tree]] for interaction.

=M-x cmacs-libregnum-gobject-graph= visualises the live GObject
type tree.  With a prefix arg you can pass a leading type-name
prefix (e.g. =Gtk=, =Lrg=, =Mcp=) to scope the graph.  Depth on
=Y=, siblings fan out on =X=; hue derived from the first uppercase
prefix in the type name so e.g. =Lrg= types cluster visually
against =Gtk= types.

=M-x cmacs-libregnum-mind-map= parses an org file's heading tree
into a radial mind map.  Each heading is a node, parent/child
relationships are =LrgLine3D= edges, and the layout is
deterministic so reopening the same file produces the same map.

=M-x cmacs-libregnum-toggle-animation= switches the current view
between on-demand rendering and continuous animation at
=cmacs-libregnum-target-fps= (default 60).  Use it for scenes that
move on their own; static visualisations don't need it (they already
redraw in real time on orbit/zoom).  The primitive is
=cmacs-libregnum-set-animated= (=BUFFER FLAG &optional TARGET-FPS=).

* Navigating the project tree

The project-tree scene is interactive.  Every node (directory or
file) is recorded in a node table that drives picking, labels and a
keyboard navigation model.

Mouse:

- *Left-click a file* -> open it in Emacs (=find-file=).
- *Left-click a directory* -> drill in: the scene re-roots at that
  directory so you can focus on one subtree at a time.
- *Left-drag* still orbits, *right-drag* pans, *scroll* zooms.  A
  click is distinguished from a drag by whether the pointer moved.

** In-scene labels

Node labels are painted by default in cairo, over the blitted framebuffer, from
=pgtk_handle_draw=.  That has two consequences worth naming: they do not exist
at all under =emacs --lrg=, and they never appear in =cmacs-libregnum-snapshot=
— so no automated test can see them.

=cmacs-libregnum-set-inscene-labels= moves the pass *into* the framebuffer,
drawn as a screen-space pass at the end of =render_to_bgra=.  Both display
backends funnel through that one function (with a NULL destination on the lrg
FBO-only path), so a single code path serves both, and snapshots show the
result.  The cairo pass suppresses itself when the flag is on, so nothing is
double-drawn under pgtk; a context that never sets the flag keeps the legacy
behaviour byte for byte.  Companions: =cmacs-libregnum-set-label-font= (a real
TTF, baked large at 32px and drawn small through a bilinear filter, with an
extended codepoint set so em dashes and accents are not missing-glyph boxes)
and =cmacs-libregnum-set-label-style= (size, shadow, decluttering, per-frame
cap).

Two rules govern any 2D pass added there.  Both cost real debugging time:

1. *Do not flip Y.*  The colour attachment is bottom-up in memory and the blit
   flips it at paint time, which strongly invites a compensating
   ~y = vh - y - th~.  That is wrong: =BeginTextureMode= already installs a
   projection making raylib's 2D drawing top-down in the texture's own space,
   the same orientation =GetWorldToScreenEx= reports.  Adding the flip mirrors
   every label about the middle of the viewport, so it lands *below* its node
   instead of above.
2. *Flush the batch.*  =EndMode3D= submits the 3D batch, but anything drawn
   after it opens a fresh batch that =EndTextureMode= only submits *after*
   =glReadPixels=.  =rlDrawRenderBatchActive()= must therefore be unconditional
   and sit immediately before the readback.  Omit it and labels render fine
   under =--lrg= (which never reads back) and are invisible under pgtk — the
   same asymmetry the calculator's =chart_mode= documents.

=cmacs-libregnum-ink-bbox= exists to make rule 1 testable: it returns the
bounding box of the non-background pixels of a freshly rendered frame, in
*displayed* orientation.  A snapshot proves that pixels changed; the ink box
proves they changed in the right place, which is the distinction a mirrored
label slips through.

** Click dispatch & the loading invariant

All viewport clicks are handled in C (=cmacs-libregnum-input.c=): the click
ray-picks a node synchronously, then *defers* a dispatch onto the cmacs
GMainContext to one of four Elisp entry points — =cmacs-libregnum--node-clicked=
(scenes, gnuseye and roamgraph, with the node id, its *path string*, is-dir
flag, and the view-local click pixel), =cmacs-libregnum-editor--on-select=,
=cmacs-libregnum-editor--drop=, and =cmacs-libregnum-editor--context-menu=.

Two invariants follow from this design — both learned the hard way:

1. *The dispatcher's file must be loaded before a view can exist.*  The C
   side calls =intern= + =safe_call=, which *mutes* a =void-function= error
   — the click dies silently (the only trace is an "Error muted by
   safe_call" line in =*Messages*=).  Every entry point that creates a view
   must guarantee the load: =cmacs-gnuseye.el= ~(require 'cmacs-libregnum)~
   for exactly this reason (a globe-only session never loaded the
   dispatcher and *every* click was dropped); the editor's dispatchers live
   in the same file as its =cmacs-libregnum-editor= entry command, and the
   MCP =lrg_editor_open= tool requires the file before calling it.
2. *Numeric node ids go stale across scene rebuilds; path strings do not.*
   The dispatch is deferred, so anything that rebuilds the node table
   between pick and dispatch (gnuseye's smooth tick re-renders moving
   layers every ~0.4 s) renumbers the ids.  gnuseye therefore resolves
   clicks by the pick-time *path* (its entity id) and uses the numeric id
   only as a fast hint.  The editor is safe by construction: its node table
   only changes on explicit edit operations, and the engine-side selection
   (=set_selected=) happens *synchronously* at click time — the deferred
   Elisp call only syncs the outliner/inspector panels.

When debugging "clicks do nothing": check =*Messages*= for muted
=safe_call= errors first.

Keyboard (a selection cursor highlights one node; the camera eases
to frame it, and its name is echoed):

| Key                 | Action                                  |
|---------------------+-----------------------------------------|
| =<up>= / =k=        | select parent                           |
| =<down>= / =j=      | select first child                      |
| =<left>= / =h=      | select previous sibling                 |
| =<right>= / =l=     | select next sibling                     |
| =RET=               | open file / drill into directory        |
| =u= or =^=          | go up one directory (re-root to parent) |

Picking is a ray-cast (raylib =GetScreenToWorldRayEx= +
=GetRayCollisionBox= against each node's AABB) done on the main
thread from the live camera; the file-open / drill action is
deferred onto the cmacs GMainContext so no Lisp runs inside the GTK
event handler.  =cmacs-libregnum-tree-nodes= exposes the model to
Lisp (a vector of =(:id :name :path :dir :depth :parent)= plists).

* Scene appearance & navigation API

A second wave of render-context knobs, driven by the roamgraph subsystem
([[file:cmacs-roamgraph.org][cmacs-roamgraph.org]]).  *Every one of them defaults to the previous
behaviour*, so the tree, gobject, mindmap, gnuseye, CAD and editor scenes
are byte-for-byte unchanged unless they opt in.

** Per-node flags

A bitmask alongside the node table, kept deliberately separate from
=selected= — that is a single =gint= and is already load-bearing (the
highlight marker, =focus_node=, the editor's multi-select).  A search
match set and a selection are different things and must coexist.

| Bit | Name        | Meaning                          |
|-----+-------------+----------------------------------|
|   1 | =MATCH=       | A search hit                     |
|   2 | =DIM=         | De-emphasised                    |
|   4 | =PINNED=      | User pinned                      |
|   8 | =NEIGHBOUR=   | One hop from the selection       |

- =cmacs-libregnum-set-node-flags= / =-clear-node-flags= / =-node-flags=
- =cmacs-libregnum-set-match-set= — replaces the *whole* set in one call,
  optionally dimming everything else.

That bulk call is the point: an incremental search costs one call per
keystroke rather than one per node.  =MATCH=, =PINNED= and =NEIGHBOUR= also
override the per-node label policy, because highlighting something you
then cannot read the name of is useless.

** Spatial navigation

- =cmacs-libregnum-nearest-in-direction= — the nearest node to another
  within a screen-space cone.  Candidates are scored =distance / cos³(angle)=
  so alignment beats raw distance, and ties break on the lower node id so
  repeated presses never oscillate.
- =cmacs-libregnum-node-onscreen-p= — projects inside the viewport, inset
  by a margin.  Lets a caller move the camera only when the target would
  otherwise be off-screen.

Both live in C because the alternative is one projection call per
candidate per keypress, against a camera that may be mid-tween.

Note that a cone metric is *not self-inverse*: going right then left can
land somewhere new.  A caller that wants exact reversal has to remember
the move rather than recompute it.

** Appearance

- =cmacs-libregnum-set-label-decor= — a translucent plate behind label
  text (the scene's own geometry runs through it otherwise), and
  screen-space emphasis rings on the selected, hovered and matched nodes.
  Rings are screen-space on purpose: they read the same at any zoom,
  which a fixed world-space marker does not.
- =cmacs-libregnum-set-selection-style= — =box= (the legacy wireframe cube,
  right for scenes whose nodes *are* boxes), =halo= (a wireframe shell,
  right for spheres), or =none= for a scene drawing its own marker.
- =cmacs-libregnum-set-label-font= bakes a real TTF at a large size and
  draws it small through a bilinear filter.  Its codepoint set covers
  ASCII, Latin-1 and General Punctuation — the loader's default is the 95
  printable ASCII characters, which turns every em dash and accent in a
  user's own prose into a missing-glyph box.

** Navigation profiles

Two mouse conventions, both opt-in:

- =cmacs-libregnum-set-right-drag-pans= — the *map* profile: left-drag
  orbits, right-drag pans.  The default is the *CAD* profile (either
  button orbits, the middle one pans), which suits a modelling viewport
  but assumes a middle button worth using.
- =cmacs-libregnum-set-wheel-up-zooms-in= — the conventional wheel
  direction.  GDK reports a *positive* delta for scrolling *down*, and the
  zoom kernel moves closer for a positive amount, so passing the delta
  straight through means scrolling down moves you closer.  That is the
  inherited behaviour and it is backwards; scenes opt out rather than
  having it flipped underneath them.

A right-*click* without movement still opens the context menu under
either profile — only a drag moves the camera.

- =cmacs-libregnum-set-orbit-locked= — stop the camera tumbling while
  leaving pan and zoom live.  For a scene showing a planar layout
  head-on, orbiting only reveals that everything is coplanar.
- =cmacs-libregnum-orbit= / =cmacs-libregnum-pan= drive the camera from
  Lisp, which is also what makes the lock testable.

** Keeping picks in sync

=cmacs-libregnum-render-ctx-move-node= moves a node's pick box.  A scene
that mutates its drawables in place — an animated force layout, a dragged
node — must call it, or picking and labelling keep pointing at where the
node used to be.

* Game module hosting

Beyond the built-in scene visualisers, a =cmacs-libregnum= buffer can
host a *full libregnum game*.  A game built with the
=LRG_DEFINE_GAME_MODULE= macro produces a host-agnostic shared module
(=.so=); cmacs loads it, drives it each frame, and forwards input to
it, so the game runs *inside an Emacs buffer*.

=M-x cmacs-libregnum-play= prompts for a game module and opens a buffer
that renders and plays it:

#+begin_example
  (cmacs-libregnum-play "/path/to/libmygame.so")
#+end_example

Both =cmacs-libregnum-play= and the lower-level =cmacs-libregnum-load-game=
take an optional =ARGV= --- a list of strings passed verbatim to the module
as a =main()=-style argument vector.  It is applied through libregnum's
=LrgConfigurable= interface (=lrg_game_template_apply_args=) *before*
startup, so the module configures itself from the same flags its standalone
binary accepts; a rejected argument warns but does not abort the load:

#+begin_example
  (cmacs-libregnum-play "/path/to/blackhole.so" '("--profile" "warm"))
#+end_example

This is what the screensaver subsystem uses to drive several configured
variants of one module (see =doc_org/cmacs/cmacs-screensaver.org=).

** How it works

The game is driven through libregnum's host abstraction =LrgGameHost=.
cmacs implements =CmacsFboGameHost=, which lends the game cmacs's
already-running engine and renders it into the view's FBO — exactly the
offscreen path the scene visualisers use — so no extra window is
created.  Each frame, =render_to_bgra= advances the game
(=lrg_game_template_update=, with a monotonic delta since the FBO path
never presents a backbuffer) and draws it (=lrg_game_template_render=),
then reads the FBO back into the buffer's surface as usual.

Because the host owns no =LrgWindow=, an embedded game never grabs the
real cursor (an FPS enabling mouse-look is a no-op on the cursor), and
it never starts or stops the shared engine (engine startup is
reference-counted in libregnum, so the host and the game share one).

** Input

- *Mouse* is routed by the C layer: in a game buffer,
  =cmacs-libregnum-handle-motion/button/scroll= forward the pointer and
  buttons to the game instead of orbiting the scene camera.
- *Keyboard* is forwarded by the =cmacs-libregnum-game-mode= minor mode
  (enabled automatically by =cmacs-libregnum-play=).  Emacs delivers no
  key-/release/ events, so a held key is emulated from keyboard
  auto-repeat: the first press is sent immediately, each auto-repeat
  re-arms a release timer, and when the repeats stop the key is
  released.  Tune =cmacs-libregnum-game-key-release-delay= (default
  =0.4=) a little above your system's key-repeat delay to keep a held
  key from stuttering.

Letters, digits, space, the arrows, common editing/function keys and
1:1 punctuation are mapped to graylib =GrlKey= codes and sent on.  Quit
with =C-c C-q= (=cmacs-libregnum-game-quit=), which releases held keys,
unloads the game, and kills the buffer.

Under Doom/Evil the buffer stays in Evil emacs state so these keys reach
the game; the =C-w= window-command prefix is preserved, so window
management (=C-w v=, =C-w s=, =C-w h/j/k/l=, …) still works while playing.

** Host-agnostic modules

A game module links *no* libregnum of its own: its libregnum symbols
are left undefined and resolved at load time from whichever host loads
it.  The same =.so= therefore runs unchanged under the standalone
=lrg-launcher= shim (which provides libregnum via its shared library)
and under cmacs (which static-links libregnum into Emacs with
=--whole-archive --export-dynamic=; see [[*Building]]).  This keeps
exactly one copy of the engine and the GType registry in the process.

* Buffer text format

A minimal YAML subset.  Comments start with =#=; blank lines are
ignored.  Recognised keys:

#+begin_example
  # -*- mode: cmacs-libregnum -*-
  scene_type: project_tree
  project_root: /var/home/zach/source/projects/cmacs
  position: [10.0, 8.0, 14.0]
  target:   [0.0, 0.0, 0.0]
  fov:      60.0
#+end_example

=scene_type= dispatches the rebuild:

| scene_type       | Required key | Notes                            |
|------------------+--------------+----------------------------------|
| =project_tree=   | =project_root= | absolute path of a directory   |
| =gobject=        | =namespace=  | optional prefix; empty = all     |
| =mindmap=        | =org_file=   | absolute path to a =.org= file   |

The =position=/=target=/=fov= triple is updated on save and
re-applied on next open via =before-save-hook= and the mode's
initialization scan.

* Known limitations (v1)

- Multi-window: each on-screen view now auto-resizes its framebuffer to
  its window's pixel size (a debounced =window-size-change= hook,
  =cmacs-libregnum--fit-views=), so a single view is no longer stretched
  when its window is resized.  The same buffer shown in *two* windows of
  *different* sizes still shares one framebuffer, so only one of them is
  pixel-exact.
- No labels on the GObject / mindmap scenes yet — class and
  heading names live in the underlying nodes but are not blitted
  as text-billboards.  Tracked as a follow-up.
- Pick (click-to-jump) is not yet wired: =LrgSceneEntity= has the
  picking primitive but the scenes use raw drawable lists, not
  scene entities, for v1 simplicity.  Following commits will add
  a payload map keyed by drawable identity.

* Editor / Level Authoring

** Overview

libregnum now ships an IDE-hostable editor runtime alongside its game engine.
The relationship mirrors Unreal Engine ↔ Unreal Editor: the *editor runtime
lives entirely inside libregnum* and is host-agnostic; cmacs is one frontend,
and a standalone engine-drawn editor is another.  See the design plan at
=~/.claude/plans/we-recently-added-support-stateless-rossum.md= for the full
architecture.

The level model (=LrgLevel= / =LrgNode=, serialized as =.rlevel= YAML files)
is a new *authoring layer* that sits above the existing runtime layers:

- =LrgLevel= / =LrgNode= — the editable document (authoring layer, new,
  =deps/libregnum/src/editor/=).
- =LrgScene= / =LrgSceneObject= — the renderer's geometry model (existing;
  produced by baking a level with =lrg_level_to_scene=).
- =LrgWorld= / =LrgGameObject= — the ECS runtime (existing; produced by
  instantiating a level with =lrg_level_instantiate= for play-in-editor).

Neither bridge mutates the source =LrgLevel=, so editing, baked previews,
and play-in-editor can coexist safely.

** Engine-side editor types (implemented)

The following types are part of the libregnum library and are available
in the =Libregnum= GIR typelib.  Because cmacs loads the libregnum typelib
via the =gi= subsystem, all of these types are reachable from Elisp through
=cmacs-gi-require=, =cmacs-gi-call=, and =cmacs-gi-method-call= today.

*** LrgLevel — the level document

=LrgLevel= (=src/editor/lrg-level.h=) is a final GObject.  It owns a root
=LrgNode= whose descendants form the editable scene tree, level-wide settings
(name, =default-2d= flag), and emits three signals so a host IDE can keep its
panels in sync:

- =node-added= (=LrgNode *node=)
- =node-removed= (=LrgNode *node=)
- =node-changed= (=LrgNode *node=)

Key API:
- =lrg_level_new (name)= — create an empty level with a single root node.
- =lrg_level_get_root (level)= — the root =LrgNode= (not serialized as content).
- =lrg_level_add_node / remove_node / find_node (level, …)= — tree management.
- =lrg_level_notify_node_changed (level, node)= — trigger panel refresh.

*** LrgNode — the scene-tree element

=LrgNode= (=src/editor/lrg-node.h=) is a *derivable* GObject — the single
unifier of 2D and 3D content.  Every node carries:

- A stable =guid= string (survives save/load round-trips).
- A local *TRS* transform: =location= / =rotation= (Euler radians) / =scale=
  as =GrlVector3= values.  World transform is computed lazily as
  =parent * T*R*S=.  2D nodes live at Z=0 with =is-2d= set as a gizmo/camera
  hint — the transform is always 3D.
- An optional =LrgNodeVisual= payload describing what the node renders.
- An ordered =GPtrArray= of =LrgComponentDesc= records.
- An ordered =GPtrArray= of =LrgScriptBinding= records.
- =visible= / =locked= flags.

Custom node kinds may subclass =LrgNode= and override the =instantiate=
virtual method to build their own runtime representation.

*** LrgNodeVisual — visual payload

=LrgNodeVisual= (=src/editor/lrg-node-visual.h=) is a tagged record
discriminated by =LrgNodeVisualKind=:

| Kind                              | Payload                                     |
|-----------------------------------+---------------------------------------------|
| =LRG_NODE_VISUAL_NONE=            | Empty / group node                          |
| =LRG_NODE_VISUAL_PRIMITIVE=       | =LrgPrimitiveType= + =LrgMaterial3D=         |
| =LRG_NODE_VISUAL_MESH_ASSET=      | Asset reference (path or guid) + material   |
| =LRG_NODE_VISUAL_SPRITE=          | 2D texture asset reference                  |
| =LRG_NODE_VISUAL_TILEMAP=         | Tileset asset reference                     |
| =LRG_NODE_VISUAL_LIGHT=           | Kind-specific params (intensity, color, …)  |
| =LRG_NODE_VISUAL_CAMERA=          | Kind-specific params (fov, near/far, …)     |
| =LRG_NODE_VISUAL_AUDIO_EMITTER=   | Audio asset reference + positional params   |
| =LRG_NODE_VISUAL_PREFAB_INSTANCE= | Prefab guid + property overrides            |

Kind-specific scalar settings live in a typed =GValue= parameter bag
(=lrg_node_visual_set_param= / =get_param= / =set_param_double= /
=get_param_double=).

*** LrgEditor — the editor runtime core

=LrgEditor= (=src/editor/lrg-editor.h=) is a final GObject and the
central C API contract.  It owns:

- The =LrgLevel= being edited (=lrg_editor_get_level= / =set_level= /
  =load_level= / =save_level=).
- A selection model (=LrgEditorSelection=, via =lrg_editor_get_selection=
  and =lrg_editor_select=).
- A command stack: all mutating operations go through reversible
  =LrgEditorCommand= objects.  Mutating operations:
  - =lrg_editor_add_node= / =delete_node= / =reparent_node=
  - =lrg_editor_set_node_transform= (full TRS in one command)
  - =lrg_editor_set_node_property= (any =GObject= property, undoable)
- Undo/redo: =lrg_editor_can_undo= / =can_redo= / =undo= / =redo=.
- Active tool: =lrg_editor_get_tool= / =set_tool= with =LrgEditorTool=
  values (=SELECT=, =TRANSLATE=, =ROTATE=, =SCALE=).
- Snap: =lrg_editor_set_snap= / =get_snap= (translate / rotate / scale
  increments; 0 disables).

An =LrgEditor= is created with =lrg_editor_new ()= and immediately has an
empty level ready to use.

*** LrgEditorHost — the embedding contract

=LrgEditorHost= (=src/editor/lrg-editor-host.h=) is a GInterface mirroring
=LrgGameHost=: the environment the editor borrows from its host.  A host
IDE implements =get_engine=, =get_render_size=, =begin_frame= / =clear= /
=end_frame=, =get_frame_delta=, =get_input_source=, =get_viewport_camera=,
=is_2d_mode=, and =request_redraw=.  =LrgEditorSoftwareHost= is a simple
concrete implementation that stores the borrowed environment; it is used by
IDE-driven embedding and by tests.

*** Bake and instantiate bridges

=lrg_level_to_scene (level)= (=src/editor/lrg-level-instantiate.h=) bakes
the renderable (primitive-visual) nodes of a level into a new =LrgScene= for
geometry rendering.  =lrg_level_instantiate (level, world, engine, error)=
materializes the level into a runtime =LrgWorld= of =LrgGameObject= instances
with their components, for play-in-editor.  Neither bridge mutates the source
=LrgLevel=.

A converter in the other direction, =lrg_level_from_scene= (=src/editor/
lrg-scene-import.h=), opens existing Blender =.yaml= scene exports in the
editor.

*** LrgProject and LrgAssetDatabase

=LrgProject= (=src/editor/lrg-project.h=) describes a game project on disk:
a root directory plus a =project.ryaml= manifest naming the project, its
default level, asset directories, and the game-module build output.

=LrgAssetDatabase= (=src/editor/lrg-asset-database.h=) scans the project's
asset directories, classifies assets by extension (texture / model / audio /
font / level / prefab / script / tileset), assigns stable guids, and exposes
a queryable list suitable for an asset browser.

*** Other editor types

- =LrgComponentDesc= (=src/editor/lrg-component-desc.h=) — serializable
  component description: a registry type name plus a =GHashTable= of
  property values.  Materialized onto a =LrgGameObject= at instantiate time.
- =LrgScriptBinding= (=src/editor/lrg-script-binding.h=) — a
  ={language, script_path_or_guid, enabled}= record.  The =language= field
  is a =LrgScriptLanguage= enum value (=NONE=, =LUA=, =PYTHON=, =GJS=,
  =CRISPY=, =ELISP=).  The =ELISP= backend is *not* part of libregnum; it is
  supplied at runtime by the cmacs =--with-cmacs-lrgscript= subsystem (see
  [[file:lrgscript/index.org][CMacs Lrgscript]]), which registers an Emacs Lisp
  backend with libregnum's scripting manager.  So an =.el= behaviour can be
  attached to a node just like a Lua/crispy script.
- =LrgPrefab= (=src/editor/lrg-prefab.h=) — a =.rprefab= file is a saved
  one-node subtree with an exported-property manifest; =lrg_prefab_save=,
  =load=, and =instantiate= manage the round-trip.  =PREFAB_INSTANCE= nodes
  store a prefab guid plus per-property overrides.

Full engine API reference: =deps/libregnum/docs/editor/=.

** Reaching the editor from cmacs today (via the gi subsystem)

The editor types are GI-annotated and are part of the =Libregnum= typelib
that cmacs loads through the =gi= subsystem.  This means you can reach the
full level-authoring API from Elisp right now — headlessly or inside a running
cmacs session — using =cmacs-gi-require= / =cmacs-gi-call= /
=cmacs-gi-method-call=, or from an MCP agent through =eval=.

The general approach for headless level authoring from Elisp:

#+begin_src emacs-lisp
  ;; Ensure the Libregnum typelib is loaded
  (cmacs-gi-require "Libregnum")

  ;; Create a new level
  (let ((editor (cmacs-gi-call "Libregnum" "editor_new"))
        (level  (cmacs-gi-call "Libregnum" "level_new" "My Level")))

    ;; Add a node with a primitive visual
    (let* ((node   (cmacs-gi-call "Libregnum" "node_new" "Cube"))
           (visual (cmacs-gi-call "Libregnum" "node_visual_new"
                                  (cmacs-gi-enum-value "Libregnum"
                                                       "NodeVisualKind"
                                                       "PRIMITIVE"))))
      (cmacs-gi-method-call visual "set_primitive"
                            (cmacs-gi-enum-value "Libregnum"
                                                 "PrimitiveType" "CUBE"))
      (cmacs-gi-method-call node "set_visual" visual)
      (cmacs-gi-method-call editor "add_node" node nil))

    ;; Save to a .rlevel file
    (cmacs-gi-method-call editor "save_level"
                          "/tmp/my-level.rlevel" nil))
#+end_src

The snippet above illustrates the approach.  Exact GI function names follow
the C symbols stripped of the =lrg_= prefix and with the class name portion
also stripped per typelib convention; when in doubt, use
=cmacs-gi-list-functions "Libregnum"= to enumerate what is available, or
=cmacs-gi-describe "Libregnum" "editor_new"= to inspect a specific function's
signature.

Play-in-editor from Elisp is also reachable: =lrg_level_instantiate= produces
a =LrgWorld=, and the existing game =.so= hosting (=cmacs-libregnum-play=, see
[[*Game module hosting]]) can run a game against that world in a buffer.

** Native editor frontend

The core native editor is implemented: an =cmacs-libregnum-editor-mode= viewport
buffer hosting an engine =LrgEditor=, with the level baked into the scene
drawables so the existing FBO/Cairo blit pipeline, ray-picking and
=cmacs-libregnum-tree-nodes= node model double as the editor viewport and
outliner.  Objects move by mouse drag or keyboard nudge with optional grid
snapping.  A property-inspector panel, asset-browser drag-and-drop,
rotate/scale gizmo handles and play-in-editor remain planned (see below).

*** Implemented

- *C layer* — an editor host path inside =cmacs-libregnum-render.c= (no new
  translation unit, so no =configure= change), reusing the scene-drawable
  pipeline rather than a separate gizmo renderer.  It exposes a plain-C
  opaque-pointer API (=cmacs_libregnum_render_ctx_editor_*=) across the raylib
  firewall, wrapped by these DEFUNs in =cmacs-libregnum-defuns.c=:
  - =cmacs-libregnum-editor-new= /​ =-open= /​ =-save= (BUFFER [PATH])
  - =cmacs-libregnum-editor-active-p= (BUFFER)
  - =cmacs-libregnum-editor-add-primitive= (BUFFER PRIM &optional NAME) →
    new scene node id (PRIM is an =LrgPrimitiveType= int)
  - =cmacs-libregnum-editor-delete= /​ =-select= (BUFFER NODE-ID)
  - =cmacs-libregnum-editor-set-position= (BUFFER NODE-ID X Y Z) — one
    undoable edit
  - =cmacs-libregnum-editor-undo= /​ =-redo= /​ =-can-undo-p= (BUFFER)
  - =cmacs-libregnum-editor-node-guid= (BUFFER NODE-ID)
  - =cmacs-libregnum-editor-node-location= (BUFFER NODE-ID) → =(X Y Z)=, and
    =cmacs-libregnum-editor-selected-id= (BUFFER) → the engine selection (so
    viewport picks and keyboard commands share one selection)
  - =cmacs-libregnum-editor-focus= (BUFFER NODE-ID) — frame the camera on a node
  - =cmacs-libregnum-editor-set-snap= (BUFFER SNAP) — translate grid for drag/move
  - =cmacs-libregnum-editor-drag-begin= /​ =-drag-update= /​ =-drag-end= — the
    mouse drag-to-move pipeline (view-local pixels → ground-plane move, one
    coalesced undo step per drag); also scriptable and used by the move ERT test
  - =cmacs-libregnum-editor-node-rotation= /​ =-node-scale= (BUFFER NODE-ID) →
    =(X Y Z)= (rotation in euler radians), and
    =cmacs-libregnum-editor-set-rotation= /​ =-set-scale= (BUFFER NODE-ID X Y Z)
    — each one undoable transform edit
  - =cmacs-libregnum-editor-reparent= (BUFFER CHILD-ID PARENT-ID) — re-nest a
    node (PARENT-ID negative == the level root)
  - =cmacs-libregnum-editor-add-visual= (BUFFER KIND &optional ASSET NAME) — add
    a non-primitive node by =LrgNodeVisualKind= (mesh-asset / sprite / light /

  - =cmacs-libregnum-editor-attach-script= (BUFFER NODE-ID LANGUAGE PATH) +
    =-node-script-count= — attach an =LrgScriptBinding= (persisted in =.rlevel=)
  - =cmacs-libregnum-editor-play= /​ =-stop= /​ =-playing-p= /​ =-play-tick= —
    play-in-editor: instantiate the level into a throwaway =LrgWorld= and run it
    (the document is never mutated)
  - =cmacs-libregnum-editor-set-tool= /​ =-get-tool= (0 select / 1 translate /
    2 rotate / 3 scale) + =-gizmo-begin= /​ =-gizmo-drag= /​ =-gizmo-end= — the
    on-screen transform gizmo (axis-constrained, one coalesced undo per drag)
  - =cmacs-libregnum-project= (BUFFER WX WY WZ VW VH) → =(SX SY)= — world →
    view-local pixels (used to aim the gizmo + for scripting/tests)
  - =cmacs-libregnum-snapshot= (BUFFER PATH) — render the view synchronously to
    a PNG (engine FBO read-back); works headless, used by the render ERT test
  - =cmacs-libregnum-editor-set-shading= (BUFFER BOOL) /
    =cmacs-libregnum-editor-shading-p= (BUFFER) — enable/query the Blinn-Phong
    shader pass; =cmacs-libregnum-editor-toggle-shading= (BUFFER) flips it
  - =cmacs-libregnum-editor-look-through= (BUFFER NODE-ID) — render the
    viewport from the given CAMERA node's transform and =fov= param;
    =cmacs-libregnum-editor-look-through-off= (BUFFER) restores the edit
    camera; =cmacs-libregnum-editor-look-through-p= (BUFFER) → t/nil

- *Elisp layer* (in =lisp/cmacs/cmacs-libregnum.el=) —
  - =cmacs-libregnum-editor= — entry command; opens =*cmacs-libregnum editor*=
    on an empty level (or, with a prefix arg, a =.rlevel= file).
  - =cmacs-libregnum-editor-mode= (derived from =cmacs-libregnum-mode=) with
    keymap: =c= /​ =b= /​ =y= /​ =n= add cube /​ sphere /​ cylinder /​ plane,
    arrows /​ =hjkl= nudge the selection on the ground (X/Z), =J= /​ =K= and
    PageUp/Down nudge vertically (Y), =[= /​ =]= rotate (yaw) and =\{= /​ =\}=
    pitch, =+= /​ =-= scale up/down, =s= cycles the snap grid, =f= frames the
    selection, =m= types exact coordinates, =x= /​ =<delete>= delete current,
    =u= /​ =C-r= undo /​ redo, =o= outliner, =p= palette, =i= inspector,
    =C-x C-s= save-as.  Numeric prefixes multiply the move/rotate/scale step.
  - =cmacs-libregnum-editor-outliner= + =cmacs-libregnum-outliner-mode= — a
    side-window node tree (built from =cmacs-libregnum-tree-nodes=); =RET=
    selects the node in the editor viewport, =g= refreshes, and =m= marks a
    node then =P= reparents it under the node at point (=r= reparents to root).
  - =cmacs-libregnum-editor-palette= + =cmacs-libregnum-palette-mode= (key
    =p=) — a left-column palette in three sections: *Primitives* (all eleven:
    Cube/Sphere/IcoSphere/Cylinder/Cone/Torus/Plane/Circle/Grid/Rect2D/Circle2D),
    *Objects* (Light/Camera/Audio gizmo nodes), and *Assets* (Mesh.../Sprite...,
    which prompt for a file).  Click or =RET= an item to add it and select it.
    Under Evil the palette and outliner are read-only =motion=-state panels, so
    =hjkl= navigation works; =RET= acts on the item on the current line.  (The
    viewport stays in =emacs= state so its single-key tool commands are not
    intercepted.)
  - =cmacs-libregnum-editor-assets= + =cmacs-libregnum-assets-mode= (key =A=) —
    an asset browser that scans a directory for model/image files
    (=cmacs-libregnum-editor-asset-extensions=); click a file to place it as a
    mesh (models) or sprite (images) node.
  - =cmacs-libregnum-editor-add-script= (key =L=) — attach a script
    (Lua/Python/Gjs/crispy/elisp) to the selection; =cmacs-libregnum-editor-play-toggle=
    (=<f5>=) runs / stops play-in-editor (ticks the instantiated world ~30 Hz).
  - =cmacs-libregnum-editor-inspector= + =cmacs-libregnum-inspector-mode= (key
    =i=) — a right-column =widget.el= property form for the selected node
    (position, rotation in degrees, scale).  =C-c C-c= (or the *Apply* button)
    routes edits through the undoable editor commands; it refreshes whenever the
    selection changes.  The editor perspective opens palette + outliner (left),
    inspector (right), viewport (centre).
  - *Transforming objects* — click a shape in the viewport to select it (the
    outliner highlight + inspector follow the pick).  An *on-screen gizmo* draws
    over the selection: =w= translate (drag the coloured arrows), =e= rotate
    (drag the rings), =r= scale (drag the cube-tipped handles), =t= hides it.
    Dragging a handle is axis-constrained; or *drag the body* to free-move on the
    ground plane, or *nudge* with arrows / =hjkl= (=[= =]= rotate, =+= =-=
    scale; numeric prefix multiplies).  =s= cycles a snap grid honoured by drag,
    gizmo and nudge; =f= frames the camera.  The bake applies each node's
    rotation + scale, so all transforms show live; dragging empty space orbits
    the camera, and one drag (handle or body) is a single undo step.

  Edits go through the engine's undoable =LrgEditorCommand= stack, so
  =cmacs-libregnum-editor-undo= / =-redo= reverse any placement / move /
  delete.  Levels round-trip to =.rlevel= via =cmacs-libregnum-editor-save= /
  =-open=.

*** Now also implemented

- *Real mesh + sprite rendering* — MESH_ASSET loads + draws a glTF/OBJ model
  (=grl_model_new_from_file= + =grl_model_draw_ex=); SPRITE loads its texture and
  draws it as a flat textured quad via a unit-plane =GrlModel= (the mesh/VAO path
  composites in the editor FBO batch, unlike raylib's =rlgl= textured immediate
  mode + =DrawBillboard=, which silently drop out — the same reason tilemap tiles
  are colour-sampled).
- *On-screen gizmo handles* — draggable translate/rotate/scale axis handles
  (=w= /​ =e= /​ =r=), axis-constrained, one coalesced undo per drag.
- *2D camera mode* (=v=) — a top-down orthographic view; picking/projection
  honour the projection.
- *Running script logic* — the *crispy* backend is enabled
  (=deps/libregnum= built =CRISPY=1=; cmacs already links =libcrispy=), so a
  crispy script attached to a node compiles + runs when the level plays.
  =lrg_level_instantiate= now materialises each node's =LrgScriptBinding= as an
  =LrgScriptComponent=.  With =--with-cmacs-lrgscript= the *Emacs Lisp* backend
  is also available (language =ELISP=, integer 5): an =.el= behaviour's
  =lrg-script-start/update/detach= hooks run when the level plays, and a whole
  game can be authored in elisp — see [[file:lrgscript/index.org][CMacs Lrgscript]] and
  [[file:lrgscript/games.org][Writing a complete game in Emacs Lisp]].
- *Play rendering of the running world* — =cmacs-libregnum-editor-play-tick=
  ticks the instantiated =LrgWorld= and reflects its object positions back onto
  the baked scene, so script-driven motion shows in the viewport.
- *Drop-at-point* — arm a palette/asset item (=D=) then click a viewport point;
  the C input layer ray-casts to the ground plane and drops it there.
- *Mouse drag-and-drop* — press a palette/asset row and release over the
  viewport to drop the item at that 3-D point.  Uses Emacs's own =drag-mouse-1=
  event (and stock =pgtk-dnd= for external file drops), so it needs *no* upstream
  pgtk change --- see =doc_org/cmacs/cmacs-upstream-changes.org=.
- *Right-click context menu* — *right-click* an entity in the viewport to pop a
  real GTK menu of actions on it (a *right-drag* still pans the camera, =scroll=
  still zooms).  It is Emacs's own =x-popup-menu=, which the pgtk build renders
  as a native =GtkMenu= — so it matches every other right-click menu in Emacs,
  with *no* raw GTK code.  The C input layer ray-picks the node, captures the
  ground point, and defers =cmacs-libregnum-editor--context-menu=, which pops the
  menu from the *command loop* (a 0-delay timer) rather than from the GLib
  dispatch — a nested GTK menu loop must not run inside the pselect wait.  The
  picked node is selected first, so the chosen action operates on it.

  The items vary by the node's *kind*: every node gets the common actions
  (*Rename*, *Set position*, a *Rotate* submenu, *Reset transform*, *Duplicate*,
  *Toggle visible/locked*, an *Attach script* submenu, *Inspector*, *Focus
  camera*, *Reparent to root*, *Save as prefab*, *Delete*), while asset and
  special nodes add their own: *mesh/sprite/audio* get *Open asset file*; *light*
  gets *Set light range/color*; *camera* gets *Set camera FOV*; *audio* gets *Set
  audio range* + *Play audio*; *tilemap* gets *Set tilemap brush*.
  *Right-clicking empty space* pops an *Add* menu (the palette's Primitives /
  Objects / Assets sections) that places the chosen item at the clicked ground
  point.

  Two items open real nested GTK *submenus*: *Rotate* offers ±45° and ±90° about
  *each* axis (X / Y / Z) plus *Reset rotation*; *Attach script* offers *New
  script…* (scaffolds a starter file in the chosen language, attaches it, and
  opens it) and *Existing script…* (attach a file already on disk).

  *Rename* showcases the new name in the outliner: each row reads =Type (Name)=
  when the node has been renamed (e.g. =Cube (Player)=) and just =Type= otherwise
  (=Cube=, =Light=), so the type is always visible and a custom name stands out.
  Renaming goes through =cmacs-libregnum-editor-set-name=, which re-bakes the
  level so the outliner's cached labels refresh (a plain GObject =name= set would
  not).  The concrete shape label comes from
  =cmacs-libregnum-editor-node-primitive=.

  The menu is *data-driven and easy to extend*: it is built from the
  =cmacs-libregnum-editor-context-menu-items= list, where each entry is a plist —
  =(:label STRING :kinds KINDS :action FN)= for a command,
  =(:label STRING :kinds KINDS :submenu SYMBOL)= for a static submenu (SYMBOL
  names a list of sub-items in the same shape, e.g.
  =cmacs-libregnum-editor-rotate-menu-items=),
  =(:label STRING :kinds KINDS :items-fn FN)= for a *dynamic* submenu (=FN= is
  called as =(FN BUFFER ID)= to build the item list at pop time — used by the
  scripts submenu to reflect the node's current attachment list), or =(:sep)= for
  a divider.  Items may carry =:enable PRED= (a predicate called as =(PRED BUFFER
  ID)= to grey-out inapplicable entries) and =:keys STRING= to show a keyboard
  accelerator.  =KINDS= is =t= (all kinds) or a list of node-kind symbols
  (=group=, =primitive=, =mesh=, =sprite=, =tilemap=, =light=, =camera=,
  =audio=, =prefab=), and action =FN= is called as =(FN BUFFER ID)= on the
  right-clicked node.  *Adding an item — or a whole submenu — is a one-line
  edit*; no other code changes.  The node's kind comes from the
  =cmacs-libregnum-editor-node-kind= DEFUN (an int matching the
  =cmacs-libregnum-visual-*= constants, =1= = a primitive, =nil= = a group node).
  The menu is a keymap (so submenus are native), popped with =x-popup-menu= and
  resolved with =lookup-key=.  Like the Emacs =drag-mouse-1= path, this needs
  *no* upstream pgtk change: it rides the existing libregnum button hook in
  =src/pgtkterm.c= and reuses Emacs's own menu machinery.  The menu header shows
  the right-clicked node's label.  The same menu is available by right-clicking a
  row in the *outliner* panel, not only in the 3-D viewport.

  A subsystem can append its *own* actions to the menu per-buffer via the
  buffer-local =cmacs-libregnum-editor-extra-menu-items= (same plist shape,
  appended after the built-ins), so the editor core stays
  subsystem-agnostic — the CAD model viewer uses it to add its print
  section (Insert, Export G-code, Slicer settings, Supports, Set bed size).
  The chosen action runs with the editor as the current buffer, so an
  action that reads =current-buffer= (e.g. the interactive =Delete= /
  =x=) works even when the menu pops from a sibling panel such as that
  sidebar (the popup defers from the command loop, whose current buffer is
  otherwise whatever pane was selected).

  *Expanded common items (all kinds)* — the set of actions every node receives
  was enlarged:

  - *Scale ▸* submenu — *2×*, *½×*, *Reset scale*, *Set scale…* (prompted).
  - *Drop to ground* — snaps the node's Y position to the ground plane.
  - *Snap to grid* — rounds the position to the current grid size.
  - *Reset position* — zeroes the node's translation.
  - *Tool ▸* submenu — switch the active gizmo to *Translate*, *Rotate*,
    *Scale*, or *Select* without leaving the menu.
  - *Cut* / *Copy* / *Paste* — clipboard operations via a temporary prefab;
    *Copy GUID* copies the node's identifier string.
  - *Reparent under…* — interactively pick a new parent node (complements the
    existing *Reparent to root*).
  - *Add child ▸* — add a new primitive or group directly under this node.
  - *Add empty group* — inserts a bare group node as a child.
    DEFUNs: =cmacs-libregnum-editor-node-parent=,
    =cmacs-libregnum-editor-add-empty=.
  - *Select ▸* submenu — *Add to selection*, *Remove from selection*, *Clear
    selection*, *Select parent* — backed by the engine's =LrgEditorSelection=
    and the new DEFUNs =cmacs-libregnum-editor-select-add= /
    =-select-remove= / =-select-clear= / =-selected-ids=.

  *Appearance (primitive / mesh kinds)* — a *Material ▸* submenu lets you *Set
  color* (=cmacs-libregnum-editor-set-color=), *Set roughness*
  (=-set-roughness=), and *Set metallic* (=-set-metallic=), written through the
  node's =LrgMaterial3D=.  The bake now honours a node's authored material colour
  instead of a fixed per-kind colour (=cmacs-libregnum-editor-node-color= reads it
  back).  *Toggle wireframe* authors a ="wireframe"= visual param rendered via
  =grl_model_draw_wires_ex=; *Toggle cast shadow* authors a ="cast_shadow"= param
  (persisted in the =.rlevel=; shadow mapping is not yet implemented).

  *Duplicate* now performs a native engine deep-clone (fresh GUIDs for the
  entire subtree) placed under the original node's parent, replacing the older
  temp-prefab path.  DEFUN: =cmacs-libregnum-editor-duplicate-node=.

  *Manage scripts ▸* — a dynamic submenu (=:items-fn=) that lists each script
  currently attached to the node with *Edit* and *Detach* sub-actions
  (=cmacs-libregnum-editor-node-scripts= /​ =-detach-script=), plus *Attach
  new…* and *Attach existing…* (the existing paths, now also reachable here).

  *Per-kind additions:*

  - *light* — *Set intensity* (=cmacs-libregnum-editor-set-light=) and a *Light
    type ▸* submenu to switch between *Point*, *Spot*, and *Directional*.
  - *camera* — *Align to current view* (=cmacs-libregnum-camera-state=) snaps
    the camera node's transform to the live viewport camera pose; *Look through
    this camera* (=cmacs-libregnum-editor-look-through=) renders the viewport
    from that camera until =cmacs-libregnum-editor-look-through-off= is called.
  - *audio*, *mesh*, *sprite* — *Replace asset* (=-set-node-asset=) lets you
    swap the underlying asset file without recreating the node.
  - *tilemap* — *Enter paint mode*, *Clear*, and *Resize* (in addition to the
    existing *Set tilemap brush*).
  - *prefab* — *Unpack* (=cmacs-libregnum-unpack-prefab=) expands the prefab
    instance into a plain node subtree in place.

  *Multi-selection* — the engine =LrgEditorSelection= is exposed as Lisp:
  =cmacs-libregnum-editor-select-add= /​ =-select-remove= /​ =-select-clear= /
  =-selected-ids=.  Several nodes can be selected (each draws its own wireframe)
  and acted on together; the menu offers *Delete selected* and *Group selected*
  when a multi-selection is active.
- *Tilemaps — paint, render, persist* — =T= (=cmacs-libregnum-editor-tilemap-create=)
  makes a TILEMAP node from a tileset image + tile/map dimensions;
  =cmacs-libregnum-editor-tilemap-paint= arms a sticky brush so each viewport
  click paints the cell under the cursor with the current tile
  (=cmacs-libregnum-editor-tilemap-set-brush=, finish with
  =cmacs-libregnum-editor-stop-paint=).  The grid of tiles is stored in the
  node's visual params (=tw= /​ =th= /​ =cols= /​ =mw= /​ =mh= /​ =tiles= CSV) so it
  round-trips in the =.rlevel=.  Each non-empty cell renders the *actual tileset
  art*: the tile's sub-rect is sliced (=grl_image_from_region= →
  =grl_texture_new_from_image=) into a textured unit-plane =GrlModel= drawn on
  the ground (the mesh path that composites in the FBO batch), cached per tile
  index, with a colour-sampled cell as fallback.  DEFUNs:
  =cmacs-libregnum-editor-tilemap-config= /​ =-set-tile= /​ =-info=.
- *Dedicated MCP tools* — =cmacs/mcp/cmacs-mcp-tools-libregnum.c= registers
  =lrg_editor_object_tree= / =_add_primitive= / =_add_visual= / =_move= /
  =_select= / =_delete= / =_open= / =_save= / =_play= / =_stop=, so an agent can
  author levels with typed tools (the =eval= tool still reaches every DEFUN).
- *Introspection-driven inspector* — the inspector still shows the undoable
  transform fields, and now also enumerates the selected node's GObject
  properties (name / visible / locked / is-2d / …) via a node→GObject bridge
  (=cmacs-libregnum-editor-node-object=) + =gobject-list-properties= /
  =gobject-property-info= / =gobject-get= / =gobject-set=.  Editable fields are
  chosen from each =GParamSpec='s type; writes go straight through the GObject
  (not the undo stack — transform still is undoable).
- *Prefabs* — =C-c p= saves the selected node's subtree to a =.rprefab=
  (=lrg_prefab_save=); =C-c P= instantiates one under the selection or root
  (=lrg_prefab_load= + =lrg_editor_add_node=).  DEFUNs
  =cmacs-libregnum-editor-save-prefab= / =-instantiate-prefab=.
- *Scene import* — =C-c i= imports a Blender-exported =.yaml= scene as the
  current level (=LrgSceneSerializerBlender= → =lrg_level_from_scene=).
- *Multi-language scripts (Lua / Python / Gjs / crispy)* — the =L= script picker
  lists the backends libregnum was actually built with, queried at runtime via
  =lrg_scripting_manager_get_available= (=cmacs-libregnum-scripting-languages=).
  With the scripting =-devel= packages installed (=luajit-devel=,
  =python3-devel=, =gjs-devel= --- see =install-deps=) all four are available:
  =(("Lua" . 1) ("Python" . 2) ("JavaScript (Gjs)" . 3) ("Crispy" . 4))=.  cmacs
  links the system =libluajit-5.1= / =libpython3.x= / =libgjs= + =libmozjs= (the
  scripting libs are appended to =CMACS_LIBREGNUM_LIBS=, and the build passes
  =HAS_GI=1= + =GI_RUNTIME_*= so the Gjs backend's introspection base compiles
  under =BUILD_GIR=0=).  Each backend degrades out cleanly if its =-devel= is
  absent (crispy, from the bundled submodule, is always present).
- *Script hot-reload* — attaching a script through =L= opens its file with an
  =after-save-hook= that, while the level is playing, restarts play so the
  edited script recompiles + reloads.
- *Projects + asset database* — =M-x cmacs-libregnum-project-new= scaffolds a
  project (levels/ assets/ scripts/ + a =project.ryaml= manifest + a starter
  level); =cmacs-libregnum-project-open= opens one and loads its default level
  (=LrgProject=).  =cmacs-libregnum-assetdb-scan= classifies a directory's
  assets via =LrgAssetDatabase= (texture/model/audio/font/script/level/prefab/
  tileset/scene).  DEFUNs =cmacs-libregnum-project-create= /
  =cmacs-libregnum-editor-open-project= / =cmacs-libregnum-assetdb-scan=.

*** Also implemented (drag-source + standalone editor)

- *GTK GDK drag-source* — palette/asset rows can be dragged with a real GDK
  drag (cross-process, and onto the viewport) via =cmacs-libregnum-dnd.c= + a
  small guarded hook in =src/pgtkterm.c= (arm on =[down-mouse-1]= → motion
  threshold → =gtk_drag_begin=; receiver decodes =application/x-libregnum=).
  Complements the Emacs =drag-mouse-1= path.  See the Upstream Changes manual.
- *Standalone engine-drawn editor* — =deps/libregnum/src/editor/ui/lrg-editor-app=
  is now a real app (3-pane outliner | 3-D viewport | properties, orbit camera,
  add/select/delete/undo/save) with an =examples/editor-standalone= launcher,
  built with =make BUILD_EDITOR_UI=1=.  A second, non-cmacs frontend on the same
  =LrgEditor= core.
- *Lights / cameras / audio — data-accurate viz + audio playback* — the viewport
  now renders each light's range as a wireframe sphere in its authored colour,
  each camera as a frustum at its field of view, and each audio emitter as a
  range sphere (read live from the node's visual params).  Author them with
  =cmacs-libregnum-editor-set-light= (range + r/g/b),
  =-set-camera-fov=, =-set-audio-range= (over the
  =cmacs-libregnum-editor-set-visual-param= primitive), and *play* an emitter's
  sound with =C-c a= (=cmacs-libregnum-editor-play-audio=, via the cmacs
  GStreamer audio subsystem when =--with-cmacs-audio= is present, falling back
  to Emacs' =play-sound-file=).  The context menu also exposes *Stop audio* and
  *Set volume* (volume persists as a node param).

*** Also implemented (shading, look-through, audio controls, wireframe)

- *Real-time scene shading* — an opt-in toggle
  (=cmacs-libregnum-editor-toggle-shading=, with getters/setters
  =cmacs-libregnum-editor-set-shading= / =-shading-p=) loads a Blinn-Phong GLSL
  shader and illuminates MESH_ASSET geometry from the scene's LIGHT nodes
  (position, colour, and intensity).  Imported glTF/OBJ models are lit in the
  editor viewport by the scene lights.  Scope boundary: only the shaderable VAO
  / mesh path is lit; primitive immediate-mode shapes and editor gizmos stay
  flat by design; no shadow mapping yet.
- *Look-through camera* — right-click a camera node → *Look through this
  camera* renders the viewport from that camera's transform (position, yaw/pitch,
  and its =fov= param).  Implemented by overriding the single camera chokepoint
  so picking, projection, and gizmos stay consistent; orbit/pan/zoom are
  suspended while looking through.  A command restores the edit camera.  DEFUNs:
  =cmacs-libregnum-editor-look-through= (BUFFER NODE-ID),
  =cmacs-libregnum-editor-look-through-off= (BUFFER),
  =cmacs-libregnum-editor-look-through-p= (BUFFER).
- *Audio volume + stop* — the editor now plays audio nodes through the cmacs
  GStreamer audio subsystem (async, with a pipeline handle) instead of the
  blocking =play-sound-file=, so *Stop audio* and *Set volume* work in the
  context menu; volume persists as a node param.  Falls back to
  =play-sound-file= when =--with-cmacs-audio= is absent.
- *Wireframe per node* — *Toggle wireframe* in the context menu authors a
  ="wireframe"= visual param honoured by the render loop (mesh assets via
  =grl_model_draw_wires_ex=).  *Toggle cast shadow* authors a ="cast_shadow"=
  param (metadata persisted in the =.rlevel=; actual shadow mapping remains
  deferred).
- *Per-window framebuffer fit* — a debounced =window-size-change= hook
  (=cmacs-libregnum--fit-views=) keeps each on-screen view's framebuffer
  sized to its window, so the overlay's 1:1 blit never stretches content
  (squares stay square) as windows resize.
  =cmacs_libregnum_render_ctx_resize= allocates the new render target
  before discarding the old one and commits only on success, so a
  reallocation that fails (e.g. before the GL context is current) keeps
  the valid framebuffer and a later resize retries — it never blanks the
  view.
- *Rotate in place* — node rotation about all three axes (the rotate
  gizmo and the context-menu *Rotate* submenu) pivots about the node's own
  bounding-box centre, and the selection box tracks the rotated extents,
  so a part turns in place instead of swinging about the world origin.
  The model draw composes the full Euler XYZ orientation (quaternion →
  axis-angle), not just yaw.

*** GObject Introspection (gjs + Python-GI bindings)

The whole editor/authoring surface is exposed over GObject Introspection, and
cmacs *auto-builds* the typelib so scripts can drive it:

- *Auto-built typelib* — the cmacs build runs libregnum with =BUILD_GIR=1=
  whenever =g-ir-scanner= is available, producing =Libregnum-1.typelib=
  (=LrgLevel=, =LrgNode=, =LrgNodeVisual=, =LrgEditor=, =LrgProject=,
  =LrgAssetDatabase=, =LrgScriptingManager=, =LrgScriptComponent=, the
  =LrgNodeVisualKind= / =LrgScriptLanguage= / =LrgEditorTool= enums, …).  Cross/
  sandboxed builds without the scanner fall back to =BUILD_GIR=0= and just skip
  the typelib.
- *gjs + Python (standalone / in-game)* — with =GI_TYPELIB_PATH= set, both fully
  import and drive the editor types:
  =imports.gi.versions.Libregnum='1'; const L = imports.gi.Libregnum= in gjs, and
  =gi.require_version('Libregnum','1'); from gi.repository import Libregnum= in
  Python (needs =python3-gobject=).  Verified end-to-end: create =Level= /
  =Node=, =add_child=, read the enums.  This is what gives a libregnum *game's*
  =gjs= / =python= scripting backends typed access to the engine + editor types.
- *cmacs's own =gi= subsystem* sees it too: =(cmacs-gi-require "Libregnum")= then
  e.g. =(cmacs-gi-enum-value "Libregnum" "NodeVisualKind" "light")= → 5.
- *Caveat — scripts running embedded inside cmacs*: a =gjs=/=python= script
  executed by the libregnum backends *while inside the cmacs process* currently
  conflicts with cmacs's own =libgirepository= (=cannot register existing type
  'GIRepository'=) because two GObject-Introspection consumers share one process.
  The bindings + typelib are correct (proven standalone); making an embedded
  second GI runtime coexist with cmacs's =gi= subsystem is separate, deferred
  work (see [[file:cmacs-libregnum-design-notes.org]]).
- *How it builds cleanly* — the graylib gir include path was corrected, and the
  internal GI scripting *bridges* (=lrg-scripting-@{gi,pygobject,gjs@}=, which
  pull in =girepository.h=) are excluded from the scan so the typelib does not
  depend on a =GIRepository-2.0= namespace that gjs/PyGObject cannot resolve.
  The bridge classes are engine-internal; script authors use the editor types +
  the =LrgScripting= base/manager/component + the =LrgScriptLanguage= enum.

*** Planned

The following items remain for future renderer work:

- *Shadow mapping* — real-time shadows from LIGHT nodes; the ="cast_shadow"=
  node param is authored now but not yet consumed by a shadow pass.
- *Shading of primitive immediate-mode shapes* — the Blinn-Phong shader covers
  the mesh/VAO path; primitive shapes drawn via immediate-mode calls stay flat.
- *Spatial/3D audio attenuation* — audio range is visualised and the volume
  knob persists as a param, but distance-based attenuation is not yet wired in
  the GStreamer pipeline.

*** Context-menu items formerly deferred — now implemented

The following four items were carried as deferred in earlier versions and are
now implemented (see the sections above):

- *Real-time scene shading* — Blinn-Phong GLSL shader for mesh/model geometry.
- *Look-through camera* — viewport renders from the selected camera node.
- *Audio volume / stop* — GStreamer pipeline handle; volume persists as a node
  param; fallback to =play-sound-file= when audio subsystem absent.
- *Wireframe / cast-shadow flags* — ="wireframe"= and ="cast_shadow"= visual
  params authored per node; shadow mapping remains deferred.
