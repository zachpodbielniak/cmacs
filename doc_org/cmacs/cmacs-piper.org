#+TITLE: cmacs-piper — offline text-to-speech via Piper
#+AUTHOR: Zach Podbielniak
#+OPTIONS: toc:t num:t

* Overview

cmacs-piper invokes [[https://github.com/rhasspy/piper][Piper]] as a subprocess via
~g_subprocess_new~:

#+begin_src bash
piper --model VOICE.onnx --output_raw < text > pcm
#+end_src

The S16LE PCM stream is fed back into
~cmacs-audio--playback-open-pcm-1~ for live playback, or written to
a WAV via ~with-temp-file~ for archival.  Spawning uses
~g_subprocess_communicate_async~ so polling happens on the cmacs
~GMainContext~ — no extra thread.

* Requirements

** Build flags

#+begin_src text
--with-cmacs-audio      # required (playback path)
--with-cmacs-piper      # this subsystem
#+end_src

** Piper binary

cmacs uses the [[https://github.com/OHF-Voice/piper1-GPL][OHF-Voice piper1-GPL fork]] — the active community
fork after rhasspy/piper went quiet.  It's distributed as a Python
package (~piper-tts~ on PyPI) that installs a ~piper~ console-script.
configure probes for ~piper~ on PATH at configure time
(~AC_PATH_PROG~).  If absent, the configure still succeeds and the
macro ~CMACS_PIPER_DEFAULT_BINARY~ falls back to literal ~"piper"~ —
the binary is resolved at runtime via ~g_find_program_in_path~, so
installing Piper post-build works without reconfigure.

Install:

#+begin_src bash
# Preferred (per-user, no extra layers)
/usr/bin/python3 -m pip install --user piper-tts

# Alternative (isolated env -- but see below)
pipx install --python /usr/bin/python3 piper-tts
#+end_src

*Why pip first rather than pipx?*  piper-tts ships a scikit-build-core
wheel that races pipx's metadata-readback step when pipx uses ~uv~
as its backend (auto-detected on systems where ~uv~ is on PATH).
You get =Pipx Internal Error: cannot find package 'piper-tts'
metadata.= even though the wheel installed fine.  Plain
~pip --user~ sidesteps the whole pipx/uv layer.

You also need ~espeak-ng~ at runtime for phonemization (installed
automatically by ~install-deps~ alongside the audio packages).

~deps/piper/~ is checked out as a submodule for reference and for the
test fixtures only.  It is NOT built from source — the CMake file in
that tree builds a Python C extension, not the standalone ~piper~ CLI.

** Voices

Voices are looked up via ~cmacs-piper-voices-search-path~:

1. ~~/.local/share/cmacs/piper-voices/~ — user dir.
2. ~/usr/share/cmacs/piper-voices/~ — system dir, populated by
   container image builds (see ~build-container~).  The bundled
   default voice (~en_US-amy-low.onnx~ + sidecar, ~64 MB) lands
   here.

User-installed voices take precedence.  Get more from the upstream
[[https://huggingface.co/rhasspy/piper-voices/tree/main][rhasspy/piper-voices]] HF mirror.  Each voice has a ~.onnx~ file +
~.onnx.json~ sidecar describing its sample rate.

Override the bundled voice at image-build time:

#+begin_src bash
PIPER_VOICE_NAME=en_GB-alba-medium.onnx \
PIPER_VOICE_DIR=en/en_GB/alba/medium \
  ./build-container
#+end_src

* Architecture

** Subprocess invocation

~cmacs-piper-synth-async~ creates a ~GSubprocessLauncher~ with all
three std pipes, spawns piper, then ~g_subprocess_communicate_async~
the input text.  The completion callback fires on the cmacs
GMainContext (no thread).  Output bytes are wrapped in a unibyte
Lisp string and handed to the user's callback.

** Playback wiring

~cmacs-piper-speak-async~ takes the PCM and:

1. Reads the voice's ~.onnx.json~ for ~audio.sample_rate~ (defaults
   to ~cmacs-piper-default-rate~ = 22050).
2. Opens a PCM playback stream via ~cmacs-audio--playback-open-pcm-1~.
3. Pushes the PCM with ~cmacs-audio-push-pcm~.
4. Starts the stream and pushes the handle onto
   ~cmacs-piper--playback-stack~ so ~cmacs-piper-stop~ can interrupt.

* Quick Start

#+begin_src elisp
;; Speak a literal string
(cmacs-piper-speak "Hello, cmacs.")

;; Speak the active region (dwim falls back to sentence-at-point)
M-x cmacs-piper-speak-region   ;; C-c v s

;; Interrupt the most recent playback
M-x cmacs-piper-stop           ;; C-c v S
#+end_src

* PGTK right-click context menu

~lisp/cmacs/cmacs-piper-context-menu.el~ adds an entry to
~context-menu-functions~ (the standard Emacs 28+ hook used by PGTK's
~mouse-3~) that contextually shows:

- *Speak selection (Piper)* — when a region is active.
- *Speak sentence (Piper)* — no region, takes sentence at point.
- *Stop speaking* — appears while playback is live.

Auto-enables ~context-menu-mode~ unless
~cmacs-piper-auto-enable-context-menu~ is set to nil.

Toggle the integration explicitly:

#+begin_src elisp
M-x cmacs-piper-context-menu-mode
#+end_src

* Elisp API

| DEFUN / function | Purpose |
|------------------+---------|
| ~cmacs-piper-supported-p~ | t if piper executable is locatable |
| ~cmacs-piper--synth-sync-1~ | Internal: text → PCM bytes (sync) |
| ~cmacs-piper--synth-async-1~ | Internal: text → callback(PCM) (async) |
| ~cmacs-piper-speak~ | Public sync: text → playback handle |
| ~cmacs-piper-speak-async~ | Public async with optional callback |
| ~cmacs-piper-speak-region~ | Speak active region (or sentence) |
| ~cmacs-piper-speak-buffer~ | Speak entire buffer |
| ~cmacs-piper-stop~ | Interrupt most recent playback |
| ~cmacs-piper-stop-all~ | Interrupt every in-flight playback |
| ~cmacs-piper-list-voices~ | List ~.onnx~ files in voices dir |

* MCP tool

~synthesize_speech~ accepts ~text~ + optional ~output_path~:

#+begin_src json
{"name": "synthesize_speech",
 "arguments": {"text": "Hello, agent", "output_path": "/tmp/out.wav"}}
#+end_src

If ~output_path~ is omitted, the audio plays through the default
sink.  Companion read-only tool: ~list_voices~.

* Troubleshooting

** Piper not found

~cmacs-piper-supported-p~ returns nil; ~M-x cmacs-piper-speak~ raises
a ~user-error~.  Install piper-tts (see Requirements above) and
re-run; cmacs resolves the binary at runtime via
~g_find_program_in_path~, so no rebuild is needed.

** ~pipx install piper-tts~ fails with "cannot find package metadata"

Symptom (verbatim):

#+begin_src text
Pipx Internal Error: cannot find package 'piper-tts' metadata.
#+end_src

This is what you get when ~pipx~ has been built (or auto-detected)
to use ~uv~ as its backend AND you try to install ~piper-tts~.
piper-tts ships a scikit-build-core wheel that compiles a C
extension wrapping piper-phonemize; uv's pip-install of that wheel
finishes the install but doesn't populate the ~PKG-INFO~ /
~METADATA~ files in the layout pipx scans afterwards.  pipx then
tears the venv back down and raises this error, even though the
wheel itself was fine.

You'll see ~pipx~ log the line:

#+begin_src text
Backend resolved to uv (source: auto-path)
#+end_src

right before ~installing piper-tts...~ — that's the smoking gun.

*Fix:* skip pipx entirely and use plain pip:

#+begin_src bash
/usr/bin/python3 -m pip install --user piper-tts
#+end_src

CPython's own pip runs the wheel install synchronously and
populates metadata in the expected places.  The ~piper~ console-
script lands at ~~/.local/bin/piper~ — make sure that's on PATH.

*Why /usr/bin/python3 explicitly?*  On systems where Homebrew /
conda / asdf has put a non-distro Python first on PATH, pipx may
have cached a venv path that points into a stale brew prefix
(e.g. ~/home/linuxbrew/.linuxbrew/opt/python@3.14/libexec/bin/python~).
After a brew upgrade reshuffles that path, every subsequent
~pipx install~ dies with ~No interpreter found at path~ before
even reaching the backend.  Using the system interpreter is more
stable across brew updates.

*If you must use pipx* (e.g. you actively want the isolated env):

#+begin_src bash
PIPX_DEFAULT_PYTHON=/usr/bin/python3 pipx reinstall-all
pipx install --python /usr/bin/python3 --pip-args=--no-build-isolation piper-tts
#+end_src

The ~--no-build-isolation~ flag is supposed to force scikit-build-
core to use the venv's pre-installed metadata helpers; this works
intermittently.  Plain ~pip --user~ is the more reliable path.

** ~No interpreter found at path~

#+begin_src text
× No interpreter found at path
│ `/home/linuxbrew/.linuxbrew/opt/python@3.14/libexec/bin/python`
#+end_src

pipx remembers the Python it was first set up with, baked into its
internal venvs metadata.  When Homebrew updates ~python@3.14~ the
~libexec/bin/python~ symlink moves and every ~pipx~ invocation
fails before doing any actual work.

Fixes (in order of preference):

1. Bypass pipx entirely:
   ~/usr/bin/python3 -m pip install --user piper-tts~.
2. Reset pipx to the system Python:
   ~PIPX_DEFAULT_PYTHON=/usr/bin/python3 pipx reinstall-all~.
3. Nuke pipx state and start over:
   ~rm -rf ~/.local/share/pipx ~/.local/pipx && pipx ensurepath~.

** Choppy / wrong-pitch playback

Sample-rate mismatch.  Confirm the voice's sidecar:

#+begin_src bash
cat ~/.local/share/cmacs/piper-voices/en_US-amy-low.onnx.json | jq .audio.sample_rate
#+end_src

If absent, set ~cmacs-piper-default-rate~ to the right value.
