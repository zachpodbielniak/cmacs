#+TITLE: cmacs-redact — One Redaction Table for Every Model-Facing Surface
#+AUTHOR: Zach Podbielniak
#+OPTIONS: toc:2 num:t

* Overview

The activity journal has a rule set that says what must not be kept: exclude this window, drop that title, rewrite account numbers, hash a project name ([[file:cmacs-journal.org][cmacs-journal]], /Filters/). Those rules used to protect the journal and nothing else. The same window title still reached a model through the window list, the screen inventory in a chat prompt, a screenshot, the clipboard.

=cmacs-redact= makes that rule set the *one* policy for everything a model is shown. There is no second rule format and no second matcher: every function here builds an event in the journal's own shape and hands it to the journal's filter engine.

Four things about it, stated plainly:

- *It is on by default.* ~cmacs-redact-mode~ is a global minor mode that starts enabled. Nothing has to be configured for the shipped rules (password managers, private browser windows, authentication prompts, =.gpg= and =.authinfo= files, =~/.ssh=) to apply.
- *It does not need the journal.* The rules are the journal's, loaded on first use. ~cmacs-journal-mode~ can stay off; nothing is recorded by redacting.
- *It fails closed.* When the rules cannot be loaded, model-facing surfaces show nothing until they can.
- *It never says which rule matched.* A refusal reads the same whatever caused it.

And one thing it is not: *a sandbox*. An agent you have allowed to evaluate Lisp, run a shell command or read arbitrary files can get at anything you can. Redaction covers the surfaces listed under [[*Surfaces][Surfaces]]; that table also says, line by line, what is not covered.

#+begin_src emacs-lisp
;; The rules are the journal's.  Elisp:
(setq cmacs-journal-filters
      '((:match ((:app . "^org\\.keepassxc")) :exclude t)
        (:match ((:title . "Invoice"))
         :replace ((:title "[0-9]\\{6,\\}" "***")))
        (:match ((:text . "sk-[A-Za-z0-9]\\{20,\\}"))
         :replace ((:text "sk-[A-Za-z0-9]\\{20,\\}" "[api key]")))))
(cmacs-journal-filters-reload)
#+end_src

#+begin_src yaml
# ~/.config/cmacs/journal-filters.yaml -- outside your tracked dotfiles
filters:
  - match: {file: '/clients/'}
    exclude: true
  - match: {text: 'sk-[A-Za-z0-9]{20,}'}
    replace: [{field: text, regexp: 'sk-[A-Za-z0-9]{20,}', with: '[api key]'}]
#+end_src

It is pure Elisp (=lisp/cmacs/cmacs-redact.el=) and has no configure flag of its own: it ships wherever the journal's filter engine does.

* Who counts as a model

The functions act only for a *model-facing* caller. While ~cmacs-redact-mode~ is on, a caller is model-facing when any of these holds:

| Surface  | When                                                                                                                                                              |
|----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =tool=   | A brigade tool call is running: inside ~cmacs-brigade-call-tool~ or ~cmacs-brigade-call-tool-async~, and, for an asynchronous call, until it has delivered its result |
| =rpc=    | ~inhibit-interaction~ is bound, which cmacs's RPC dispatch does around everything arriving over MCP, D-Bus, =emacsctl= and bacon                                    |
| =prompt= | The code composing a model prompt said so with the macro ~cmacs-redact-as-model~. =cmacs-ai-view= does                                                              |

~cmacs-redact-surfaces~ is the list of those three symbols; removing one stops redaction for that kind of caller and nothing else.

Otherwise -- a command you ran, your own Lisp -- nothing is redacted. The rules are about what leaves for a model, not about what you may see on your own machine.

Three consequences worth knowing:

- *Your own =emacsctl= from a terminal is redacted.* Over the RPC channel you are indistinguishable from a program, and the program is assumed. The journal makes the same assumption about its rows.
- *While an asynchronous tool call is in flight, everything is treated as the tool's.* An async tool finishes in a process sentinel, far outside the call that started it, and that is exactly where OCR text or a clipboard entry gets redacted. A sentinel cannot be told from a timer, so for those seconds a redaction function called from anywhere acts. It errs toward redacting.
- *A chat turn is a model prompt even though you sent it.* That is what ~cmacs-redact-as-model~ is for: the screen inventory is composed inside it.

Callers do not decide any of this. They call the function; ~cmacs-redact-active-p~ decides.

* What the rules mean on each kind of thing

A rule is written against fields (=kind=, =app=, =title=, =pid=, =tags=, =monitor=, =buffer=, =file=, =mode=, =project=, =url=, =detail=, =text=). Each kind of thing is put to the rules as the event the journal would record for it, so a rule written for the journal matches here without change.

| Thing     | Event it is matched as                                                                                                                                                             |
|-----------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Window    | =kind= =focus=, with =app=, =title=, =pid=                                                                                                                                          |
| Buffer    | =kind= =buffer=, =app= =emacs=, with =buffer=, =file=, =mode=, =project=. A Dired buffer's directory and an indirect buffer's base file stand in as =file=                          |
| Web page  | A gsurf buffer is =kind= =url=, =app= =gsurf=, with =url=, =title=, =buffer=, =mode=, and =detail= =container:NAME=. A bare URL is =kind= =url= with =url= alone                      |
| File      | The buffer visiting it, when there is one; else =kind= =buffer= with =file= and the base name as =buffer=. Judged under its own name and, for a local file, with symbolic links resolved |
| Free text | =kind= =text=, with =text=                                                                                                                                                          |

What each action does:

- =exclude= :: The thing is not shown at all. An excluded window is not listed and cannot be captured; an excluded buffer is not listed and cannot be read; an excluded URL is nil.
- =drop= :: The field is blanked. A window with its title dropped is still listed, without a title.
- =replace= / =hash= :: The field is rewritten, exactly as the journal would store it. Without the journal's per-install key (it is created when the journal is first turned on) a hash is keyed with a random key that lives only as long as this Emacs.

One of this Emacs's own frames is a window to the compositor, titled with the buffer in it. Such a window is also excluded when a buffer on that frame is, since the rules that hide the buffer are written on its file or mode, not on a window title.

** Free text

A clipboard entry, text read off the screen, a buffer inlined into a prompt: none of it has fields. ~cmacs-redact-text~ applies two things, in this order.

1. *Rules on the =text= field.* The text is the event =(:kind text :text STRING)=, so a rule matching on =text= does to it what any rule does to its field: =exclude= replaces the whole text with =[withheld by your privacy rules]=, =drop= gives the empty string, =replace= and =hash= rewrite it. Write these for things that are sensitive wherever they appear: API keys, private key blocks, card numbers.
2. *What the other rules call sensitive inside a field* (~cmacs-redact-text-field-rules~, on by default). Every =replace= entry is applied to the text whatever field it names and whether or not its rule's match holds -- free text has no fields to hold it against. And for every field a rule both matches on and hashes, each occurrence of that match regexp in the text becomes its hash. So a rule that rewrites account numbers in window titles rewrites them in a screenshot's text too, without being written twice.

The limits of the second part, on purpose:

- A regexp that can match the empty string (=.*=, =[0-9]*=) means "the whole field" where it was written and means nothing inside a larger text. It is skipped.
- A regexp anchored to the start or end of its field only matches at the start or end of the whole text.
- An =exclude= or =drop= written for another field has nothing in free text to act on. A window being excluded does not remove its title from OCR text of a screenshot; what removes it is that the screenshot is refused (below).
- A rule whose match is a predicate function is only ever applied through part 1.

Set ~cmacs-redact-text-field-rules~ to nil when a field rule is too broad to be searched for in running text; then only =text= rules touch free text.

YAML and Elisp stay in step: =text= is a field name like any other in both (=match: {text: ...}=, =replace: [{field: text, ...}]=, =:match ((:text . ...))=). The journal never builds an event with a =text= field, so such a rule changes nothing the journal keeps.

** Images

An image cannot be rewritten the way a title can, so the answer is whole: if something the rules exclude would be in the picture, there is no picture. The tool returns the error =a window excluded by your privacy rules is visible; nothing was captured=, the same words whatever matched.

"On screen" for a desktop capture means the windows on a tag some monitor is showing, plus the buffers in this Emacs's visible frames. A password manager parked on a hidden tag does not block screenshots. When the shown tags cannot be read, every window counts as on screen. A capture of a single named window asks about that window only, and an excluded one is reported exactly like a pattern that matched nothing.

* Sensitive variables

A variable has no window, buffer or file for a rule to name, so the rules cannot say "not this one". Two kinds of variable must never be printed for a model all the same:

- *The rule set itself.* What a person excludes is exactly what the rule files are kept out of a dotfiles repository to protect, and nothing may reveal the rule set or which rule matched. =describe_variable cmacs-journal-filter--rules= used to print every rule to any agent that asked.
- *Holders of secrets*: an API key in an option, an auth-source answer kept in a variable, the process environment.

So there is a registry, and every surface that prints a variable's value asks it.

| Option | Holds |
|--------+-------|
| ~cmacs-redact-default-sensitive-variables~ | What ships: the journal's rule options (~cmacs-journal-default-filters~, ~cmacs-journal-filters~, ~cmacs-journal-filter-files~), its hash key, everything named =cmacs-journal-filter--...=, redaction's own copies of the rules and key, these two lists themselves, ~cmacs-ai-search-api-key~, ~cmacs-ai-openai-compatible-endpoints~, the GNU's Eye key tables, ~process-environment~ and ~initial-environment~, ~auth-sources~ and the auth-source caches, ~password-data~, and any variable whose name contains =api-key=, =password= / =passwd=, =secret=, =credential= or an =access= / =auth= / =bearer= / =refresh= =-token= |
| ~cmacs-redact-sensitive-variables~ | Yours. Empty by default |

Both are lists of symbols (that variable) and strings (a regexp matched, case-sensitively, against variable names), consulted together:

#+begin_src emacs-lisp
(setq cmacs-redact-sensitive-variables
      '(my-work-vpn-settings "\\`my-private-"))
#+end_src

A subsystem that keeps a secret in a variable adds it with ~add-to-list~. Leave the shipped list alone and add to your own, so that a later version's additions reach you.

What follows for a sensitive variable, for a model-facing caller:

- =describe_variable= answers =This variable is withheld by your privacy rules= and nothing else: not the value, not the documentation. The sentence is the same for a variable that is bound, one that is void, and a name that was never a variable, so it says nothing about what the session holds.
- The =variable://= resource is refused the way an excluded buffer is: reported as not found.
- =list_hooks= leaves the variable out.
- An *alias* is as sensitive as what it names.
- *It fails closed.* An entry that is neither a symbol nor a valid regexp makes every variable sensitive until it is fixed.

What it does not do:

- It is not asked of you. ~M-x describe-variable~ and your own Lisp see everything; like the rest of this file it acts for model-facing callers only (~cmacs-redact-active-p~).
- *=eval= is out of scope.* It is privileged: an agent you have granted =eval= (or =crispy_eval=, a shell, =cmacs_c_*=) can read any variable, these included. The registry protects the read-only surfaces an agent gets by default.
- It protects variables by *name*. A secret copied into a variable with an ordinary name is not found; the free-text rules (a =text= rule for =sk-...=) are what catch a value wherever it appears.

* LQL sources

An agent that can run a query can read the editor-state sources, so they are redacted where every query passes: the snapshot. A Lisp source's rows are turned into JSON on the editor thread just before a query is submitted, inside the dynamic extent of whoever submitted it. When that is a model-facing caller the rows go through the rules first; your own queries (=M-x cmacs-lql-query=, the REPL, a results buffer) never do.

A source says what its columns /are/, and the rules do the rest. The declaration is the fifth argument of ~cmacs-lql-define-source~, or ~cmacs-lql-set-source-redaction~ afterwards:

#+begin_src emacs-lisp
(cmacs-lql-define-source
 "tickets" '(("file" string) ("dir" string) ("summary" string) ("state" string))
 #'my-ticket-rows "My tickets."
 '(("file" . file) ("dir" . derived) ("summary" . text) ("state" . plain)))
#+end_src

| Role      | The column is                                                                 | For a model                                                                                              |
|-----------+-------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------|
| =buffer=  | A buffer name                                                                 | The row goes when the buffer is excluded; else the name as the rules rewrite it                          |
| =file=    | A file name                                                                   | The row goes when the file is excluded, judged by its name alone; else the name as rewritten             |
| =url=     | A URL                                                                         | Likewise                                                                                                 |
| =app=, =title=, =pid= | Together, one window                                              | The row goes when the window is excluded; else app and title as rewritten                                |
| =text=    | Free text (a string, or a list of strings)                                    | Through the free-text rules                                                                              |
| =derived= | Computed from this row's buffer, file, URL or window: a directory, a relative path, a base name | Kept when the rules left those alone; blanked when they rewrote one                     |
| =plain=   | Not sensitive: a mode, a state, an id                                         | As it is                                                                                                 |

Instead of an alist the declaration may be a function of the rows (alists keyed by column name) returning the rows a model may see, for a source whose rule is not a matter of roles; it can call ~cmacs-lql-redact-rows~ for the part that is. =windows= does: its =frame= column is the title of one of this Emacs's frames. Or the symbol =none=, for rows that are already safe: the journal's =activity= was filtered when it was recorded.

*A source that declares nothing* is not left open. In a model-facing query every string in every one of its rows -- in any column, declared in the schema or not, and inside lists -- goes through the free-text rules. Nothing can be dropped that way, since nothing says which column names a file; declare the roles to get that. In a declared source an undeclared string column is =text= as well.

What keeps this safe and cheap:

- *The two snapshots never meet.* A source with a generation function has its snapshot cached. The cache is keyed by source name /and/ by whether the snapshot was made for a model, so the user's rows and a model's rows are different entries, and a model's entry also carries the rule set's generation: new rules, new snapshot.
- *It fails closed.* When the rules are not usable, or a source's redaction signals, a model's query sees that source with no rows. You still see yours.
- *No disk.* Files are judged by name: nothing is opened, no symbolic link is followed, no project is looked up (one the editor already knows is used). Values are memoised across a snapshot, since a column repeats itself down a table. Redacting =buffers= costs a few tenths of a millisecond per buffer.
- *Nothing is counted.* A dropped row leaves no placeholder and the query is not told how many there were.

The limits: a =file= role does not see through a symbolic link (reading the file is still refused, by ~cmacs-redact-file-p~); =gowl_clients= rows now carry =app_id=, =title=, =pid=, =tags= and =floating= beside =client=, because a window cannot be judged by an opaque object; and the engine's own sources are not Lisp and are not covered (see the table above).

* Failing closed

The rule set is unusable when a listed YAML file exists but cannot be read or parsed, or any rule holds a key, action, field or regexp the engine does not understand (see /Fail closed/ in [[file:cmacs-journal.org][cmacs-journal]]). While it is:

| Function                                              | Answers                                             |
|-------------------------------------------------------+-----------------------------------------------------|
| ~cmacs-redact-window~, ~cmacs-redact-url~, ~cmacs-redact-event~, ~cmacs-redact-buffer~ | nil: excluded                     |
| ~cmacs-redact-buffer-p~, ~cmacs-redact-file-p~, ~cmacs-redact-capture-refused-p~      | non-nil: excluded                 |
| ~cmacs-redact-text~                                     | =[withheld: redaction rules failed to load]= (the empty string stays empty) |
| ~cmacs-redact-capture-guard~, ~cmacs-redact-resource-guard~ | signal                                         |

So the inventory is empty, resources are refused, screenshots are refused. The warning that says which file and why is the journal's (=*Warnings*=); fix it and run ~M-x cmacs-journal-filters-reload~.

A failed load is not retried on every call -- that would re-read a broken file thousands of times. It is retried when a filter file changes: the journal watches its files only while its mode is on, so redaction compares their modification times itself, at most every ~cmacs-redact-check-interval~ seconds (2). A change to ~cmacs-journal-filters~ in Elisp needs ~cmacs-journal-filters-reload~, as it always did.

The C callers fail closed too: each asks through the dispatch with a form that begins =(require 'cmacs-redact)= and a guard that signals, so a missing file, a broken guard and a refusal are the same answer.

* Checking

~M-x cmacs-redact-test~ shows what a model would be given of what you are looking at -- the focused window under gowl, else the selected buffer -- as it is and as it would be shown. With a prefix argument it asks for the fields of a sample instead, and optionally a line of free text, so you can check a rule against a title you would rather not have on screen. It shows the result and never which rule produced it. It answers as a model would see it even though you ran it.

~M-x cmacs-journal-filter-test~ is the same question for the journal.

Rules for a new surface:

- List only what ~cmacs-redact-window~ / ~cmacs-redact-buffer-p~ let through, and print the rewritten values, not the originals.
- Never report that something was left out: no "3 windows hidden", no placeholder row. A count is a fact about the rule set.
- Never put a rule, a regexp or a rule number in an error.
- A surface that prints the value of a variable chosen by the caller asks ~cmacs-redact-variable-p~ first, by name, before looking at whether the variable is bound.
- Text produced later (a sentinel, a timer) by an async brigade tool is covered by the =tool= surface. Text produced later by anything else is not: wrap its composition in ~cmacs-redact-as-model~.
- A tool handler written in C asks through the dispatch, with the form beginning =(require 'cmacs-redact)= and names escaped by =cmacs_dispatch_lisp_escape=.

* Internals

- *One engine.* =cmacs-redact.el= calls ~cmacs-journal-filter-apply~ for events and ~cmacs-journal-filter-apply-text~ for free text; both live in =cmacs-journal-filter.el=. The only change to the engine is the =text= field and the free-text function.
- *One event shape.* A buffer is described by ~cmacs-journal--buffer-event~, the function the journal records it with. Loading =cmacs-journal.el= for that turns nothing on.
- *The advice.* ~cmacs-brigade-call-tool~ gets an around advice that binds a variable; ~cmacs-brigade-call-tool-async~ gets one that also wraps the callback, so the call counts as in flight until that function's exactly-once callback runs. A lost callback is forgotten after fifteen minutes.
- *Loaded from inside a tool call.* Callers require the file in a function body, so the first load may happen inside a tool call the advice was too late to wrap. The file looks at the backtrace when it loads and, if it finds a brigade call on it, counts that call as in flight for a minute.
- *The hash key is never changed here.* ~cmacs-journal-filter-hash-key~ is bound, not set, around each application, so a session key standing in for a missing journal key can never end up in a journal file.
- *LQL.* =cmacs-lql.el= redacts in ~cmacs-lql--snapshot-1~ and keys ~cmacs-lql--snapshot-cache~ by =(NAME . REDACTED)=. =test/cmacs/cmacs-lql-redact-tests.el= covers the roles, the default, fail closed, that the two snapshots never share an entry or a generation, and that every shipped source declares every string column.
- *Sensitive variables.* The registry is two lists and one predicate; ~cmacs-redact-resource-guard~ asks it for the =variable= kind, which is how the C resource handler is covered with no change to the C. =test/cmacs/cmacs-redact-variables-tests.el= covers the registry (including that every rule-holding variable of =cmacs-journal-filter.el= is in it, read from the source), the three surfaces, and a source guard: a tool family file that reads a variable chosen at run time must mention ~cmacs-redact-variable-p~.
- *Tests.* =test/cmacs/cmacs-redact-tests.el=: each contract function against rules; fail closed; who is asking, including the async window; the screen inventory; captures and resources; that no result or error contains the rule; and a source guard that every C image handler and resource handler still asks first.
