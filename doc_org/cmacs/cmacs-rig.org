#+TITLE: cmacs-rig — A Private cmacs --gowl Session to Test Against
#+AUTHOR: Zach Podbielniak
#+OPTIONS: toc:2 num:t

* Overview

The rig is a second cmacs, started as =emacs --gowl -Q= on wlroots' headless backend, with its own MCP server, its own D-Bus session bus and real Wayland clients inside it. Tests drive it from the outside, over the real MCP socket, the way an agent or =emacsctl= does. Nothing is stubbed: a =tools/call= goes through the socket, the publisher, the registry and the dispatch that a user's call goes through; a text field is a real text-input-v3 client; a window is a window.

It exists because features were landing with unit tests that called the Lisp handler directly and stubbed the C primitives. Two bugs were found only when one test talked to a real socket (migrated Lisp tools were not replacing their C twins; a =tools/call= with no ="arguments"= crashed the editor). Neither is reachable from a test that never leaves its own process. The first runs of the rig found seven more; see /What it found/.

Three files, all in =test/cmacs/=:

| File | What it is |
|------+------------|
| =cmacs-rig.el= | The harness: start and stop the child, an MCP client, =cmacs-rig-eval= and =cmacs-rig-do=, client spawning, screenshots. |
| =cmacs-rig-field.c= | The text-field client: a Wayland window that is one text-input-v3 field, built by the test at run time. |
| =cmacs-rig-tests.el= | The ERT tests. |

* Running it

#+begin_src sh
just test-rig                 # the whole file
just test-rig 'edit-field'    # tests whose name matches a regexp
#+end_src

which is

#+begin_src sh
CMACS_RIG=1 src/emacs --batch -Q -L lisp/cmacs -L test/cmacs \
  --eval '(setq load-prefer-newer t)' -l ert \
  -l test/cmacs/cmacs-rig-tests.el -f ert-run-tests-batch-and-exit
#+end_src

A run takes about two minutes, most of it the sweep that calls every migrated tool twice.

It is *not* part of =make -C test check-cmacs=. That target loads every =.el= in =test/cmacs/=, these two included, so both must be harmless there: =cmacs-rig.el= defines no tests, and every test in =cmacs-rig-tests.el= skips unless =CMACS_RIG= is set in the environment. The reasons it is separate: it is slower than the unit suites, it compiles a C program and launches processes, and it needs =gcc=, =pkg-config=, =wayland-scanner=, =wayland-protocols=, =dbus-daemon= and =timeout=. A test whose requirement is missing skips and says which.

** Environment variables

| Variable | Effect |
|----------+--------|
| =CMACS_RIG= | Set to anything: run the tests. Unset: every test skips. |
| =CMACS_RIG_SHOTS= | A directory. Each scenario saves =NN-scenario-step.png= there at its meaningful moments, and a test that does not pass saves =NN-not-passed-NAME.png=. Unset: no pictures. |
| =CMACS_RIG_KEEP= | Set: the rig's directory (log, client logs, dump files) is left behind and its name printed. A rig that fails to start is always kept. |
| =CMACS_RIG_RENDERER= | =WLR_RENDERER= of the child; default =pixman=, which needs no GPU. =gles2= exercises the effect modules where a render node exists. |
| =CMACS_RIG_DISABLE= | Set: no rig starts (every test skips). |

** Pictures

With =CMACS_RIG_SHOTS= set, =cmacs-rig-shot= saves a PNG of the child's headless output. The picture is taken *inside* the child, by its own =gowl-screenshot= of its own output, from its main loop rather than over RPC, so it also shows the states a model-facing screenshot is refused in. The pixman renderer draws real frames: the bar, the Emacs frame, the client windows and their text are all there. The field client draws its title and text when =pangocairo= is installed and is a plain rectangle otherwise.

* The isolation guarantees

The developer's desktop is itself a =cmacs --gowl= session, so a rig that reached it could kill it. Each of these is enforced in =cmacs-rig.el=, and =cmacs-rig-test-isolation= checks the result from =/proc/PID/environ= of the child: what the kernel says the child was started with, not what the harness believes it passed.

- *The environment is built, not inherited.* Five names are copied (=PATH=, =TZ=, =USER=, =LOGNAME=, =LD_LIBRARY_PATH=); everything else is set by the harness. =DBUS_SESSION_BUS_ADDRESS= of the parent cannot leak: it is not on the list.
- *=WAYLAND_DISPLAY=, =WAYLAND_SOCKET= and =DISPLAY= are explicitly unset.* This is not decoration. When =process-environment= has no entry for =DISPLAY=, Emacs hands a subprocess the =DISPLAY= of =initial-environment= (callproc.c), which is the live session's X server. The isolation test found exactly that in the first version of the harness.
- *Private directories.* =XDG_RUNTIME_DIR= (mode 0700), =HOME= and the four XDG base directories are fresh directories under one =make-temp-file= directory. No user init, journal, gabbrev or bar state is read or written. The parent of that directory is the user's runtime directory when there is one, because a socket path has 108 bytes; the rig's runtime directory is a new directory inside it, never it.
- *Headless.* =WLR_BACKENDS=headless=, =WLR_HEADLESS_OUTPUTS=1=, =WLR_RENDERER=pixman=, =GOWL_DISABLE_SYSTEMD=1=: the launch recipe of =cmacs-gowl-tests--run-headless=. No DRM, no parent compositor, no input devices.
- *A bus of its own.* A =dbus-daemon --session= listening in the private runtime directory. =NO_AT_BRIDGE=, =GSETTINGS_BACKEND=memory=, =GIO_USE_VFS=local= and =GVFS_DISABLE_FUSE= keep the desktop's services from being activated on it.
- *It refuses before it starts.* =cmacs-rig--assert-private= signals =cmacs-rig-unsafe= if a computed directory is one of the live session's, is outside the rig, is not 0700, already holds a socket, is too long for a socket path, or if the environment names a display or a bus that is not the rig's. The tests treat that signal as a failure, never as a skip.
- *Clients see one display.* A program started with =cmacs-rig-spawn= gets the rig's environment plus the =WAYLAND_DISPLAY= of the child compositor.
- *Processes are known by PID and signalled by PID.* Before a PID that is not one of this Emacs's own process objects is signalled, =/proc/PID/environ= must name the rig's runtime directory. The last step of a stop sweeps every process of this user whose environment does, which catches a program the child spawned itself. Nothing is ever killed by name or pattern.
- *Every wait has a deadline.* Starting, each MCP request, each poll. The child ends itself when the Emacs that started it disappears, and =timeout(1)= ends it after =cmacs-rig-lifetime= seconds whatever happens.
- *On failure it says where the evidence is.* The rig's directory, the child's PID and the tail of its log are in every error the harness signals.

Two things the rig does *not* isolate: the network (a tool that fetches from the internet will; the sweep leaves those out by name, see =cmacs-rig-tests-sweep-excluded=), and =/tmp= (anything in cmacs that writes to a fixed path there writes to the real one; =cmacs-c-compile= no longer does, =cmacs-print='s spool directory still does).

* What it covers

| Area | Tests | What must be true |
|------+-------+-------------------|
| The rig | =isolation=, =dbus-private-bus= | The child's environment and sockets are private; it serves =org.cmacs.Editor= on its own bus. |
| MCP wire | =wire-lists-migrated-tools=, =wire-no-argument-sweep=, =wire-tools-with-arguments= | Every migrated tool is listed once. Every migrated tool with no required parameter answers a real =tools/call=, with an empty ="arguments"= and with none; the child survives. A few tools with arguments give the right answer. |
| Which side answers | =wire-registry-serves-migrated-tool=, =wire-eval-cannot-be-replaced= | A migrated tool is dispatched by the registry (the sweep checks this for all of them); a registry tool called =eval= never replaces the built-in. |
| Redaction | =redaction-*= | With a rule file in the child's own =~/.config/cmacs/journal-filters.yaml=, an excluded window and buffer appear in no model-facing answer over MCP or D-Bus, a screenshot is refused while the window is visible, and a rule file that does not load shows nothing at all. |
| Text fields | =text-field-*=, =edit-field-*= | =gowl-text-field-read= returns what the application holds and =-replace= changes it (non-ASCII, checked against the application's own dump). The edit-field command opens a floating editor without moving any tiled window, and finishing writes back. |
| AI field | =ai-field-*= | Field text goes to the model and its answer comes back into the field; the model is a function inside the child. Focus moved meanwhile: nothing is typed anywhere. |
| Journal | =journal-*= | Focus changes become spans in the child's own journal directory (0700/0600); an agent sees none of it; a checkpoint lists the rig's windows; a restore relaunches a closed window on its recorded tag. |
| LQL watch | =lql-watch-fires-once= | A watch on =buffers= fires once when a buffer appears and not on idle ticks. |
| Deixis | =deixis-pointer-history= | The pointer ring answers "where was it at time T" with the right window after injected motion. |

* Writing a case

#+begin_src emacs-lisp
(cmacs-rig-deftest my-feature ()
  "What must be true."
  (skip-unless (cmacs-rig-field-client))
  (let ((field (cmacs-rig-spawn-field rig :title "rig-mine" :text "hello")))
    (cmacs-rig-focus rig (plist-get field :id))
    (cmacs-rig-do rig '(my-command))
    (cmacs-rig-shot rig "my-feature-after")
    (cmacs-rig-wait-field-text rig field "HELLO")))
#+end_src

=rig= is bound in the body. The macro skips without =CMACS_RIG=, starts the shared rig if need be, resets it afterwards, and asserts the child is still alive.

** Two callers, on purpose

| Helper | Runs as | Use it for |
|--------+---------+------------|
| =cmacs-rig-call=, =cmacs-rig-tool-text=, =cmacs-rig-request= | An MCP client | What an agent sees. |
| =cmacs-rig-eval= | The MCP =eval= tool, inside the RPC dispatch | Reading state; setting things up. =inhibit-interaction= is bound and redaction is in force. |
| =cmacs-rig-do= | A zero timer in the child's main loop | A command as the person at the keyboard runs it. No RPC, no redaction, not "an agent". |
| =cmacs-rig-dbus= | =gdbus= on the rig's bus | The D-Bus surface. |

The difference is the point of several tests. =cmacs-journal-events= answers =cmacs-rig-do= and returns nothing to =cmacs-rig-eval=; the redaction functions are the identity for one and active for the other. A command tested only through =cmacs-rig-eval= is tested as an agent would run it, which is not how it is reached.

The MCP =eval= tool evaluates with dynamic binding: a =lambda= in a form sent through =cmacs-rig-eval= closes over nothing. =cmacs-rig-do= evaluates lexically.

** Rules

- The child never waits. Poll from the parent with =cmacs-rig-wait-for=; never send a form that sleeps.
- Name everything a test creates =rig-...=: the reset kills buffers by that prefix and closes every window that is not the child's own frame.
- A test for a bug that is not fixed yet is marked =:expected-result :failed= with a comment naming the bug. The file stays green, and turns red ("unexpectedly passed") the day the bug is fixed and the marker should go.
- A value returned through =cmacs-rig-eval= must print readably: select fields rather than returning a client object.

* The text-field client

=cmacs-rig-field.c= speaks text-input-v3 itself and uses no toolkit. A GTK entry was the first attempt and cannot work in the rig: GTK enables its text input only while its window has keyboard focus, which it learns from =wl_keyboard.enter=, and a headless gowl has no keyboard device, so its seat advertises no =wl_keyboard= at all. A virtual keyboard did not change that either. Both are fixed in gowl (a virtual keyboard counts, and =GOWL_SEAT_KEYBOARD=always= forces the capability; =deps/gowl/docs/configuration.org=, /Machines without a keyboard/), so a toolkit client can now be hosted once the rig sets that variable; the field client stays toolkit-free because it needs no toolkit.

What it does is what a toolkit does: on =enter= it enables the text input and reports its surrounding text; on =delete_surrounding_text= / =commit_string= / =done= it applies one edit; on =leave= it disables. It rewrites a dump file whenever the text changes, which is what the *application* holds, as opposed to what the compositor believes.

By default it sends the compositor a =wl_display.sync= every 20 ms, as a desktop with anything alive on it does. =:idle t= turns that off; the difference is a bug (see below).

* What it found

The first runs found these. Each has a test marked =:expected-result :failed=, or is noted where no test could be written.

| Bug | Test |
|-----+------|
| =gowl-text-field-read= / =-replace= do not flush the client after entering the borrowed text input. On an idle desktop the =enter= is written only when the operation's own 250 ms timeout turns the event loop, which then gives up: about half the calls report =no-field=. | =text-field-read-on-an-idle-desktop= |
| =cmacs-gowl-ai-field--withheld-p= asks =cmacs-redact-window= without =cmacs-redact-as-model=. From a key binding the redaction functions are the identity, so an excluded window's field is sent to the model and rewritten. | =ai-field-excluded-window-is-withheld= |
| D-Bus =Compositor.ListClients= and =Compositor.FocusedClient= are composed in C and never redacted. | =redaction-dbus-compositor-clients= |
| D-Bus =BufferManager.List= names excluded buffers. | =redaction-dbus-buffer-list= |
| No migrated tool sets =destructiveHint=, =delete_window= included. | (the sweep's exclusion list exists because of it) |
| =gnuseye_list_layers= and its siblings fetch textures from the network when first called. *Fixed:* nothing is fetched until a globe is open. | =test/cmacs/cmacs-load-quiet-tests.el=; the sweep's exclusion can go |
| A headless or keyboard-less seat advertises no =wl_keyboard=, even with a virtual keyboard: injected keys reach no client. *Fixed in gowl:* a virtual keyboard counts, and the capability can be forced. | =deps/gowl/tests/test-seat-keyboard.c=, =test/cmacs/cmacs-gowl-seat-keyboard-tests.el= |
