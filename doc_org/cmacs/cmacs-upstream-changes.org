#+TITLE: CMacs Upstream Changes
#+STARTUP: showall
#+OPTIONS: toc:2 num:t

* Why this file exists

cmacs tracks upstream GNU Emacs and merges it in every few weeks.  To keep
those merges painless, new features live in *new* files under
=cmacs/<subsystem>/= and =lisp/cmacs/=, and edits to stock Emacs sources
(=src/*.c=, =src/*.in=, =lisp/*.el=, =src/Makefile.in=, =configure.ac=) are
kept as small and as guarded as possible --- ideally a single =#ifdef
HAVE_CMACS_*= block calling into a =cmacs_*= function defined in a new file.

This file is the authoritative catalogue of *every* edit cmacs makes to an
upstream file, so that when a merge conflict lands on one of them you know
exactly what the change is, why it exists, and how to re-apply it.  Many
hunks carry a =/* CMACS ... */= comment in the source, but not all, so use
this list as the index.  *If you add or remove an upstream touch-point,
update this file and =doc/cmacs/cmacs.texi= in the same commit.*

Everything cmacs adds is gated behind a =HAVE_CMACS_*= macro, so with the
cmacs flags off, an upstream-style build still works and every hunk below
compiles out.

* Generated files (NOT hand-edited)

These contain =cmacs= strings but are build artifacts regenerated from the
sources below --- do not edit them, and ignore them in a merge:
=src/config.h= (from =configure.ac= + =src/config.in= via autoheader),
=src/globals.h= (make-docfile, from the cmacs DEFUNs), =src/buildobj.h=,
=src/epaths.h= (from =src/epaths.in=), and the generated lisp loaders
=lisp/loaddefs.el=, =lisp/cus-load.el=, =lisp/finder-inf.el=,
=lisp/subdirs.el= (they discover =lisp/cmacs/= automatically).

* C sources

** src/emacs.c

Several small hunks, all in =main()= / its init path:

- *Includes* (gated): =cmacs-bacon.h=, =cmacs-crispy.h=, =<gowl.h>= /
  =<wayland-server-core.h>=.
- *=--bacon= entry* (=HAVE_CMACS_BACON=): scan =argv= and enter the
  embedded shell via =cmacs_bacon_main= before any Emacs init; never
  returns.  =cmacs_bacon_main= itself also handles the batch forms
  =--bacon -c CMD= and =--bacon SCRIPT= (no extra emacs.c hunk).
- *=--crispy= entry* (=HAVE_CMACS_CRISPY=): identical shape to the
  =--bacon= scan, directly below it.  Calls =cmacs_crispy_main= to run
  a crispy script / inline code / stdin / terminal REPL without any
  Emacs initialization; never returns.
- *=--gowl= early start* (=HAVE_CMACS_GOWL=): create + configure the
  =GowlCompositor= (incl. the =evaluate-gowl-config-with-cmacs= /
  =evaluate-c-config-with-cmacs= gates) and start it before display init,
  so PGTK/GDK connects to gowl's own Wayland display.
- *JSC GC-signal redirect* (=HAVE_CMACS_GSURF || HAVE_XWIDGETS=), plus a
  guarded =#include <dlfcn.h>=, at the very top of =main()=:
  #+begin_src c
  #if defined HAVE_CMACS_GSURF || defined HAVE_XWIDGETS
    int (*cmacs_jsc_configure_gc_signal) (int)
      = (int (*) (int)) dlsym (RTLD_DEFAULT, "JSConfigureSignalForGC");
    if (cmacs_jsc_configure_gc_signal != NULL)
      cmacs_jsc_configure_gc_signal (40);   /* 40 = SIGRTMIN+5 on Linux */
  #endif
  #+end_src
  WebKit's JavaScriptCore (pulled in by gsurf and/or =--with-xwidgets=)
  pauses threads for GC using a signal defaulting to *SIGUSR1* (signal 10)
  --- the same signal podomation's =engine= source (=on_sigusr1=),
  libreclaw's thread dump, and Emacs's =[sigusr1]= use, so JSC steals it.
  JSC installs its handler during early GTK/library init, before any cmacs
  runtime code runs, so this is the only reliable place to redirect it to a
  free real-time signal.  We call JSC's private =JSConfigureSignalForGC()=
  (resolved by =dlsym=, so it is a no-op if absent) rather than setting the
  =JSC_SIGNAL_FOR_GC= environment variable: the env var works, but JSC's
  option parser also scans every =JSC_*= var and rejects it with =ERROR:
  invalid option: JSC_SIGNAL_FOR_GC=40= (once per JSC process).  The
  programmatic call sets the same config field with no such noise.
  =SIGUSR2= / =SIGHUP= are unaffected.
- *=syms_of_cmacs_*= block*: register every subsystem's DEFUNs at dump
  time (one =#ifdef HAVE_CMACS_*= guard per subsystem: glib, gobject,
  dbus, gi, crispy, bacon, gowl, podomation, libreclaw, org-ex, mcp,
  cintrospect, cpatch, video, audio, whisper, piper, ai, libregnum,
  gnuseye, gsurf).
- *=init_cmacs_*= late-init block* (marked =/* CMACS: late init ... */=):
  run each subsystem's runtime initialisation after terminal setup
  (=init_cmacs_glib=, =init_cmacs_dbus=, =init_cmacs_gowl=,
  =init_cmacs_podomation=, ... =init_cmacs_gsurf=).

** src/process.c --- GLib event-loop hooks

cmacs does *not* replace Emacs's event loop; it hooks Emacs's =pselect()=
so a =GMainContext= is iterated around the same wait.  Include of
=cmacs/glib/cmacs-glib-loop.h=, then in the select loop
(=HAVE_CMACS_GLIB=): =cmacs_glib_prepare= before the wait and
=cmacs_glib_dispatch= after.  =cmacs_glib_dispatch= must clear
=waiting_for_input= before dispatch and restore it after, or a Lisp error
raised from a GLib callback aborts with =Fatal error 6: Aborted=.

** src/pgtkterm.c --- paint hooks + libregnum input routing

- *Overlay includes* (gated): =cmacs-ink-overlay.h= (=HAVE_CMACS_GLIB=),
  =cmacs-video.h=, =cmacs-audio.h=, =cmacs-libregnum.h=.
- *Paint hooks* in =pgtk_handle_draw= (after the back-surface blit):
  =cmacs_video_overlay_paint= (=HAVE_CMACS_VIDEO=),
  =cmacs_audio_overlay_paint= (=HAVE_CMACS_AUDIO=),
  =cmacs_libregnum_overlay_paint= (=HAVE_CMACS_LIBREGNUM=), and
  =cmacs_ink_overlay_paint= (=HAVE_CMACS_GLIB=, painted last so strokes
  sit on top).  (The ink paint was deliberately moved here from the
  earlier expose path --- see the comments at the old call sites.)
- *libregnum pointer input* (=HAVE_CMACS_LIBREGNUM=): when the selected
  window shows a libregnum view, route motion / button / scroll into the
  libregnum input controller (=cmacs_libregnum_handle_motion= /
  =_handle_button= / =_handle_scroll=) before Emacs's own mouse machinery;
  non-view buffers fall through unchanged.  Viewport orbit/pan/zoom, node
  picking, gizmo handle drags, and object move-drags all run here (the
  controller is pure C in =cmacs/libregnum/cmacs-libregnum-input.c=).
- *libregnum GDK drag-source* (=HAVE_CMACS_LIBREGNUM=): two thin hunks in
  =pgtk_set_event_handler= and =motion_notify_event= call helpers from the new
  file =cmacs/libregnum/cmacs-libregnum-dnd.c=:
  1. =pgtk_set_event_handler= (near end, before closing brace): \
     =#ifdef HAVE_CMACS_LIBREGNUM= \
     =/* CMACS: libregnum editor drag-source ... */= \
     =cmacs_libregnum_dnd_setup_frame (f);= \
     =#endif= \
     Connects =drag-data-get= / =drag-end= signals to the frame widget once.
  2. =motion_notify_event= (inside the existing =#ifdef HAVE_CMACS_LIBREGNUM= block,
     after the =cmacs_libregnum_handle_motion= check): \
     =/* CMACS: libregnum editor drag-source ... */= \
     =if (cmacs_libregnum_dnd_check_motion (frame, event)) return TRUE;= \
     Initiates =gtk_drag_begin_with_coordinates= when a palette/asset drag was
     armed from Elisp (=[down-mouse-1]=) and the pointer crossed GTK's threshold.
  The includes block gains =#include "cmacs-libregnum-dnd.h"= inside the
  existing =#ifdef HAVE_CMACS_LIBREGNUM= include guard.  All three sub-hunks
  compile out cleanly when =HAVE_CMACS_LIBREGNUM= is unset.

*** Editor drag-and-drop

The libregnum editor supports two drag paths that complement each other:

- *Intra-Emacs drag* (=drag-mouse-1=, no upstream edit beyond the input-routing
  hook above): Emacs delivers the drag to the *start* buffer's keymap with the
  *release* position, so the palette/asset handler receives the viewport drop
  coordinates and ray-casts them to the ground plane
  (=cmacs-libregnum-editor-screen-to-ground=).  The pgtkterm motion hook does
  *not* intercept this because the palette buffer has no libregnum view, so
  =selected_view_for_frame= returns NULL and the motion falls through to Emacs's
  normal =drag-mouse-1= synthesis.  Good for all in-frame drops.
- *GTK-native GDK drag-source* (=[down-mouse-1]= → =cmacs-libregnum-dnd-arm= →
  =cmacs_libregnum_dnd_check_motion= → =gtk_drag_begin_with_coordinates=): adds
  real OS-level DnD so palette/asset items can be dragged to external GTK apps.
  The one upstream hunk this requires is the pair in =pgtkterm.c= described above
  (NOT =pgtkselect.c=; the signal connections live in =pgtk_set_event_handler=
  which is in =pgtkterm.c=).  All logic is in =cmacs-libregnum-dnd.c=; the hunk
  is a single call per place.  The key invariant: we do *not* call
  =gtk_drag_source_set= (which would intercept every button press on the whole
  frame widget); instead we arm from Elisp and check the threshold in the motion
  callback.
- *External file drag* (e.g. dropping a =.glb= from a file manager onto the
  viewport): handled by Emacs's stock =pgtk-dnd= extended with our
  ="application/x-libregnum"= entry in =pgtk-dnd-types-alist= (pure Elisp,
  no upstream edit).

*** Editor right-click context menu --- NO upstream change needed

The viewport entity context menu (right-click an entity → a GTK menu of
actions) requires *no new upstream edit*.  It rides the existing *libregnum
pointer input* hunk above: a right-click (button-3 press+release without
movement) is detected inside =cmacs_libregnum_handle_button= (pure C in
=cmacs/libregnum/cmacs-libregnum-input.c=), which ray-picks the node and defers
=cmacs-libregnum-editor--context-menu= onto the cmacs GMainContext.  The menu
itself is Emacs's own =x-popup-menu= (a native =GtkMenu= in the pgtk build),
popped from the command loop via a 0-delay timer — so no GTK-menu code is added
anywhere, and the existing button hook already routes the event.  A right-drag
still pans (also handled in that same controller).

** src/xwidget.c / src/xwidget.h --- gowl client embedding

All gated =HAVE_CMACS_GOWL= (and =HAVE_PGTK= for the event paths).  gowl
embeds Wayland clients as a kind of xwidget:

- =xwidget.h=: a =Qgowl= xwidget type, two opaque fields on
  =struct xwidget= (=void *gowl_client=, =void *gowl_view=), and externs
  =cmacs_xwidget_allocate_gowl=, =xwidget_gowl_set_focused_view=,
  =xwidget_gowl_clear_focused_view=.
- =xwidget.c=: includes =cmacs-gowl.h= / =cmacs-gobject.h=; skips the
  normal WebKit construction for =Qgowl=; =cmacs_xwidget_allocate_gowl=
  (called from =cmacs-gowl.c=) allocates a bare xwidget for an embedded
  client; and the focus/event-forwarding helpers
  (=gowl_focused_view= / =gowl_hovered_view=, =xwidget_gowl_forward_event=)
  route GTK key/pointer events to the focused gowl view's Wayland client.

** src/lisp.h --- init/syms externs

A single =/* CMACS */= block of =extern void init_cmacs_*= /
=syms_of_cmacs_*= declarations, one =#ifdef HAVE_CMACS_*= per subsystem,
so =emacs.c= can call them.

* Build system

** configure.ac + src/config.in

=configure.ac= adds all the =--with-cmacs-*= / =--enable-cmacs-*= options
(plus the =--with-gsurf= / =--with-gowl= aliases), their dependency checks
(e.g. gsurf/libregnum require =--with-cmacs-glib= and =--with-pgtk=; ai
shares libreclaw's =ai-glib= archive), the =AC_DEFINE([HAVE_CMACS_*])= and
=AC_SUBST= of each subsystem's =OBJ= / =CFLAGS= / =LIBS= / =BUNDLED= vars.
=src/config.in= carries the matching =#undef HAVE_CMACS_*= lines
(autoheader-maintained from =configure.ac=) plus
=#undef CMACS_PIPER_DEFAULT_BINARY=.  Each subsystem's =CMACS_*_OBJ= list is
appended to here as the subsystem grows --- e.g. =CMACS_LIBREGNUM_OBJ= gained
=cmacs-libregnum-dnd.o= (editor GDK drag-source) and =CMACS_MCP_OBJ= gained
=cmacs-mcp-tools-libregnum.o= (editor MCP tools), each under its existing
=--with-cmacs-libregnum= / MCP guard.  (Re-run =autoconf= + =./config.status
--recheck= after editing, not bare =./configure=.)

** src/epaths.in

Adds =#define PATH_CMACS_API "/usr/local/lib/cmacs"= --- where crispy and
bacon locate =libcmacs-api.so= / =cmacs-api.h= on an installed system.

** Makefile.in (top-level) --- install & docs targets

The top-level build/install Makefile gains: the =cmacsapidir= install
location and rules that install =cmacs/api/libcmacs-api.so= +
=cmacs-api.h= and the bacon =.so= modules; a =sed= step that rewrites
=PATH_CMACS_API= in the installed =epaths.h= to =cmacsapidir=; the
=cmacs-deps-docs= target (a prerequisite of =actual-all=, so it runs on
every =make=) that mirrors each =deps/<dep>/docs= tree into
=doc_org/cmacs/deps/=; and the optional "Print to cmacs" printer and
=org.cmacs.Editor= D-Bus service install/uninstall targets.

** java/Makefile.in --- Android Doom bundle

When =build-aux/android-doom-bundle/= exists (populated by
=build-aux/android-build.sh= from the host's =~/.config/{emacs,doom}=),
copy it into =install_temp/assets/doom-bundle= so the APK ships an
embedded Doom config.

** src/Makefile.in --- linking & static-library dedup

- =vpath %.c= / =vpath %.h= entries for each =cmacs/<subsystem>/= source
  dir; =CMACS_*_OBJ= / =_CFLAGS= / =_LIBS= / =_BUNDLED= variable block.
- Subsystem static libraries (e.g. =libgsurf.a=, =liborgex-1.0.a=) are
  whole-archived into temacs.
- *Static-library dedup* (the critical invariant): crispy and yaml-glib
  objects are vendored in several archives, possibly from different
  commits.  The =_bacon_strip= / =_gowl_strip= / =_libreclaw_strip= /
  =_gsurf_strip= machinery runs =ar d= to delete duplicate objects from
  the downstream archives before linking, and strips any
  =-Wl,-z,muldefs= from the per-lib LIBS.  *Never* re-add
  =-Wl,-z,muldefs= --- it silently picks one implementation, giving an ABI
  mismatch and non-deterministic crashes.
- =make-docfile= / =gl-stamp= need the cmacs =.c= files visible from
  =srcdir=; a =cmacs-symlinks= prerequisite + the
  =/* CMACS: make-docfile needs .c files visible from srcdir. */= hunk
  arrange that.  The =cmacs-symlinks= recipe walks =CMACS_ALL_OBJ= and
  symlinks each =cmacs/<subsystem>/NAME.c= into =srcdir=; new subsystem
  objects (e.g. the libregnum editor's =cmacs-libregnum-dnd.o=) are picked
  up automatically once added to a =CMACS_*_OBJ= var.
- *Submodule build rules*: recipes build the vendored deps before linking.
  The =deps/libregnum= rule passes =CRISPY=1 HAS_GI=1= +
  =GI_RUNTIME_{CFLAGS,LIBS}= (so crispy + the gjs/PyGObject scripting backends
  compile), and =BUILD_GIR=1= *when =g-ir-scanner= is present* (else
  =BUILD_GIR=0= as a fallback for cross/sandboxed builds where the scanner's
  =dlopen= of =liblibregnum.so= is unreliable).  =BUILD_GIR=1= produces
  =Libregnum-1.typelib= so cmacs's =gi= subsystem and the libregnum
  gjs/PyGObject scripting backends can introspect the editor types; the
  Justfile =run= recipe exports =GI_TYPELIB_PATH= to the libregnum + graylib
  gir dirs (symbols resolve from temacs's own =-rdynamic= statics, so no
  matching =LD_LIBRARY_PATH= is added).  It deliberately does *not* pass
  =BUILD_EDITOR_UI=1=, so the engine's standalone editor app is not compiled
  into temacs (a separate, optional frontend).  The =deps/gsurf= rule
  similarly pins =STATIC=1 BUILD_GIR=1 GTK_BACKEND=gtk3=.

** test/Makefile.in --- cmacs test-suite support

Three small hunks (each marked =## CMACS: ...=):

- Add =cmacs= to the =SUBDIRS= find so the =check-cmacs= target exists
  (runs every =test/cmacs/*-tests.el=).
- Skip the test-to-source dependency heuristic for =cmacs/%= tests
  (=$(filter cmacs/%,$(1))= in the =test_template= condition): the
  heuristic derives =../cmacs/FOO.el=, but cmacs sources live in
  =lisp/cmacs/= and =cmacs/<subsystem>/=, so the bogus prerequisite
  made every individual =make -C test cmacs/FOO-tests= target fail.
- Export a writable =XDG_CACHE_HOME= (=TEST_XDG_CACHE=, next to
  =TEST_HOME=) in the two test-running recipes: crispy tests compile C
  via gcc into the user cache dir, which cannot be created under the
  sandboxed =HOME=/nonexistent=.

* Lisp

** lisp/startup.el

One hunk (marked =;; CMacs: ...=): after Elisp init, on an interactive
session, =(require 'cmacs-config)= and call =cmacs-config-load-all= so the
user's bacon / C config files are loaded.

=lisp/site-start.el= is a *new* cmacs file (not an edit): it rides Emacs's
stock =site-run-file= load to bootstrap the embedded Doom config on the
first Android launch.  Everything else cmacs adds is a *new* file under
=lisp/cmacs/= picked up by the generated loaders.

.gitignore also gains entries for cmacs build artifacts (generated
=doc_org/cmacs/deps/= tree, installed module =.so= files, etc.).

* Re-applying after a merge

1. Search the upstream files for =CMACS= comments; each marks a hunk above.
2. For hunks without a marker, use this catalogue to re-create them.
3. Rebuild, forcing a relink if temacs-linked objects changed:
   =rm -f src/temacs && make -j$(nproc)=.
4. Sanity-check the DEFUNs are present:
   =just check-defuns= (or =M-x= a known =cmacs-= command).
