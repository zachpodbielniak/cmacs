#+TITLE: Crispy C Scripting
#+STARTUP: showall
#+OPTIONS: toc:2 num:t

* Overview

CMacs integrates the Crispy library for evaluating C code at runtime.
Scripts are compiled to shared objects (=.so=), cached by content hash
(SHA256), and loaded into the Emacs process via =g_module_open()=.

Because scripts run *in-process*, they can call back into Emacs through
the [[file:api.org][CMacs API]] using the DIRECT transport --- zero IPC overhead.

* Writing Config in C

Place an =init.c= in =~/.config/cmacs/= (preferred) or =~/.emacs.d/=.
CMacs checks =$XDG_CONFIG_HOME/cmacs/= first, then =user-emacs-directory=.

The file is loaded after =init.el= via =crispy-run=.  The CMacs API
headers and library are automatically available --- no manual
=CRISPY_PARAMS= needed.

** Minimal Example

#+begin_src c
/* ~/.config/cmacs/init.c */
#include <cmacs-api.h>

int main(int argc, char **argv)
{
    CmacsApi *api = cmacs_api_new(NULL);
    if (!api) return 1;

    cmacs_message(api, "Hello from init.c!");
    cmacs_api_free(api);
    return 0;
}
#+end_src

** Full Configuration Example

#+begin_src c
/* ~/.config/cmacs/init.c */
#include <cmacs-api.h>

int main(int argc, char **argv)
{
    CmacsApi *api = cmacs_api_new(NULL);
    if (!api) return 1;

    /* Appearance */
    cmacs_theme(api, "modus-vivendi");
    cmacs_font(api, "Iosevka", 14);

    /* Settings */
    cmacs_set(api, "inhibit-startup-screen", "t");
    cmacs_set(api, "ring-bell-function", "ignore");
    cmacs_set(api, "scroll-conservatively", "101");
    cmacs_set(api, "use-short-answers", "t");

    /* Modes */
    cmacs_mode(api, "electric-pair");
    cmacs_mode(api, "global-display-line-numbers");
    cmacs_mode(api, "column-number");
    cmacs_mode(api, "show-paren");

    /* Packages */
    cmacs_pkg_install(api, "magit");
    cmacs_pkg_install(api, "which-key");
    cmacs_pkg_install(api, "vertico");

    /* Keybindings and custom elisp */
    cmacs_eval(api, "(global-set-key (kbd \"C-x g\") 'magit-status)");
    cmacs_eval(api, "(setq custom-file "
                    "(concat user-emacs-directory \"custom.el\"))");

    /* Open a file on startup */
    cmacs_open(api, "~/Documents/notes/todo.org");

    cmacs_message(api, "C config loaded!");
    cmacs_api_free(api);
    return 0;
}
#+end_src

** How It Works

1. =cmacs-config-load-crispy-init= finds =init.c=
2. Calls =(crispy-run "~/.config/cmacs/init.c")=
3. Crispy compiles the file with GCC, injecting =-I= / =-L= / =-rpath=
   flags for =cmacs-api.h= and =libcmacs-api.so=
4. The compiled =.so= is cached by SHA256 hash
5. =g_module_open= loads it into the Emacs process
6. =main()= is called as a function pointer on the Emacs main thread
7. The CMacs API uses the DIRECT transport --- function calls, no IPC

** Using GObject Introspection from C

Since crispy scripts are compiled with GLib flags, you can use GI:

#+begin_src c
#include <cmacs-api.h>

int main(int argc, char **argv)
{
    CmacsApi *api = cmacs_api_new(NULL);

    /* Use GLib functions directly */
    const gchar *user = g_get_user_name();
    gchar *greeting = g_strdup_printf("Hello, %s!", user);
    cmacs_message(api, greeting);
    g_free(greeting);

    cmacs_api_free(api);
    return 0;
}
#+end_src

* Elisp Primitives

** crispy-eval

#+begin_example
(crispy-eval CODE)
#+end_example

Compile and execute inline C code string.  Returns the exit code as
an integer.

#+begin_src emacs-lisp
(crispy-eval "int main() { return 42; }")
;; => 42
#+end_src

** crispy-eval-string

#+begin_example
(crispy-eval-string CODE)
#+end_example

Compile and execute C code, capturing stdout as a string.

#+begin_src emacs-lisp
(crispy-eval-string "#include <stdio.h>\nint main() { printf(\"hello\"); return 0; }")
;; => "hello"
#+end_src

#+begin_src emacs-lisp
;; With CMacs API
(crispy-eval-string "
#include <cmacs-api.h>
#include <stdio.h>
int main() {
    CmacsApi *api = cmacs_api_new(NULL);
    gchar *val = NULL;
    cmacs_get(api, \"major-mode\", &val);
    printf(\"%s\", val);
    g_free(val);
    cmacs_api_free(api);
    return 0;
}")
;; => "emacs-lisp-mode"
#+end_src

** crispy-run

#+begin_example
(crispy-run FILE &rest ARGS)
#+end_example

Compile and execute a =.c= script file with optional arguments.
Returns the exit code.

#+begin_src emacs-lisp
(crispy-run "~/.config/cmacs/init.c")
;; => 0

;; With arguments
(crispy-run "/tmp/script.c" "arg1" "arg2")
#+end_src

** crispy-compile

#+begin_example
(crispy-compile FILE)
#+end_example

Compile a =.c= file and return the cached binary path (without
executing it).

#+begin_src emacs-lisp
(crispy-compile "/tmp/test.c")
;; => "/home/zach/.cache/crispy/abc123.so"
#+end_src

** crispy-repl-eval

#+begin_example
(crispy-repl-eval CODE)
#+end_example

Evaluate code in the persistent REPL and return the exit code.
Preprocessor directives (=#include=, =#define=), function definitions,
and type declarations accumulate in a *preamble* that stays in scope
for later calls; plain statements are compiled and executed once.
Output goes to Emacs's own stdout --- use =crispy-repl-eval-string=
to capture it.

#+begin_src emacs-lisp
(crispy-repl-eval "int square(int x) { return x * x; }")  ;; persists
(crispy-repl-eval "g_print(\"%d\\n\", square(7));")       ;; uses it
#+end_src

** crispy-repl-eval-string

#+begin_example
(crispy-repl-eval-string CODE)
#+end_example

Like =crispy-repl-eval=, but returns the combined stdout and stderr
output as a string.  Bare expressions (no trailing semicolon) are
auto-printed as ~=> VALUE~.  Compilation errors signal =crispy-error=
with the gcc diagnostic.  This is what the =*crispy*= REPL buffer and
the scratchpad use.

#+begin_src emacs-lisp
(crispy-repl-eval-string "1 + 2")
;; => "=> 3\n"

(crispy-repl-eval-string "#include <math.h>")          ;; preamble
(crispy-repl-eval-string "int sq(int x){return x*x;}") ;; preamble
(crispy-repl-eval-string "sq(7)")
;; => "=> 49\n"
#+end_src

** crispy-repl-preamble

#+begin_example
(crispy-repl-preamble)
#+end_example

Return the accumulated REPL preamble as a string (empty if the REPL
has not evaluated anything yet).

** crispy-repl-reset

#+begin_example
(crispy-repl-reset)
#+end_example

Reset the persistent REPL state.  The accumulated preamble (includes,
functions, types) is cleared.

** crispy-cache-status

#+begin_example
(crispy-cache-status)
#+end_example

Return the crispy cache directory path.

#+begin_src emacs-lisp
(crispy-cache-status)
;; => "/home/zach/.cache/crispy"
#+end_src

* The Crispy REPL

=M-x crispy-repl= opens the =*crispy*= buffer, a comint-based C REPL
backed by the persistent =crispy-repl-eval-string= primitive:

- The prompt is *read-only* (it cannot be deleted or edited).
- =#include= / =#define= directives, function definitions, and type
  declarations accumulate in the preamble and stay in scope.
- Bare expressions auto-print: typing =1 + 2= prints ~=> 3~.
- =RET= evaluates only when braces/parens/brackets balance; an
  unclosed ={= continues on an indented new line.  =C-j= forces a
  continuation line; =C-c C-c= / =M-RET= force-send.
- =TAB= at the start of input completes colon commands.
- REPL state is shared with =%crispy= scratchpad blocks.

** Colon Commands

GHCi-style meta-commands, typed at the prompt:

| Command          | Alias    | Description                                       |
|------------------+----------+---------------------------------------------------|
| =:help=          | =:h :?=  | Show command help                                 |
| =:type EXPR=     | =:t=     | Show the C type of EXPR (preamble in scope)       |
| =:info NAME=     | =:i=     | cintrospect info: type layout / symbol / DEFUN    |
| =:def NAME=      | =:d=     | Show =file:line= of C function NAME and visit it  |
| =:doc NAME=      |          | Docstring of Lisp function or variable NAME       |
| =:browse GLOB=   | =:b=     | List C symbols matching GLOB (cintrospect)        |
| =:preamble=      | =:p=     | Show the accumulated preamble                     |
| =:load FILE=     | =:l=     | Load a C file into the preamble                   |
| =:reset=         | =:r=     | Reset REPL state (clear the preamble)             |
| =:clear=         |          | Clear the REPL buffer                             |
| =:cache=         |          | Show the crispy cache directory                   |
| =:elisp EXPR=    | =:e=     | Evaluate EXPR as Emacs Lisp                       |
| =:bacon CMD=     | =:!=     | Run CMD in bacon (shell fallback if not running)  |
| =:quit=          | =:q=     | Bury the REPL buffer                              |

=:type= compiles a probe using =__typeof__= and
=__builtin_types_compatible_p= --- the same trick as the standalone
=crispy repl= --- so it works for expressions involving preamble
definitions.  =:info=, =:def=, and =:browse= are powered by the
[[file:cintrospect.org][cintrospect]] subsystem (DWARF introspection of the running binary)
and degrade gracefully with a message when cmacs is built without it.

Example session:

#+begin_example
crispy> :t 1 + 2.0
double
crispy> int fib(int n) { return n < 2 ? n : fib(n-1) + fib(n-2); }
crispy> fib(10)
=> 55
crispy> :i Lisp_String
type Lisp_String
  symbol-name  Lisp_String
  kind         struct
  size         32
  ...
crispy> :d Fcar
Fcar → /path/to/src/data.c:713
#+end_example

* Scratch Buffer Polyglot Eval

=cmacs-scratchpad-mode= (auto-enabled in =*scratch*= and Doom scratch
buffers) lets the scratch buffer execute crispy and bacon blocks
alongside ordinary Emacs Lisp.

A block starts with a marker line and ends at a blank line, the next
marker, previous output, or end of buffer:

#+begin_example
;; plain elisp -- C-j still works, or C-c C-c:
(+ 1 2)

%crispy
for (int i = 0; i < 3; i++)
    g_print("%d\n", i);

%bacon
ls /tmp | head -2
#+end_example

- =C-c C-c= (=cmacs-scratchpad-eval-block=) evaluates the block at
  point; output is inserted *inline* right below the block, shown in
  the =shadow= face.
- Re-evaluating a block *replaces* its previous output instead of
  stacking copies.
- =C-c C-k= (=cmacs-scratchpad-clear-output=) deletes the output at
  point; with a prefix argument it clears all output in the buffer.
- Crispy blocks share the persistent REPL with the =*crispy*= buffer:
  a function defined in the scratchpad is callable at the REPL prompt
  and vice versa.
- Bacon blocks run line-by-line through =bacon-eval= when the bacon
  shell is running, falling back to =shell-command-to-string=.
- Elisp blocks may contain several forms; they are wrapped in =progn=
  and the final value prints as ~=> VALUE~.

The buffers affected are controlled by
=cmacs-scratchpad-buffer-regexp= (default: =*scratch*= and
=*doom:scratch...*=).

* Command-line Usage

=--crispy= runs crispy code from the command line without starting
the editor, analogous to =--batch= for Lisp.  It is checked before
any Emacs initialization (like =--bacon=):

#+begin_example
emacs --crispy SCRIPT [ARGS...]   # run a .c script; exit code propagates
emacs --crispy -i CODE            # run inline C statements
emacs --crispy -                  # read a full script from stdin
emacs --crispy                    # tty: interactive terminal REPL;
                                  # pipe: evaluate stdin quietly
#+end_example

#+begin_src sh
$ emacs --crispy -i 'g_print("hi\n");'
hi
$ echo 'g_print("hello world\n");' | emacs --crispy
hello world
$ echo '1 + 2' | emacs --crispy
=> 3
$ echo 'int main(void){ return 3; }' | emacs --crispy -; echo $?
3
#+end_src

With no arguments and *piped stdin*, the input is evaluated with full
REPL semantics (preamble accumulation, ~=> VALUE~ auto-print,
multi-line ={ }= blocks) but with no banner and no prompts --- only
the code's own output reaches stdout; compile errors go to stderr and
the exit code is nonzero.  As at the REPL prompt, plain statements
do not persist between chunks --- group statements that share locals
in one ={ ... }= block.

Note that =-i= wraps bare statements in a =main()= with GLib includes,
while script-file and explicit =-= stdin modes expect a complete
translation unit with its own =main()=.  Scripts compile and link against
=libcmacs-api=; since no Emacs is running in this mode, the API's
in-process DIRECT transport is unavailable, but the other transports
can reach a separately running cmacs.

* Customization

| Variable                    | Description                            | Default |
|-----------------------------+----------------------------------------+---------|
| =cmacs-config-load-crispy=  | Whether to load init.c at startup      | =t=     |
| =cmacs-config-directory=    | Where to look for init.c first         | =~/.config/cmacs= |
