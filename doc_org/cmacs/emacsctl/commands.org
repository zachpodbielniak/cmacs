* Global flags

Accepted anywhere on the command line:

| Flag                | Meaning                                          |
|---------------------+--------------------------------------------------|
| =-c=, =--context=   | use a named context from the config file         |
| =--instance SEL=    | target instance: =<pid>=, =primary=, or =auto=   |
| =--host DEST=       | remote editor over ssh (=user@machine=)          |
| =-o=, =--output=    | =table= (default), =json=, =yaml=, =raw=         |
| =-w=, =--watch=     | stream changes where supported (=logs=)          |
| =--timeout SECS=    | RPC timeout (default 30; long evals may need more) |
| =--config PATH=     | config file (default =~/.config/cmacs/emacsctl.yaml=, or =$EMACSCTL_CONFIG=) |
| =-q=, =--quiet=     | suppress non-essential output                    |
| =--version=         | client version                                   |
| =-h=, =--help=      | contextual help (see below)                      |

Precedence: command-line flags > the selected context > config
=settings:= > built-in defaults.

* Getting help

Help is contextual and available everywhere (all generated through
GLib's option parser, so flag listings can never drift from the
parser):

#+begin_src sh
  emacsctl --help                   # global: commands, groups, options
  emacsctl get --help               # a group: all of get's subcommands
  emacsctl logs --help              # a command: its flags + globals
  emacsctl help get content-org     # `help WORDS…' == `WORDS… --help'
#+end_src

A bare group (=emacsctl get=) prints the same subcommand listing and
exits 2; an unknown flag exits 2 with a =--help= hint; a typo'd verb
gets a did-you-mean suggestion.

* Agents: =brigade spawn= / =brigade send= / =brigade log=

Hands work to a brigade agent and then goes on talking to it. The same verbs an
agent gets as MCP tools, so a shell script and a model drive the queue through
one code path.

#+begin_src bash
emacsctl brigade spawn "audit the config loader" reviewer
# -> 3f2a1c...

emacsctl brigade status 3f2a1c
emacsctl brigade result 3f2a1c
#+end_src

=send= continues the conversation rather than starting a new one. It works
whether the agent is still running — the message is delivered when its current
turn ends — or finished long ago, in which case it starts again on the same
provider session and remembers everything from before.

#+begin_src bash
emacsctl brigade send 3f2a1c "now check the error paths too"
emacsctl brigade inbox 3f2a1c          # queued but not yet delivered
emacsctl brigade drop 3f2a1c 0         # changed your mind; omit the index for all
emacsctl brigade close 3f2a1c          # done with it; releases the session
#+end_src

=log= prints the whole transaction log — every message, reply and tool call in
order. It works on any task, not only ones you started, which is what makes it
useful for looking at an agent that is misbehaving:

#+begin_src bash
emacsctl brigade log 3f2a1c
emacsctl brigade log 3f2a1c 2          # only from turn 2 onward
#+end_src

A task whose worker has no session concept (=shell=) refuses =send= rather than
re-running with the follow-up as though it were a first prompt.

* AI: =ai prompt= / =ai call= / =ai models= / =ai chat=

The ai verbs take provider, model, and system prompt as flags
(=-p/--provider=, =-m/--model=, =-s/--system=) instead of positional
slots.  =ai prompt= composes its text from positionals, stdin, and
=-f/--file= attachments (repeatable; each file is appended with a
=--- FILE: name ---= header so the model can tell sources apart):

#+begin_src sh
  emacsctl ai prompt 'why is the sky blue?'
  emacsctl ai prompt -p ollama -m llama3.2 'one-liner: rsync a dir'
  git diff | emacsctl ai prompt -s 'Review this diff for bugs'
  emacsctl ai prompt -f main.c -f util.c 'find the bug'

  emacsctl ai models                      # provider/model table, all
  emacsctl ai models -p claude            # one provider
  emacsctl ai models -p ollama -o json    # {"ollama": ["llama3.2", ...]}

  emacsctl ai chat -p claude -m claude-opus-5 'hello'
#+end_src

=ai call= is like =ai prompt= (same =-p/-m/-s/-f= flags, positionals,
stdin) but adds =-t/--tools=: with it, the model is given the built-in
agent tools (bash/read/write/edit/glob/grep/ls/web_fetch) and runs a
synchronous multi-turn loop, returning the final answer.

#+begin_src sh
  emacsctl ai call 'summarise this in one line: ...'   # no tools
  emacsctl ai call -t 'how many .c files are under src/, and why?'
#+end_src

*DANGER:* a tool-enabled call runs the loop on the target's main
thread; under =emacs --gowl= that is the Wayland compositor, so a long
loop freezes the desktop.  Keep =-t= loops short, and prefer =ai
prompt= (no tools) when driving a live =--gowl= session.

=ai generate-image= generates an image and inserts it into a buffer of
the target instance.  In an Org buffer it is attached to the current node
and previewed inline; elsewhere it is saved under =cmacs-ai-image-dir=.

#+BEGIN_EXAMPLE
  emacsctl ai generate-image -p gemini -a 16:9 'a brass telescope'
  emacsctl ai generate-image -m gemini-3-pro-image-preview \
      -r logo.png::style -r subject.jpg::subject \
      -b notes.org 'combine these into a poster'
#+END_EXAMPLE

=-r/--ref= is repeatable and each entry is =PATH= or =PATH::ROLE=; the
role tells the model what that reference is for, which is what makes
multi-image conditioning work.  =-b/--buffer= picks the target buffer.
Not every model accepts references -- =emacsctl eval
'(cmacs-ai-image-list-models)'= shows which do.

Like =ai call=, this blocks the target's main thread for its whole
duration, which for image generation is tens of seconds.

=ai models= renders a provider/model table; =-o json= / =-o yaml=
emit the provider→models map as structured data.  Without =-p= every
provider is queried (API providers over the network, CLI providers
from static tables) and unavailable ones report inline, so the call
never fails outright --- but it can take a while; =-p= keeps it
fast.  The model names that =ai models= prints are exactly what
=-m/--model= accepts.

The underlying typed methods are =Editor1.Ai= =Prompt= / =Call= /
=ListModels= / =OpenChat= / =GenerateImage=, with MCP parity via
=ai_prompt= / =ai_call= / =ai_list_models= / =ai_open_chat= /
=generate_image=.

* Second brain: =sb ingest= / =sb tree= / =sb find=

The =sb= group is the notes repository from a shell — the =emacsctl= face of =cmacs-secondbrain-ingest= (see the secondbrain manual). =second-brain=, =secondbrain= and =second_brain= are aliases.

#+begin_src sh
  emacsctl sb ingest https://youtu.be/dQw4w9WgXcQ            # captions -> summary -> note
  emacsctl sb ingest -p resources -c technical/linux notes.pdf
  emacsctl sb ingest -w -t "meeting,work" -T meeting call.mp3 # wait for the note
  emacsctl sb ingest --crawl --depth 2 --max-pages 30 https://docs.example.com/
  git log -5 | emacsctl sb ingest -f text --title "Recent commits" -p inbox
  emacsctl sb ingest --dry-run -o json article.epub          # the plan, no work
  emacsctl sb ingest -N -p inbox scan.pdf                    # no model at all

  emacsctl sb jobs                                            # the queue
  emacsctl sb status sbi-3
  emacsctl sb tree -p resources -c technical                  # sbi --list
  emacsctl sb tree -f -o raw | fzf                            # every note, pickable
  emacsctl sb find zfs snapshots                              # sbf
  emacsctl sb doctor                                          # what this host can read
#+end_src

=sb ingest= queues jobs and returns their statuses at once; the work — fetching, transcribing, the model — runs on the editor's main loop. =-w/--wait= polls =IngestStatus= from the client until every job is done and prints the final statuses (=--wait-timeout=, default 900 s). Polling from the client rather than blocking in the editor is deliberate: a =--gowl= editor's main thread is the desktop.

Placement: =-p/--para= (=inbox=, =projects=, =areas=, =resources=, =detect=) and =-c/--category= (a sub path), or =-d/--directory= for an exact root-relative directory. Without any, the editor's =cmacs-secondbrain-ingest-placement= decides — by default the model chooses from the real tree and falls back to the inbox when unsure.

Text: =-= as an input, =-i/--stdin=, or a pipe with no positionals reads stdin; =-f/--format= names it (=org=, =markdown=, =text=, =json=, =csv=, =html=) when the guess would be wrong. Relative file paths are resolved in the shell's working directory, not the editor's.

The model: =-T/--type= picks the summary template (=auto= lets the model pick), =--prompt= appends instructions, =--principle= adds a principles section, =-n/--no-summary= skips the summary but still places and tags, =-N/--no-ai= uses no model at all, =-P/--provider= and =-m/--model= override =claude-code= / =sonnet=. =-s/--sanitize= redacts with the default rules; =--sanitize-rules email,phone,bank-account= names rules.

Sites: =--crawl= turns a URL into a site directory with a =00_index.org= and one note per page; =--depth=, =--max-pages=, =--include= and =--exclude= (Emacs regexps) bound it; robots.txt is honoured. A =.zip= or =.tar= of saved pages is a site too. =--web gsurf= fetches through an offscreen WebKit view so JavaScript runs and logins apply.

Other flags: =-t/--tags=, =--title=, =--name= (file-name seed), =-a/--append= (add to an existing note instead of uniquifying), =-r/--recursive= (descend into directories), =--no-link=, =--keep-source= (copy the original into =.attachments/=), =--root DIR=, =-b/--branch NAME= (=ROOT/trees/NAME=, for a notes worktree).

Migration and the drop folder:

#+begin_src sh
  emacsctl sb migrate                        # the plan: every .md, its target, unresolved links
  emacsctl sb migrate 02_areas/work/people   # one directory
  emacsctl sb migrate --apply --remove trash # do it; originals to the trash
  emacsctl sb watch true                     # ingest whatever lands in ~/Documents/inbox
#+end_src

=sb migrate= plans by default and writes nothing; =--apply= converts each Markdown note into an Org node in place (=--include-archives=, =--ai=, =--remove trash=). =sb watch= toggles the editor's =file-notify= watcher on the drop folder; the podomation rule (=cmacs-secondbrain-ingest-podomation-install=) is the other way to feed it.

The underlying typed methods are =Editor1.SecondBrain= =Ingest= / =IngestStatus= / =IngestList= / =IngestCancel= / =Tree= / =Find= / =Doctor= / =Migrate= / =Watch=, with MCP parity via =secondbrain_ingest= / =secondbrain_ingest_status= / =secondbrain_ingest_cancel= / =secondbrain_tree= / =secondbrain_find= / =secondbrain_doctor= / =secondbrain_migrate=.

* Org buffers: =text insert-org=

Org-aware insertion: target a headline, choose the spot inside the
entry, wrap the text, or file it as a new child entry.  The text
comes from the argument or stdin; =-e= expands escapes like
=echo -e=.

#+begin_src sh
  # Code block under a nested section (slash outline path):
  emacsctl text insert-org -b notes.org -H 'Projects/cmacs' \
    --src elisp '(message "hi")'

  # Journal: create the path if missing, file a TODO child entry
  # with tags and an inactive timestamp, body from a pipeline:
  git log -1 --oneline | emacsctl text insert-org -b notes.org \
    -H 'Log/2026' --create --child "$(date +%F)" \
    --todo TODO --tags log:daily --timestamp

  # Quote at the top of an entry's body:
  emacsctl text insert-org -b notes.org -H Inbox -p top \
    --quote 'wise words'
#+end_src

| Flag                  | Meaning                                       |
|-----------------------+-----------------------------------------------|
| =-H=, =--heading PATH= | exact title (any depth), or slash path like =Projects/cmacs/Log= |
| =-C=, =--create=      | create missing path components                |
| =-p=, =--position POS= | =top=, =bottom= (default: end of the entry's own body, before child headings), =subtree-end=, =point= |
| =-q=, =--quote=       | wrap in =#+begin_quote=                       |
| =-s=, =--src LANG=    | wrap in =#+begin_src LANG=                    |
| =--example= / =--verse= / =--center= | the other standard blocks      |
| =--block NAME=        | any custom =#+begin_NAME= block               |
| =--drawer NAME=       | wrap in a =:NAME:= drawer (e.g. LOGBOOK)      |
| =-c=, =--child TITLE= | new child headline; the text becomes its body |
| =--todo KEYWORD=      | TODO keyword for the child                    |
| =--tags TAGS=         | colon-separated tags for the child            |
| =-t=, =--timestamp=   | prepend an inactive org timestamp             |
| =-e=, =--escapes=     | expand backslash escapes                      |

Wrapping composes inside-out: block, then drawer, then the child
headline.  The underlying typed method is =Editor1.Edit.InsertOrg=
(options travel as an extensible string dict), with MCP parity via
the =insert_org= tool.

* Org buffers: =get content-org=

=get content BUFFER= prints a buffer verbatim.  For org-mode buffers,
=get content-org= parses the document *in the editor* (org's own
parser — =org-map-entries=, planning info, property drawers, the
agenda match syntax) and returns a structured tree, so =-o yaml= /
=-o json= give you real data instead of a text blob:

#+begin_src sh
  emacsctl get content-org notes.org                # outline table
  emacsctl get content-org notes.org -o yaml        # nested tree
  emacsctl get content-org notes.org --match "/TODO" -o json
  emacsctl get content-org notes.org --match "work+urgent" --depth 2
  emacsctl get content-org notes.org --no-body --no-properties
#+end_src

| Flag                | Meaning                                        |
|---------------------+------------------------------------------------|
| =--match EXPR=      | org agenda match string: tags/todo/property    |
|                     | queries like =work+urgent/TODO= or =/DONE=     |
| =--depth N=         | limit headline depth                           |
| =--no-body=         | structure only, drop entry body text           |
| =--no-properties=   | drop property drawers                          |

Each headline carries =title=, =level=, =todo=, =priority=, =tags=,
=scheduled= / =deadline= / =closed=, =properties=, =body=, and
=children=; the document carries =buffer=, =file=, and the =#+TITLE= /
=#+AUTHOR= / =#+DATE= / =#+FILETAGS= keywords.  Keys are omitted when
empty, so the YAML stays tight.  The default table output renders an
indented outline (level, todo, title, tags, scheduled).

#+begin_src sh
  # All TODO deadlines this file knows about, as JSON:
  emacsctl get content-org work.org --match "/TODO" --no-body \
    -o json | jq -r '.. | .deadline? // empty'
#+end_src

* Output formats

#+begin_src sh
  emacsctl get buffers                # aligned table (human)
  emacsctl get buffers -o json        # pretty JSON array
  emacsctl get buffers -o yaml        # YAML sequence
  emacsctl get buffers -o raw         # one name per line, stable
  emacsctl eval '(+ 1 2)' -o raw      # "3" — byte-exact, no newline
#+end_src

- *table* — aligned columns with an upper-case header for lists;
  =key: value= lines for documents; scalars verbatim.
- *json* — the canonical data, pretty-printed (indent 2).
- *yaml* — same data through yaml-glib.
- *raw* — for scripts: scalars byte-exact, lists one-per-line,
  documents as compact one-line JSON.

* Examples

#+begin_src sh
  # Save every modified buffer whose name ends in .org:
  emacsctl get buffers -o raw \
    | grep '\.org$' \
    | while read -r b; do emacsctl buffer save "$b"; done

  # Jump the compositor to whatever workspace firefox is on:
  emacsctl compositor find firefox -o json | jq .

  # Editor health one-liner for a status bar:
  emacsctl describe instance -o json | jq -r .uptime

  # Hot-patch a C primitive, then verify:
  emacsctl c patch some-defun my_replacement_fn
  emacsctl c patch-log
#+end_src
