#+TITLE: Gowl Wayland Compositor
#+STARTUP: showall
#+OPTIONS: toc:2 num:t

* Overview

Gowl is a wlroots-based Wayland compositor embedded in CMacs.  When
launched with =--gowl=, Emacs becomes a tiling window manager: the
editor renders as a Wayland client inside its own compositor, and other
Wayland apps (terminals, browsers, viewers) tile alongside or embed
directly inside Emacs windows.

The integration provides 47+ C primitives (DEFUNs) for full compositor
control from Elisp: spawning clients, managing tags, switching layouts,
querying monitors, and embedding client windows inside Emacs buffers.

* Starting the Compositor

#+begin_example
src/emacs --gowl              # launch Emacs as a Wayland WM
#+end_example

Inside Emacs, the compositor is controlled via =cmacs-gowl-mode=:

#+begin_example
M-x cmacs-gowl-mode           ;; toggle (usually auto-enabled by --gowl)
#+end_example

* Monitor Management

Gowl provides full control over connected monitors (outputs): listing,
mode changes, scale adjustments, transforms, and enable/disable.  All
operations work on both physical monitors (DRM backend) and nested
Wayland outputs.

** Listing Monitors

=M-x cmacs-gowl-list-monitors= displays a table of all outputs:

#+begin_example
Name    Mode          Position  Scale  Status   Transform
WL-1    1280x720@60   0,0      1.0    enabled  normal
DP-1    2560x1440@144  1280,0  1.0    enabled  normal
#+end_example

From the shell:

#+begin_example
bacon> cmacsgi monitor list
WL-1
DP-1

bacon> cmacsgi monitor info WL-1
name=WL-1
mode=1280x720@60
position=0,0
scale=1.000000
enabled=t
transform=0
#+end_example

** Changing Resolution

=M-x cmacs-gowl-set-resolution= prompts with the monitor's advertised
modes.  For outputs with no advertised modes (common for nested Wayland
sessions), specify a custom mode directly.

#+begin_src emacs-lisp
;; From Elisp:
(gowl-set-monitor-mode 1920 1080 0 (gowl-find-monitor "WL-1"))
#+end_src

#+begin_example
;; From the shell:
bacon> cmacsgi monitor set-mode WL-1 1920x1080
bacon> cmacsgi monitor set-mode DP-1 2560x1440@144000
#+end_example

The refresh rate is in millihertz (60000 = 60 Hz).  Use 0 to match any
refresh rate, or omit the =@RATE= suffix.

** Scaling

Scale controls the output DPI.  A scale of 2.0 doubles the pixel
density, halving the logical resolution.

#+begin_src emacs-lisp
;; HiDPI (2x):
(gowl-set-monitor-scale 2.0 (gowl-find-monitor "WL-1"))

;; Lower density for more screen real-estate:
(gowl-set-monitor-scale 0.8 (gowl-find-monitor "WL-1"))
#+end_src

#+begin_example
bacon> cmacsgi monitor scale WL-1 2.0
bacon> cmacsgi monitor scale WL-1 0.8
bacon> cmacsgi monitor scale WL-1 1.0    ;; reset to default
#+end_example

At scale 0.8 on a 1280x720 output the logical area grows to 1600x900;
at scale 2.0 it shrinks to 640x360.  Clients automatically resize to
fill the new logical area.

** Transform (Rotation/Flip)

Transform values follow the Wayland =wl_output_transform= enum:

| Value | Name         | Effect                          |
|-------+--------------+---------------------------------|
|     0 | normal       | No rotation                     |
|     1 | 90           | Rotate 90° clockwise            |
|     2 | 180          | Rotate 180°                     |
|     3 | 270          | Rotate 270° clockwise           |
|     4 | flipped      | Horizontal flip                 |
|     5 | flipped-90   | Flip + rotate 90°               |
|     6 | flipped-180  | Flip + rotate 180°              |
|     7 | flipped-270  | Flip + rotate 270°              |

#+begin_example
bacon> cmacsgi monitor transform WL-1 1     ;; rotate 90°
bacon> cmacsgi monitor transform WL-1 0     ;; back to normal
#+end_example

** Enable / Disable

#+begin_example
bacon> cmacsgi monitor disable DP-2
bacon> cmacsgi monitor enable DP-2
#+end_example

Or interactively: =M-x cmacs-gowl-toggle-monitor=.

** How It Works

When a mode, scale, or transform change is committed via
=wlr_output_commit_state()=, gowl updates the monitor geometry by
querying =wlr_output_layout_get_box()=, which returns the correct
logical dimensions accounting for scale and transform.  This matches
the approach used by dwl.

The compositor then calls =gowl_compositor_arrange()=, which re-tiles
all clients on the affected monitor.  Fullscreen clients (including
the Emacs frame in standalone =--gowl= mode) are resized to fill the
full monitor area.  Normal tiling clients are re-laid-out by the
active layout function (tile, monocle, etc.).

On the Wayland backend (nested compositors), =on_layout_change()=
typically fires synchronously during the output commit.  As a safety
net, each setter also queries the layout box and calls =arrange()=
directly, ensuring correct behavior even if the asynchronous path is
delayed.

* Client Embedding

Wayland clients can render /inside/ Emacs buffer windows.  The client's
scene node is reparented into Emacs's compositor scene tree and
positioned over the window body area.  The compositor renders the client
directly---no pixel copying, no GPU readback.  Input is routed by the
compositor's focus-follows-mouse.

#+begin_example
┌─ Emacs frame (tiled, layer 2) ─────────────────────┐
│ ┌─ window: code.el ────┐┌─ window: *gowl: foot* ──┐│
│ │ (defun hello ()      ││┌─────────────────────────┐││
│ │   (message "hi"))    │││  foot terminal          │││
│ │                      │││  (embedded client)      │││
│ │                      ││└─────────────────────────┘││
│ │-:-- code.el     L3  ││-:-- *gowl: foot*    L1  ││
│ └──────────────────────┘└──────────────────────────┘│
│ M-x                                                 │
└─────────────────────────────────────────────────────┘
#+end_example

** Embedding Commands

| Command             | Description                                        |
|---------------------+----------------------------------------------------|
| =gowl-embed=       | Spawn a command and embed it in the current window |
| =gowl-embed-client= | Embed an existing gowl client in current window   |
| =gowl-unembed=     | Release an embedded client back to normal tiling   |

** How It Works

1. =gowl-embed= spawns a Wayland client and pre-registers its PID so
   the compositor floats and hides it on map.
2. A 100ms timer polls =gowl-list-clients= to match the PID.
3. Once matched, the client is reparented into Emacs's scene tree
   (=gowl-embed-into=) and positioned over the window body
   (=gowl-position-embedded=).
4. =window-configuration-change-hook= keeps the overlay in sync when
   windows resize, split, or switch buffers.
5. A 1-second health timer detects client exit and cleans up the buffer.

** Lifecycle

- *Client exits*: health timer detects it gone from =gowl-list-clients=
  (compared by PID), kills the placeholder buffer.
- *Buffer killed*: =kill-buffer-hook= closes the Wayland client via
  =gowl-close-client=.
- *Window hidden*: overlay is hidden via =gowl-set-client-visible=.
  Switching back to the buffer re-shows it.

** Keyboard Focus (ESC Escape-Hatch)

Embedded clients receive keyboard input directly from the compositor.
An ESC-based escape hatch lets you switch between the embedded client
and Emacs:

- *ESC* (single press): returns keyboard focus to Emacs.  Subsequent
  keys are processed by Emacs (e.g. Evil normal-mode commands).
- *ESC ESC* (double press): sends a single ESC to the embedded client
  (useful for apps that use ESC, like vim or bash with =set -o vi=).
- *i / a* (in Evil normal state): gives keyboard focus back to the
  embedded client.  Also works with =I=, =A=, =o=, =O=, and =RET=.
- *Click* on the embedded area: also returns keyboard focus to the
  embedded client.

The escape hatch uses a 200ms timer to distinguish single from double
ESC.  Pressing ESC followed by another key within the timeout sends
the second key to Emacs.

The underlying primitive =gowl-embed-focus= can be called from Elisp
to programmatically give keyboard focus to any embedded client.

* Compositor Signals

Gowl emits GObject signals when compositor state changes.  These
signals are exposed to Elisp via =gobject-connect= on the compositor
object returned by =gowl-compositor=.

| Signal            | Arguments                     | Description                          |
|-------------------+-------------------------------+--------------------------------------|
| =client-added=   | =client=                      | A new client has been mapped         |
| =client-removed= | =client=                      | A client has been unmapped/destroyed |
| =focus-changed=  | =client= (or =nil=)          | Keyboard focus has moved             |

#+begin_src emacs-lisp
;; Low-level signal connection:
(gobject-connect (gowl-compositor) "focus-changed"
  (lambda (client)
    (message "Focus: %s" (gowl-client-info client))))
#+end_src

* Elisp Convenience Functions

The Elisp layer provides convenience wrappers around compositor
signals, making it easy to react to common events without manually
calling =gobject-connect=.

| Function                         | Description                                 |
|----------------------------------+---------------------------------------------|
| =cmacs-gowl-on-focus-changed=   | Register a callback for focus changes       |
| =cmacs-gowl-on-client-added=    | Register a callback for new clients         |
| =cmacs-gowl-on-client-removed=  | Register a callback for client removal      |

#+begin_src emacs-lisp
(cmacs-gowl-on-focus-changed
  (lambda (client)
    (when client
      (message "Focused: %s" (alist-get 'title (gowl-client-info client))))))

(cmacs-gowl-on-client-added
  (lambda (client)
    (message "New client: %s" (alist-get 'app-id (gowl-client-info client)))))
#+end_src

* Modes

** cmacs-gowl-spatial-mode

A minor mode that replaces the default tag-based workspace switching
with spatial directional navigation.  Move focus between clients
using directional keys (left, right, up, down) instead of tag
numbers.  Useful for multi-monitor setups where spatial reasoning is
more natural than numbered workspaces.

#+begin_example
M-x cmacs-gowl-spatial-mode
#+end_example

** cmacs-gowl-dashboard

A dashboard buffer that displays a live overview of the compositor:
connected monitors, active clients, tags, layout, and resource usage.
Updates in real time via compositor signals.

#+begin_example
M-x cmacs-gowl-dashboard
#+end_example
