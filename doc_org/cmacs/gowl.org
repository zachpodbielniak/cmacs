#+TITLE: Gowl Wayland Compositor
#+STARTUP: showall
#+OPTIONS: toc:2 num:t

* Overview

Gowl is a wlroots-based Wayland compositor embedded in CMacs.  When
launched with =--gowl=, Emacs becomes a tiling window manager: the
editor renders as a Wayland client inside its own compositor, and other
Wayland apps (terminals, browsers, viewers) tile alongside or embed
directly inside Emacs windows.

The integration provides 49+ C primitives (DEFUNs) for full compositor
control from Elisp: spawning clients, managing tags, switching layouts,
querying monitors, and embedding client windows inside Emacs buffers.

* Starting the Compositor

#+begin_example
src/emacs --gowl              # launch Emacs as a Wayland WM
#+end_example

Inside Emacs, the compositor is controlled via =cmacs-gowl-mode=:

#+begin_example
M-x cmacs-gowl-mode           ;; toggle (usually auto-enabled by --gowl)
#+end_example

** Desktop launchers and =emacsclient --gowl=

=make install= (and the container build) install two application launchers
next to the usual *Emacs* / *Emacs (Client)* and *Emacs Libregnum* ones:

- *Emacs Gowl* — runs =emacs --gowl= (=etc/emacs-gowl.desktop=).
- *Emacs Gowl (Client)* — runs =emacsclient --gowl=
  (=etc/emacsclient-gowl.desktop=), with a *New Instance* action for
  =emacs --gowl=.

Both set =StartupWMClass=cmacs=.  Neither declares a =MimeType=: a
compositor session is deliberately *not* registered as the handler for
text files, so double-clicking a source file still opens the plain
*Emacs* launchers.

Clicked from inside a running Wayland session (GNOME, or another gowl),
both launchers give an *embedded session*: wlroots comes up on its nested
backend, so the compositor is a window inside the outer one rather than a
seat session.  (For a real seat session use a Wayland session entry — see
the GDM recipe below.)

=emacsclient= accepts =--gowl= (shown in both =emacsclient --help= and
=emacs --help=).  There is one compositor per process, so it never starts
a *second* one: it sends a =-gowl= request and the server brings up (or
just returns) the embedded session in its own process via
=cmacs-gowl-attach=, instead of opening a frame on the launcher's
terminal.  Add =-c= if you also want a new Emacs frame
(=emacsclient --gowl -c=).  When no server is reachable, =--gowl= defaults
=--alternate-editor= to =emacs --gowl=, so a bare click always ends up in
a gowl session.  Unlike the other clients, =emacsclient --gowl= needs no
file argument — the request is complete on its own.

=M-x cmacs-gowl-attach= does the same thing from inside a running Emacs:
it enables =cmacs-gowl-mode= on demand (a no-op when gowl is already
running, whichever way it started) and returns the frame hosting the
session.  It signals a clean error when cmacs was built without
=--with-cmacs-gowl=, or when there is no display to nest inside — a
headless daemon cannot host a compositor, so start the Emacs that should
own it inside a graphical session.

** Running as a GDM login session (in-repo debug build)

To test compositor changes in a *real seat session* (not nested) without
rebuilding an OS image — handy on an immutable/bootc host — add a custom
Wayland session that launches the freshly-built in-repo binary, then pick
*CMacs (Debug)* from GDM's gear menu on the login screen.

1. A standup script that exports the same module/typelib environment as
   =just gowl= and *forces the seat backend*.  On an ostree/bootc host put
   it in =/usr/local/bin= (=→ /var/usrlocal/bin=, which is writable and
   *persists* across reboots and image upgrades, and is on =PATH=):

   #+begin_src bash
   # /usr/local/bin/cmacs-debug   (chmod 0755; restorecon -F on SELinux)
   #!/bin/bash
   REPO=/var/home/zach/source/projects/cmacs   # <-- this checkout
   # A real seat session has no parent compositor, but the systemd --user
   # env can leak a stale WAYLAND_DISPLAY/DISPLAY (+ a leftover wayland-0
   # socket).  cmacs treats a non-empty WAYLAND_DISPLAY as "nested" and
   # forces WLR_BACKENDS=wayland, which then fails to connect.  Force the
   # seat backend: cmacs only does setenv(WLR_BACKENDS,...,0) (no-overwrite),
   # so our value wins and wlroots autocreate honours WLR_BACKENDS over the
   # WAYLAND_DISPLAY/GDK heuristics.
   unset WAYLAND_DISPLAY WAYLAND_SOCKET DISPLAY
   export WLR_BACKENDS=libinput,drm
   cd "$REPO" || exit 1
   export CMACS_MODULE_DIR="$REPO/cmacs/bacon/modules"
   export CMACS_GSURF_MODULE_DIR="$REPO/cmacs/gsurf/modules"
   export CMACS_GOWL_MODULE_DIR="$REPO/deps/gowl/build/release/modules"
   export CMACS_SCREENSAVER_MODULE_DIR="$REPO/deps/screensavers/build/release"
   export CMACS_SCREENSAVER_RENDER_BIN="$REPO/src/cmacs-screensaver-render"
   export GI_TYPELIB_PATH="$REPO/deps/libregnum/build/release/gir:$REPO/deps/libregnum/deps/graylib/build/gir${GI_TYPELIB_PATH:+:$GI_TYPELIB_PATH}"
   exec "$REPO/src/emacs" --gowl "$@"
   #+end_src

2. A Wayland session entry.  GDM hands the =Exec= value to
   =gdm-wayland-session=, which accepts *one* positional argument — so
   =Exec= must be a *single bare token* (no =bash -lc "..."=; the quotes
   are split and the session dies with "gdm-wayland-session takes one
   argument" before cmacs ever launches).  Use
   =/usr/local/share/wayland-sessions= (also =→ /var/usrlocal=, persistent);
   =/usr/share/wayland-sessions= also works but is wiped on the next reboot
   if it was only made writable via =bootc usr-overlay=.

   #+begin_src conf
   # /usr/local/share/wayland-sessions/cmacs-debug.desktop
   [Desktop Entry]
   Name=CMacs (Debug)
   Comment=CMacs in-repo dev build (cmacs --gowl)
   Exec=/usr/local/bin/cmacs-debug
   Type=Application
   DesktopNames=CMacs-Debug:wlroots
   #+end_src

   =DesktopNames= ends in =:wlroots= so =XDG_CURRENT_DESKTOP= becomes
   =CMacs-Debug:wlroots=.  The =wlroots= element matters: it is what the
   =xdg-desktop-portal-wlr= backend matches on (its =UseIn= line lists
   =wlroots;sway;Wayfire;river;phosh;Hyprland=), so screen-sharing apps
   (Zoom, OBS, browsers) get the wlroots =ScreenCast= portal instead of
   the GNOME backend, which fails under gowl because it requires Mutter.
   Without =:wlroots= the portal frontend finds no =ScreenCast= backend
   and the share picker silently does nothing.  The leading =CMacs-Debug=
   keeps the session's own identity for anything that keys on it.

   *Monitor vs window capture.*  Sharing a whole monitor works whenever
   gowl is built against wlroots 0.19 or 0.20.  Sharing a *single window*
   (Zoom's "use system window capture", OBS window sources) additionally
   needs gowl built against *wlroots 0.20+* --- it requires the
   =ext-image-copy-capture= + =ext-foreign-toplevel= protocols that 0.19
   lacks.  gowl auto-builds against the newest wlroots present; on a host
   with only 0.19 (e.g. Fedora 42/43) window capture is unavailable and
   the app's window list comes up empty (share a monitor instead).  The
   capability is reported by =gowl_capture_provider_get_capabilities= and
   surfaced to portals via the wlroots protocol globals.

3. Log out → pick *CMacs (Debug)*.  Rebuild (=rm -f src/temacs && make=)
   and log back in to test new changes — no OS image rebuild needed.  For
   *nested* testing inside an existing session use =just gowl= instead
   (it keeps =WAYLAND_DISPLAY= so wlroots uses the nested backend).

Each of these bounced us back to GDM at least once; diagnose from the
journal: =journalctl -b | grep -iE 'gdm-wayland-session|cmacs|gowl|wlr|backend'=.

** Nested mode: capturing the host compositor's shortcuts (Super)

When gowl runs *nested* inside another Wayland compositor (=just gowl=,
or =./src/emacs --gowl= from inside a GNOME session), the host
compositor sees the key events first.  GNOME's Mutter claims the whole
=Super= key for the Activities overview (=org.gnome.mutter overlay-key=),
plus =Alt-Tab=, =Super-L= and the rest of its bindings, so those never
reach gowl and every =Super=-prefixed gowl keybind is dead.

cmacs handles this the same way a VM viewer or remote-desktop client
"grabs" the keyboard: it asks the host for
=zwp_keyboard_shortcuts_inhibit_unstable_v1= on the nested output
surface.  While that surface holds the host's keyboard focus, the host
stops running its own bindings and forwards the raw keys through;
focus another window and the host's shortcuts come straight back.  No
configuration is needed — cmacs requests it automatically at startup
whenever it detects a nested Wayland output, on both the =--gowl= early
path and =M-x gowl-start=.

Mutter has honoured the inhibitor for the overlay key since GNOME 3.36,
so a current GNOME needs nothing extra.  If =Super= still opens the
overview, turn on debug logging (=G_MESSAGES_DEBUG=all=) and look for
the =gowl:= lines:

#+begin_example
gowl: requested shortcut inhibition on 1 nested output surface(s)
gowl: parent-compositor shortcut inhibition ACTIVE
#+end_example

The =ACTIVE= line comes from the host and is the only proof the grab
really took.  Common failures each log a warning of their own: a host
that does not implement the protocol at all (older wlroots compositors,
some X11-hosted setups), or one that exposes no =wl_seat=.  Nothing is
logged and nothing is requested when gowl owns a real seat (DRM
backend) — there is no host to inhibit.

As a last-resort fallback on a host that cannot be inhibited, clear the
host's own binding instead, e.g. =gsettings set org.gnome.mutter
overlay-key ""=, or bind gowl's modifier to something the host does not
claim.

** Running X11 applications (XWayland)

gowl runs its own rootless *XWayland* server, so unmodified X11
applications — including non-Wayland GUI toolkits and raylib/GLFW apps
such as =gst --lrg=2d= — run inside the session.  When the compositor
starts it sets =DISPLAY= to gowl's own X server (e.g. =:1=), separate
from any parent session's X server.

=gowl-spawn= (and the launch commands that use it) point spawned X11
clients at gowl's XWayland by setting =DISPLAY= to
=gowl_compositor_get_xwayland_display=; Wayland-native toolkit hints are
also set so GTK/Qt/SDL/Electron prefer Wayland.  X11 windows are managed
like native ones (tiled, tagged, focusable, and closable with
=Super+Shift+c=).

X11 clients differ from Wayland ones in one way that matters
throughout the compositor: they carry a =wlr_xwayland_surface= and a
=NULL= =xdg_toplevel=.  Anything that talks to a client's shell
surface must branch on =client_is_x11()= (or go through a wrapper that
does, such as =gowl_client_close()=) — sending an XDG request to an
X11 client derefs =NULL= inside wlroots, and because the compositor
*is* the =emacs --gowl= session, that crash takes the whole desktop
and every application in it.

X11 /override-redirect/ surfaces — popup menus, combo dropdowns,
tooltips, and app confirmation dialogs (e.g. Zoom's "End meeting /
Leave") — are handled on a dedicated /unmanaged/ path: they float at
their own position with no border, take keyboard focus if they request
it, and hold an exclusive grab so the compositor will not steal focus
back or deactivate their parent window while they are up.  Without this a
menu would lose its grab the instant focus moved and dismiss itself after
a fraction of a second.  Set =GOWL_DEBUG_XWAYLAND=1= in the session
environment to log each X11 surface as it maps (override-redirect vs
managed, with class/title) — useful when diagnosing a misbehaving X11
dialog.

This requires the =Xwayland= binary (Fedora: =xorg-x11-server-Xwayland=)
and a gowl built with =BUILD_XWAYLAND=1= (the default).  If neither is
present, =DISPLAY= is left unset and only Wayland-native clients run.

* Input Capture / KVM (deskflow)

Software-KVM tools such as [[https://deskflow.org][deskflow]] (and
input-leap / Synergy) share one keyboard and mouse across several machines
by moving the pointer off a screen edge.  On Wayland this needs the
freedesktop *InputCapture* portal (to capture local input when sharing
*out*) and the *RemoteDesktop* portal (to inject input when sharing *in*).
Only GNOME's Mutter-backed portal implements InputCapture for the wlroots
world, which is why deskflow works under GNOME but logs =CreateSession
failed= under a plain wlroots compositor.

gowl implements both portals itself, so deskflow works under =cmacs --gowl=
just as it does under GNOME — for both the server (capture) and client
(inject) roles.  The implementation is a gowl subsystem; see the *Input
Capture & Injection* chapter in gowl's own =docs/input-capture.org= for the
architecture.  In short: gowl core carries a D-Bus-free capture state
machine driven over a private Wayland protocol, and a standalone
=xdg-desktop-portal-gowl= binary (built when =libeis= is present) owns the
=org.freedesktop.impl.portal.desktop.gowl= D-Bus name and runs the EIS
server deskflow connects to.

*Enabling it.*  =make install= installs the portal binary, its =.portal=
registration, a =portals.conf= that routes InputCapture/RemoteDesktop to
gowl (ScreenCast still goes to =xdg-desktop-portal-wlr=), and a D-Bus
=.service=.  The =cmacs --gowl= session's =XDG_CURRENT_DESKTOP= must contain
=gowl=; =install-wm= sets =DesktopNames=CMacs:gowl= for this reason.  The
portal binary is launched at session start (and is D-Bus-activatable as a
fallback).  Install =libeis-devel= (Fedora) before building.

*Using it.*  Configure deskflow as usual (server on the machine whose
keyboard/mouse you share, clients on the others).  Under =cmacs --gowl= the
server's "ei screen for wayland" path now succeeds: move the pointer across
the configured screen edge and input is captured and forwarded to the
remote.

*Security.*  Input capture sees every keystroke and injection can drive any
app; access is gated by the =xdg-desktop-portal= permission model.  The
private Wayland protocol trusts only its single client (the portal binary,
which the compositor launches) and is not a public interface.

*Troubleshooting.*  If deskflow still logs =CreateSession failed=, the
backend is not being routed: confirm =gowl= is in =XDG_CURRENT_DESKTOP=,
the =gowl.portal= file is installed, and =libeis= was present at build time.
Run =xdg-desktop-portal= with =G_MESSAGES_DEBUG=all= to see which backend it
selects.  If instead the pointer reaches the edge but never crosses (deskflow
loops activating and releasing the capture), check the deskflow side: its own
screen layout must have a neighbour on that edge.  Running =deskflow-core
server= standalone does *not* translate the deskflow GUI's screen grid into
links, so either launch deskflow via its GUI or set =[server]
externalConfig=true= in its config; deskflow's debug log (=[log] level=7=)
shows "no neighbor on <side>" when the link is missing.  (The deeper gowl-side
cause of that loop — a missing EIS device region — is fixed; see the
*Troubleshooting* section of gowl's =docs/input-capture.org=.)  If the cursor
crosses fine but typing on the remote spams =failed to open x11 default
display=, deskflow (a Flatpak) is denied X11: it still uses an X11 display to
translate keycodes even on Wayland, and its default =fallback-x11= permission
withholds X11 while Wayland is present.  gowl runs XWayland (=DISPLAY=:0=), so
just grant access: =flatpak override --user --socket=x11 org.deskflow.deskflow=,
then restart deskflow.  This is a deskflow/Flatpak limitation, not a gowl bug.

* Input Recording (teach-a-task)

The observing counterpart to =send_keys= and the =gowl_send_*= tools:
a bounded recorder that captures real key and pointer events, so a
demonstration you perform on the desktop can be turned into a reusable
procedure.  The mechanism is a gowl subsystem, =GowlInputRecorder=;
the full reference — including exactly where its secret suppression
stops — is gowl's own =docs/input-recording.org=.

*Consent.*  Recording is off until =input-recording: true= is in the
gowl config.  That key is deliberately *not* the switch that allows
input injection: an agent allowed to click on your behalf must not
thereby be allowed to watch you type.  Setting it back to =false= and
reloading stops a recording that is already running.

*While it runs* the whole output layout is framed in saturated red,
above every window and above the lock layer.  It stops itself after
=max_seconds= (default 120, maximum 3600).

*Stopping one you did not start.*  =Super+Shift+Escape= from the
keyboard, or =M-x gowl-stop-recording= with no argument.  Neither
needs the recording's token, which is the point: "ask the agent to
stop" is not a way out of being recorded.

** Elisp

| Command                    | Description                                            |
|----------------------------+--------------------------------------------------------|
| =gowl-start-recording=     | Start; returns JSON with the token, limits and counters |
| =gowl-drain-recording=     | Take what is buffered, keep recording (needs the token) |
| =gowl-stop-recording=      | Stop; with no token, stop whatever is running           |
| =gowl-recording-status=    | State and counters as JSON, consuming nothing           |
| =gowl-recording-active-p=  | =t= while a recording runs                              |

#+begin_src elisp
(let* ((status (json-parse-string (gowl-start-recording 60 2048)))
       (token  (gethash "token" status)))
  ;; ... demonstrate the task ...
  (gowl-stop-recording token))
#+end_src

** MCP

The same four, as =gowl_start_recording=, =gowl_drain_recording=,
=gowl_stop_recording= and =gowl_recording_status=.  There is no push
notification when the state changes; instead every payload carries
=active= and =stop_reason=, so a consumer that is already draining
learns on its next call that the recording ended and why.

** What it can and cannot keep out of a trace

Capture is suppressed while the session is locked, and while the
focused window's app-id or title matches a deny list that ships with
the common credential prompts (pinentry, polkit, gcr-prompter,
KeePassXC, Bitwarden, ...) and with title patterns such as
=*password*= and =*sign in*=.  Add your own with
=input-recording-deny-apps=; they are added to that list, never
substituted for it.

*gowl cannot see a password field.*  There is no Wayland equivalent of
GNOME Shell's "the key-focus actor is a password entry" — a client's
widget tree is private to the client, and a compositor knows only a
surface, an app-id and a title.  A password typed into a form inside
an ordinary window whose title the deny list does not name *is
recorded*.  Treat a trace as credential material until you have read
it.

Withheld events are counted and explained rather than silently
skipped: =suppressed=, =suppressed_total= and =suppress_reasons= are in
every payload, alongside =dropped= for the ring's own overflow.

* Tags and Workspaces

gowl uses the dwm/dwl *tag* model: there are nine tags (1--9), each a
bit in a per-monitor bitmask.  Viewing a tag shows the clients tagged
with it and hides the rest; a client can carry one or several tags.
Tags behave like workspaces.  Emacs's own frame is an ordinary tiled
client and lives on tag 1 — so switching to an empty tag hides Emacs
(classic dwm behaviour), and =Super+1= brings it back.

This complements [[*Client Embedding][embedding]]: =gowl-embed= runs an
app /inside/ an Emacs window (always visible on tag 1), whereas the
launch-into-tag commands run an app as an independent client in another
workspace.

** Switching from M-x

You don't need the keyboard shortcuts — everything is available as a
command:

- =M-x cmacs-gowl-view-tag= — switch the focused monitor to a tag by
  number.  This performs a full view: it shows/hides clients, re-tiles,
  and moves focus (just like =Super+N=).
- =M-x cmacs-gowl-switch-tag= — a friendlier picker that lists the nine
  tags each annotated with what's open on them (e.g. =Tag 2 — Firefox,
  gimp= or =Tag 3 — (empty)=); pick one to switch to it.
- =M-x cmacs-gowl-switch-to-app= — a *window picker*: lists every open
  window across all tags and monitors (title, app-id, and its tag).
  Selecting one reveals that window's tag on its monitor and focuses
  it — the way to reach an app that is open in another tag/monitor
  without hunting for it.  Embedded clients are excluded (use =C-x b=).

** Multi-monitor

Tags are *per-monitor*: every output has its own independent tag set,
so each tag can live on its own monitor.  On mode start (when
=cmacs-gowl-monitor-tags-on-launch= is non-nil, the default) each
monitor is given its own initial tag — the main (first) monitor views
tag 1, the second views tag 2, and so on, up to nine monitors.  Re-run
=M-x cmacs-gowl-assign-monitor-tags= after hotplugging a monitor.

The tag-action keybinds act on the *focused* monitor: focus a monitor
with =Super+,= / =Super+.=, then =Super+N= switches that monitor's
tags, =Super+Ctrl+Shift+,= / =.= moves the focused client to the previous /
next monitor.  Each monitor's bar shows its own tag state.

Launching into a tag follows the tag to its monitor:
=cmacs-gowl-spawn-in-tag= (and the launch commands below) find the
monitor currently showing the target tag and place the new client
there, so launching on tag 2 lands on the monitor whose workspace is
tag 2 — never hidden on the wrong output.

:END:

=M-x cmacs-gowl-describe-keybinds= (=Super+/=) lists every active
compositor keybind and what it does.

It reads the *live* table out of the running compositor rather than
any config file, so binds added at runtime --- by a module, a
podomation rule, an MCP tool --- appear alongside the defaults.  Binds
sort by modifier count first, so the modifierless media keys group
together ahead of the =Super= binds.

A bind that carries a description shows it.  One that does not ---
anything from a YAML config, or a module's own binds --- falls back to
its action and argument (=spawn: wofi --show drun=), which is still
more use than a bare action nick.

** Pointer lock (games, VMs, remote desktops)
:PROPERTIES:
:CUSTOM_ID: pointer-lock
:END:

The compositor implements =pointer-constraints-v1= and
=relative-pointer-v1=, so a client can hide the cursor and read raw
motion deltas instead of absolute position.  That is what an FPS, a VM
console and an RDP or VNC client need; without it the pointer walks
out of the window and the view stops turning.

Nothing is configured for this --- a client asks and the compositor
answers.  Worth knowing only for one reason: while a client holds the
lock the cursor deliberately does not move, which is indistinguishable
from a frozen cursor if you do not know a constraint exists.
=gowl_compositor_pointer_is_locked()= reports it.

** Layouts and motion
:PROPERTIES:
:CUSTOM_ID: layouts
:END:

Tile, monocle, float and scrolling are separate Gowl plugins. CMacs
loads all four before windows map; standalone Gowl enables layouts in
its =modules= config. Additional layout plugins join the same list.

=Super+<= and =Super+>= (Super+Shift+comma/period) cycle backward and
forward through active layouts. =Super+Tab= and =Super+Shift+Tab= remain
aliases. =Super+t= selects tile, =Super+s= scrolling, =Super+m= monocle,
and =Super+f= float. Layout selection and scroll offset belong to the
current tag view on the current monitor; changing one does not change
another tag. A combined tag view keeps its own selection.

=gowl-list-layouts= returns active layouts; =gowl-set-layout= selects a
name and =gowl-cycle-layout= cycles the same list. Monitor-move shortcuts
are now =Super+Ctrl+Shift+comma/period=; Super+comma/period still focus
another monitor.

=Super+Shift+c= closes ordinary windows, but cannot close a window owned
by the main CMacs process. An attempted close shows “Can't close CMacs:
it owns this session” for 1.2 seconds. Repeated presses refresh the notice
and remain blocked. Separate Emacs processes are still closable. Use the
normal Emacs quit command (or =Super+Shift+q=) to end the session deliberately.

CMacs shows a brief layout toast at the top of the active monitor when
its layout changes. Rapid switches replace the toast; it disappears after
1.2 seconds and never takes focus or intercepts clicks. Disable the
layout-indicator module to hide these notices.

Layouts adapt to each monitor's current logical dimensions on every
arrangement, including live mode and rotation changes. When height is
greater than width, tile puts the master above the stack (a horizontal
split), scrolling runs top to bottom, centered-master uses a central
horizontal band, and Fibonacci starts with a horizontal split. Square
and landscape monitors keep the normal orientation. Bars and gaps do
not affect this decision, and monitors choose independently. Monocle
still fills the usable area; floating windows retain their positions.
An explicitly enabled =vsplit= continues to select top/bottom tiling
on landscape and square monitors too.

*** The scrolling layout

A niri-style strip: full-height columns laid left to right on landscape
and square monitors, or full-width rows running top to bottom on portrait
monitors. The viewport scrolls along them instead of squeezing windows to
fit. =Super+s= selects it; =Super+[= and =Super+]= scroll.

Window size along the scrolling axis is gowl's =scroll-column-width=
(default 0.5, so two columns or rows are visible at a time; 1.0 gives one).
It is a fraction of usable width on landscape and square monitors, or
usable height on portrait monitors.  The name matches
Hyprland's =scrolling.column_width=, which is what Omarchy configures,
so a Hyprland config translates.

Focusing a window scrolls the strip by the smallest amount that reveals
it, and does nothing when it is already visible --- otherwise every
focus change would move the world.

*** Motion

CMacs bundles and loads Gowl's =animation.so= module before windows map,
including the early =--gowl= startup path. The module owns the motion
engine; standalone Gowl leaves it unloaded until the user sets
=modules.animation.enabled: true= in its configuration. Existing CMacs
animation settings and defaults are unchanged. Disabling the module
with =(gowl-disable-module "animation")= restores live windows and full
effect opacity immediately; =(gowl-enable-module "animation")= enables it
again. The =animations= setting remains a separate effects switch.

Windows open with a centered pop from 84% size and two diminishing
squash/stretch bounces, and close with a quick squeeze and shrink. The fade completes
before the entrance finishes, making the motion clearly visible.
Position and size animate together on layout changes, with borders
following the same rectangle. Repeated layout updates retain the
animation clock instead of making the window trail behind.

gowl's =animations= switch controls the effects. Defaults are
=animation-duration= (260 ms for layout changes and release jiggles),
=animation-duration-open= (360 ms), =animation-duration-close= (180 ms),
=animation-popin-scale= (0.84), =animation-curve-open= (=ease-out-back=),
and =animation-curve= (=ease-out-expo=). Set =animation-duration= to 0 to
disable all animation; set an open or close duration to 0 to disable
that effect alone. =animation-jiggle-strength= defaults to 1; use 0 to
remove the jiggle, 0.5 for a softer effect, or 2 for double intensity.
These settings live in =~/.config/gowl/config.yaml=.

For an entrance closer to Omarchy's Hyprland defaults, use scale 0.87
and the =ease-out-quint= entrance curve, with jiggle strength 0. The
CMacs default adds a larger pop and squash/stretch for emphasis.

The compositor scales a snapshot of the surface tree, including
subsurfaces and cropped client decorations. Clients receive only the
final size, and live content returns when the transition ends. The
embedded editor frame is exempt from snapshot resizing. Interactive
drags track the pointer directly, with a brief jiggle when you release a
moved or resized window. The jiggle never changes the final placement.
Fullscreen and embedded clients do not jiggle.

Keyboard focus cycling with Super+j/k gives the newly active window a
small 220 ms wiggle while retaining the focus border color. It does not
change window placement or interrupt an entrance or layout transition.
It follows =animation-jiggle-strength= (0 disables it), and skips
fullscreen and embedded windows.

*** The desktop cube

Switching tags turns the desktop instead of cutting to it: the visible
desktop is one side of a solid, and the new tag is the next side round.
Crossing several tags turns several times and shows each tag on the way
past, so Super+1 followed by Super+4 turns three times through tags 2 and
3 rather than jumping.

CMacs bundles and loads Gowl's =cube.so= before windows map, including
the early =--gowl= startup path. Standalone Gowl leaves it unloaded until
the user sets =modules.cube.enabled: true=. =(gowl-disable-module "cube")=
returns tag switches to an instant cut immediately;
=(gowl-enable-module "cube")= brings it back.

It runs *alongside* =animation.so=, not instead of it. gowl dispatches
scene presentation to one provider, so the cube registers ahead of the
animation module and hands down every call it does not answer itself ---
window pops, fades, layout motion and jiggles are unchanged with both
loaded. The one thing it does answer is the fade-in of windows revealed
by the tag change it is about to animate: the rotation's first captured
side already shows them, so fading them in as well would fade the desktop
up after the rotation had landed.

Each side is that tag's wallpaper and windows, captured once when the
rotation starts. The bar and any notifications stay live above the
rotation rather than being baked into every side. The CMacs frame is an
ordinary tagged client and rides its own side; the views CMacs embeds
INSIDE its buffers are pinned over the frame rather than placed by tag,
so they go onto every side and their live copies come down for the
rotation --- gowl parks them above the rotation, and left alone they
would hang motionless while the desktop turned underneath.

Both ends of the rotation are the flat desktop exactly: with no camera
pull-back and no pitch the leading side projects to precisely the
viewport, so a tag switch has no visible cut into or out of the effect.

Defaults are =cube-duration= (520 ms for one turn),
=cube-step-duration= (150 ms added per extra turn, capped at three times
the base), =cube-curve= (=ease-in-out-cubic=), =cube-faces= (4, a cube;
3 to 12 are allowed), =cube-zoom= (1.45), =cube-pitch= (14 degrees),
=cube-shading= (0.78), =cube-reflection= (0.32), =cube-motion-blur=
(0.35), =cube-caps= (on), =cube-backdrop-color= (=#12141f=) and
=cube-all-monitors= (off --- only the focused output turns). Set
=cube-duration= to 0, or =cube= to =false=, to switch it off. These live
in =~/.config/gowl/config.yaml= alongside the =animation-*= keys.

The cube borrows the compositor's GLES2 context rather than adding a
renderer of its own. Under any other renderer it logs a message and
stands down, and tag switches stay instant; a rotated output sits
rotations out for the same reason. Tags that hold several bits at once
use their lowest tag as the ordinal, so replacing a tag view turns and
merely adding a tag to one does not.

*** Turning the cube by hand

With =cube-gesture= on (the default), a three-finger touchpad swipe turns
the solid directly rather than triggering a rotation. The desktop is
exactly as far round as your fingers have pushed it, and letting go
settles to whichever side is nearer: past halfway it commits and changes
tag, short of it the same rotation runs backwards to where it started.

The drag is deliberately not eased. A curve applied to a direct
manipulation makes the desktop lag behind the touchpad and then catch up,
which reads as the machine being slow rather than as motion design.

A gesture the cube claims never reaches the focused client --- a swipe
that turned the desktop and also scrolled the browser underneath it is
nobody's intent --- so =cube-gesture: false= is also how you give
applications their three-finger swipes back.

*** Overview: every tag at once

Super+backtick, or a four-finger swipe up, pulls the camera back out of
the tag you are on to show all of them as a grid of live thumbnails.
Arrows or =hjkl= move, =1= to =9= jump straight to a tag, Return or a
click picks, Escape leaves everything as it was, and clicking the gap
dismisses without changing tag.

CMacs bundles and loads gowl's =expo.so=; standalone gowl leaves it until
the user sets =modules.expo.enabled: true=. =M-x cmacs-gowl-expo= opens
it from Elisp.

The grid moves as one object under a single transform, so it reads as a
camera pulling back from one desktop rather than as nine pictures flying
into formation --- and at both ends that transform is exact, so the
overview opens out of the live desktop and closes back into the tag you
picked with no cut. Settings are the =expo-*= keys; the interesting ones
are =expo-tags= (fewer means bigger tiles), =expo-hide-empty= and
=expo-columns=.

*** Window switcher, with Emacs as the picker

Super+Tab opens a strip of live window previews, in focus order, opening
on the second card --- so one tap lands on the window you were in before
this one. Hold Super and tap Tab to move; let go to commit. Each card is
a capture of that WINDOW with everything else hidden, so three terminals
with the same icon are told apart by what is in them.

The more interesting door is =M-x cmacs-gowl-switch-window=. It runs an
ordinary =completing-read= over the window list while the compositor's 3D
strip follows the selection underneath it, and picking a candidate lands
on the window you were looking at. That combination is the point:
=completing-read= is the best list-of-choices widget on the machine ---
your history, your completion style, your embark actions --- and the one
thing it cannot do is show you what a window looks like. The compositor
can do nothing else.

The preview is best-effort by design. "Which candidate is the user on" is
not part of the completion API, so it is read through whichever front end
is installed (vertico, ivy, icomplete, selectrum) and simply does not
happen when none is recognised. Losing it costs a picture; the command
still selects the window you chose. Set
=cmacs-gowl-switcher-preview= to nil to skip the strip entirely.

The strip is driven by commands --- =switcher-next=, =switcher-select N=,
=switcher-list= --- so anything that can call =gowl-run-command= can
drive it.

*** Magnifier

Hold Super and scroll to magnify the whole output around the pointer;
Super+plus, Super+minus and Super+0 do the same from the keyboard when
you have not bound those keys yourself. It zooms towards the pointer
rather than the middle of the screen, so what you are pointing at stays
where it is.

It sits above the bar, since a magnifier that magnified everything except
the panel would be useless to somebody who needs it to read the panel,
and it is the only effect that captures every frame --- the thing it
magnifies is live. At 1:1 it puts everything away and costs nothing.

=magnifier-smooth: false= turns off filtering, which is what somebody
magnifying to inspect pixels actually wants. A scroll the magnifier
claims never reaches the client, so =magnifier-modifier= has to name a
combination applications do not use.

*** Frosted glass and shadows

Translucent windows (through the =alpha= module or a window rule) get a
blurred backdrop, and every window gets a soft drop shadow. CMacs loads
gowl's =blur.so= by default.

*What the blur actually blurs is the wallpaper*, computed once and
cropped per window --- not other windows. Doing that honestly would cost
a full scene render per translucent window per frame; this costs one
capture and one blur for as long as the wallpaper stays put. A
translucent terminal over the desktop is indistinguishable either way; a
translucent window over another window shows blurred wallpaper rather
than a blurred copy of the window below.

Shadows are computed rather than drawn and blurred: a blurred rectangle
has a closed form, so a shadow costs one CPU pass when a window is
resized and nothing per frame. Neither decoration claims any event, so
loading this changes nothing about how windows move. Settings are the
=blur-*= and =shadow-*= keys.

*** A wallpaper per tag

=wallpaper= is still the picture every tag uses. =wallpaper-tags=
overrides it for individual tags and a tag with no entry keeps the
default, so this is purely additive to an existing config:

#+begin_src yaml
wallpaper: "~/Pictures/default.jpg"
wallpaper-fade: 320
wallpaper-tags:
  1: "~/Pictures/code.jpg"
  4: "~/Pictures/mail.png"
#+end_src

Keys are the tag numbers in the bar, so 1-based; anything outside 1-9 is
reported as a typo and skipped rather than landing on tag 1. A combined
tag view uses its lowest tag to choose, the same rule the cube uses to
pick a face. The change cross-fades rather than cutting, and the blurred
backdrop behind translucent windows follows it.

*** Reaching a plugin from Elisp

=(gowl-run-command "expo")= runs a compositor command and returns the
reply. That is how Elisp reaches a gowl plugin at all: a module is a
shared object the compositor dlopens, and it exports a NAME rather than a
function pointer --- so "expo" opens the overview without cmacs or gowl's
core knowing that an overview exists. The same string works from a
keybind (=@{ action: ipc_command, arg: "expo" @}=) and from the IPC
socket.

*** How six effects share one compositor

All six --- animation, cube, expo, switcher, magnifier, blur --- are
separate plugins implementing one interface, and CMacs loads all of them.
gowl decides who gets a given hook per event rather than handing the
whole interface to one module: the hooks that decide where a window IS
stop at the first module that claims them, and the per-frame and teardown
hooks reach every module. So the cube claims the reveal of a tag it is
rotating to, expo claims one while the overview is up, blur claims
nothing at all, and window geometry keeps reaching the animation module
throughout.

None of them adds a renderer; they borrow the context wlroots' GLES2
renderer already owns. Under any other renderer each declines to run and
the desktop behaves exactly as it did without it. Disable any of them at
runtime with =(gowl-disable-module "expo")= and re-enable with
=(gowl-enable-module "expo")=.

** One palette for editor and compositor
:PROPERTIES:
:CUSTOM_ID: palette
:END:

A gowl session used to carry five independent sets of colours: three
border colours, gowlbar's twelve-key block, the lock screen's four, the
terminal's, and the editor's.  Changing "the" colour of the desktop
meant editing all of them, so nobody did --- and they had already
drifted far enough that the shipped config's borders were dwm's
=#005577= while its bar three hundred lines below was Catppuccin.

gowl now has a palette: one flat name-to-colour map that every colour
setting resolves against.

#+begin_src yaml
palette:
  name: latte
  accent: "#d20f39"

border-color-focus: accent
border-color-unfocus: surface
border-color-urgent: red
#+end_src

Any colour setting --- in this file or in any module --- may be a
literal =#rrggbb=, a palette entry name, or =name/aa= for the same
colour at a different opacity, which is how the bar gets a translucent
version of the background the borders use.  Five flavours ship: the
four Catppuccin ones, and =dwm= for exactly what gowl looked like
before palettes existed.

*** The editor drives it

The interesting direction is Emacs to gowl.  The theme in the editor is
the palette actually being curated; the borders are the thing that
never got updated to match it.  So =cmacs-gowl-mode= turns on
=cmacs-gowl-palette-follow-theme-mode=, and enabling a theme repaints
the borders, the bar and the lock screen with it.

| Command | Does |
|---------+------|
| =cmacs-gowl-palette-apply= | Push the editor's colours now |
| =cmacs-gowl-set-palette= | Switch to a built-in flavour |
| =cmacs-gowl-palette-show= | Show the current palette, with swatches |

What gets derived is deliberately small.  A theme has hundreds of faces
and gowl needs fifteen colours; guessing which face means "surface"
across every theme is not solvable.  =cmacs-gowl-palette-face-map=
names one face attribute per entry, and an entry it cannot read is
simply not sent --- gowl keeps that one from the flavour underneath, so
a sparse theme gives a partial retint rather than a black desktop.

=accent= reads the =link= face rather than the mode line, which decides
the colour of every focused border.  The mode line is the more obvious
choice and the wrong one: in modus-vivendi and many dark themes its
background is a neutral grey, so every border came out grey.

*** Two things that would otherwise fail silently

Both were found by running it rather than by reading it.

*A literal border follows nothing.*  gowl resolves =#005577= to itself,
so pushing a palette at a config written before this existed --- every
config --- changed the palette and left the borders exactly as they
were.  No error, and a desktop that looks like the theme did not apply.
So the first push retargets literal border colours at =accent=,
=surface= and =red=.  A border already naming an entry is left alone:
someone who wrote =border-color-focus: mauve= meant it.  Opt out with
=cmacs-gowl-palette-adopt-borders=.

*A reload puts the file's specs back.*  Palette overrides survive a
reload; the border specs pointing at them do not, because the file owns
what the file declares.  With the mode on, =gowl-reload-config= is
followed by a re-push.  With it off, the config file wins --- which is
right for anyone who did not ask for this.

** The system tray
:PROPERTIES:
:CUSTOM_ID: tray
:END:

Solaar, Syncthing, Steam, Element and a long tail of others put their
only always-available interface in a tray icon.  A gowl session has
nowhere to put one --- and neither does a stock GNOME without the
AppIndicator extension, so those applications have been running with
their interface simply absent.

The tray is not an X11 thing any more.  It is =StatusNotifierItem=:
three D-Bus interfaces and no compositor involvement at all.  A
*watcher* owns a well-known name and keeps the registry, a *host* says
it is willing to display items, and each *item* is an object on the
application's own bus name carrying a title, a status, an icon and a
menu.  Nothing in that requires pixels.

So =cmacs-tray-mode-global= is a real tray that happens to render as a
buffer.  It works identically under gowl, under GNOME, in a terminal
and over =emacsclient -nw=, and because cmacs is the watcher as well as
the host it is *the* tray on the machine rather than a second one
competing with a shell extension.  =cmacs-gowl-mode= enables it; opt
out with =cmacs-gowl-tray=.

The name is claimed only when free.  A desktop that already has a tray
host keeps it, and this says so --- two watchers means applications
register with whichever answered first and icons scatter between them.

*** Using it

=M-x cmacs-tray= lists the items.  In that buffer:

| Key   | Does                                          |
|-------+-----------------------------------------------|
| =RET= / =a= | Activate (what a left click does)       |
| =s=   | Secondary activate (a middle click)           |
| =m=   | Open the item's own menu and pick an entry    |
| =c=   | Ask the item to show its context menu         |
| =g=   | Re-read everything                            |

The menu comes from DBusMenu, the same protocol a graphical tray uses,
so what you get is the application's real menu --- Solaar's device
list, Syncthing's folder actions --- rather than an approximation.

*** What it does not do

Icons.  An item's icon arrives either as a themed name or as raw ARGB
pixmaps over D-Bus, and a list of applications with their titles and
statuses is more useful in a buffer than a row of 22-pixel images.  The
icon *name* is kept on every item, so a graphical renderer could be
added without touching any of the protocol handling.

*** One thing worth knowing

Reading an item's properties cannot be done inside the registration
handler.  A property read is a synchronous call back into the
application, which at that moment is blocked waiting for the reply to
its own registration --- so neither side proceeds and every read times
out.  It is not even a reliable failure: whether a given property
arrives depends on how fast the client returns to its main loop, which
is why an item looked complete one run and empty the next.  Answering
first and reading on the next idle turn costs nothing and makes it
deterministic.

** The control surface
:PROPERTIES:
:CUSTOM_ID: control-surface
:END:

=M-x cmacs-gowl-menu= (=Super+Escape=) is the session's power, audio,
network, bluetooth and display control, as one tree.

Omarchy solves the same problem with a Quickshell panel stack plus
=omarchy-menu.jsonc= --- a tree of entries with bash guards, rendered
by QML.  The tree is the good idea; QML is the wrong half to copy
here.  A menu is a list of choices, and Emacs has had the best
list-of-choices widget on the machine for forty years.  So this is the
same data-driven tree, rendered by =completing-read=, with its guards
evaluated in-process as Elisp rather than forked as one bash process
per open.

What that buys beyond parity: the menu works identically in a GUI
frame, in a terminal, over =emacsclient -nw= from another machine, and
under =emacs --lrg=; it composes with whatever completion framework is
already configured; and adding an entry is a line in =init.el=.

*** What is in it

| Group          | Entries                                                     |
|----------------+-------------------------------------------------------------|
| Applications   | launcher, run dialog, terminal                              |
| Audio          | output / input device, volume, mute, mic mute               |
| Network        | wifi networks, toggle wifi, status, nmtui                   |
| Bluetooth      | connect, disconnect, toggle radio                           |
| Display        | brightness, monitor list                                    |
| Compositor     | keybind cheatsheet, reload config, layouts                  |
| Power          | lock, suspend, hibernate, log out, reboot, power off        |

Reboot, power off and log out confirm first
(=cmacs-gowl-menu-confirm-destructive=); suspend does not, because a
confirmation on every reversible action is what trains people to
answer yes without reading.

*** Extending it

=cmacs-gowl-menu-tree= is a defcustom: a list of =(LABEL . PLIST)=
where a group carries =:items= (recursively the same shape) and a leaf
carries =:call= (a command symbol or a function).

=:when= is an Elisp form evaluated when the menu is built.  An entry
whose form returns nil is not shown --- which is how a machine without
bluetooth simply has no Bluetooth group, rather than a group whose
every item errors.  A guard that *signals* hides its own entry and
logs, because the entry most likely to have a broken guard is the one
whose backend is misbehaving, and that is exactly when the rest of the
menu still needs to open.

#+begin_src emacs-lisp
(add-to-list 'cmacs-gowl-menu-tree
             '("VPN"
               :when (executable-find "tailscale")
               :items (("Up"   :call (lambda () (start-process "ts" nil "tailscale" "up")))
                       ("Down" :call (lambda () (start-process "ts" nil "tailscale" "down")))))
             t)
#+end_src

*** A note on blocking

Opening the menu blocks Emacs's main loop while it waits for a choice
--- but not the compositor.  Under =--gowl= the compositor runs on its
own thread, so the desktop keeps compositing and other clients keep
animating with the menu open.

** Notifications
:PROPERTIES:
:CUSTOM_ID: notifications
:END:

A gowl session has no notification daemon.  Nothing owns
=org.freedesktop.Notifications=, so =notify-send= and every libnotify
application are silent in it --- and so are cmacs's own three
notification senders, which all end up at that same D-Bus name:
=cmacs-notify= calls it directly, while =cmacs-brigade-notify= and
podomation's cmacs module shell out to =notify-send=.  Under gowl,
gnuseye's =critical= watch alerts and the brigade's away digest have
been going nowhere.

=cmacs-notify-daemon-mode-global= claims the name and implements the
freedesktop specification, so those three work again and so does every
other application on the machine.  =cmacs-gowl-mode= enables it on
start; opt out with =cmacs-gowl-notification-daemon=.

It will not take the name from an existing owner.  Under GNOME, GNOME
Shell has it and enabling this is a no-op that says so --- stealing it
would break GNOME's own notifications and gain nothing, since those are
already visible.

*** Notifications are Org, not toasts

A notification is a headline in =*notifications*=, an Org buffer.  It
is searchable, foldable and exportable, and it *outlives the
notification's timeout*: expiry closes the notification and tells the
sender, but the entry stays.  =M-x cmacs-notify-daemon-history-buffer=
opens it.

#+begin_example
* New mail from Alice
:PROPERTIES:
:ID-NUM:   4
:APP:      mailer
:URGENCY:  normal
:TIME:     2026-09-05T16:32:53-0400
:STATE:    closed
:END:
Subject: lunch?

  - [[elisp:(cmacs-notify-daemon-invoke-action 4 "reply")][Reply]]
  - [[elisp:(cmacs-notify-daemon-invoke-action 4 "archive")][Archive]]
#+end_example

A notification's *actions* are links in that buffer.  Following one
emits =ActionInvoked= back to the sending application, so "Reply" on a
message from any application is a keypress in Emacs.  In the buffer:
=a= invokes an action, =d= dismisses, =k= clears, =g= refreshes.

*** Delivery

| Variable                                       | Default            | Effect                                    |
|------------------------------------------------+--------------------+-------------------------------------------|
| =cmacs-notify-daemon-echo=                     | =t=                | show arrivals in the echo area            |
| =cmacs-notify-daemon-echo-urgencies=           | =(normal critical)= | which urgencies reach the echo area       |
| =cmacs-notify-daemon-pop-to-buffer-urgencies=  | =(critical)=       | which additionally display the buffer     |
| =cmacs-notify-daemon-history-limit=            | 200                | entries kept in memory                    |
| =cmacs-notify-daemon-default-timeout=          | 5000               | ms when the sender says "your choice"     |
| =cmacs-notify-daemon-log-file=                 | nil                | Org file appended to, for a log that outlives the session |
| =cmacs-notify-daemon-functions=                | nil                | hook run with the notification's plist    |

The hook runs *before* display, so a function on it can speak the
notification, print it, or forward it without waiting for the user.  A
function that signals costs its own output and not the delivery.

*** What is implemented

=Notify=, =CloseNotification=, =GetCapabilities= and
=GetServerInformation=, plus the =NotificationClosed= and
=ActionInvoked= signals.  =replaces_id= supersedes an entry rather than
stacking a second one, so a progress notification updating itself does
not fill history.  Close reasons are the specification's: 1 expired, 2
dismissed by the user, 3 closed by the sender.

Capabilities claimed are =body=, =body-hyperlinks=, =actions=,
=persistence= and =icon-static= --- deliberately conservative, because
a capability is a promise the sender cannot check.  =body-markup= is
not claimed, since the markup would show as literal text.

** Media, volume and brightness keys
:PROPERTIES:
:CUSTOM_ID: media-keys
:END:

The =XF86= keys a laptop emits are bound on mode enable, controlled by
=cmacs-gowl-media-keybindings= (default on):

| Key                                                  | Command                          |
|------------------------------------------------------+----------------------------------|
| =XF86AudioRaiseVolume= / =XF86AudioLowerVolume=      | =cmacs-gowl-volume-raise/-lower= |
| =XF86AudioMute=                                      | =cmacs-gowl-volume-mute-toggle=  |
| =XF86AudioMicMute=                                   | =cmacs-gowl-mic-mute-toggle=     |
| =XF86MonBrightnessUp= / =XF86MonBrightnessDown=      | =cmacs-gowl-brightness-up/-down= |
| =XF86AudioPlay= / =Next= / =Prev= / =Stop=           | =cmacs-gowl-media-*=             |

These carry no modifier, which dispatch handles like any other bind:
it compares a *cleaned* modifier mask, so zero matches zero (and
NumLock or CapsLock being on cannot stop a bind firing).

*** Why these are Elisp and not spawned commands

A compositor keybind can only name one of gowl's built-in actions or
spawn a subprocess, so the obvious binding is
~{ action: spawn, arg: "pamixer -i 5" }~.  That works, and gives no
feedback --- the volume moves and nothing says so.

gowl's =custom= action hands its argument to the embedder instead, and
cmacs evaluates that argument as Elisp.  So these keys run
=cmacs-gowl-media= commands, which show the resulting level in the
echo area on the way past:

#+begin_example
Volume ██████████░░░░░░  62%
Brightness ████████░░░░░░░░  50%
Next: Sabaton - Bismarck
#+end_example

Route the OSD elsewhere --- a gowl layer surface, a posframe, a
notification --- by setting =cmacs-gowl-media-osd-function=, which
receives =(LABEL VALUE TEXT)=.  Set =cmacs-gowl-media-osd= to nil to
suppress it entirely.

*** Backends

| Variable                                | Default          | Used for            |
|-----------------------------------------+------------------+---------------------|
| =cmacs-gowl-media-volume-program=       | =wpctl=          | volume, mute        |
| =cmacs-gowl-media-brightness-program=   | =brightnessctl=  | backlight           |
| =cmacs-gowl-media-player-program=       | =playerctl=      | MPRIS transport     |

=wpctl= ships with wireplumber, so it is present wherever pipewire is;
the other two are separate packages.  A key whose backend is not
installed says so *once* rather than failing silently on every press.

Steps are =cmacs-gowl-media-volume-step= and
=-brightness-step= (5 points each).  =cmacs-gowl-media-volume-max=
(1.0) is the ceiling passed to wpctl, which keeps a held key from
driving the sink into software amplification.

Every call is asynchronous.  Under =--gowl= the Emacs main loop is
also the compositor's, so a synchronous =call-process= would stall
every client's frame callbacks for its duration.

Note on tag arguments: the compositor interprets a tag-action keybind
argument as a raw tag /bitmask/ (=atoi(arg) & TAGMASK=), not a 1-based
tag number, and an argument of ="0"= is a no-op.  =cmacs-gowl-mode=
therefore binds tag N to the bitmask ~(ash 1 (1- N))~ and "all" to
~(1<<9)-1~ = 511.  (gowl's shipped =default-config.c= passes plain
="1".."9"/"0"=, which is only correct for tags 1 and 2; the cmacs
installer passes real bitmasks.)

** Launching applications into a tag

These commands run an app as a separate client placed directly on a
target tag, without it first flashing onto the current tag:

#+begin_src emacs-lisp
(cmacs-gowl-launch-in-tag 3)   ;; completion over .desktop apps
(cmacs-gowl-bemenu-in-tag 3)   ;; bemenu (dmenu mode) picker
(cmacs-gowl-spawn-in-tag "firefox" 2)
#+end_src

The placement is flash-free and race-free: =cmacs-gowl-spawn-in-tag=
registers the spawned PID with the compositor via =gowl-pretag-pid=, so
the client adopts the tag's bitmask the instant it maps.
=cmacs-gowl-bemenu-in-tag= runs a dmenu-mode picker (reading the app
list on stdin) so cmacs owns the spawn — and thus the PID — and shows
the picker UI inside gowl by pointing =WAYLAND_DISPLAY= at the
compositor socket.  The picker binary is =cmacs-gowl-dmenu-command=
(default =bemenu=), deliberately separate from the =Super+p= launcher
(=cmacs-gowl-menu-command=, default =wofi --show drun=): the picker
needs a dmenu-mode binary (stdin → stdout), not a drun/run launcher.
=Super+p= keeps the classic standalone behaviour (the launcher runs
the chosen app itself, on the current tag).

* Monitor Management

Gowl provides full control over connected monitors (outputs): listing,
mode changes, scale adjustments, transforms, and enable/disable.  All
operations work on both physical monitors (DRM backend) and nested
Wayland outputs.

** Listing Monitors

=M-x cmacs-gowl-list-monitors= displays a table of all outputs:

#+begin_example
Name    Mode          Position  Scale  Status   Transform
WL-1    1280x720@60   0,0      1.0    enabled  normal
DP-1    2560x1440@144  1280,0  1.0    enabled  normal
#+end_example

From the shell:

#+begin_example
bacon> cmacsgi monitor list
WL-1
DP-1

bacon> cmacsgi monitor info WL-1
name=WL-1
mode=1280x720@60
position=0,0
scale=1.000000
enabled=t
transform=0
#+end_example

** Changing Resolution

=M-x cmacs-gowl-set-resolution= prompts with the monitor's advertised
modes.  For outputs with no advertised modes (common for nested Wayland
sessions), specify a custom mode directly.

#+begin_src emacs-lisp
;; From Elisp:
(gowl-set-monitor-mode 1920 1080 0 (gowl-find-monitor "WL-1"))
#+end_src

#+begin_example
;; From the shell:
bacon> cmacsgi monitor set-mode WL-1 1920x1080
bacon> cmacsgi monitor set-mode DP-1 2560x1440@144000
#+end_example

The refresh rate is in millihertz (60000 = 60 Hz).  Use 0 to match any
refresh rate, or omit the =@RATE= suffix.

*** Default size for nested sessions

A nested output (running =cmacs --gowl= inside another Wayland/X11
compositor, e.g. for testing under GNOME) has no advertised modes, so it
comes up at gowl's built-in default of 1280×720.  Override that *startup*
size with the =GOWL_OUTPUT_SIZE= environment variable (=WIDTHxHEIGHT=):

#+begin_example
GOWL_OUTPUT_SIZE=1920x1080 ./src/emacs --gowl
GOWL_OUTPUT_SIZE=2560x1440 just gowl
#+end_example

It applies only to outputs without a native mode list (nested/headless);
real monitors keep their native mode.  You can still resize the nested
window afterwards, or change modes at runtime with
=cmacs-gowl-set-resolution=.

** Scaling

Scale controls the output DPI.  A scale of 2.0 doubles the pixel
density, halving the logical resolution.

#+begin_src emacs-lisp
;; HiDPI (2x):
(gowl-set-monitor-scale 2.0 (gowl-find-monitor "WL-1"))

;; Lower density for more screen real-estate:
(gowl-set-monitor-scale 0.8 (gowl-find-monitor "WL-1"))
#+end_src

#+begin_example
bacon> cmacsgi monitor scale WL-1 2.0
bacon> cmacsgi monitor scale WL-1 0.8
bacon> cmacsgi monitor scale WL-1 1.0    ;; reset to default
#+end_example

At scale 0.8 on a 1280x720 output the logical area grows to 1600x900;
at scale 2.0 it shrinks to 640x360.  Clients automatically resize to
fill the new logical area.

** Transform (Rotation/Flip)

Transform values follow the Wayland =wl_output_transform= enum:

| Value | Name         | Effect                          |
|-------+--------------+---------------------------------|
|     0 | normal       | No rotation                     |
|     1 | 90           | Rotate 90° clockwise            |
|     2 | 180          | Rotate 180°                     |
|     3 | 270          | Rotate 270° clockwise           |
|     4 | flipped      | Horizontal flip                 |
|     5 | flipped-90   | Flip + rotate 90°               |
|     6 | flipped-180  | Flip + rotate 180°              |
|     7 | flipped-270  | Flip + rotate 270°              |

#+begin_example
bacon> cmacsgi monitor transform WL-1 1     ;; rotate 90°
bacon> cmacsgi monitor transform WL-1 0     ;; back to normal
#+end_example

*** Persisting Transform (and Other Monitor Settings) via YAML

For a machine where a display always wants the same orientation,
scale, or position (a tablet with a portrait-default panel, a
left-of-laptop external monitor, a HiDPI screen at non-default scale),
put the override in =~/.config/gowl/config.yaml= under the
=monitors:= key so it applies on every boot:

#+begin_src yaml
monitors:
  eDP-1:                 # mobile screen: boot already-rotated
    transform: 90
  HDMI-A-1:              # external 1440p at 144 Hz, placed right
    width: 2560
    height: 1440
    refresh: 144.0
    x: 1920
    y: 0
    scale: 1.0
    enabled: true
#+end_src

Every field is independently optional — set only what you want to
override.  Unset fields are left at the compositor's defaults, so a
=transform: 90= line on its own is valid.  =transform= accepts either
the integer code (0–7) or the canonical name (=normal=, =90=, =180=,
=270=, =flipped=, =flipped-90=, =flipped-180=, =flipped-270=).

Discover output names via =M-: (cmacs-gowl-list-monitors)= or
=cmacsgi monitor list=.

Changes take effect live on =M-x cmacs-gowl-reload-config= /
=cmacsgi compositor reload= / =Mod+R= — no compositor restart needed.

** Enable / Disable

#+begin_example
bacon> cmacsgi monitor disable DP-2
bacon> cmacsgi monitor enable DP-2
#+end_example

Or interactively: =M-x cmacs-gowl-toggle-monitor=.

** Closed Laptop Lid / Off Displays

gowl automatically powers off the laptop's built-in panel (an
=eDP=/=LVDS=/=DSI= connector) while the lid is shut *and* at least one
external display is connected.  The selected monitor and any windows on
the internal panel migrate to the external output, and the internal
panel is removed from the layout so the cursor and newly launched
windows never land on the dark screen.  This is what you want when
docking a closed laptop to a single external monitor: gowl renders only
on the attached display.

The behaviour is fully live and ordering-independent:

- Booting =cmacs --gowl= with the lid already shut leaves the internal
  panel off from the first frame (the initial state is read from
  =/proc/acpi/button/lid=).
- Closing or opening the lid while running toggles the panel via the
  libinput lid switch.
- Single-display safety: if the lid is shut and there is *no* external
  display, the internal panel stays on — gowl never blanks the only
  screen.  Unplugging the external while the lid is shut brings the
  internal panel back automatically.
- Idempotent (clamshell boot): if the DRM driver already powered the
  panel down (the enable commit for a shut lid fails, so it comes up
  =enabled=nil= but still mapped), gowl still removes it from the output
  layout, so a "half-disabled" panel never lingers there stealing the
  cursor and newly launched windows.  (gowl does *not* destroy the
  disabled output's =wlr_scene_output=; a disabled output stops emitting
  frame events, so its scene output simply never commits again.  An
  earlier version destroyed it and hit a use-after-free in the render
  thread — see =doc_org/cmacs/cmacs-upstream-changes.org= / the
  gowl-lid-wallpaper notes.)

This is controlled by the =manage-lid= compositor setting (default on).
Turn it off at runtime to keep driving a closed-lid panel:

#+begin_src emacs-lisp
(gobject-set (gowl-config-object) "manage-lid" nil)
#+end_src

** How It Works

When a mode, scale, or transform change is committed via
=wlr_output_commit_state()=, gowl updates the monitor geometry by
querying =wlr_output_layout_get_box()=, which returns the correct
logical dimensions accounting for scale and transform.  This matches
the approach used by dwl.

The compositor then calls =gowl_compositor_arrange()=, which re-tiles
all clients on the affected monitor.  Fullscreen clients (including
the Emacs frame in standalone =--gowl= mode) are resized to fill the
full monitor area.  Normal tiling clients are re-laid-out by the
active layout function (tile, monocle, etc.).

On the Wayland backend (nested compositors), =on_layout_change()=
typically fires synchronously during the output commit.  As a safety
net, each setter also queries the layout box and calls =arrange()=
directly, ensuring correct behavior even if the asynchronous path is
delayed.

* Touchpad and Pointer Input

gowl applies GNOME-like defaults to libinput *touchpads* as they connect
(=create_pointer= in =gowl-compositor.c=):

- *Tap-to-click* and *tap-and-drag* enabled.
- *Natural (reverse) scrolling* — two fingers up scrolls the content up,
  matching GNOME.  Applied only to touchpads, so a plain mouse keeps its
  normal wheel direction.
- *Two-finger scroll* and *disable-while-typing*.

A device is treated as a touchpad when libinput reports a non-zero tap
finger count (mice report zero).

*Gestures.*  Swipe, pinch, and hold events are relayed to the focused
client through the pointer-gestures protocol (=zwp_pointer_gestures_v1=),
so applications get three-finger swipe, pinch-to-zoom, etc.  Two-finger
scrolling is ordinary pointer-axis scrolling and works everywhere.

These are compiled-in defaults (no per-device config knob yet).  Because
the static =libgowl.a= now calls =libinput_device_config_*= directly,
cmacs links =libinput= — see the =CMACS_GOWL_DEPS= pkg-config list in
=configure.ac=.

* Client Embedding

Wayland clients can render /inside/ Emacs buffer windows.  The client's
scene node is reparented into Emacs's compositor scene tree and
positioned over the window body area.  The compositor renders the client
directly---no pixel copying, no GPU readback.  Input is routed by the
compositor's focus-follows-mouse.

#+begin_example
┌─ Emacs frame (tiled, layer 2) ─────────────────────┐
│ ┌─ window: code.el ────┐┌─ window: *gowl: foot* ──┐│
│ │ (defun hello ()      ││┌─────────────────────────┐││
│ │   (message "hi"))    │││  foot terminal          │││
│ │                      │││  (embedded client)      │││
│ │                      ││└─────────────────────────┘││
│ │-:-- code.el     L3  ││-:-- *gowl: foot*    L1  ││
│ └──────────────────────┘└──────────────────────────┘│
│ M-x                                                 │
└─────────────────────────────────────────────────────┘
#+end_example

** Embedding Commands

| Command             | Description                                        |
|---------------------+----------------------------------------------------|
| =gowl-embed=       | Spawn a command and embed it in the current window |
| =gowl-embed-client= | Embed an existing gowl client in current window   |
| =gowl-unembed=     | Release an embedded client back to normal tiling   |

** How It Works

1. =gowl-embed= spawns a Wayland client and pre-registers its PID so
   the compositor floats and hides it on map.
2. A 100ms timer polls =gowl-list-clients= to match the PID.
3. Once matched, the client is positioned on the OVERLAY layer at
   the Emacs window's monitor-absolute coordinates.  The frame's
   compositor geometry (from =gowl-client-info=) is added to the
   frame-relative window coordinates to account for bar height and
   vanitygaps.
4. =window-configuration-change-hook= keeps the overlay in sync when
   windows resize, split, or switch buffers.
5. A 1-second health timer detects client exit and cleans up the buffer.

** Lifecycle

- *Client exits*: health timer detects it gone from =gowl-list-clients=
  (compared by PID), kills the placeholder buffer.
- *Buffer killed*: =kill-buffer-hook= closes the Wayland client via
  =gowl-close-client=.
- *Window hidden*: overlay is hidden via =gowl-set-client-visible=.
  Switching back to the buffer re-shows it.

** Keyboard Focus (ESC Escape-Hatch)

Embedded clients receive keyboard input directly from the compositor.
An ESC-based escape hatch lets you switch between the embedded client
and Emacs:

- *ESC* (single press): returns keyboard focus to Emacs.  Subsequent
  keys are processed by Emacs (e.g. Evil normal-mode commands).
- *ESC ESC* (double press): sends a single ESC to the embedded client
  (useful for apps that use ESC, like vim or bash with =set -o vi=).
- *i / a* (in Evil normal state): gives keyboard focus back to the
  embedded client.  Also works with =I=, =A=, =o=, =O=, and =RET=.
- *Click* on the embedded area: also returns keyboard focus to the
  embedded client.

The escape hatch uses a 200ms timer to distinguish single from double
ESC.  Pressing ESC followed by another key within the timeout sends
the second key to Emacs.

The underlying primitive =gowl-embed-focus= can be called from Elisp
to programmatically give keyboard focus to any embedded client.

*** Launchers and other keyboard-interactive layer surfaces

A layer-shell surface that asks for the keyboard -- a launcher such as
=wofi= or =rofi=, an on-screen keyboard -- gets an *exclusive grab*
from the compositor when it maps at the =TOP= or =OVERLAY= layer.
While that grab is held, every cmacs path that would otherwise move
seat keyboard focus does nothing:

| Path                          | Behaviour while a launcher holds the keyboard |
|-------------------------------+-----------------------------------------------|
| =gowl-grant-focus-to-emacs=   | returns =nil=, focus unchanged                |
| =gowl-return-focus-to-embed=  | returns =nil=, the redirect token is *kept*   |
| =gowl-embed-focus=            | returns =nil=, focus unchanged                |
| Prefix-key redirect           | no focus move                                 |
| Focus-follows-mouse on an xwidget | no focus move                             |
| Click on an embedded area     | no keyboard focus move (pointer still works)  |

=gowl-return-focus-to-embed= deliberately keeps its token rather than
popping it, so the restore simply happens on the first command after
the launcher goes away -- =post-command-hook= calls it after every
command anyway.

This matters because cmacs moves seat focus *directly*, without going
through the compositor's =gowl_compositor_focus_client()= -- embedded
clients are deliberately absent from the compositor's focus stack.
That bypasses the compositor's own guards, so each of these paths
checks the grab itself, via
=gowl_compositor_has_exclusive_keyboard_layer()=.

Without those checks the launcher loses the keyboard within
milliseconds of mapping (=post-command-hook= restoring embed focus is
the usual culprit) and ends up *visible, on top of the whole output,
and completely deaf* -- impossible to type into, impossible to
dismiss, and covering everything that is still responding.  If you
ever see that symptom again, confirm it client-side with:

#+BEGIN_SRC bash
WAYLAND_DEBUG=1 wofi --show drun 2>&1 | grep wl_keyboard
#+END_SRC

The last event must be =wl_keyboard.enter=.  A trailing =.leave= with
no =.enter= after it is the bug.

The grab is derived from live surface state, so it releases the
instant the surface unmaps or stops asking for the keyboard; it cannot
wedge keyboard focus.  The compositor-side rules are documented in
=deps/gowl/docs/architecture.org= under *Keyboard Focus Arbitration*.

=kill-client=, =set-mfact= and the rest --- resolved from gowl's own
=GowlAction= enum rather than a list kept in cmacs, so an action added
upstream works here with no change.  Underscores are accepted in place
of hyphens.  Its optional fourth argument is the bind's *description*.

=gowl-list-keybinds= returns =((key . "Super+p") (action . spawn) (arg
. "wofi --show drun") (desc . "App launcher"))= per bind.  =action= is
the symbol, not the enum's integer.

=gowl-run-keybind= runs what a key is bound to *without* pressing it,
which is what makes a =custom= bind reachable from a menu or a test.
Note that =gowl-send-key= does **not** do this: injected keys go to
the focused client and never consult the keybind table.

* Modules

Gowl provides a module system for extending the compositor with

** Where modules are loaded from

A module =.so= is resolved by =cmacs_gowl_find_module= in this order:

1. =$CMACS_GOWL_MODULE_DIR/<name>.so= — an explicit override directory;
2. the in-tree dev build,
   =<exe-dir>/../deps/gowl/build/release/modules/<name>.so=;
3. the installed location, =PATH_EXEC/gowl-modules/<name>.so=.

=just run= and =just gowl= set =CMACS_GOWL_MODULE_DIR= to
=deps/gowl/build/release/modules= so local testing always loads the
freshly-built modules, never a system-installed copy.  Running
=src/emacs --gowl= directly still finds the in-tree modules via step 2,
but set =CMACS_GOWL_MODULE_DIR= yourself to be explicit (e.g. to test a
debug build under =build/debug/modules=).

(when (and (fboundp 'gowl-running-p) (gowl-running-p))

** Wallpaper

Set the desktop wallpaper with =gowl-set-wallpaper=:

#+begin_src emacs-lisp
(gowl-set-wallpaper "~/Pictures/wallpaper.png")        ;; mode = "fill"
(gowl-set-wallpaper "~/Pictures/wallpaper.png" "fit")  ;; explicit mode
(gowl-wallpaper-info)
  ;; => ((path . "~/Pictures/wallpaper.png") (mode . "fill"))
#+end_src

The optional second argument is the scaling mode:

| Mode      | Behaviour                                                       |
|-----------+-----------------------------------------------------------------|
| =fill=    | (default) GNOME-style zoom: scale to cover the monitor, aspect preserved, centre-cropped — never stretched or tiled |
| =fit=     | Scale the whole image to fit inside the monitor (letterbox)     |
| =center=  | Place the image 1:1 at the centre                               |
| =stretch= | Distort the image to the exact monitor size                    |
| =tile=    | Repeat the image at native size                                |

Each monitor is scaled independently, so a single large (e.g.
multi-monitor panorama) image is zoomed to fit *each* display rather
than tiled into a grid on the larger ones.

*** Seeing the Wallpaper Through Emacs

To make the Emacs frame transparent so the gowl wallpaper is visible
behind it, two things are needed:

1. *PGTK =alpha-background=*: Makes Emacs render its background with
   transparent pixels.  Text and UI elements stay fully opaque.
2. *Compositor-level alpha*: Any client opacity less than 1.0 forces
   wlroots to skip the opaque-region optimization and composite the
   wallpaper behind the frame.

wlroots resets scene buffer opacity to 1.0 on every surface commit.
Gowl re-applies the stored alpha after each commit so the
transparency persists across frames.

#+begin_src emacs-lisp
;; Complete setup (e.g. in Doom config.el):
(when (and (fboundp 'gowl-running-p) (gowl-running-p))
  (gowl-start)
  (gowl-enable-module "alpha")
  (gowl-set-focused-alpha 0.9)
  (gowl-set-unfocused-alpha 0.9)
  (gowl-set-wallpaper "~/Pictures/wallpaper.png")
  ;; PGTK: transparent background, solid text
  (set-frame-parameter nil 'alpha-background 85)
  (add-to-list 'default-frame-alist '(alpha-background . 85))
  ;; Force compositor to blend behind the Emacs frame
  (gowl-set-all-alpha 0.99))
#+end_src

** Screenlock

Full-screen session locking with PAM authentication.  Each monitor
gets a lock surface on the =BLOCK= scene layer; the password is verified
against PAM before the session unlocks.

=M-x gowl-lock= is the simplest entry point — it *loads and activates
the screenlock module on demand*, points it at a working PAM service,
and engages the lock so the password prompt is drawn:

#+begin_src emacs-lisp
(gowl-lock)     ;; load screenlock if needed, then lock
#+end_src

To customise first (optional), enable + configure it explicitly:

#+begin_src emacs-lisp
(gowl-enable-module "screenlock")
(gowl-configure-screenlock
  '(("pam-service" . "gowl")
    ("auto-lock-timeout" . "300")
    ("bg-color" . "#1e1e2e")))
(gowl-lock)
#+end_src

*PAM is required to unlock.*  =gowl-lock= refuses to engage (signalling
=gowl-error=) unless a usable service exists under =/etc/pam.d= — it
never drops you onto a blank, unopenable screen.  It looks for
=/etc/pam.d/gowl= first, then falls back to =system-auth= and =login=.
Install the bundled profile system-wide with:

#+begin_example
sudo make install-cmacs-pam      # or it runs as part of `sudo make install'
#+end_example

=M-x gowl-unlock= force-unlocks (administrative override, no password) —
useful as an escape hatch while testing.

*Animated lock background.*  When the screensaver subsystem is built
(=--with-cmacs-screensaver=) and =cmacs-screensaver-lock-config= names a
config, =gowl-lock= shows that libregnum screensaver as the lock
background, with the password box and typing indicator composited on top
while the animation keeps running.  Leaving the variable =nil= keeps the
ordinary static lock.  The animation stops automatically when the session
unlocks.  See =doc_org/cmacs/cmacs-screensaver.org=.

*Embedded caveat:* the lock owns gowl's Wayland seat, so it locks the
compositor and its clients.  In a *nested* =--gowl= test session the
host Emacs frame is not a gowl client, so test the locker in a real
gowl session (or the standalone =gowl= binary) for the full effect.

* Window Rules and Floating Popups

CMacs ships with two gowl modules that work together to keep
modal/popup windows out of the tiled layout:

- =windowrules= --- applies rules from the gowl config's =rules:=
  section to every new client at map time.  The rules are
  evaluated *before* the client is assigned a monitor, so a
  matched rule can force floating, override tags, pin a monitor,
  or set an explicit geometry without causing a visible
  tile→float flicker.  The module also re-evaluates rules when
  a client's title changes, which is the only way to catch apps
  like Zoom that rename their toplevel after map (the "Join
  Meeting" window is a classic case).
- =dropdown= --- manages Guake-style toggleable windows.  Each
  dropdown entry has a =spawn-cmd=, =keybind=, and =geometry=
  spec.  On first keypress the command is spawned and its first
  Wayland toplevel captured via a compositor prefloat hint; on
  subsequent presses the window is hidden/shown without being
  destroyed, and re-positioned on the currently focused output.

The default terminal spans the output width and two-thirds of its usable
height. It is a fixed floating overlay: opening it never rearranges tiles,
and move, resize, centering, and fullscreen shortcuts cannot displace it.
Super+grave (also Super+Shift+grave / tilde) toggles it; focusing another
app dismisses it while preserving the shell session. With the animation
module enabled, it slides from its anchor edge and reverses smoothly when
toggled mid-transition. Without animation, visibility changes immediately.

** YAML config

#+begin_example
rules:
  # Match by glob (default).  Float the pavucontrol popup.
  - app-id: "pavucontrol"
    floating: true

  # Match by regex.  Zoom sets its title to "Zoom Meeting" after
  # the initial xdg configure, so a post-map rule is needed.
  - title: "^Zoom Meeting$"
    floating: true
    regex: true

  # Explicit size + center on target monitor.
  - app-id: "org.keepassxc.KeePassXC"
    title: "Unlock"
    floating: true
    width: 500
    height: 200
    center: true

dropdowns:
  - name: term
    spawn-cmd: "foot"
    keybind: "Super+grave"
    width-pct: 1.0
    height-pct: 0.666667
    anchor: top

  - name: btop
    spawn-cmd: "foot -e btop"
    keybind: "Super+F10"
    width-pct: 0.8
    height-pct: 0.6
    anchor: top
#+end_example

|-----------+---------+-------------------------------------------------|
| =app-id=  | string  | Pattern matched against Wayland app_id         |

| =tags=    | int     | Tag bitmask to assign                           |
| =monitor= | int     | Monitor index (-1 = any)                        |
| =width=   | int     | Explicit pixel width, 0 = keep natural          |
| =height=  | int     | Explicit pixel height, 0 = keep natural         |
| =center=  | bool    | Center floated match on monitor (default true) |

| Key          | Type          | Description                             |
|--------------+---------------+-----------------------------------------|

=grow-float-*=, =shrink-float-*=).

** Why this matters (debugging escape hatch)

The =dropdown= module runs entirely inside the gowl compositor,
not in Emacs's event loop.  If Emacs freezes --- native
compilation stall, infinite Lisp loop, deadlock in a modal
prompt --- the =Super+grave= keybind still fires, the terminal
still appears, and you retain a shell from which to =gdb
--pid=$(pidof emacs)=, send signals, or inspect state.  This is
the primary motivation for the feature: an always-available
escape hatch that survives Emacs pathologies.

* Customization

#+begin_src emacs-lisp
(setq cmacs-gowl-border-width 2)
(setq cmacs-gowl-border-color-focus "#5e81ac")
(setq cmacs-gowl-border-color-unfocus "#4c566a")
(setq cmacs-gowl-layouts '("tile" "monocle" "float"))
(setq cmacs-gowl-default-layout "tile")
(setq cmacs-gowl-autostart '("waybar"))

;; Tags / keybindings / bar (see "Tags and Workspaces").
(setq cmacs-gowl-default-keybindings t)  ;; install dwm-style binds
(setq cmacs-gowl-menu-command "wofi --show drun")  ;; Super+p launcher
(setq cmacs-gowl-run-command "wofi --show run")    ;; Super+Shift+p run dialog
(setq cmacs-gowl-terminal-command nil)   ;; nil → dropdown terminal
(setq cmacs-gowl-bar-show-tags t)        ;; enable bar + tag indicator
(setq cmacs-gowl-monitor-tags-on-launch t) ;; monitor i → tag i+1
#+end_src
