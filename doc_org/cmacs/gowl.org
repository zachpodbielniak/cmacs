#+TITLE: Gowl Wayland Compositor
#+STARTUP: showall
#+OPTIONS: toc:2 num:t

* Overview

Gowl is a wlroots-based Wayland compositor embedded in CMacs.  When
launched with =--gowl=, Emacs becomes a tiling window manager: the
editor renders as a Wayland client inside its own compositor, and other
Wayland apps (terminals, browsers, viewers) tile alongside or embed
directly inside Emacs windows.

The integration provides 47+ C primitives (DEFUNs) for full compositor
control from Elisp: spawning clients, managing tags, switching layouts,
querying monitors, and embedding client windows inside Emacs buffers.

* Starting the Compositor

#+begin_example
src/emacs --gowl              # launch Emacs as a Wayland WM
#+end_example

Inside Emacs, the compositor is controlled via =cmacs-gowl-mode=:

#+begin_example
M-x cmacs-gowl-mode           ;; toggle (usually auto-enabled by --gowl)
#+end_example

* Tags and Workspaces

gowl uses the dwm/dwl *tag* model: there are nine tags (1--9), each a
bit in a per-monitor bitmask.  Viewing a tag shows the clients tagged
with it and hides the rest; a client can carry one or several tags.
Tags behave like workspaces.  Emacs's own frame is an ordinary tiled
client and lives on tag 1 — so switching to an empty tag hides Emacs
(classic dwm behaviour), and =Super+1= brings it back.

This complements [[*Client Embedding][embedding]]: =gowl-embed= runs an
app /inside/ an Emacs window (always visible on tag 1), whereas the
launch-into-tag commands run an app as an independent client in another
workspace.

** Switching from M-x

You don't need the keyboard shortcuts — everything is available as a
command:

- =M-x cmacs-gowl-view-tag= — switch the focused monitor to a tag by
  number.  This performs a full view: it shows/hides clients, re-tiles,
  and moves focus (just like =Super+N=).
- =M-x cmacs-gowl-switch-tag= — a friendlier picker that lists the nine
  tags each annotated with what's open on them (e.g. =Tag 2 — Firefox,
  gimp= or =Tag 3 — (empty)=); pick one to switch to it.
- =M-x cmacs-gowl-switch-to-app= — a *window picker*: lists every open
  window across all tags and monitors (title, app-id, and its tag).
  Selecting one reveals that window's tag on its monitor and focuses
  it — the way to reach an app that is open in another tag/monitor
  without hunting for it.  Embedded clients are excluded (use =C-x b=).

** Multi-monitor

Tags are *per-monitor*: every output has its own independent tag set,
so each tag can live on its own monitor.  On mode start (when
=cmacs-gowl-monitor-tags-on-launch= is non-nil, the default) each
monitor is given its own initial tag — the main (first) monitor views
tag 1, the second views tag 2, and so on, up to nine monitors.  Re-run
=M-x cmacs-gowl-assign-monitor-tags= after hotplugging a monitor.

The tag-action keybinds act on the *focused* monitor: focus a monitor
with =Super+,= / =Super+.=, then =Super+N= switches that monitor's
tags, =Super+Shift+,= / =.= moves the focused client to the previous /
next monitor.  Each monitor's bar shows its own tag state.

Launching into a tag follows the tag to its monitor:
=cmacs-gowl-spawn-in-tag= (and the launch commands below) find the
monitor currently showing the target tag and place the new client
there, so launching on tag 2 lands on the monitor whose workspace is
tag 2 — never hidden on the wrong output.

** Restored keybindings

Under =emacs --gowl= the compositor starts with an *empty* keybind
table, so =cmacs-gowl-mode= installs the standard dwm-style set on
enable (controlled by =cmacs-gowl-default-keybindings=, default on).
The compositor evaluates these before forwarding keys to the focused
surface, so they work globally even while Emacs or an embedded client
holds focus.

| Keybinding              | Action                                  |
|-------------------------+-----------------------------------------|
| =Super+Return=          | Launch terminal (=cmacs-gowl-terminal-command=) |
| =Super+p=               | Launch menu (=cmacs-gowl-menu-command=, bemenu) |
| =Super+Shift+c=         | Kill focused client                     |
| =Super+j= / =Super+k=   | Focus next / previous in stack          |
| =Super+h= / =Super+l=   | Shrink / grow the master area           |
| =Super+i= / =Super+d=   | Increment / decrement master count      |
| =Super+Shift+Return=    | Zoom (promote to master)                |
| =Super+t= / =f= / =m=   | Tile / float / monocle layout           |
| =Super+space=           | Toggle floating                         |
| =Super+Shift+space=     | Toggle fullscreen                       |
| =Super+1=..=9=          | View tag N                              |
| =Super+Shift+1=..=9=    | Move focused client to tag N            |
| =Super+Ctrl+1=..=9=     | Toggle visibility of tag N              |
| =Super+Shift+Ctrl+1=..=9= | Toggle tag N on the focused client    |
| =Super+0=               | View all tags                           |
| =Super+Shift+0=         | Tag focused client to all tags          |
| =Super+,= / =Super+.=   | Focus previous / next monitor           |
| =Super+Shift+,= / =.=   | Move client to previous / next monitor  |
| =Super+Shift+q=         | Quit the compositor                     |
| =Super+Shift+r=         | Reload config                           |

#+begin_quote
*Caution:* under =--gowl= the compositor /is/ the Emacs session, so
=Super+Shift+q= quits Emacs.  Set =cmacs-gowl-default-keybindings= to
nil and install your own binds with =gowl-add-keybind= to customise.
#+end_quote

Note on tag arguments: the compositor interprets a tag-action keybind
argument as a raw tag /bitmask/ (=atoi(arg) & TAGMASK=), not a 1-based
tag number, and an argument of ="0"= is a no-op.  =cmacs-gowl-mode=
therefore binds tag N to the bitmask ~(ash 1 (1- N))~ and "all" to
~(1<<9)-1~ = 511.  (gowl's shipped =default-config.c= passes plain
="1".."9"/"0"=, which is only correct for tags 1 and 2; the cmacs
installer passes real bitmasks.)

** Launching applications into a tag

These commands run an app as a separate client placed directly on a
target tag, without it first flashing onto the current tag:

#+begin_src emacs-lisp
(cmacs-gowl-launch-in-tag 3)   ;; completion over .desktop apps
(cmacs-gowl-bemenu-in-tag 3)   ;; bemenu (dmenu mode) picker
(cmacs-gowl-spawn-in-tag "firefox" 2)
#+end_src

The placement is flash-free and race-free: =cmacs-gowl-spawn-in-tag=
registers the spawned PID with the compositor via =gowl-pretag-pid=, so
the client adopts the tag's bitmask the instant it maps.
=cmacs-gowl-bemenu-in-tag= runs bemenu in /dmenu mode/ (reading the app
list on stdin) so cmacs owns the spawn — and thus the PID — and shows
the bemenu UI inside gowl by pointing =WAYLAND_DISPLAY= at the
compositor socket.  =Super+p= keeps the classic standalone behaviour
(=bemenu-run= launches the app itself, on the current tag).

* Monitor Management

Gowl provides full control over connected monitors (outputs): listing,
mode changes, scale adjustments, transforms, and enable/disable.  All
operations work on both physical monitors (DRM backend) and nested
Wayland outputs.

** Listing Monitors

=M-x cmacs-gowl-list-monitors= displays a table of all outputs:

#+begin_example
Name    Mode          Position  Scale  Status   Transform
WL-1    1280x720@60   0,0      1.0    enabled  normal
DP-1    2560x1440@144  1280,0  1.0    enabled  normal
#+end_example

From the shell:

#+begin_example
bacon> cmacsgi monitor list
WL-1
DP-1

bacon> cmacsgi monitor info WL-1
name=WL-1
mode=1280x720@60
position=0,0
scale=1.000000
enabled=t
transform=0
#+end_example

** Changing Resolution

=M-x cmacs-gowl-set-resolution= prompts with the monitor's advertised
modes.  For outputs with no advertised modes (common for nested Wayland
sessions), specify a custom mode directly.

#+begin_src emacs-lisp
;; From Elisp:
(gowl-set-monitor-mode 1920 1080 0 (gowl-find-monitor "WL-1"))
#+end_src

#+begin_example
;; From the shell:
bacon> cmacsgi monitor set-mode WL-1 1920x1080
bacon> cmacsgi monitor set-mode DP-1 2560x1440@144000
#+end_example

The refresh rate is in millihertz (60000 = 60 Hz).  Use 0 to match any
refresh rate, or omit the =@RATE= suffix.

** Scaling

Scale controls the output DPI.  A scale of 2.0 doubles the pixel
density, halving the logical resolution.

#+begin_src emacs-lisp
;; HiDPI (2x):
(gowl-set-monitor-scale 2.0 (gowl-find-monitor "WL-1"))

;; Lower density for more screen real-estate:
(gowl-set-monitor-scale 0.8 (gowl-find-monitor "WL-1"))
#+end_src

#+begin_example
bacon> cmacsgi monitor scale WL-1 2.0
bacon> cmacsgi monitor scale WL-1 0.8
bacon> cmacsgi monitor scale WL-1 1.0    ;; reset to default
#+end_example

At scale 0.8 on a 1280x720 output the logical area grows to 1600x900;
at scale 2.0 it shrinks to 640x360.  Clients automatically resize to
fill the new logical area.

** Transform (Rotation/Flip)

Transform values follow the Wayland =wl_output_transform= enum:

| Value | Name         | Effect                          |
|-------+--------------+---------------------------------|
|     0 | normal       | No rotation                     |
|     1 | 90           | Rotate 90° clockwise            |
|     2 | 180          | Rotate 180°                     |
|     3 | 270          | Rotate 270° clockwise           |
|     4 | flipped      | Horizontal flip                 |
|     5 | flipped-90   | Flip + rotate 90°               |
|     6 | flipped-180  | Flip + rotate 180°              |
|     7 | flipped-270  | Flip + rotate 270°              |

#+begin_example
bacon> cmacsgi monitor transform WL-1 1     ;; rotate 90°
bacon> cmacsgi monitor transform WL-1 0     ;; back to normal
#+end_example

*** Persisting Transform (and Other Monitor Settings) via YAML

For a machine where a display always wants the same orientation,
scale, or position (a tablet with a portrait-default panel, a
left-of-laptop external monitor, a HiDPI screen at non-default scale),
put the override in =~/.config/gowl/config.yaml= under the
=monitors:= key so it applies on every boot:

#+begin_src yaml
monitors:
  eDP-1:                 # mobile screen: boot already-rotated
    transform: 90
  HDMI-A-1:              # external 1440p at 144 Hz, placed right
    width: 2560
    height: 1440
    refresh: 144.0
    x: 1920
    y: 0
    scale: 1.0
    enabled: true
#+end_src

Every field is independently optional — set only what you want to
override.  Unset fields are left at the compositor's defaults, so a
=transform: 90= line on its own is valid.  =transform= accepts either
the integer code (0–7) or the canonical name (=normal=, =90=, =180=,
=270=, =flipped=, =flipped-90=, =flipped-180=, =flipped-270=).

Discover output names via =M-: (cmacs-gowl-list-monitors)= or
=cmacsgi monitor list=.

Changes take effect live on =M-x cmacs-gowl-reload-config= /
=cmacsgi compositor reload= / =Mod+R= — no compositor restart needed.

** Enable / Disable

#+begin_example
bacon> cmacsgi monitor disable DP-2
bacon> cmacsgi monitor enable DP-2
#+end_example

Or interactively: =M-x cmacs-gowl-toggle-monitor=.

** How It Works

When a mode, scale, or transform change is committed via
=wlr_output_commit_state()=, gowl updates the monitor geometry by
querying =wlr_output_layout_get_box()=, which returns the correct
logical dimensions accounting for scale and transform.  This matches
the approach used by dwl.

The compositor then calls =gowl_compositor_arrange()=, which re-tiles
all clients on the affected monitor.  Fullscreen clients (including
the Emacs frame in standalone =--gowl= mode) are resized to fill the
full monitor area.  Normal tiling clients are re-laid-out by the
active layout function (tile, monocle, etc.).

On the Wayland backend (nested compositors), =on_layout_change()=
typically fires synchronously during the output commit.  As a safety
net, each setter also queries the layout box and calls =arrange()=
directly, ensuring correct behavior even if the asynchronous path is
delayed.

* Client Embedding

Wayland clients can render /inside/ Emacs buffer windows.  The client's
scene node is reparented into Emacs's compositor scene tree and
positioned over the window body area.  The compositor renders the client
directly---no pixel copying, no GPU readback.  Input is routed by the
compositor's focus-follows-mouse.

#+begin_example
┌─ Emacs frame (tiled, layer 2) ─────────────────────┐
│ ┌─ window: code.el ────┐┌─ window: *gowl: foot* ──┐│
│ │ (defun hello ()      ││┌─────────────────────────┐││
│ │   (message "hi"))    │││  foot terminal          │││
│ │                      │││  (embedded client)      │││
│ │                      ││└─────────────────────────┘││
│ │-:-- code.el     L3  ││-:-- *gowl: foot*    L1  ││
│ └──────────────────────┘└──────────────────────────┘│
│ M-x                                                 │
└─────────────────────────────────────────────────────┘
#+end_example

** Embedding Commands

| Command             | Description                                        |
|---------------------+----------------------------------------------------|
| =gowl-embed=       | Spawn a command and embed it in the current window |
| =gowl-embed-client= | Embed an existing gowl client in current window   |
| =gowl-unembed=     | Release an embedded client back to normal tiling   |

** How It Works

1. =gowl-embed= spawns a Wayland client and pre-registers its PID so
   the compositor floats and hides it on map.
2. A 100ms timer polls =gowl-list-clients= to match the PID.
3. Once matched, the client is positioned on the OVERLAY layer at
   the Emacs window's monitor-absolute coordinates.  The frame's
   compositor geometry (from =gowl-client-info=) is added to the
   frame-relative window coordinates to account for bar height and
   vanitygaps.
4. =window-configuration-change-hook= keeps the overlay in sync when
   windows resize, split, or switch buffers.
5. A 1-second health timer detects client exit and cleans up the buffer.

** Lifecycle

- *Client exits*: health timer detects it gone from =gowl-list-clients=
  (compared by PID), kills the placeholder buffer.
- *Buffer killed*: =kill-buffer-hook= closes the Wayland client via
  =gowl-close-client=.
- *Window hidden*: overlay is hidden via =gowl-set-client-visible=.
  Switching back to the buffer re-shows it.

** Keyboard Focus (ESC Escape-Hatch)

Embedded clients receive keyboard input directly from the compositor.
An ESC-based escape hatch lets you switch between the embedded client
and Emacs:

- *ESC* (single press): returns keyboard focus to Emacs.  Subsequent
  keys are processed by Emacs (e.g. Evil normal-mode commands).
- *ESC ESC* (double press): sends a single ESC to the embedded client
  (useful for apps that use ESC, like vim or bash with =set -o vi=).
- *i / a* (in Evil normal state): gives keyboard focus back to the
  embedded client.  Also works with =I=, =A=, =o=, =O=, and =RET=.
- *Click* on the embedded area: also returns keyboard focus to the
  embedded client.

The escape hatch uses a 200ms timer to distinguish single from double
ESC.  Pressing ESC followed by another key within the timeout sends
the second key to Emacs.

The underlying primitive =gowl-embed-focus= can be called from Elisp
to programmatically give keyboard focus to any embedded client.

* Compositor Signals

Gowl emits GObject signals when compositor state changes.  These
signals are exposed to Elisp via =gobject-connect= on the compositor
object returned by =gowl-compositor=.

| Signal            | Arguments                     | Description                          |
|-------------------+-------------------------------+--------------------------------------|
| =client-added=   | =client=                      | A new client has been mapped         |
| =client-removed= | =client=                      | A client has been unmapped/destroyed |
| =focus-changed=  | =client= (or =nil=)          | Keyboard focus has moved             |

#+begin_src emacs-lisp
;; Low-level signal connection:
(gobject-connect (gowl-compositor) "focus-changed"
  (lambda (client)
    (message "Focus: %s" (gowl-client-info client))))
#+end_src

* Modules

Gowl provides a module system for extending the compositor with
shared-object plugins.  When running with =--gowl=, call
=gowl-start= before using any module functions.  The =--gowl= flag
pre-starts the compositor early, but =gowl-start= is still needed to
load bundled modules and initialize the Elisp integration.

#+begin_src emacs-lisp
(when (and (fboundp 'gowl-running-p) (gowl-running-p))
  (gowl-start)
  (gowl-enable-module "vanitygaps")
  (gowl-configure-module "vanitygaps"
    '(("inner-gap" . "16") ("outer-gap" . "8"))))
#+end_src

| Function                          | Description                              |
|-----------------------------------+------------------------------------------|
| =gowl-start=                     | Initialize modules and Elisp integration |
| =gowl-enable-module=             | Find, load, activate a module by name    |
| =gowl-disable-module=            | Deactivate a loaded module               |
| =gowl-configure-module=          | Configure a module with an alist         |
| =gowl-list-modules=              | List loaded module info alists           |

** Alpha (Window Opacity)

Per-client window opacity with automatic focus dimming.

#+begin_src emacs-lisp
(gowl-enable-module "alpha")
(gowl-set-focused-alpha 0.9)
(gowl-set-unfocused-alpha 0.9)
;; Per-client override:
(gowl-set-client-alpha client 0.5)
;; Set all clients at once:
(gowl-set-all-alpha 0.8)
;; Query:
(gowl-alpha-info)
  ;; => ((focused-alpha . 0.9) (unfocused-alpha . 0.9))
#+end_src

| =gowl-set-unfocused-alpha=       | Set unfocused window opacity             |

*** Seeing the Wallpaper Through Emacs

To make the Emacs frame transparent so the gowl wallpaper is visible
behind it, two things are needed:

1. *PGTK =alpha-background=*: Makes Emacs render its background with
   transparent pixels.  Text and UI elements stay fully opaque.
2. *Compositor-level alpha*: Any client opacity less than 1.0 forces
   wlroots to skip the opaque-region optimization and composite the
   wallpaper behind the frame.

wlroots resets scene buffer opacity to 1.0 on every surface commit.
Gowl re-applies the stored alpha after each commit so the
transparency persists across frames.

#+begin_src emacs-lisp
;; Complete setup (e.g. in Doom config.el):
(when (and (fboundp 'gowl-running-p) (gowl-running-p))
  (gowl-start)
  (gowl-enable-module "alpha")
  (gowl-set-focused-alpha 0.9)
  (gowl-set-unfocused-alpha 0.9)
  (gowl-set-wallpaper "~/Pictures/wallpaper.png")
  ;; PGTK: transparent background, solid text
  (set-frame-parameter nil 'alpha-background 85)
  (add-to-list 'default-frame-alist '(alpha-background . 85))
  ;; Force compositor to blend behind the Emacs frame
  (gowl-set-all-alpha 0.99))
#+end_src

** Status Bar

Compositor-level status bar showing, left to right: a dwm-style *tag
indicator*, the focused window title, and system widgets (cpu, memory,
clock, …).  Semi-transparent background so the wallpaper shows through.
Tiling layout automatically accounts for bar height.

Under =cmacs-gowl-mode= the bar is enabled automatically when
=cmacs-gowl-bar-show-tags= is non-nil (the default); set it to nil to
start without a bar (you can still =gowl-bar-enable= later).

#+begin_src emacs-lisp
(gowl-bar-enable)
(gowl-bar-configure
  '(("height" . "28")
    ("bg-color" . "#1e1e2ecc")
    ("fg-color" . "#cdd6f4")
    ("font" . "Hack Nerd Font Mono")
    ("font-size" . "13")))
#+end_src

*** Tag Indicator

The left edge renders one numbered box per tag (1--9), coloured by
state:

| State    | Meaning                                  |
|----------+------------------------------------------|
| selected | viewed on this monitor (filled)          |
| urgent   | has a client demanding attention (filled) |
| occupied | has clients but not selected             |
| empty    | no clients                               |

The indicator updates live as tags and windows change.  *The tag boxes
are clickable*: left-click a box to view that tag on that monitor,
right-click to toggle the tag's visibility — the same effect as
=Super+N= / =Super+Ctrl+N=, but per the monitor whose bar you click
(so it works naturally across monitors).

Toggle it and recolour it with the =show-tags= key and the tag colour
keys:

#+begin_src emacs-lisp
(gowl-bar-configure
  '(("show-tags" . "true")
    ("tag-active-bg" . "#89b4fa")
    ("tag-active-fg" . "#1e1e2e")
    ("tag-occupied-fg" . "#cdd6f4")
    ("tag-urgent-bg" . "#f38ba8")
    ("tag-urgent-fg" . "#1e1e2e")
    ("tag-empty-fg" . "#6c7086")))
#+end_src

| Function                          | Description                              |
|-----------------------------------+------------------------------------------|
| =gowl-bar-enable=                | Load and activate the bar module         |
| =gowl-bar-disable=               | Deactivate and reclaim tiling space      |
| =gowl-bar-configure=             | Configure bar appearance                 |
| =gowl-bar-redraw=                | Force full redraw                        |
| =gowl-bar-set-title=            | Set bar title (nil to revert to default) |

To keep the bar title in sync with the active Emacs buffer, use a
polling timer (hooks fire before window state is finalized):

#+begin_src emacs-lisp
(run-with-timer 0.2 0.2
  (lambda ()
    (ignore-errors
      (gowl-bar-set-title
        (buffer-name (window-buffer (selected-window)))))))
#+end_src

* Window Rules and Floating Popups

CMacs ships with two gowl modules that work together to keep
modal/popup windows out of the tiled layout:

- =windowrules= --- applies rules from the gowl config's =rules:=
  section to every new client at map time.  The rules are
  evaluated *before* the client is assigned a monitor, so a
  matched rule can force floating, override tags, pin a monitor,
  or set an explicit geometry without causing a visible
  tile→float flicker.  The module also re-evaluates rules when
  a client's title changes, which is the only way to catch apps
  like Zoom that rename their toplevel after map (the "Join
  Meeting" window is a classic case).
- =dropdown= --- manages Guake-style toggleable windows.  Each
  dropdown entry has a =spawn-cmd=, =keybind=, and =geometry=
  spec.  On first keypress the command is spawned and its first
  Wayland toplevel captured via a compositor prefloat hint; on
  subsequent presses the window is hidden/shown without being
  destroyed, and re-positioned on the currently focused output.

** YAML config

#+begin_example
rules:
  # Match by glob (default).  Float the pavucontrol popup.
  - app-id: "pavucontrol"
    floating: true

  # Match by regex.  Zoom sets its title to "Zoom Meeting" after
  # the initial xdg configure, so a post-map rule is needed.
  - title: "^Zoom Meeting$"
    floating: true
    regex: true

  # Explicit size + center on target monitor.
  - app-id: "org.keepassxc.KeePassXC"
    title: "Unlock"
    floating: true
    width: 500
    height: 200
    center: true

dropdowns:
  - name: term
    spawn-cmd: "foot"
    keybind: "Super+grave"
    width-pct: 1.0
    height-pct: 0.4
    anchor: top

  - name: btop
    spawn-cmd: "foot -e btop"
    keybind: "Super+F10"
    width-pct: 0.8
    height-pct: 0.6
    anchor: top
#+end_example

Rule fields:

| Key       | Type    | Description                                     |
|-----------+---------+-------------------------------------------------|
| =app-id=  | string  | Pattern matched against Wayland app_id         |
| =title=   | string  | Pattern matched against window title           |
| =regex=   | bool    | =true= for PCRE regex, otherwise shell glob    |
| =floating= | bool    | Force floating state                            |
| =tags=    | int     | Tag bitmask to assign                           |
| =monitor= | int     | Monitor index (-1 = any)                        |
| =width=   | int     | Explicit pixel width, 0 = keep natural          |
| =height=  | int     | Explicit pixel height, 0 = keep natural         |
| =center=  | bool    | Center floated match on monitor (default true) |

Dropdown fields:

| Key          | Type          | Description                             |
|--------------+---------------+-----------------------------------------|
| =name=       | string        | Unique identifier                        |
| =spawn-cmd=  | string        | Shell command spawned on first toggle    |
| =keybind=    | string        | Keybind (e.g. "Super+grave")             |
| =width-pct=  | float         | Fractional width (0.0–1.0)               |
| =height-pct= | float         | Fractional height (0.0–1.0)              |
| =width=      | int           | Absolute width in pixels (overrides pct) |
| =height=     | int           | Absolute height in pixels                |
| =anchor=     | top/bottom/left/right | Edge to attach to                |

** Elisp API

The rule and dropdown lists can also be defined from =init.el=
via defcustoms.  =cmacs-gowl-mode= pushes them into the running
gowl config at mode-enable time.

#+begin_src emacs-lisp
(setq cmacs-gowl-float-rules
      '((:app-id "pavucontrol"     :floating t)
        (:title  "^Zoom Meeting$"  :floating t :regex t)
        (:app-id "ch.protonmail.protonmail-bridge" :floating t)
        (:title  "Join Meeting"    :floating t)))

(setq cmacs-gowl-dropdowns
      '((:name "term"
         :spawn-cmd "foot"
         :keybind "Super+grave"
         :width-pct 1.0
         :height-pct 0.4
         :anchor top)
        (:name "btop"
         :spawn-cmd "foot -e btop"
         :keybind "Super+F10"
         :width-pct 0.8
         :height-pct 0.6
         :anchor top)))

(cmacs-gowl-mode 1)
#+end_src

Shipped defaults under =cmacs-gowl-float-rules= cover common
modal/popup windows: Zoom "Join Meeting", Proton Mail Bridge,
KeePassXC unlock, pavucontrol, pinentry, GTK/KDE "Open File" /
"Save As" / "Print" dialogs, and similar one-shot UI windows.
=cmacs-gowl-default-dropdown-terminal= lets you override the
default terminal used when a dropdown entry's =:spawn-cmd= is
nil.

Interactive commands:

| Command                         | Description                                 |
|---------------------------------+---------------------------------------------|
| =M-x cmacs-gowl-toggle-float=   | Toggle floating on the focused client       |
| =M-x cmacs-gowl-dropdown-toggle= | Prompt and toggle a dropdown by name        |
| =M-x cmacs-gowl-reapply-float-rules= | Re-sync rules from defcustom           |
| =M-x cmacs-gowl-reapply-dropdowns= | Re-sync dropdowns from defcustom          |

Float keybinds (served by the =windowrules= module):

| Key                   | Action                                    |
|-----------------------+-------------------------------------------|
| =Super+Space=         | Toggle floating on focused client         |
| =Super+c=             | Center focused floater on output          |
| =Super+Shift+Arrow=   | Move focused floater                      |
| =Super+Ctrl+Arrow=    | Resize focused floater                    |

These are configurable via the =windowrules= module's YAML
section (keys =toggle-float=, =center-float=, =move-float-*=,
=grow-float-*=, =shrink-float-*=).

** Why this matters (debugging escape hatch)

The =dropdown= module runs entirely inside the gowl compositor,
not in Emacs's event loop.  If Emacs freezes --- native
compilation stall, infinite Lisp loop, deadlock in a modal
prompt --- the =Super+grave= keybind still fires, the terminal
still appears, and you retain a shell from which to =gdb
--pid=$(pidof emacs)=, send signals, or inspect state.  This is
the primary motivation for the feature: an always-available
escape hatch that survives Emacs pathologies.
