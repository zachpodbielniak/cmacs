#+TITLE: Multi-Display Setup in cmacs --gowl
#+STARTUP: showall
#+OPTIONS: toc:2 num:t

* Overview

When running =emacs --gowl=, the gowl compositor manages all
connected displays.  You can query, reposition, and configure
monitors from Elisp to match your physical layout.

* Listing Monitors

#+begin_src emacs-lisp
;; List all monitors with their names
(mapcar (lambda (m)
          (cdr (assq 'name (gowl-monitor-info m))))
        (gowl-list-monitors))
;; => ("eDP-1" "DP-11" "DP-12")

;; Full info for a monitor
(gowl-monitor-info (car (gowl-list-monitors)))
;; => ((name . "eDP-1") (current-mode (2256 1504 59999)) ...)

;; Current positions
(mapcar (lambda (m)
          (cons (cdr (assq 'name (gowl-monitor-info m)))
                (gowl-monitor-position m)))
        (gowl-list-monitors))
;; => (("eDP-1" . (0 . 0)) ("DP-11" . (2256 . 0)) ...)
#+end_src

* Positioning Monitors

Use =gowl-set-monitor-position= to arrange monitors.  Coordinates
are in layout space (pixels).

#+begin_src emacs-lisp
(gowl-set-monitor-position X Y MONITOR)
#+end_src

** Example: Two External Monitors + Laptop Below

Two 2560x2880 monitors side-by-side at the top, laptop centered
below (mirroring a typical GNOME layout):

#+begin_src emacs-lisp
(let ((monitors (gowl-list-monitors)))
  ;; Find monitors by name
  (let ((laptop (cl-find-if
                  (lambda (m)
                    (string= "eDP-1"
                      (cdr (assq 'name (gowl-monitor-info m)))))
                  monitors))
        (ext1 (cl-find-if
                (lambda (m)
                  (string= "DP-11"
                    (cdr (assq 'name (gowl-monitor-info m)))))
                monitors))
        (ext2 (cl-find-if
                (lambda (m)
                  (string= "DP-12"
                    (cdr (assq 'name (gowl-monitor-info m)))))
                monitors)))
    ;; External monitors side-by-side at top
    (gowl-set-monitor-position 0 0 ext1)
    (gowl-set-monitor-position 2560 0 ext2)
    ;; Laptop centered below
    (gowl-set-monitor-position 1501 2880 laptop)))
#+end_src

** Example: Simple Side-by-Side

#+begin_src emacs-lisp
(let ((monitors (gowl-list-monitors)))
  (gowl-set-monitor-position 0 0 (nth 0 monitors))
  (gowl-set-monitor-position 1920 0 (nth 1 monitors)))
#+end_src

* Mirroring GNOME Layout

GNOME stores monitor layout in =~/.config/monitors.xml=.  To
mirror it in gowl, read the =<logicalmonitor>= entries and match
connectors (note: connector names may differ between GNOME and
gowl — =DP-9= in GNOME might be =DP-11= in gowl since the
Wayland backend creates new connector IDs).

Check both layouts:

#+begin_src shell
# GNOME layout
grep -E "<x>|<y>|<connector>" ~/.config/monitors.xml

# Gowl monitor names
emacs --batch --eval '(message "%S" (mapcar ...))'
#+end_src

* Monitor Properties

| Function                     | Description                        |
|------------------------------+------------------------------------|
| =gowl-list-monitors=        | List all monitor GObjects          |
| =gowl-monitor-info=         | Get full info alist for a monitor  |
| =gowl-monitor-position=     | Get current (x . y) position       |
| =gowl-set-monitor-position= | Set position in layout space       |
| =gowl-monitor-scale=        | Get current scale factor           |
| =gowl-set-monitor-scale=    | Set scale factor                   |
| =gowl-monitor-modes=        | List available modes               |
| =gowl-monitor-current-mode= | Get current mode (w h refresh)     |
| =gowl-usable-area=          | Get usable area after bar/gaps     |

* Multiple Frames (One Per Monitor)

Emacs supports multiple frames sharing the same session.  In
=--gowl= mode, each frame is a separate Wayland client that gowl
tiles on its own monitor.  No =emacsclient= needed — create frames
from within the running session:

#+begin_src emacs-lisp
;; Create a new frame (tiled on next available monitor)
(make-frame)
#+end_src

Each frame has its own buffer, window splits, and modeline, but
shares the same Emacs state (buffers, kill ring, variables).

** Auto-create frames for all monitors

#+begin_src emacs-lisp
;; In your IS-GOWL config, after positioning monitors:
(when (> (gowl-monitor-count) 1)
  (dotimes (_ (1- (gowl-monitor-count)))
    (make-frame)))
#+end_src

This creates one frame per monitor.  With 3 monitors you get 3
independent Emacs frames, each tiled on its own display.

** Why not emacsclient?

The =--daemon= + =emacsclient -c= approach also works but is
trickier with =--gowl= because the compositor thread must survive
the daemon fork.  =make-frame= from within the running session
avoids this entirely.

* Testing Multi-Monitor in a Nested Session

When developing inside GNOME (or another Wayland compositor), you
can simulate multiple monitors using wlroots' =WLR_WL_OUTPUTS=
environment variable:

#+begin_src shell
LIBDECOR_PLUGIN_DIR=/nonexistent WLR_WL_OUTPUTS=3 ./src/emacs --gowl
#+end_src

This creates 3 separate undecorated windows on your GNOME desktop,
each acting as a gowl output/monitor.

** Why LIBDECOR_PLUGIN_DIR=/nonexistent?

Gowl uses libdecor for window decorations in nested Wayland sessions.
Libdecor intercepts the first wlr_output and replaces it with a
decorated window.  With =WLR_WL_OUTPUTS > 1=, this conflicts:

- The decorated output starts at 0x0 dimensions (waiting for a
  configure from the parent compositor)
- The Emacs PGTK frame may map on the 0x0 output and never appear
- The swapchain reports "No free output buffer slot" errors

Setting =LIBDECOR_PLUGIN_DIR= to a nonexistent path disables
libdecor plugins, so all outputs are plain undecorated windows.
You lose the window title bar and close button, but all outputs
initialize correctly.

** Known Limitations

- The nested multi-output simulation creates undecorated windows
  without title bars (no resize handles, close buttons)
- For production multi-monitor use, launch from a TTY/login session
  where gowl controls real DRM outputs directly
- The =No free output buffer slot= warning from wlroots is harmless
  and occurs during initial output setup

* Tips

- After repositioning monitors, the bar and wallpaper automatically
  update via the =on_layout_change= callback.
- Each monitor gets its own independent tiling layout, wallpaper,
  and bar surface.
- The =gowl-bar-restart= function recreates bar surfaces if they
  appear at the wrong size after a layout change.
