#+TITLE: LibreClaw Installation
#+AUTHOR: Zach Podbielniak

* Prerequisites

LibreClaw pulls in a fairly large dependency graph.  On Fedora:

#+begin_src bash
sudo dnf install \
    glib2-devel gobject-introspection-devel \
    libsoup3-devel json-glib-devel libyaml-devel \
    cmark-devel sqlite-devel libetpan-devel \
    libpq-devel
#+end_src

On Debian/Ubuntu:

#+begin_src bash
sudo apt install \
    libglib2.0-dev libgirepository1.0-dev \
    libsoup-3.0-dev libjson-glib-dev libyaml-dev \
    libcmark-dev libsqlite3-dev libetpan-dev \
    libpq-dev
#+end_src

* Submodule

LibreClaw is *not* a submodule of cmacs.  It is clawtilla's, and cmacs
builds that one copy, at =deps/clawtilla/deps/libreclaw=.

The two projects move together, so a second pin here would put two
versions of the same library into one binary --- which is what the
static-library dedup rules in =src/Makefile.in= exist to survive, and
not a thing to add more of on purpose.  Clawtilla owns the pin:
*bumping libreclaw means bumping clawtilla*.

After cloning cmacs, run:

#+begin_src bash
git submodule update --init deps/clawtilla
git -C deps/clawtilla submodule update --init --recursive deps/libreclaw
#+end_src

The nested submodules =deps/ai-glib=, =deps/yaml-glib=, and
=deps/podomation= inside libreclaw are pulled in at the same time ---
though cmacs overrides =AI_GLIB_DIR= so libreclaw compiles against
cmacs's canonical =deps/ai-glib= rather than building a second one.

* Configure flag

Build cmacs with:

#+begin_src bash
./configure \
    --with-cmacs-glib --with-cmacs-gi \
    --with-cmacs-podomation \
    --with-cmacs-libreclaw \
    ... other flags ...
make -j$(nproc)
#+end_src

=--with-cmacs-libreclaw= implies =--with-cmacs-podomation= at runtime
(libreclaw shares its PodEngine), so make sure both are on.

* System vs bundled

Like the other cmacs subsystems, libreclaw supports:

- =--with-cmacs-libreclaw= — build from =deps/clawtilla/deps/libreclaw= (default)
- =--with-cmacs-libreclaw=system= — link against a system-installed
  =libreclaw >= 0.21.0= via =pkg-config= (0.21.0 added the bridge
  subsystem used by the remote mode; libdex-1 was also added to the
  system-deps set at the same time so the bundled mcp-glib can be
  embedded into the main library)

The bundled path pulls in libreclaw's vendored ai-glib, yaml-glib,
and podomation submodules.  The dedup logic in =src/Makefile.in=
strips yaml-glib and podomation duplicates from libreclaw's archive
at link time so the canonical cmacs versions win.

* GIR / typelib

Starting with libreclaw 0.18.0, the build always produces
=Lc-1.0.gir= and =Lc-1.0.typelib= (unless you pass =GIR=0=).  When
installed via =make install=, these land in
=$(libdir)/girepository-1.0= and =$(datadir)/gir-1.0= respectively.

For in-tree builds, point =GI_TYPELIB_PATH= at
=deps/clawtilla/deps/libreclaw/build/release= so =cmacs-gi=' =(gi-require "Lc" "1.0")=
finds the typelib:

#+begin_src bash
export GI_TYPELIB_PATH=$(pwd)/deps/clawtilla/deps/libreclaw/build/release:$GI_TYPELIB_PATH
src/emacs
#+end_src
