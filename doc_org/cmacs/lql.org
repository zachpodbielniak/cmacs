* Overview

LQL ([[https://git.podbielniak.com/zachpodbielniak/libre-query-language][libre-query-language]], the =deps/libre-query-language= submodule) is a pipeline query language: a source, then stages separated by =|=.

#+begin_src lql
fetch buffers
| filter modified and file != null
| fields name, file, size
| sort size DESC
#+end_src

=--with-cmacs-lql= links the language into cmacs.  You get every source the =lql= program has, plus the editor's own state as sources.  Results land in a grid you can sort, filter, mark and export, or in a REPL.  =.lql= files open with =lql-mode= and a language server that already knows cmacs's sources, with no setup.

What you get:

- *Every source the =lql= program has*: files of any format (JSON, JSON Lines, CSV, TSV, YAML, TOML, INI, XML, systemd units, logs in many dialects, compressed with gzip/zstd/xz/bzip2), =git_log= and the other git sources, =exec= and the command definitions (built-in plus =~/.config/lql/commands=), the systemd journal, coredumps, Kubernetes, and SQLite/PostgreSQL through =sql=.
- *The editor as data*: =buffers=, =windows=, =processes=, =recentf=, =kill_ring=, =bookmarks=, =org_headings=, =gowl_clients=, and anything you add with =cmacs-lql-define-source=.
- *Your notes as data*: =notes=, =note_headings=, =note_links= and =note_properties= over your PARA repository (=~/Documents/notes= by default), with named queries for inbox triage, stale projects, open TODOs, orphans, broken links and header lint (=M-x cmacs-lql-notes=).
- *A results grid* (=cmacs-lql-results-mode=), shared with the libresearch client: sort, narrow, refine locally, mark, copy, export, and =RET= to visit whatever a row names.
- *An async REPL* (=M-x cmacs-lql-repl=) with liblql's own completion and signature help.
- *=.lql= files that just work*: =lql-mode= (font-lock and indentation from upstream), eglot running the tree's =lql-language-server= against an environment file cmacs writes, and =C-c C-c= to run the query at point.
- *Agent and CLI surfaces*: the =lql_query= / =lql_sources= tools (in-process agents, CLI agents and MCP clients), =org.cmacs.Editor1.Lql= on D-Bus, and =emacsctl lql=.

Everything is read-only.  LQL has no statement that writes, and no cmacs source writes to the editor.

** Requirements

- Configure flag =--with-cmacs-lql=.  It is part of the default flag set and requires =--with-cmacs-glib=.
- Libraries: GLib/GIO, json-glib, yaml (libyaml), libxml2, zstd, xz (liblzma) and bzip2.  Optional: libsystemd (the journal source), sqlite3 and libpq (=sql= sources).
- Fedora packages: =json-glib-devel libyaml-devel libxml2-devel libzstd-devel xz-devel bzip2-devel=; optional =systemd-devel sqlite-devel libpq-devel=.  =./install-deps= installs them, and =./install-deps --check= reports any that are missing.

* Quick start

| Do this                                          | Get                                                                |
|--------------------------------------------------+--------------------------------------------------------------------|
| =M-x cmacs-lql-query RET fetch buffers RET=      | Every buffer, in a grid                                            |
| =M-x cmacs-lql-repl=                             | The REPL; type a query, =RET= runs it, =TAB= completes             |
| Visit =foo.lql=, write a query, =C-c C-c=        | The query at point (the region, or the block between blank lines) in a grid |
| =emacsctl lql query 'fetch processes'=           | The same from a shell, against a running cmacs                     |

Some queries to start from:

#+begin_src lql
# the ten biggest modified buffers
fetch buffers | filter modified | sort size DESC | limit 10

# TODOs across your agenda files, by file
fetch org_headings
| filter todo == "TODO"
| summarize n = count(), by: {file}
| sort n DESC

# who touched this repo most in the last month
fetch git_log | filter time > now() - 30d
| summarize commits = count(), by: {author}
| sort commits DESC

# failed units in the journal since boot
fetch journal | filter priority <= 3 | fields time, unit, message
#+end_src

* Architecture

** Two archives, one environment

The build links two archives from the submodule:

- =liblql-1.0.a= :: The language: parser, checker, evaluator, executor, built-in functions and commands, the memory source, and the assist code (completion, hover, signature, diagnostics, format).  It needs only GLib.
- =liblql-tools.a= :: The sources and formats the =lql= program offers.  =lql_tool_register_sources= and =lql_tool_register_sql= register them on an environment exactly as the program does.  This archive is why a query in cmacs can read what the CLI can.

cmacs builds exactly one =LqlEnvironment= per process, on first use, not at startup.  An Emacs that never runs a query never reads =~/.config/lql= and never probes for =kubectl= or =journalctl=.  The registration order matches the =lql= program:

1. the language's built-ins (=lql_environment_new=);
2. the tool sources (files, git, exec and command definitions, journal, coredumps, Kubernetes);
3. SQL;
4. the user's aliases, last, so an alias can never take the name of a source;
5. the Elisp sources, as they are defined.

** The C/Lisp split

The subsystem has three translation units, split the way dbexplorer is:

| File                       | Sees               | Role                                                      |
|----------------------------+--------------------+-----------------------------------------------------------|
| =cmacs/lql/cmacs-lql-env.c=    | =<lql.h>=, tool headers | The environment, snapshots, result JSON, the assist wrappers |
| =cmacs/lql/cmacs-lql-defuns.c= | =lisp.h=           | The DEFUNs, the job registry, the worker thread           |
| =cmacs/lql/cmacs-lql-init.c=   | =lisp.h=           | =syms_of_= / =init_= aggregation                          |

=cmacs-lql-env.c= never includes =lisp.h= and =cmacs-lql-defuns.c= never includes =<lql.h>=.  Only C strings cross between them: JSON in, JSON out.

** Threading: queries never run on the editor's thread

A query can take seconds: a =git_log= over a large repo, the journal, a remote PostgreSQL.  So:

1. =cmacs-lql--run= queues a job on a one-thread =GThreadPool= and returns an integer id at once.  Jobs run one at a time.
2. The worker runs the job under a private thread-default =GMainContext=, so an async source never touches the editor's loop.  (cmacs-ai-libresearch.c does the same, because MCP and D-Bus callers wait with polling from inside a dispatch, and a request bound to the editor's own context would never complete there.)
3. The payload comes back either to a callback, delivered once on the Lisp thread through =cmacs_glib_invoke_on_main=, or to a caller polling =cmacs-lql--poll=.  Pending callbacks live in a =staticpro='d hash table, never in the C job.

*Editor state is never read from the worker thread.*  Before submitting, Lisp finds which Elisp sources the query names (whole-symbol matches) and calls their functions on the Lisp thread.  It serialises the rows to JSON and sends them with the job as =:snapshots=.  The worker installs them as =LqlMemorySource= tables while it holds the environment lock, then runs the query.

** Locking: the editor never waits

=ENV_LOCK= guards the environment.  A run holds it from installing its snapshots until its table is built, so a snapshot is never swapped under a running fetch.

The editor-side helpers are completion, hover, signature, diagnostics, describe, explain and format.  They only *try* the lock.  If a query holds it, they signal =cmacs-lql-busy= (a child of =cmacs-lql-error=), and the Lisp wrappers turn that into "no answer this time".  A frozen minibuffer would be worse than a missing candidate.

Source definitions go on a separate pending list with its own small lock, and the next holder of =ENV_LOCK= applies them.  So =cmacs-lql-define-source= never blocks either.

** Payloads and result JSON

| Payload                                                 | Meaning               |
|---------------------------------------------------------+-----------------------|
| =(:ok :json JSON :text TEXT :rows N :elapsed SECONDS)=  | Success               |
| =(:error MESSAGE)=                                      | Parse/check/run error |
| =(:cancelled)=                                          | =cmacs-lql--cancel=   |

=JSON= is =&#123;"columns":[&#123;"name","type"&#125;],"rows":[[...]],"total":N&#125;=.  Cells are liblql's own JSON for each value, so arrays and records stay structured.  =total= counts every row the query produced, even when =:max-rows= truncated =rows=.  =TEXT= is present only when =:text-width= asked for it; it is =lql_table_to_text_wrapped=.  =cmacs-lql-parse= turns =JSON= into =(:columns ((NAME . TYPE)...) :rows (VECTOR...) :total N)=.

** Offsets

liblql uses byte offsets into UTF-8.  A multibyte Lisp string's data is UTF-8 for any text a query can contain, so the DEFUNs pass =SSDATA= unchanged and convert the character position on the way in (=string_char_to_byte=).  Offsets in the returned JSON stay in bytes; =cmacs-lql--byte-to-char= converts the few Lisp needs (completion bounds).

(add-hook 'cmacs-lql-results-visit-functions

#+end_src

** The REPL (=cmacs-lql-repl-mode=)

- =RET= runs a complete query.  A line ending in =|=, =,= or =(= continues on the next line, and =C-j= always does.  =M-RET= sends regardless.
- =TAB= completes from =lql_assist_complete=: sources (cmacs's included), commands, functions, columns of the source in play, keywords.  Candidates carry their kind and documentation for corfu/company.
- Eldoc shows the signature of the call at point.
- Queries run async on the worker; the prompt comes back with the rows, and =C-c C-k= cancels.
- Each table prints as aligned text, at most =cmacs-lql-repl-max-rows= rows, followed by a =[grid]= button that opens the full result in a grid.

** Defining your own

#+begin_src emacs-lisp
(cmacs-lql-define-source
 "features"
 '(("name" string) ("autoloaded" boolean))
 (lambda ()
   (mapcar (lambda (f) (list :name f :autoloaded (and (autoloadp (symbol-function f)) t)))
           features))
 "Loaded Lisp features.")
#+end_src

- =NAME= must be an identifier (=[A-Za-z_][A-Za-z0-9_]*=).  It cannot shadow a built-in or tool source; the definition is dropped with a warning.  Redefining an Elisp source replaces it.
- Column types: =string=, =int=, =double=, =boolean=, =timestamp=, =duration=, =array=, =record=, =any=.  Aliases =integer=, =float=, =number=, =bool= and =list= are accepted.
- A row is a plist (=:col VALUE ...=) or an alist.  Columns a row leaves out are =NULL=, and fields beyond the declared columns come along untyped.
- Conversion: =nil= in a boolean column is false and elsewhere =NULL=.  A Lisp time value or =float-time= seconds becomes a Timestamp, and a number in a duration column is seconds.  A list becomes an Array, a keyword plist a Record, a buffer its name.
- A function that signals costs that source's rows (a message says why); the query still runs.

* Notes sources: your PARA repository

=lisp/cmacs/cmacs-lql-notes.el= makes your org notes repository four LQL sources:

#+begin_src lql
fetch notes | filter para == "inbox" | sort modified DESC
#+end_src

** Where your notes are

The notes directory is =cmacs-para-roots=, whose default is =("~/Documents/notes")=.  That one setting is shared with roamgraph, secondbrain and the brigade memory index, so moving your notes moves all of them:

#+begin_src emacs-lisp
(setq cmacs-para-roots '("~/notes"))
#+end_src

To point only the LQL sources somewhere else, set =cmacs-lql-notes-directories= (nil means "same as =cmacs-para-roots="):

#+begin_src emacs-lisp
(setq cmacs-lql-notes-directories '("~/work-notes" "~/Documents/notes"))
#+end_src

PARA classification (=para=, =scope=, =area=) is made against whichever directory holds the file.  Several directories are fine; the longest match wins.

*** =note_headings= --- one row per heading

=file=, =path=, =para=, =scope=, =area=, =line=, =level=, =heading= (without keyword, priority or tags), =todo=, =done=, =priority=, =tags=, =scheduled=, =deadline=, =closed= (Timestamps), =id=, =olpath= (=Parent / Child=).

TODO keywords come from the file's own =#+TODO:= / =#+SEQ_TODO:= / =#+TYP_TODO:= lines when it has them.  Otherwise they come from =cmacs-lql-notes-todo-keywords= and =cmacs-lql-notes-done-keywords=.

*** =note_links= --- one row per =[[link]]=

=file=, =path=, =para=, =line=, =type= (=id=, =file=, =https=, ..., or =fuzzy= for an internal link), =target=, =description=, =resolved= (the file an =id:= or =file:= link points at), =exists=.

A remote (Tramp) target is never checked, because a query must not open SSH connections.  Its =exists= is false.

*** =note_properties= --- one row per property-drawer entry

=file=, =path=, =para=, =line=, =heading= (NULL for the file-level drawer), =key=, =value=.

** Queries worth keeping

=M-x cmacs-lql-notes= offers these by name (=cmacs-lql-notes-queries=, an alist you can extend), or runs whatever LQL you type:

| Name                         | Query (abridged)                                                          |
|------------------------------+---------------------------------------------------------------------------|
| Inbox triage                 | =fetch notes \vert{} filter para == "inbox" \vert{} sort modified DESC=   |
| Recently updated (7 days)    | =filter updated > now() - 7d=                                             |
| Stale projects               | projects, not indexes, =age_days > cmacs-lql-notes-stale-days=            |
| Open TODOs                   | =fetch note_headings \vert{} filter is_not_null(todo) and not done=       |
| Due within a week            | =filter not done and is_not_null(deadline) and deadline < now() + 7d=     |
| Missing header keywords      | =filter not has_header=                                                   |
| Orphans (nothing links here) | =filter backlinks == 0 and not index and not daily=                       |
| Broken links                 | =fetch note_links \vert{} filter (type == "id" or type == "file") and not exists= |
| Notes per area               | =summarize notes = count(), words = sum(words), by: {para, area}=         |
| Tags                         | =expand tags, as: tag \vert{} filter is_not_null(tag) \vert{} summarize ...= |
| Unsaved notes                | =filter unsaved=                                                          |

In a note:

| Command                      | Shows                                    |
|------------------------------+------------------------------------------|
| =cmacs-lql-notes-backlinks=  | Every link anywhere pointing at this note |
| =cmacs-lql-notes-outgoing=   | Every link this note makes               |

*NULL is three-valued in LQL.*  =x != null= is NULL, never true, so =filter todo != null= keeps nothing.  Test presence with =is_not_null(x)= / =is_null(x)=.

** How it stays fast

- Files are parsed with plain regexps (no =org-mode= per file) and cached by modification time and size.  Only files that changed since the last query are read again.  A note open in a buffer is read from the buffer, unsaved edits included.
- Each source has a generation function (=cmacs-lql-set-source-generation=), so while nothing changed a query reuses the last snapshot's JSON instead of re-serialising every row.  The hour is part of the key because =age_days= moves with the clock.
- With =cmacs-lql-notes-warm-in-idle= (default =t=), the cache warms in idle time, =cmacs-lql-notes-warm-batch= files per step, and stops at the first input.  A cold first query over about 3,500 notes takes several seconds; a warm one takes a fraction of a second.
- Files larger than =cmacs-lql-notes-max-file-size= contribute only their header.  =cmacs-lql-notes-exclude-regexp= skips =.git=, =.stversions=, =node_modules= and =.trash=.  =cmacs-lql-notes-include-archives= nil leaves =04_archives= out.
- =M-x cmacs-lql-notes-clear-cache= forgets everything.

* The language server and =lql-mode=

=lql-mode= is upstream's, from =deps/libre-query-language/editors/emacs= in a dev tree or the installed =site-lisp=.  It provides font-lock, indentation and the =.lql= association.  cmacs adds:

- =auto-mode-alist= sends =.lql= through =cmacs-lql-mode-autoload=, which loads the mode and binds the keys above.
- *eglot*: =eglot-server-programs= maps =lql-mode= to =cmacs-lql-server-contact= (upstream's own registration is turned off so the two cannot race).  The contact runs the tree's =lql-language-server= (=build/debug= or =build/release=, or =CMACS_LQL_DIR=), else the one on =PATH=, with =--environment= pointing at =cmacs-lql-environment-file= (=$XDG_CACHE_HOME/cmacs/lql-environment.json=), plus any =lql-environment-commands=.
- *The environment file* is =lql_environment_describe= of cmacs's own environment: built-ins, tool sources and the Elisp sources.  So completion, hover and diagnostics in =.lql= files know =buffers= and its columns.  It is rewritten (debounced, write-then-rename) whenever a source is defined, and the server reloads it on change.
- =cmacs-lsp-ensure= starts eglot when a =.lql= file opens, under =cmacs-lql-auto-eglot=.
- *=ob-lql=*: loaded after org, with =ob-lql-program= pointed at the tree's =lql= so =#+begin_src lql= blocks run with no PATH setup.

What the language server answers is listed in [[file:../../deps/libre-query-language/docs/editor/][the LQL editor docs]]: completion with resolve and snippets, hover with column types per pipeline stage, signature help, go to definition, references, rename, document symbols, inlay hints (the schema after each stage), code actions (did-you-mean), formatting, folding, semantic tokens and pull diagnostics.

* Agent, D-Bus and CLI surfaces

** Agent tools

=lisp/cmacs/cmacs-brigade-research.el= defines two brigade tools.  A brigade tool reaches in-process agents, CLI agents over the MCP relay, and external MCP clients from one definition:

- =lql_query= :: =query=, optional =max_rows= (default 100, at most 2000).  Returns the rows as a text table plus a count and timing.
- =lql_sources= :: Every source, with the editor's own listed separately.

** D-Bus: =org.cmacs.Editor1.Lql=

| Method      | In                    | Out     |
|-------------+-----------------------+---------|
| =Query=     | =s query=, =i max_rows= | =s table= |
| =QueryJson= | =s query=, =i max_rows= | =s json=  |
| =Explain=   | =s query=             | =s plan=  |
| =Sources=   |                       | =s sources= |

A bad query is a normal reply that starts with =error: =, not a D-Bus error.  =max_rows= <= 0 means 100, capped at 10000.  The query text reaches Lisp only through =cmacs_dbus_lisp_escape=.

** =emacsctl lql=

#+begin_src sh
emacsctl lql query 'fetch buffers | filter modified' 20
emacsctl lql json 'fetch processes' -o table
emacsctl lql explain 'fetch git_log | limit 5'
emacsctl lql sources
#+end_src

* Lisp API

| Function                          | Does                                                            |
|-----------------------------------+-----------------------------------------------------------------|
| =cmacs-lql-run QUERY CALLBACK &rest OPTS= | Async run; returns the id.  OPTS: =:max-rows= =:text-width= =:timeout= (seconds) |
| =cmacs-lql-run-sync QUERY &rest OPTS= | Run and wait (safe inside MCP/D-Bus dispatch); returns the payload |
| =cmacs-lql-wait ID &optional TIMEOUT= | Wait for an id                                               |
| =cmacs-lql-parse JSON=            | Result JSON → table plist                                       |
| =cmacs-lql-payload-table PAYLOAD= | Table plist of an =:ok= payload                                 |
| =cmacs-lql-define-source NAME COLUMNS FN &optional DOC= | Define an Elisp source            |
| =cmacs-lql-completions TEXT POS=  | =(LABEL KIND DETAIL DOC START END)= list, or nil while busy     |
| =cmacs-lql-hover-text TEXT POS=   | Hover markdown, or nil                                          |
| =cmacs-lql-results-show QUERY TABLE &key target mode buffer= | Show a computed table in a grid  |
| =cmacs-lql-results--loading QUERY &key target buffer mode parent= | Open a grid and run QUERY on TARGET |

A /target/ is =local=, =libresearch=, or a function =(lambda (query callback))= whose callback receives a table plist or =(:error MSG)=.  The libresearch search grid is built this way.

** Primitives (=cmacs/lql/cmacs-lql-defuns.c=)

=cmacs-lql--run=, =--poll=, =--cancel=, =--define-source=, =--describe=, =--complete=, =--hover=, =--signature=, =--diagnose=, =--explain=, =--format=, =--sources=, =--version=.  Errors: =cmacs-lql-error=, and =cmacs-lql-busy= (a child of it).

* Build notes

- =configure.ac= decides which optional drivers =liblql-tools.a= gets (journal, sqlite, postgres) by probing, passes them to the sub-make (=CMACS_LQL_MAKE_FLAGS=), and links exactly those libraries.  =TUI= is always off.
- LQL's nested =deps/yaml-glib= is skipped (=admin/cmacs-submodules.sh=).  The tools archive and programs use cmacs's canonical =deps/yaml-glib= (=YAML_GLIB_DIR=), linked last so an archive that already embeds those objects (libregnum) satisfies them first.
- LQL's include directories are =-isystem=, so cmacs's warning set does not land on a third-party header.  Because =CMACS_LQL_CFLAGS= is in =ALL_CFLAGS= and names =build/<type>/include= (generated by LQL's build), every object is order-only on the LQL build.  Without that, a fresh parallel build warns =-Wmissing-include-dirs= once per object.
- =make install= installs =lql=, =lql-language-server= and upstream's =lql-mode.el= / =ob-lql.el= into the standard =site-lisp=.
- =just verify-fresh= covers the archives (class =dep-libre-query-language=).

* Troubleshooting

- *"an LQL query is running; try again"* :: A helper (completion, explain, describe) found the environment busy.  Wait for the query, or =C-c C-k= it.
- *A new source is not offered by completion in a =.lql= buffer* :: The environment file is rewritten on an idle timer; =M-x cmacs-lql-write-environment= forces it.
- *=fetch NAME= says unknown source* :: =M-x cmacs-lql-repl= then =:sources=.  An Elisp source whose name collides with a built-in one is refused (see =*Messages*=).
- *An Elisp source returns no rows* :: Its function signalled; =*Messages*= has =cmacs-lql: source NAME failed: ...=.
- *=.lql= opens in =prog-mode= with a message* :: =lql-mode= was not found: the submodule is missing in a dev tree, or the installed site-lisp copy is.
