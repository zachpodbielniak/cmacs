* What this subsystem is for

Six formats — =.docx=/=.odt=, =.xlsx=/=.ods=, =.pptx=/=.odp= — treated as
structured documents rather than as opaque blobs rendered to page images.

The formats are two vocabularies over one idea: a zip package of XML parts, called
OPC by OOXML and an ODF package by OpenDocument. That shared shape is why one
container layer serves all six, and why the work factors into a container, three
document models, and six thin codecs rather than six independent implementations.

* Roadmap

Every phase is implemented. This table is the honest status.

| Phase | Scope | Status |
|-------+-------+--------|
| 0 | Package container: open, enumerate, read, replace, delete, save, save-as; hostile-input guards; the round-trip gate | *Implemented* |
| 1 | Package layer over OPC/ODF metadata, the codec registry, content-based format detection, relationships, normalised metadata | *Implemented* |
| 2 | Text and cell extraction for all six formats, projected to an org buffer with writeback anchors | *Implemented* |
| 3 | Spreadsheets: cell editing with run-length splitting, grid projection, formulas through GNU Calc | *Implemented* |
| 4 | Word documents: surgical paragraph editing resolved by anchor | *Implemented* |
| 5 | Slides: shape text editing across both shape conventions | *Implemented* |
| 6 | Authoring =.docx= from org via a template donor; =ox-odt= handoff for =.odt= | *Implemented* |
| 7 | Page preview through =doc-view=, with flatpak-aware LibreOffice discovery | *Implemented* |
| 8 | Brigade/MCP tools so agents can read and edit these documents | *Implemented* |

** Why breadth before depth

Phase 2 gives text extraction for all six formats before any one format gets deep
treatment. Once the container exists that is cheap, and it is what makes every
Office file in the notes repo and every mail attachment greppable and
agent-readable — which is most of the day-to-day value, delivered before the
expensive work starts.

Phases 3, 4 and 5 are independent of each other. Any of them can be reordered or
deferred without stranding the others.

* The two rules to not break

1. *The shadow package.* Never regenerate a part you did not parse. This is what
   makes partial format coverage safe rather than reckless. [[file:fidelity.org][fidelity.org]] explains
   the consequences in detail.

2. *The container never sees =lisp.h=.* Keeping the package layer free of Emacs
   headers is what keeps it testable without a Lisp VM, and what would let it be
   lifted into a standalone library later without restructuring.
