#+STARTUP: showall

* What Is CMacs

CMacs is GNU Emacs with deep GLib/GObject/Wayland integration.  It adds
several subsystems as C primitives (DEFUNs), all built into the editor:

The list below is the compile-time feature set.  It is generated from
the same table that backs the =IS-CMACS-*= variables ---
=cmacs/core/cmacs-features.c=, the single source of truth for what is
built in --- so =(cmacs-compiled-features)= in a live editor returns
exactly these names.  Ask =(cmacs-feature-p 'roamgraph)= for one of them,
or read [[file:build.org][build.org]] for the configure flags.

** Foundations

| Subsystem      | Directory            | Purpose                                                   |
|----------------+----------------------+-----------------------------------------------------------|
| *glib*         | =cmacs/glib/=          | GMainContext event-loop integration, D-Bus, eval dispatch |
| *gobject*      | =cmacs/gobject/=       | GObject ↔ Lisp bridge, GClosure wrappers                  |
| *gi*           | =cmacs/gi/=            | GObject Introspection --- call any GI-registered library    |
| *api*          | =cmacs/api/=           | Shared C library (=libcmacs-api.so=) for editor control     |
| *dbus*         | =cmacs/dbus/=          | The =org.cmacs.Editor1= surface and its events firehose     |
| *mcp*          | =cmacs/mcp/=           | MCP server over a Unix socket; AI-native introspection    |
| *emacsctl*     | =cmacs/emacsctl/=      | kubectl-style CLI over D-Bus; standalone binary           |

** Languages and shells

** Tools

| Subsystem      | Directory            | Purpose                                                   |
|----------------+----------------------+-----------------------------------------------------------|
| *calculator*   | =cmacs/calculator/=    | Desktop / financial / physics / CAS over GNU Calc          |

Two entries are pure Elisp and so have no =cmacs/<name>/= directory:
*transcode* and *transcribe* live entirely in =lisp/cmacs/=.  *gsurf-lrg*
is a second backend inside =cmacs/gsurf/= rather than a subsystem of its
own, but it carries its own configure flag and so its own feature name.

* Source Layout

#+begin_example
cmacs/                C source, one directory per subsystem
  core/               Feature registry (cmacs-features.c) -- always linked
  glib/               GLib loop, D-Bus, eval dispatch
  gobject/  gi/       GObject bridge; GObject Introspection
  dbus/               org.cmacs.Editor1 surface + events firehose
  api/                Shared C library (libcmacs-api.so)
  crispy/  bacon/     C scripting; embedded shell
    bacon/modules/    Bacon native modules (starship, fzf, ...)
  gowl/               Wayland compositor
  gsurf/              Embedded web browser (+ its --lrg backend)
    gsurf/modules/    gsurf native modules
  libregnum/          3D scene buffers; the shared render context
  lrgterm/            output_lrg display backend
  lrgscript/          Elisp as a libregnum scripting language
  gnuseye/            Planetary globe
  roamgraph/          org-roam knowledge graph
  imgedit/  vidstudio/  Image and video editors
  screensaver/        Screensavers as wallpaper / lock / buffer
    screensaver/render/  Out-of-process render child
  cad/                Parametric CAD
  video/  audio/  whisper/  piper/   Media, STT, TTS
  ai/  ai-brigade/  libreclaw/       AI surface, fabric, chat gateway
  calculator/  lsp/   Calculator; in-binary LSP servers
  podomation/         Automation engine
  org-ex/             Org widget embedding (+ org-ex/lib/)
  mcp/                MCP server
  emacsctl/           emacsctl/cmacsctl CLI (standalone binary)
  cintrospect/  cpatch/   Runtime C introspection and hot-patching
  print/              CUPS virtual printer
  compat/             Compatibility shims
  cmacs.h             Master header
deps/                 Git submodules (crispy, bacon, gowl, libregnum, ...)
lisp/cmacs/           Elisp layer for each subsystem
test/cmacs/           ERT tests, one file per subsystem
doc/cmacs/            Texinfo manual
doc_org/cmacs/        Org manual (this documentation)
#+end_example

Every =.c= named in a subsystem's =CMACS_*_OBJ= is symlinked from
=cmacs/<dir>/= into =src/= by the =cmacs-symlinks= target and compiled by
the ordinary =src/= rules, which is why there is no per-directory
Makefile.  =CMACS_DIRS= in =src/Makefile.in= lists the directories that
target searches.

* How The Pieces Fit Together

#+begin_example
┌─────────────────────────────────────────────────────────┐
│                    Emacs (temacs)                        │
│                                                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│  │ GLib loop │  │ GObject  │  │    GI    │              │
│  │ + D-Bus   │  │  bridge  │  │  bridge  │              │
│  └────┬─────┘  └──────────┘  └──────────┘              │
│       │                                                 │
│  ┌────┴──────────────────────────────┐                  │
│  │         eval dispatch             │                  │
│  │  (cmacs-eval-dispatch.c)          │                  │
│  └────┬──────────────┬───────────────┘                  │
│       │              │                                  │
│  ┌────┴─────┐   ┌────┴──────┐   ┌──────────┐           │
│  │  Bacon   │   │  Crispy   │   │   Gowl   │           │
│  │  shell   │   │ C scripts │   │ Wayland  │           │
│  └────┬─────┘   └────┬──────┘   └──────────┘           │
│       │              │                                  │
│       │         ┌────┴──────┐                           │
│       │         │ DIRECT    │                           │
│       │         │ dispatch  │                           │
│       │         └────┬──────┘                           │
│       │              │                                  │
│  ┌────┴──────────────┴───────────────┐                  │
│  │      libcmacs-api.so              │                  │
│  │  transport / helpers / commands   │                  │
│  └───────────────────────────────────┘                  │
└─────────────────────────────────────────────────────────┘
#+end_example

- *Bacon* communicates via socketpair (FD transport) --- it forks from Emacs
- *Crispy* scripts run in-process via =g_module_open= (DIRECT transport) --- zero IPC
- *External tools* use D-Bus transport (=org.cmacs.Editor1=)
- All three share =libcmacs-api.so= for the same command set

* Config File Search Order

CMacs checks for config files in this priority:

1. =$XDG_CONFIG_HOME/cmacs/= (default: =~/.config/cmacs/=)
2. =user-emacs-directory= (=~/.emacs.d/=)

This keeps CMacs-specific config (=init.bacon=, =init.c=) separate from
vanilla Emacs.  Elisp =init.el= is always loaded from =user-emacs-directory=.
