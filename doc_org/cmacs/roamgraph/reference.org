* Node plist schema

The vector handed to =cmacs-roamgraph-set-graph=. Only =:id= is required.

| Key       | Type    | Meaning                                                  |
|-----------+---------+----------------------------------------------------------|
| =:id=       | string  | The org-roam id.  *The identity key* — everything keys on it |
| =:title=    | string  | Display title (defaults to =:id=)                          |
| =:file=     | string  | Absolute path of the file the note lives in              |
| =:level=    | integer | 0 for a file-level node, >0 for a heading-level one       |
| =:pos=      | integer | Character position of the node within =:file=              |
| =:tags=     | list    | Strings, without the surrounding colons                  |
| =:aliases=  | list    | Strings                                                  |
| =:refs=     | list    | Strings                                                  |
| =:group=    | string  | Colour/grouping bucket, e.g. the PARA directory          |
| =:color=    | integer | =0xRRGGBBAA=                                               |

Any *other* key is preserved untouched and handed back by =cmacs-roamgraph-node-at=. That is the extension point: attach whatever your source knows, read it back on a pick.

=:level= and =:pos= are not decoration. =RET= uses them to open a heading-level node at its own heading rather than at line 1 of a long file, which is roughly half the nodes in a mature database.

* Edge plist schema

| Key      | Type   | Meaning                                        |
|----------+--------+------------------------------------------------|
| =:from=    | string | Source node id                                 |
| =:to=      | string | Destination node id                            |
| =:kind=    | symbol | =id= (default), =cite=, or =sim=                     |
| =:weight=  | float  | Attraction weight; defaults to 1.0             |

Edges whose endpoints are not *both* present are dropped silently — dangling =[[id:]]= links are normal in a live tree. Self-loops are dropped. An =A→B= and =B→A= pair collapses to one spring rather than double-weighting it.

=sim= edges are weighted 0.35 in the solver so they nudge without competing with real links, render violet, and are excluded from link navigation.

=cmacs-roamgraph-neighbors= returns forward links first, then backlinks, each group ordered by the neighbour's title. That order is stable across a rebuild, which is what makes =>= then =<= land back where it started.

| DEFUN                                | Notes                                  |

** Panes

Node list and tags are =motion= state under Evil; the inspector is =normal=. All three are promoted with =cmacs-evil-intercept-mode-map= so evil-snipe stops shadowing =s=/=f=/=t=. =SPC= is deliberately never bound in a pane — it is the Doom leader there.

| Pane      | Keys                                                    |
|-----------+---------------------------------------------------------|
| nodes     | =RET= select, =TAB= peek, =o= other window, =/= =s= =f= =c= =g= =q=   |
| tags      | =RET= or =x= toggle the filter, =c= clear, =g= =q=            |
| inspector | =RET= =O= =f= =y= =g= =q=, plus =1=–=9= / =a=–=z= live link keys  |

* Performance

Measured on a 1166-node, 1321-edge database at 1400×900:

| Stage                     | Time    |
|---------------------------+---------|
| Read the database         | 0.06 s  |
| Build the graph and scene | 0.01 s  |
| Full layout solve         | 0.70 s  |
| One render + readback     | ~36 ms  |

The solve is 408 iterations at 1.7 ms each. Brute-force repulsion at that node count would be ~1.4M pair evaluations per iteration, which is why Barnes–Hut is not a deferred optimisation.
