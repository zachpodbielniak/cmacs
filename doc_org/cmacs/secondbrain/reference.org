* Node plist

Passed to =cmacs-secondbrain-set-graph=. *Any key not listed here is preserved* and comes back from =cmacs-secondbrain-node-at=, which is how the context menu and the AI resolver read their own fields.

| Key | Meaning |
|-----+---------|
| =:id= | identity key, required.  Scene indices churn on rebuild; this does not |
| =:title= | display title (defaults to =:id=) |
| =:file= | absolute path, when the node is backed by one |
| =:ring= | =skills= / =memory= / =routines= / =applications=, or an index |
| =:kind= | =hub= / =file= / =folder= / =app= / =routine= / =skill= / =centre= |
| =:department= | grouping within a ring; laid out as a contiguous arc |
| =:parent= | the =:id= of the parent node, for collapse |
| =:collapsed= | non-nil to fold this node's subtree |
| =:color= | =0xRRGGBBAA=; defaults to the ring's colour |

An unrecognised =:ring= falls back to =memory= rather than signalling — a source that grows a category should degrade, not take the graph down.

| =:edge-kind= | =id= (default), =cite= or =sim= |

* Keys

Press =?= in the map (=cmacs-secondbrain-menu=, a transient showing each toggle's state) or =M-?= (=cmacs-secondbrain-help=, plain text with the legend); the manual has the same list.  The map is =cmacs-secondbrain-mode-map=, deriving from =cmacs-libregnum-mode-map=.

The mode declares Evil *emacs state* for itself.  It has to: =evil-set-initial-state= is looked up per mode, so inheriting from a parent that declares it is not enough, and without it =h=, =j=, =k=, =l=, =n=, =a=, =e= and =c= are Evil motions — which is what made this a mouse-only tool under Doom.

* Mouse

| Gesture | Effect |
|---------+--------|
| Left click on a department | select it *and expand or fold it* |
| Left click on a leaf | select it; the inspector follows |
| Double click a node | select it and fly the camera to it |
| Left drag a node | move it; it pins where you drop it |
| (no click moves the camera) | =f= flies deliberately, keeping context |
| Hover anything | light up it and what it links to, dim the rest |
| Left drag | orbit (3D), continuously through the poles; no effect in the locked 2D view |
| Right drag | pan |
| Wheel | zoom, wheel-up towards the scene |
| Right click | the context menu for that node's kind, AI section last |

Clicking a department expands it because that is the whole interaction: the rings tell you what exists, and a click tells you what is inside.  Making expand a separate keystroke would mean the obvious gesture on the obvious target does nothing.

*A click does not move the camera.* libregnum's input layer flies to whatever a left click hits, which is right for a scene you navigate /by/ clicking and wrong here: the click starts an animation, and the camera arriving on top of the hub hides the one thing you clicked to see. =f= flies deliberately, keeping =cmacs-secondbrain-fly-context= of the graph's extent between camera and node — the node's own size says nothing about the scale of the graph around it, so without that floor a fly-to frames one sphere and none of its surroundings.

** The framebuffer must match its window

=cmacs-secondbrain--fit-window-now= resizes the framebuffer to the window's *body* pixel size — the text area, fringes and mode line excluded — and =window-size-change-functions= re-runs it (coalesced through a 0.06 s idle timer) whenever the window changes.

This is not cosmetic, and neither is the word /body/.  The picture, the click mapping and the framebuffer are a three-party contract: the pgtk overlay and the =--lrg= backend paint into =window_box TEXT_AREA=, the input layer maps clicks against that same box, and this hook sizes the FBO to match.  Any party on a different rect puts every click somewhere other than where it was aimed.  Both failure modes have shipped: before the hook existed nothing was clickable at all, and later the /paint/ used the full window rect against a text-area click mapping, so every node had to be clicked above and to the right of where it was drawn.
